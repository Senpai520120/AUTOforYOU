# Тест-кейсы E2E

Разбор всех автотестов Playwright: что проверяется, к какому типу относится, и чего не покрыто.

Backend-тесты (Django, 442 шт.) сюда не входят — они разобраны в [`BACKEND_TESTS.md`](BACKEND_TESTS.md).

## Как запускать

Тестам нужен поднятый стек — они ходят по настоящему сайту, а не по моку.

```powershell
cd D:\pyCharm\AUTOforYOU
docker compose up -d
```

Ждём, пока `backend` и `db` покажут `(healthy)`:

```powershell
docker compose ps
```

Дальше **обязательно из `frontend/`**:

```powershell
cd frontend
npx playwright test
```

Запуск из корня репозитория не сработает: там нет ни `node_modules`, ни конфига, и `npx` подтянет из реестра другую версию Playwright. Раннер и библиотека окажутся разными экземплярами, и прогон упадёт с `Playwright Test did not expect test.describe() to be called here`. Признак ошибки — пути вида `frontend\e2e\catalog.spec.ts` в выводе вместо `catalog.spec.ts:16:7`.

| Команда | Что делает |
|---|---|
| `npx playwright test` | Полный прогон |
| `npm run test:e2e:ui` | UI-режим: дерево тестов, watch, trace на лету |
| `npm run test:e2e:headed` | С видимым браузером |
| `npm run test:e2e:debug` | Инспектор с пошаговым выполнением и Pick locator |
| `npm run test:e2e:report` | Открыть HTML-отчёт последнего прогона |
| `npm run test:e2e:codegen` | Запись действий в код |
| `npx playwright test -g "текст"` | Только тесты, чьё имя содержит текст |
| `npx playwright show-trace <путь к trace.zip>` | Trace Viewer: таймлайн, DOM на каждом шаге, сеть, консоль |

Видео, trace и скриншот пишутся **только для упавших** тестов — `retain-on-failure` в конфиге. У зелёных артефактов нет.

## E2E: роли, фикстуры, `@e2e.test`, `@smoke`/`@mobile`, `fixme` (задачи 0.4 и 0.5)

Отдельный стек, боевой `.env` не используется (шаблон `.env.docker.example` + переменные e2e):

```powershell
cp .env.docker.example .env.e2e      # добавить E2E_SEED_ALLOWED=true, SECURE_SSL_REDIRECT=false (TLS в стеке нет) и E2E_PASSWORD=<случайный>
docker compose -p autoforyou-e2e --env-file .env.e2e up -d --build
docker compose -p autoforyou-e2e exec -T backend python manage.py e2e_seed
cd frontend; $env:E2E_PASSWORD="<тот же пароль>"; npx playwright test
docker compose -p autoforyou-e2e down -v
```

- **Проекты:** `setup` (ждёт `/` и `/api/v1/pricing/rates/` до 200, до 180 с; логинит 4 роли), `chromium` (всё, кроме `@mobile`), `mobile-chrome` (Pixel 7) и `mobile-safari` (iPhone 13) — только `@mobile`, `firefox` — только `@smoke`.
- **Роли:** `buyer`, `seller`, `dealer`, `staff` (`<role>@e2e.test`, пароль из `E2E_PASSWORD`). `storageState` пишется в `frontend/e2e/.auth/<role>.json` (в `.gitignore`).
- **Фикстуры** (`e2e/fixtures.ts`): `api(role)` — API-контекст с токеном; `uniqueEmail` — `e2e-<ts>-<worker>@e2e.test`; `asRole(role)` — путь к storageState. В спеке: `test.use({ storageState: storageStatePath('buyer') })`.
- **Теги:** `@smoke` в названии describe — публичные проверки (идут и в firefox); `@mobile` — мобильные сценарии.
- **Регистрация** в тестах — только на `@e2e.test`; чистка: `manage.py e2e_cleanup`.

Ручные проверки обхода:
1. Неверный пароль: `$env:E2E_PASSWORD="wrong"; npx playwright test --project=setup` — `вхід buyer` падает с сообщением «неправильний E2E_PASSWORD або не виконано e2e_seed».
2. Белый список: `$env:E2E_BASE_URL="https://example.com"; npx playwright test --list` — ошибка «не в білому списку»; с `E2E_ALLOW_REMOTE=1` конфиг загружается (только для `@smoke`).

## Тесты используют собственный seed, а не данные админки

Числа в тестах (комиссия Copart broker $5000 salvage = $504, customs value $6800 и т.п.) привязаны к placeholder-значениям, которые создают команды `seed_rates` и `seed_auction_fees` (`pricing/management/commands/`) внутри самого теста (`setUpTestData`). Тест работает на пустой тестовой БД, поэтому:

- правка тарифов в админке (боевая или dev-БД) тесты **не ломает** — тестовая БД с ними не пересекается;
- правка **seed-команд** (значения ставок в `seed_rates`, `seed_auction_fees`) тесты **ломает**: ожидаемые цифры в `pricing/tests.py` и `tests/test_e2e.py::TestCalculatorAPIE2E` надо менять вместе с seed;
- тесты, которым нужен нестандартный тариф, создают строки сами (`TestAuctionFeeBoundary`), а не опираются на seed.

E2E (Playwright) берёт данные из `e2e_seed`, а не из админки — см. раздел про роли выше.

## Изоляция

Backend-тесты не зависят от `.env`, не ходят в сеть и не делят кэш между классами: ключи провайдеров обнуляются, внешние соединения роняют тест, кэш чистится (задача 0.2). Подробности — в разделе «Изоляция» файла [`BACKEND_TESTS.md`](BACKEND_TESTS.md). Данные для тестов создаются фабриками `tests/factories.py` (задача 0.6).

## Как отличить настоящий тест от фальшиво-зелёного

Правило простое: **зелёный прогон ничего не доказывает**. Доказывает только то, что тест краснеет, когда проверяемое поведение ломается.

В этом проекте фальшиво-зелёные тесты уже были — три из девяти. Полезно помнить, как они выглядели.

**1. Локатор объявлен и не проверен**

```ts
test('demo banner is visible on catalog page', async ({ page }) => {
  await page.goto('/listings');
  const banner = page.locator('[role="alert"]');   // объявлен
  await expect(page.locator('main')).toBeVisible(); // а проверяется main
});
```

Тест зелёный всегда. Причём `DemoBanner` на `/listings` не рендерится вообще — проверять там было нечего.

**2. Действие обёрнуто в условие**

```ts
const submitBtn = page.locator('button[type="submit"]');
if (await submitBtn.count() > 0) {
  await submitBtn.click();
  await page.waitForTimeout(3000);
}
```

Исчезнет кнопка — тест останется зелёным. Плюс `waitForTimeout` вместо ожидания результата: три секунды на пустом месте.

**3. Бессмысленный ассерт**

```ts
await expect(page.locator('text=500')).not.toBeVisible();
```

Страница ошибки Django и Next так не выглядит. Проверка не сработает никогда.

### Приём: проверка мутацией

Перед тем как считать тест готовым — сломать проверяемое поведение и убедиться, что тест покраснел.

Так проверялись тесты калькулятора: из формы удалили **один** `htmlFor`, пересобрали контейнер, прогнали. Покраснели ровно два теста из пяти — те, что зависят от этого поля. Три остальных остались зелёными. После этого разметку восстановили.

Так же проверялись тесты SSR: каталоги откатили к клиентской версии — покраснели ровно два теста серверного рендера, домашняя и sitemap не затронуты.

### Приём: подтверждать причину, а не только следствие

Негативный тест, который проверяет только отсутствие результата, останется зелёным и тогда, когда форма сломалась целиком и не отправляется вообще.

```ts
await expect(page.getByRole('heading', { name: RESULT })).toHaveCount(0);   // следствие
expect(await price.evaluate((el: HTMLInputElement) => el.validity.rangeUnderflow)).toBe(true);  // причина
```

## Чего не покрыто и почему

| Что | Почему |
|---|---|
| Блок «Свіжі авто» на главной | Рендерится на сервере и только при наличии лотов. SSR-запрос нельзя перехватить через `page.route`, а проверка «якщо блок є, то...» была бы зелёной всегда. Подтверждается вручную и через `curl` по серверному HTML |
| Личный кабинет: действия (отправка сообщения, удаление, сделки) | Покрыто только открытие страниц на данных сида (0.5). Эндпоинты `me/*` не покрыты и backend-тестами (13-S2), так что кабинет в целом не имеет проверки ни на одном уровне |
| Оплата через LiqPay | Нужны реальные ключи и публичный HTTPS-адрес для колбэка |
| B2B-доска | Нужен верифицированный дилер в БД |
| Подача объявления целиком | Нужна модерация: объявление уходит в `pending` и не появляется в каталоге |
| Мобильная вёрстка | Есть smoke в `mobile-chrome`/`mobile-safari`; полная проверка — задача 6.1 |
| Другие браузеры | Firefox и WebKit не подключены |

## Что стоит добавить дальше

1. **Авторизованные сценарии.** Логин через API в `globalSetup`, сохранение `storageState` — тогда откроются кабинет, избранное, сообщения.
2. **Мобильный проект** в `playwright.config.ts` — сайт адаптивный, но это не проверяется.
3. **Полный цикл подачи объявления**: подача → модерация через API администратором → появление в каталоге.
4. **Визуальные снапшоты** ключевых страниц — ловят вёрстку, которую текстовые ассерты не видят.
