## Сверка с BRIEF.md

**Совпадает:**
- Калькулятор «аукцион + доставка + растаможка» (Бриф §1 п.1) — есть, цифры из БД (`pricing/views.py:160-251`).
- Тарифы — данные, редактируются в админке (Бриф §2) — все 8 справочников зарегистрированы (`pricing/admin.py:16-75`), с `valid_from/valid_to`.
- `is_estimate` возвращается всегда (Бриф §2 «тестовые данные помечены») — `pricing/views.py:341`.
- Отсутствие тарифа → понятная ошибка 422, а не выдуманные цифры (Бриф §2 «честный статус») — `pricing/views.py:273-277`.

**Противоречит:**
- Бриф §2: «После заполнения данных пометки исчезают автоматически». Сейчас `is_estimate=True` захардкожен (`pricing/views.py:335,341`, `pricing/calculator.py:140`), а демо-баннер зависит от переменной сборки фронта `NEXT_PUBLIC_DEMO_MODE` (по умолчанию включён, `frontend/components/ui/DemoBanner.tsx:4`). У тарифных моделей нет признака «проверено/демо», поэтому система не может сама понять, что владелец ввёл реальные ставки.
- Бриф §2 «внешние API через адаптеры с real + demo»: курс НБУ — прямой `urlopen` (`pricing/nbu.py:28-33`), demo-реализации и статуса интеграции нет. Сиды подкладывают фиксированный курс 41.50 / 0.92 (`pricing/management/commands/seed_rates.py:82-89`), на экране он выглядит как настоящий курс.
- CLAUDE.md «Бизнес-логика в calculator.py, не во views»: подбор тарифов, выбор брекета пенсионного сбора, фоллбэк курса (~100 строк) лежат во view (`pricing/views.py:160-251`).

**Не хватает:**
- **Главный бизнес-сценарий (Бриф §1):** заявки после расчёта нет вообще: ни модели, ни API, ни формы на `/calculator` (`frontend/components/calculator/CalcBreakdown.tsx:51-53` заканчивается номером расчёта и предупреждением). Брокер ничего не получает ни в Telegram, ни в админке, статусов нет.
- Роль broker (Бриф §3) отсутствует (`users/models.py:25-28`: buyer/dealer/admin), значит кабинета брокера со статусами тоже нет.
- Тарифы брокера (комиссия, услуги) как статьи расчёта отсутствуют (Бриф §2 «тарифы брокера»).
- Доставка по Украине до города/области не реализована: есть только «порт ЕС → UA» одной суммой.
- `docs/LAUNCH_CHECKLIST.md` отсутствует; прожиточный минимум, сетки и логистика не описаны как пункты для владельца.

- `pricing/tests.py` — 64 теста: возрастной коэффициент (6), акциз бензин/дизель/EV/PHEV, пошлина, НДС, итоги, Decimal-точность, нулевая цена, аукционные сборы (flat/%/границы/IAAI), граница тиров IAAI с БД, дефолты сериализатора, E2E-расчёт с БД (Copart broker $5000), инвалидация кэша (4), Celery-задача НБУ (2).
- `tests/test_e2e.py:145-256` — 9 тестов API `POST /calculate/` на сид-тарифах (201, поля, суммы, `is_estimate`, сохранение `Calculation`, 400).
- Playwright: `frontend/e2e/catalog.spec.ts:24-54` (демо-баннер на `/calculator`), `negative.spec.ts:86`, `test-1.spec.ts:28`.

**Не покрыто:**
- Ответ 422 при отсутствии тарифов; ответ 500 (и отсутствие утечки текста исключения).
- Выбор тарифа по `valid_from/valid_to` (истёкший/будущий тариф, перекрытие периодов).
- Фоллбэк курса на дату и выбор брекета пенсионного сбора на границах.
- `GET /rates/`.
- `/me/calculations/`: 401 для анонима и изоляция (пользователь A не видит расчёты B).
- Throttle калькулятора.
- EV через API без `battery_capacity_kwh`.

**Нужные сценарии:**
- Django: 422 со списком `missing`; тариф с `valid_to` в прошлом не применяется; при двух активных записях применяется самая новая; курс берётся ≤ `calculation_date`; пенсионный брекет на пороге 165×; `/me/calculations/` 401/изоляция; после появления заявки — создание заявки (валидация телефона, согласие), Telegram-уведомление брокеру (мок), доступ к заявкам по ролям 401/403, смена статуса брокером.
- Playwright: расчёт → форма заявки → успешная отправка; ошибка валидации телефона; EV с ёмкостью батареи; демо-баннер скрыт, когда все тарифы помечены проверенными; 422 показывает понятное сообщение «тарифы не настроены».

## Итог (≤15 строк)

Готовность пакета около 55%. Ядро калькулятора готово примерно на 85%: чистая функция, Decimal, тарифы в админке с периодами, JSON-снимок, `is_estimate`, кэш с инвалидацией. Главного сценария брифа нет.
- **02-Q1 (критично):** нет заявки после расчёта (имя/телефон/способ связи/параметры), нет мгновенного уведомления брокера в Telegram и админку, нет статусов заявки. Роли broker тоже нет (02-S6).
- Важные ошибки расчёта: пенсионный брекет выбирается по цене аукциона (02-Q2); акциз EV всегда 0 из UI (02-Q3); при перекрытии периодов побеждает старый или случайный тариф (02-Q4); фоллбэк курса берёт самый новый курс, а не предыдущий (02-Q5).
- Безопасность: `str(exc)` в ответе 500 (02-S1); анонимный калькулятор пишет в БД без отдельного throttle (02-S2).
- Бриф §2: пометки «демо» не исчезают автоматически (константа `is_estimate`, build-флаг баннера, 02-C2/C3); у курса НБУ нет demo-адаптера (02-C8).
- Бизнес-логика подбора тарифов лежит во view, а не в сервисе (02-Q6).
- Доставки по Украине до города нет, комиссии и услуг брокера в расчёте нет.
- Чужие `Calculation` через API не видны, но тестов 401 и изоляции нет.
