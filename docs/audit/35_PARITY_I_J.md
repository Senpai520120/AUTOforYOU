## Расхождения и находки этого пакета

1. **Адрес callback в LAUNCH_CHECKLIST неверный.** docs/LAUNCH_CHECKLIST.md:87 просит владельца прописать в кабинете LiqPay `https://ваш-домен/api/v1/payments/callback/`. Реальный маршрут — `payments/liqpay/callback/` (payments/urls.py:7). Задача 4.1 строит `server_url` из `SITE_URL` сама и говорит, что в кабинете ничего прописывать не нужно (4.1:72). Инструкции противоречат друг другу и обе отличаются от старого текста. Пункт I3.9.
2. **`PromotionTariff` без `valid_from`/`valid_to`.** CLAUDE.md, принцип 3, требует периоды для всех тарифов; в модели их нет (local_listings/models.py:38-51). ROADMAP.md:145 пишет «ближе всего к 4.1», но в файле 4.1 этого пункта нет (Grep `valid_from` по docs/tasks находит только 2.5 и 2.7 — калькулятор). Находка 05-C2 ни в какую задачу не взята. Пункт I1.5.
3. **Демо-цены без пометки.** Миграция local_listings/migrations/0004_seed_promotion_tariffs.py засевает 49/29/99/299 грн (05-C1); API не отмечает их как демо, оплата стартует с плейсхолдерами. LAUNCH_CHECKLIST:328 просит владельца заменить их, но программной защиты (нельзя принять деньги по демо-цене) нет. Пункт I1.6.
4. **Платное продление против Q9.** Владелец: продление бесплатное, без ограничения количества (`LISTING_FREE_RENEWALS`, 0 = без лимита, ANSWERS «шаг 4»). В коде и в 4.3 платный тариф RENEW остаётся (payments/views.py:33-39; 4.3:19-20), в базе он засеян. Если оставить активный RENEW в списке тарифов, платное «Продовжити» будет стоять рядом с бесплатным. Нужно решение: деактивировать RENEW (`active=False`) или сделать его иной услугой. Пункт I1.7. Тест 4.3:49 («второй раз → 400») также расходится с ANSWERS (0 = без лимита); это уже отмечено пакетом E4 (расхождение 2), здесь только напоминание.
5. **Формулировка «ТОП-блок».** Страница возврата обещает «Закріплення у ТОП-блоці каталогу» (frontend/app/refund/page.tsx:45), а реализовано поднятие в выдаче по `promoted_until` и значок «ТОП» (local_listings/filters.py:77-92, LocalListingCard.tsx:20-35), отдельного блока нет. Таблицу услуг после 6.4 строит API тарифов, но текст описания берётся из админки: владельцу не писать «блок», пока блока нет (пункт I1.2).
6. **`seller_type=dealer` доступен любому.** В форме тип продавца выбирает сам пользователь (local_listings/models.py:146-148), права и бейдж не привязаны к `is_verified_dealer`. Закрывает Н-10 (пакет E2); здесь нужен для J1.4 и I2.2.
7. **`listing_vip`/`listing_unlock` — не про C2C.** Эти назначения платежа относятся к импортному `Listing` пригона (payments/models.py:12-16), по Q13/Q14 отложены. «VIP-блок на главной» из эталона (I1.4) — отдельная услуга для C2C, с Q13 не смешивать: цену задаёт админка, как у `PromotionTariff`.
