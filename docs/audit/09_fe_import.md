## Сверка с BRIEF.md

| Пункт брифа | Статус | Комментарий |
|---|---|---|
| §1 Главный сценарий: расчёт → заявка (имя, телефон, способ связи, параметры) → брокер мгновенно | **противоречит** | Цепочка обрывается сразу после расчёта. Формы, эндпоинта и модели заявки нет (09-Q1) |
| §1 Каталог лотов | совпадает частично | SSR, фильтры и SEO есть. Фильтров мало, есть вопросы по фото (#11) |
| §1 Отслеживание контейнера | не хватает | Только список в кабинете, публичного трекинга нет |
| §1 B2B-доска для верифицированных | совпадает частично | Сервер закрыт корректно. На клиенте неверная проверка роли, карточки лотов недоступны (09-S2, 09-Q2) |
| §2 Тарифы в админке, без хардкода | противоречит частично | Суммы с сервера, но проценты пошлины/НДС и справочники портов/локаций/аукционов зашиты во фронт (09-C1, 09-C2). Эндпоинт `/api/v1/pricing/rates/` (`pricing/urls.py:7`) фронт не использует |
| §2 Демо-пометки исчезают автоматически после заполнения | противоречит | Баннер управляется флагом сборки `NEXT_PUBLIC_DEMO_MODE` (`components/ui/DemoBanner.tsx:4`), а не данными (09-C3) |
| §2 Честный статус «не настроено» | не хватает | Ответ 422 «Отсутствуют активные тарифы» показывается пользователю сырым JSON (09-Q6) |
| §3 JWT не в localStorage | противоречит (известно) | `api/client.ts:4,13,22,71`. Из-за этого B2B/дилерский контент нельзя отрисовать на сервере (`app/listings/WholesaleHint.tsx:9-12`) |
| §3 Согласие на обработку данных | совпадает для заявки дилера | `app/dealers/apply/page.tsx:127-143`, проверка есть и на сервере (`api/dealers.ts:9`). Для заявки после расчёта согласия нет, потому что нет самой заявки |
| §3 Нет утечек через SSR-HTML | совпадает в целом | В RSC-payload карточки попадает весь `Listing`, в том числе `seller` (id) и `calculation` (id) (09-S4) |
| §4 Этап 6: мобильная версия, пустые состояния, ошибки, SEO | частично | См. 09-Q10, 09-Q14, 09-Q15 |
| §5 Playwright на функцию | частично | Калькулятор и каталог покрыты. B2B, заявка дилера и карточка лота не покрыты |

**Django:** `listings/tests.py` (12 тестов, включая гейтинг B2B на detail-вьюхе), B2B/дилеры частично в `users/tests.py` и `tests/test_e2e.py` (число тестов именно по этим эндпоинтам не проверено).

**Нужные сценарии:**
- Playwright: расчёт → форма заявки → успешная отправка → экран «заявку получено, брокер свяжется» (успех). Отправка без согласия и без телефона блокируется (ошибка).
- Playwright: калькулятор при отсутствии тарифов (422) показывает понятное «не настроено», а не JSON.
- Playwright: электромобиль с ёмкостью батареи → акциз ≠ 0.
- Playwright: `/b2b` для гостя → редирект на `/login`. Для обычного пользователя → «Доступ обмежено». Для пользователя с `role=admin` без `is_staff` → «Доступ обмежено» (регресс 09-S2). Для верифицированного дилера → список, переход в лот не отдаёт 404 (09-Q2).
- Playwright: `/dealers/apply` повторная подача → видно сообщение о 409. Невалидный URL документов → видна ошибка поля.
- Playwright: `/listings` фильтр + пагинация сохраняют параметры. `/listings/<id>` содержит title/og:image/canonical, а canonical совпадает с URL из sitemap.
- Playwright (viewport 375px): калькулятор и разбивка без горизонтального скролла.
- Django: эндпоинт заявки (201, 400 без согласия, throttle, уведомление брокеру замокано), доступ к заявкам только брокеру/админу (401/403).
