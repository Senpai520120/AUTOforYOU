> Для владельца сайта. Здесь перечислено всё, что вы заполняете сами перед запуском (бриф §2):
> сервер и домен, ключи и адреса в файле `.env`, внешние аккаунты, таблицы в админке, тексты и реквизиты, вопросы юристу и бухгалтеру.
> Программировать ничего не нужно. Отмечайте пункты галочкой по мере выполнения.
>
> Источники: аудит `docs/audit/22_CONFIG.md`, план работ `ROADMAP.md`, вопросы `docs/QUESTIONS.md`, решения `docs/ANSWERS.md`,
> разделы «Для владельца» в `docs/tasks/*.md`. Перестроен на шаге 14 (пункт 5 промта 01). Часть пунктов помечена
> **«появится после задачи X.Y»**: сейчас вписать это значение некуда, поле появится, когда задача будет сделана.
> Итоговую сверку чек-листа с кодом делает задача 7.7 (команда `launch_check`).

## Две волны открытия сайта

Решение владельца (`docs/ANSWERS.md`, раздел «Порядок открытия сайта»):

- **ВОЛНА-1 — «Пригон».** Калькулятор, заявка брокеру, кабинет брокера, страницы доверия, каталог лотов, безопасность аккаунтов,
  юридический минимум, украинский язык, счётчики, мобильная версия, деплой, бэкапы, мониторинг. Раздел объявлений по Украине **скрыт флагом**.
- **ВОЛНА-2 — «Объявления по Украине».** Подача, фото, модерация, поиск, сделки, переписка, Telegram-канал. Включается флагом на уже работающем сайте.

Метки у пунктов:
- **[ВОЛНА-2]** — нужно только для объявлений по Украине; на ВОЛНУ-1 пропустите.
- **[ПЛАТЕЖИ]** — нужно только при включении платных услуг (`PAYMENTS_ENABLED=true`); на запуске платежи выключены.
- Без метки — нужно уже на ВОЛНЕ-1.

Условные обозначения:
- **Обязательно** — без этого сайт в проде не работает или небезопасен.
- **Если включаете функцию** — нужно, только если пользуетесь этой возможностью (оплата, бот, хранилище и т.п.).
- **Можно не трогать** — есть разумное значение по умолчанию.
- ⚠ — важное предупреждение: что сломается или что пока нельзя включать.
- *Где взять* и *Проверка* — у каждого пункта: откуда взять значение и как убедиться, что всё работает.

Порядок прохождения (следующий шаг опирается на предыдущий):

- [ ] **Шаг 1.** Раздел 0 (сразу), затем **раздел 1** (сервер, домен, DNS, HTTPS, мониторинг).
- [ ] **Шаг 2.** **Раздел 3** — завести внешние аккаунты и собрать ключи в менеджер паролей.
- [ ] **Шаг 3.** **Раздел 2** — файл `.env`. На сервере скопируйте шаблон `.env.docker.example` в `.env` и впишите значения. Файл `.env` никогда не отправляется в репозиторий и никому не пересылается.
- [ ] **Шаг 4.** Запуск: `docker compose up -d --build` (или `./deploy.sh --build`, задача 7.5). Флаг `--build` обязателен при первом запуске и после смены адреса сайта (адрес «вшивается» при сборке).
- [ ] **Шаг 5.** **Разделы 4 и 5** — админка: тарифы, реквизиты, тексты. Откройте `https://ваш-домен/admin/`.
- [ ] **Шаг 6.** **Раздел 6** — вопросы юристу и бухгалтеру (лучше закрыть до шага 5: реквизиты и сроки нужны для документов на сайте).
- [ ] **Шаг 7.** **Раздел 7** — финальная проверка и `docker compose exec backend python manage.py launch_check` (код 0 — сайт готов к открытию).

Если меняете что-то в `.env` потом: `docker compose up -d` (перезапуск). Если меняете адрес сайта — `docker compose up -d --build`.

## 1. Домен и сервер

- [ ] **Сервер (VPS)** с Docker и Docker Compose. Linux (Ubuntu 22.04/24.04 или Debian 12), минимум 2 vCPU, 4 ГБ RAM, 40 ГБ диска; SSH-доступ по ключу (задача 7.5).
  *Где взять:* любой хостинг; получить IP-адрес и SSH-доступ. Цена: платно (помесячно).
  *Проверка:* `ssh` на сервер работает, `docker compose version` отвечает; открыты порты 80 и 443.
- [ ] **Домен** и доступ к его DNS. Цена: платно (ежегодно у регистратора).
  *Где взять:* регистратор домена. Сделать: A-запись (и AAAA, если есть IPv6) на IP сервера; запись для `www.` — по желанию.
  *Куда:* адрес сайта в `.env` — `ALLOWED_HOSTS`, `CORS_ALLOWED_ORIGINS`, `SITE_URL`, `NEXT_PUBLIC_API_URL`, `NEXT_PUBLIC_SITE_URL`, `DOMAIN`.
  *Проверка:* `nslookup ваш-домен` возвращает IP сервера.
- [ ] **HTTPS-сертификат** Let's Encrypt. Цена: бесплатно. ⚠ Сейчас в веб-сервере нет настройки HTTPS (находка 12-S2) — **появится после задачи 7.1**; до этого сайт по https не откроется, а Telegram-webhook не заработает.
  *Где взять:* на сервере после `./deploy.sh --build` выполнить `./scripts/init-letsencrypt.sh` (задача 7.1); в `.env` — `TLS_MODE`, `LETSENCRYPT_EMAIL` (раздел 2.3).
  *Проверка:* `https://ваш-домен/` открывается с замком; `http://` сам переходит на `https://`.
- [ ] **Внешний uptime-мониторинг `/healthz` с оповещением в Telegram** (решение ANSWERS, шаг 9; задачи 7.3 и 7.6). Бесплатный сервис (UptimeRobot, Better Stack и т.п.): проверка `https://ваш-домен/healthz`, интервал 5 минут, оповещение в Telegram (бот или ваш чат). Сделать до открытия регистрации.
  *Где взять:* аккаунт на выбранном сервисе. `/healthz` должен быть доступен снаружи.
  *Проверка:* остановить `backend` (`docker compose stop backend`) — оповещение пришло в Telegram; запустить обратно.
- [ ] **Место для копий бэкапов вне сервера** (облачное хранилище, другой сервер) — решение владельца (ANSWERS, шаг 9; задача 7.4). Любой S3-совместимый сервис: Cloudflare R2, Backblaze B2, Hetzner Storage, AWS S3. Отдельный bucket и ключ только на запись в него. Цена: обычно платно, но недорого.
  *Куда:* переменные `BACKUP_S3_*` (раздел 2.10). Срок хранения копий согласовать с политикой конфиденциальности (раздел 6).
  *Проверка:* `./scripts/backup.sh --now` кладёт файл в `BACKUP_DIR` и в bucket.
- [ ] **Пароль шифрования бэкапов** хранить **вне сервера** (менеджер паролей). Без него бэкап из облака не восстановить (задача 7.4).
- [ ] **Автодеплой из GitHub — по желанию.** Только если хотите, чтобы сайт обновлялся сам. Настраивается **после задачи 7.5**.
  *Где взять:* секреты репозитория GitHub (Settings → Secrets): `SSH_HOST`, `SSH_USER`, `SSH_KEY`, `SSH_PORT`; Variables: `DEPLOY_ENABLED=true`, `DEPLOY_PATH` (каталог проекта на сервере). Без них деплой вручную: `./deploy.sh --pull --build`.
  *Проверка:* пуш в основную ветку запускает деплой; решить, делать ли `infra-lint` обязательной проверкой в branch protection (задача 7.5).
- [ ] **Права на тома при обновлении сервера, где стек уже работал от root** (задача 7.3) — команда смены владельца volumes появится в `deploy.sh` (7.5). *Проверка:* контейнеры стартуют без ошибок прав.

## 2. Переменные `.env`

Для каждой переменной: обязательна ли в проде, что это, где взять, как проверить.
Шаблон — `.env.docker.example`. Переменные с пометкой «можно не трогать» в шаблоне может не быть — добавляйте строку, только если хотите изменить значение.
Переменные с пометкой «появится после задачи» вписать сейчас некуда.

### 2.1. Основное и безопасность

- [ ] `SECRET_KEY` — **обязательно**. Секретный ключ сайта, подписывает входы и ссылки. Длинная случайная строка (не короче 50 символов, задача 7.2).
  *Где взять:* сгенерировать один раз: `docker compose run --rm backend python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"`. Никому не показывать, не менять без необходимости (все пользователи разлогинятся).
  *Проверка:* `docker compose exec backend python manage.py check --deploy` не ругается на SECRET_KEY.
- [ ] `DEBUG` — **обязательно `false`**. При `true` посетители видят внутренности сайта при ошибках, защита выключена.
  *Проверка:* несуществующая страница `https://ваш-домен/api/v1/нет-такой/` отдаёт короткую ошибку без технических подробностей.
- [ ] `ALLOW_DEBUG_ON_PUBLIC_HOST` — **никогда не ставить `true` на проде** (задача 7.2). *Проверка:* переменной нет в `.env` или она `false`.
- [ ] `ALLOWED_HOSTS` — **обязательно**. Адреса, на которых сайт отвечает, через запятую, без `https://`: `ваш-домен.ua,www.ваш-домен.ua`.
  ⚠ Если пусто — сайт отвечает ошибкой 400 на всё. *Проверка:* `https://ваш-домен/api/v1/` открывается без ошибки 400.
- [ ] `CORS_ALLOWED_ORIGINS` — **обязательно**. С каких адресов браузеру разрешено обращаться к API, полный адрес с `https://`: `https://ваш-домен.ua,https://www.ваш-домен.ua`.
  *Проверка:* вход в личный кабинет проходит без ошибок.
- [ ] `CORS_ALLOW_ALL_ORIGINS` — **обязательно `false`**. При `true` любой чужой сайт сможет действовать от имени ваших пользователей. Скрипт `deploy.sh` откажется запускаться при `true`.
- [ ] `CSRF_TRUSTED_ORIGINS` — **обязательно** (задача 1.3): `https://<домен>`, при необходимости `https://www.<домен>`. *Проверка:* вход и выход через сайт работают.
- [ ] `AUTH_COOKIE_SECURE` — **обязательно `true`** на проде (задача 1.3, нужен HTTPS, задача 7.1). *Проверка:* DevTools → Application → Cookies: у cookie входа стоят `Secure` и `HttpOnly`.
- [ ] `AUTH_COOKIE_DOMAIN` — пусто, если сайт и API на одном домене (задача 1.3). Можно не трогать.
- [ ] `SECURE_SSL_REDIRECT` — **обязательно `true`** (по умолчанию так и есть). Перенаправлять с http на https; `false` — только если https делает внешний балансировщик.
  ⚠ Пока нет HTTPS (до задачи 7.1), с `true` сайт уводит на несуществующий https-адрес.
  *Проверка:* `http://ваш-домен/` автоматически открывается как `https://ваш-домен/`.
- [ ] `SITE_URL` — **обязательно**. Адрес сайта для ссылок в письмах, постах Telegram и LiqPay: `https://ваш-домен.ua` (без `/` в конце).
  ⚠ Если пусто — ссылки ведут на чужой домен `autoforyou.ua`.
  *Проверка:* ссылка в письме о модерации и в посте канала ведёт на ваш сайт.
- [ ] `NUM_PROXIES` — **обязательно** (задача 1.5): `1` — сайт за nginx из `docker-compose`; `2` — если перед nginx есть ещё балансировщик или Cloudflare (тогда настроить `real_ip` в nginx).
  ⚠ Неверное значение ломает лимит по IP (в том числе лимит показа телефона гостю, задача 4.5). *Проверка:* повторные неверные входы блокируются по вашему IP, а не по IP nginx.
- [ ] `JWT_ACCESS_MINUTES` / `JWT_REFRESH_DAYS` — можно не трогать (задача 1.3; по умолчанию 15 и 7): как долго пользователь остаётся залогиненным.
- [ ] `PASSWORD_RESET_TIMEOUT` — можно не трогать (задача 1.7): сколько действует ссылка сброса пароля.
- [ ] `THROTTLE_PASSWORD_RESET_RATE` — можно не трогать (задача 1.7).
- [ ] `THROTTLE_LOGIN_RATE`, `THROTTLE_REGISTER_RATE`, `THROTTLE_REFRESH_RATE`, `LOGIN_MAX_FAILURES`, `LOGIN_FAILURE_WINDOW_MINUTES`, `LOGIN_LOCKOUT_MINUTES` — можно не трогать (задача 1.5; есть значения по умолчанию).
- [ ] `EMAIL_VERIFICATION_REQUIRED` — **`true`** (задача 1.6, подтверждение email при регистрации); `EMAIL_VERIFY_TTL_HOURS` — по желанию. *Проверка:* регистрация нового тестового пользователя присылает письмо со ссылкой.
- [ ] `THROTTLE_DATA_EXPORT_RATE` — можно не трогать (задача 1.8, выгрузка данных профиля).
- [ ] `E2E_SEED_ALLOWED` — **на проде не задавать** (или `false`) (задача 0.4). *Проверка:* `docker compose exec backend python manage.py e2e_seed` на проде падает с `CommandError`. `E2E_PASSWORD` на проде не нужен.

### 2.2. База данных, кэш, очереди

- [ ] `COMPOSE_PROJECT_NAME` — **обязательно**, значение `autoforyou`. Имя проекта Docker; если его нет или оно другое, Docker создаст новую пустую базу рядом со старой.
  В `.env.docker.example` строки нет — добавьте вручную (находка 12-C7). *Проверка:* `docker volume ls` показывает тома с началом `autoforyou_`.
- [ ] `POSTGRES_DB` — **обязательно** (можно оставить `autoforyou`). Имя базы данных.
- [ ] `POSTGRES_USER` — **обязательно** (можно оставить `postgres`). Пользователь базы.
- [ ] `POSTGRES_PASSWORD` — **обязательно**. Случайный, не короче 24 символов; пароли из шаблона `deploy.sh` не пропустит.
  *Проверка:* `docker compose ps` — сервис `db` в статусе healthy.
- [ ] `DATABASE_URL` — **обязательно**. Собирается из трёх значений выше: `postgres://ПОЛЬЗОВАТЕЛЬ:ПАРОЛЬ@db:5432/ИМЯ_БАЗЫ`.
  ⚠ Если пусто — сайт пишет данные во временный файл внутри контейнера, и они пропадут при обновлении.
  *Проверка:* `docker compose exec backend python manage.py showmigrations` выполняется без ошибок.
- [ ] `REDIS_URL` — **обязательно**, значение `redis://redis:6379/0`. Очередь фоновых задач и кэш (курс НБУ, рассылки, снятие просроченных объявлений, дедупликация просмотров).
  ⚠ Если пусто — фоновые задачи не выполняются. **[ВОЛНА-2]** Для объявлений Redis как кэш обязателен (задача 8.8).
  *Проверка:* `docker compose logs celery_worker` — видны принятые задачи.
- [ ] `REDIS_PASSWORD` — **появится после задачи 7.3/7.5** (пароль для очереди) и новый формат `REDIS_URL`.
- [ ] `CELERY_EAGER` — **появится после задачи 0.2**. В проде `false` или не указывать.
- [ ] `FAILED_TASK_RETENTION_DAYS`, `CELERY_TASK_MAX_RETRIES`, `CELERY_TASK_ACKS_LATE` — значения по умолчанию задаёт код, подтвердить при приёмке (задача 8.9). *Проверка:* админка → «Невдалі завдання» пуста (раз в неделю смотреть: непустой список означает, что письмо, сообщение или заявка не дошли).

### 2.3. Веб-сервер, HTTPS, сборка

- [ ] `NGINX_PORT` — можно не трогать (`80`).
- [ ] `GUNICORN_WORKERS` — можно не трогать (`3`). На сервере с N процессорами разумно `2×N+1` (задача 7.3).
- [ ] `GUNICORN_TIMEOUT`, `GUNICORN_MAX_REQUESTS` — можно не трогать (задача 7.3; сейчас 120 зашито в `docker/entrypoint.sh`, находка 12-C10).
- [ ] `DOMAIN` — **появится после задачи 7.1/7.5**: имя домена для веб-сервера и сертификата (сейчас в настройке веб-сервера стоит `localhost`, находка 12-C3). `DOMAIN_WWW` — `true`/`false`.
- [ ] `TLS_MODE` — **появится после задачи 7.1**: `letsencrypt` (или `external`, если TLS даёт провайдер или Cloudflare). `LETSENCRYPT_EMAIL` — email для уведомлений об истечении сертификата; `LETSENCRYPT_STAGING=false`.
- [ ] `HSTS_MAX_AGE`, `HSTS_INCLUDE_SUBDOMAINS`, `HSTS_PRELOAD` — **появятся после задачи 7.1**. Preload включать, только если все поддомены навсегда на https; отменить почти невозможно (решение — раздел 5.7 «HSTS preload»).
- [ ] `CSP_REPORT_ONLY` — **появится после задачи 7.1**: первую неделю можно `true`, затем `false`.
- [ ] `CSP_SCRIPT_SRC_EXTRA`, `CSP_CONNECT_SRC_EXTRA`, `CSP_FRAME_SRC_EXTRA`, `CSP_IMG_SRC_EXTRA` (и прочие `CSP_*_EXTRA`) — **появятся после задачи 7.1**: сюда добавляются домены Cloudflare Turnstile, GA4, пикселей Meta/TikTok и S3/R2, когда включаются (точные домены — по документации провайдеров, не из кода). *Проверка:* в режиме `CSP_REPORT_ONLY=true` нет нарушений, затем включить.
- [ ] `NGINX_MAX_BODY_SIZE`, `NGINX_AUTH_RATE` — можно не трогать (задача 7.1).
- [ ] `PORT` и `INTERNAL_API_URL` — **не менять и не заполнять**: заданы в Docker (`8000` и `http://backend:8000`), только для справки.
- [ ] `LOG_LEVEL` (обычно `INFO`), `LOG_MAX_SIZE`, `LOG_MAX_FILES`, `LOG_RETENTION_DAYS` (по ответу владельца 90) — задача 7.2. *Проверка:* логи пишутся и ротируются.
