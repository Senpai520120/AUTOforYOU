# Чек-лист запуска AUTOforYOU

> Для владельца сайта. Здесь перечислено всё, что вы заполняете сами перед запуском (бриф §2):
> ключи и адреса в файле `.env`, таблицы в админке, внешние аккаунты и решения, которые за вас никто не примет.
> Программировать ничего не нужно. Отмечайте пункты галочкой по мере выполнения.
>
> Источники: аудит `docs/audit/22_CONFIG.md`, план работ `ROADMAP.md`, вопросы `docs/QUESTIONS.md`.
> Составлен 2026-09-26, по состоянию кода до начала работ по ROADMAP. Часть пунктов помечена
> **«появится после задачи X.Y»**: сейчас вписать это значение некуда, поле появится, когда задача будет сделана.
> Итоговую сверку чек-листа с кодом делает задача 7.7.

Условные обозначения:
- **Обязательно** — без этого сайт в проде не работает или небезопасен.
- **Если включаете функцию** — нужно, только если пользуетесь этой возможностью (оплата, бот, хранилище и т.п.).
- **Можно не трогать** — есть разумное значение по умолчанию.
- ⚠ — важное предупреждение: что сломается или что пока нельзя включать.

## 1. Как пользоваться чек-листом

Порядок важен: следующий шаг опирается на предыдущий.

- [ ] **Шаг 1. Внешние аккаунты** (раздел 2). Заводите аккаунты и собираете ключи в менеджер паролей.
- [ ] **Шаг 2. Файл `.env`** (раздел 3). На сервере скопируйте шаблон `.env.docker.example` в файл `.env` и впишите значения.
  Файл `.env` никогда не отправляется в репозиторий и никому не пересылается.
- [ ] **Шаг 3. Запуск.** На сервере в папке проекта: `docker compose up -d --build`.
  Флаг `--build` обязателен при первом запуске и после любой смены адреса сайта (адрес «вшивается» в сайт при сборке).
- [ ] **Шаг 4. Админка** (раздел 4). Откройте `https://ваш-домен/admin/`, войдите суперпользователем и заполните таблицы.
- [ ] **Шаг 5. Решения и данные** (раздел 5) — желательно закрыть до шага 4, потому что реквизиты и сроки нужны для документов на сайте.
- [ ] **Шаг 6. Финальная проверка** (раздел 6). Запуск — только когда отмечены все пункты.

Если меняете что-то в `.env` потом: `docker compose up -d` (перезапуск). Если меняете адрес сайта — `docker compose up -d --build`.

## 2. Внешние аккаунты

Для каждого сервиса: что завести → что получить → куда вписать → сколько стоит.
Цены — ориентировочные на момент составления; проверяйте на сайте сервиса.

### Обязательные

- [ ] **Сервер (VPS)** с Docker и Docker Compose.
  Получить: IP-адрес, доступ по SSH. Куда: IP — в DNS домена (следующий пункт).
  Цена: платно (помесячно у хостинга).
- [ ] **Домен** и доступ к его DNS.
  Сделать: A-запись (и AAAA, если есть IPv6) на IP сервера; запись для `www.` — по желанию.
  Куда: адрес сайта в `.env` — `ALLOWED_HOSTS`, `CORS_ALLOWED_ORIGINS`, `SITE_URL`, `NEXT_PUBLIC_API_URL`, `NEXT_PUBLIC_SITE_URL`.
  Цена: платно (ежегодно у регистратора).
- [ ] **HTTPS-сертификат** Let's Encrypt.
  Цена: бесплатно. ⚠ Сейчас в веб-сервере нет настройки HTTPS (находка 12-S2) — **появится после задачи 7.1**.
  До этого сайт по https не откроется, а Telegram-webhook не заработает.
- [ ] **Почтовый сервис для писем сайта (SMTP)**: Brevo, Mailgun, Amazon SES или Gmail с паролем приложения.
  Получить: адрес сервера, порт, логин, пароль. Куда: переменные `EMAIL_*` в `.env`.
  Сделать в DNS домена: записи SPF, DKIM, DMARC по инструкции провайдера, иначе письма попадут в спам.
  Цена: у большинства есть бесплатный тариф с ограничением писем в день.
- [ ] **Место для копий бэкапов вне сервера** (облачное хранилище, другой сервер).
  Куда: **появится после задачи 7.4** (скрипта бэкапа сейчас нет, находка 12-S6). Цена: обычно платно, но недорого.

### Telegram (бесплатно)

- [ ] **Бот** — уже есть; новый токен получен в разделе 0.
  Куда: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` (имя бота без `@`).
- [ ] **Публичный канал** для объявлений. Добавить бота администратором с правом публикации.
  Получить: `@имя_канала` или числовой ID вида `-100…`. Куда: `TELEGRAM_CHANNEL_ID`.
- [ ] **Закрытый B2B-канал** для проверенных перекупщиков. Бот — администратор.
  Куда: `TELEGRAM_B2B_CHANNEL_ID`. ⚠ Если не заполнить, оптовые лоты уйдут в публичный канал (находка 07-S2).
- [ ] **Чат брокера для заявок** (группа или личный чат брокера с ботом).
  Получить: chat_id. Куда: **появится после задачи 2.2** (переменная `TELEGRAM_BROKER_CHAT_ID` или настройка в админке).

### Оплата

- [ ] **LiqPay** — мерчант-аккаунт (оформляется на ФОП или ТОВ, нужны реквизиты из раздела 5).
  Получить: публичный и приватный ключ (кабинет LiqPay → API). Куда: `LIQPAY_PUBLIC_KEY`, `LIQPAY_PRIVATE_KEY`.
  В кабинете LiqPay указать адрес уведомлений об оплате: `https://ваш-домен/api/v1/payments/callback/`.
  Цена: регистрация бесплатно, комиссия с каждого платежа по тарифу LiqPay.
  ⚠ Реальные платежи включать только **после задачи 4.1** (сейчас подпись платежа можно подделать — находка 06-S1).

### Защита от ботов

- [ ] **Cloudflare Turnstile** (или hCaptcha — решение в вопросе Q2).
  Получить: ключ сайта и секретный ключ. Куда: **появится после задачи 1.6** (переменные `CAPTCHA_*`).
  Цена: бесплатно.

### Мониторинг ошибок

- [ ] **Sentry или GlitchTip** — проект для сайта.
  Получить: DSN (адрес проекта). Куда: **появится после задачи 7.6** (переменная `SENTRY_DSN`).
  Цена: есть бесплатный тариф.

### Данные об автомобилях

- [ ] **Источник лотов Copart/IAAI** (сейчас — Apify и выбранный «актор»).
  Получить: API-токен и ID актора. Куда: `APIFY_TOKEN`; ID актора — **появится после задачи 3.3** (`APIFY_ACTOR_ID`).
  Цена: платно по объёму (есть небольшой бесплатный лимит). Права на показ фото — решение в разделе 5.
- [ ] **Opendatabot** (проверка по госреестрам Украины) — API-подписка.
  Куда: `OPENDATABOT_API_KEY`. Цена: платно.
  ⚠ Не вписывать ключ **до задачи 1.1**: сейчас при ошибке ключ показывается пользователю (находка 03-S1).
- [ ] **carVertical** (отчёт по VIN) — партнёрский API-аккаунт.
  Куда: **появится после задачи 3.2** (`CARVERTICAL_API_KEY`, `VIN_REPORT_PROVIDER`). Цена: платно, условия — у партнёрской программы.
- [ ] **НБУ (курс валют) и NHTSA (расшифровка VIN)** — аккаунт не нужен, ключей нет, бесплатно. Только проверка в разделе 6.

### По желанию

- [ ] **Хранилище фото S3 / Cloudflare R2** — если не хотите хранить фото на самом сервере.
  Получить: имя бакета, регион, ключ доступа, секрет, адрес (для R2). Куда: `S3_*`, `AWS_*`.
  Цена: платно по объёму (у R2 есть бесплатный лимит).
  ⚠ Не включать **до задачи 7.2**: сейчас при заполнении этих полей ссылки на фото ломаются (находки 01-C1, 01-C2).
- [ ] **Автодеплой из GitHub** — только если хотите, чтобы сайт обновлялся сам после изменений в репозитории.

## 3. Переменные `.env` по сервисам

Для каждой переменной: обязательна ли в проде, что это, где взять, как проверить.
Шаблон — `.env.docker.example`. Переменные с пометкой «можно не трогать» в шаблоне может не быть — добавляйте строку, только если хотите изменить значение.

### 3.1. Основное и безопасность

- [ ] `SECRET_KEY` — **обязательно**.
  Что: секретный ключ сайта, которым подписываются входы и ссылки. Длинная случайная строка.
  Где взять: сгенерировать один раз командой
  `docker compose run --rm backend python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"`.
  Никому не показывать, не менять без необходимости (все пользователи разлогинятся).
  Проверка: `docker compose exec backend python manage.py check --deploy` не ругается на SECRET_KEY.
- [ ] `DEBUG` — **обязательно `false`**.
  Что: режим разработчика. При `true` посетители видят внутренности сайта при ошибках, а защита выключается.
  Проверка: откройте несуществующую страницу `https://ваш-домен/api/v1/нет-такой/` — должна быть короткая ошибка без технических подробностей.
- [ ] `ALLOWED_HOSTS` — **обязательно**.
  Что: адреса, на которых сайт отвечает. Через запятую, без `https://`: `ваш-домен.ua,www.ваш-домен.ua`.
  ⚠ Если пусто — сайт отвечает ошибкой 400 на всё.
  Проверка: `https://ваш-домен/api/v1/` открывается без ошибки 400.
- [ ] `CORS_ALLOWED_ORIGINS` — **обязательно**.
  Что: с каких адресов браузеру разрешено обращаться к API. Полный адрес с `https://`: `https://ваш-домен.ua,https://www.ваш-домен.ua`.
  Проверка: вход в личный кабинет на сайте проходит без ошибок.
- [ ] `CORS_ALLOW_ALL_ORIGINS` — **обязательно `false`**.
  Что: «разрешить всем сайтам». При `true` любой чужой сайт сможет действовать от имени ваших пользователей. Скрипт `deploy.sh` откажется запускаться при `true`.
- [ ] `SECURE_SSL_REDIRECT` — **обязательно `true`** (по умолчанию так и есть).
  Что: перенаправлять посетителей с http на https. `false` — только если https делает внешний балансировщик.
  ⚠ Пока нет HTTPS (до задачи 7.1), с `true` сайт уводит на несуществующий https-адрес.
  Проверка: `http://ваш-домен/` автоматически открывается как `https://ваш-домен/`.
- [ ] `SITE_URL` — **обязательно**.
  Что: адрес сайта для ссылок в письмах и постах Telegram: `https://ваш-домен.ua` (без `/` в конце).
  ⚠ Если пусто — ссылки ведут на чужой домен `autoforyou.ua`.
  Проверка: ссылка в письме о модерации и в посте канала ведёт на ваш сайт.

### 3.2. База данных, кэш, очереди

- [ ] `COMPOSE_PROJECT_NAME` — **обязательно**, значение `autoforyou`.
  Что: имя проекта Docker. Если его нет или оно другое, Docker создаст новую пустую базу рядом со старой.
  В `.env.docker.example` этой строки нет — добавьте вручную (находка 12-C7).
  Проверка: `docker volume ls` показывает тома с началом `autoforyou_`.
- [ ] `POSTGRES_DB` — **обязательно** (можно оставить `autoforyou`). Имя базы данных.
- [ ] `POSTGRES_USER` — **обязательно** (можно оставить `postgres`). Пользователь базы.
- [ ] `POSTGRES_PASSWORD` — **обязательно**.
  Что: пароль базы. Сгенерируйте случайный, не короче 24 символов. Пароли из шаблона `deploy.sh` не пропустит.
  Проверка: `docker compose ps` — сервис `db` в статусе healthy.
- [ ] `DATABASE_URL` — **обязательно**.
  Что: адрес базы для сайта, собирается из трёх значений выше: `postgres://ПОЛЬЗОВАТЕЛЬ:ПАРОЛЬ@db:5432/ИМЯ_БАЗЫ`.
  ⚠ Если пусто — сайт пишет данные во временный файл внутри контейнера, и они пропадут при обновлении.
  Проверка: `docker compose exec backend python manage.py showmigrations` выполняется без ошибок.
- [ ] `REDIS_URL` — **обязательно**, значение `redis://redis:6379/0`.
  Что: очередь фоновых задач (курс НБУ, рассылки по сохранённым поискам, снятие просроченных объявлений).
  ⚠ Если пусто — фоновые задачи по расписанию не выполняются.
  Проверка: `docker compose logs celery_worker` — видны принятые задачи.
- [ ] `REDIS_PASSWORD` — **появится после задачи 7.3/7.5** (пароль для очереди, если она будет доступна по сети).

### 3.3. Веб-сервер

- [ ] `NGINX_PORT` — можно не трогать (`80`).
- [ ] `GUNICORN_WORKERS` — можно не трогать (`3`). На сервере с N процессорами разумно `2×N+1`.
- [ ] `DOMAIN` — **появится после задачи 7.1/7.5**: имя домена для веб-сервера и сертификата (сейчас в настройке веб-сервера стоит `localhost`, находка 12-C3).

### 3.4. Адрес сайта для страниц (фронтенд)

⚠ Эти значения «вшиваются» в сайт при сборке. После их изменения обязательно `docker compose up -d --build`.

- [ ] `NEXT_PUBLIC_API_URL` — **обязательно**: `https://ваш-домен.ua`.
  Что: куда страницы сайта обращаются за данными.
  ⚠ Если пусто — у посетителей сайт будет пытаться обращаться к их собственному компьютеру и не заработает.
  Проверка: каталог и калькулятор на сайте показывают данные.
- [ ] `NEXT_PUBLIC_SITE_URL` — **обязательно**: `https://ваш-домен.ua`.
  Что: адрес сайта для поисковиков и превью ссылок.
  Проверка: `https://ваш-домен/sitemap.xml` содержит ссылки на ваш домен.
- [ ] `NEXT_PUBLIC_DEMO_MODE` — **если включаете функцию**.
  Что: показывать ли баннер «демо» в калькуляторе. ⚠ Сейчас выключить его через `.env` в Docker нельзя (находка 12-C2).
  **После задачи 2.6** баннер будет исчезать сам, когда в админке тарифы отмечены как проверенные, и переменная не понадобится.

### 3.5. Почта (SMTP)

- [ ] `EMAIL_BACKEND` — **обязательно**: `django.core.mail.backends.smtp.EmailBackend`.
  ⚠ Если не задать — письма никуда не отправляются, а молча пишутся в журнал сервера.
- [ ] `EMAIL_HOST` — **обязательно**. Адрес SMTP-сервера из кабинета почтового сервиса.
- [ ] `EMAIL_PORT` — **обязательно**. Обычно `587`.
- [ ] `EMAIL_USE_TLS` — **обязательно** `true` (для порта 587).
- [ ] `EMAIL_HOST_USER` — **обязательно**. Логин SMTP.
- [ ] `EMAIL_HOST_PASSWORD` — **обязательно**. Пароль SMTP (или пароль приложения).
- [ ] `DEFAULT_FROM_EMAIL` — **обязательно**. Адрес отправителя на вашем домене, например `noreply@ваш-домен.ua`.
  ⚠ Два типа писем пока отправляются с чужого адреса независимо от настройки (находка 01-C3) — исправляется в задаче 3.4.
- [ ] Проверка всей группы: `docker compose exec backend python manage.py sendtestemail ваш@email` — письмо пришло и не в спам.
- [ ] `PASSWORD_RESET_TIMEOUT` — **появится после задачи 1.7** (сколько действует ссылка сброса пароля; есть значение по умолчанию).

### 3.6. LiqPay (платное продвижение объявлений)

- [ ] `LIQPAY_PUBLIC_KEY` — **если включаете оплату**. Публичный ключ из кабинета LiqPay.
- [ ] `LIQPAY_PRIVATE_KEY` — **если включаете оплату**. Приватный ключ. Никому не показывать.
  ⚠ Сейчас без приватного ключа любой может подделать сообщение «оплачено» (находка 06-S1, критично). До задачи 4.1 оплату не открывать.
  ⚠ В `.env.example` стоят ненастоящие «заглушки» — их нужно либо заменить настоящими ключами, либо стереть (оставить пустыми).
- [ ] `LIQPAY_SANDBOX` — **обязательно**: `true` (тестовые платежи), пока не проверена тестовая оплата и не сделана задача 4.1. Потом — `false`.
  Проверка: тестовая оплата продвижения в sandbox проходит, в админке платёж в статусе «completed».
- [ ] `LIQPAY_SERVER_URL` — **может появиться после задачи 4.1** (адрес уведомлений об оплате; скорее всего будет строиться из `SITE_URL` автоматически).

### 3.7. Telegram

- [ ] `TELEGRAM_BOT_TOKEN` — **если включаете бота**. Новый токен из раздела 0 (не старый!).
  Если пусто — бот не запускается, сайт при этом работает.
  Проверка: `docker compose logs bot` без ошибок; на `/start` бот отвечает.
- [ ] `TELEGRAM_BOT_USERNAME` — **если включаете бота**. Имя бота без `@`.
  Проверка: в личном кабинете, раздел Telegram, ссылка открывает именно ваш бот.
- [ ] `TELEGRAM_CHANNEL_ID` — **если публикуете в канал**. `@имя_канала` или `-100…`.
  Проверка: одобренное объявление появляется в канале.
- [ ] `TELEGRAM_B2B_CHANNEL_ID` — **обязательно, если заполнен `TELEGRAM_CHANNEL_ID`**. Закрытый канал перекупщиков.
  ⚠ Если пусто — оптовые лоты публикуются в общем канале.
- [ ] `TELEGRAM_WEBHOOK_SECRET` — **обязательно для бота на сервере**. Случайная строка от 32 символов (генерируется так же, как пароль).
