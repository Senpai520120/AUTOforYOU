## Задача

Провести полный детальный аудит репозитория AUTOforYOU и по его итогам составить ROADMAP.md
и файлы задач. **Код проекта не менять.** Разрешено создавать и редактировать файлы только в
`docs/audit/`, `docs/tasks/`, а также `ROADMAP.md` и `docs/LAUNCH_CHECKLIST.md`.
Можно запускать тесты и сборку, чтобы узнать текущее состояние, но не исправлять их.

## Как беречь контекст (обязательно)

- Работай **пакетами**. Каждый пакет выполняет **отдельный субагент**: он полностью читает все файлы
  своего пакета (кроме миграций — у них только список и назначение) и пишет отчёт в файл.
- В основной контекст субагент возвращает **только раздел «Итог» (не больше 15 строк)**.
  Детали остаются в файле.
- После каждого пакета обнови `docs/audit/STATUS.md`: пакет, статус (готово/в процессе), файл отчёта,
  дата. Это точка восстановления после `/clear`.
- Не читай в основном контексте то, что уже разобрал субагент. Для сводки используй файлы отчётов.

Отчёт каждого пакета — `docs/audit/<№>_<название>.md` по шаблону:

```
# Аудит: <пакет>
## Состав
Файлы, модели, эндпоинты/страницы (с путями).
## Функции
Таблица: функция | состояние (готово / частично / заглушка / сломано / отсутствует) | файл:строки | комментарий.
## Сверка с BRIEF.md
Совпадает / противоречит / не хватает — по пунктам брифа.
## Безопасность и личные данные
Конкретные проблемы с файлом и строкой, уровень: критично / важно / желательно.
## Готовность к конфигурации
Всё хардкодное (цены, ставки, ключи, контакты, URL, тексты), что должно уйти в .env или админку.
Все заглушки, TODO, placeholder, demo-данные.
## Качество кода
Дублирование, ошибки, мёртвый код, N+1-запросы, отсутствующие индексы, обработка ошибок.
## Тесты
Что покрыто, что нет, какие Playwright-сценарии нужны.
## Итог (≤15 строк)
Главное для сводки.
```

## Фаза C — сквозные проверки (по отчётам + точечно по коду)

- `docs/audit/20_SCENARIOS.md` — пройди по коду сценарии от начала до конца и отметь, где каждый рвётся:
  регистрация → подтверждение email → вход → сброс пароля → удаление аккаунта;
  калькулятор → заявка → уведомление брокеру → работа брокера со статусом;
  подача объявления → модерация → публикация → поиск → показ телефона → переписка → сделка → продвижение с оплатой;
  дилер: заявка → верификация → B2B-доска;
  контейнер: создание → смена статусов → уведомления клиенту;
  бот: команды, уведомления, публикация в канал.
- `docs/audit/21_SECURITY.md` — сводка по разделу 3 брифа: что выполнено, что нет, с файлами.
- `docs/audit/22_CONFIG.md` — полный список того, что владелец должен будет заполнить
  (переменные `.env`, модели в админке, внешние аккаунты). Это черновик `LAUNCH_CHECKLIST.md`.
- `docs/audit/23_TESTS.md` — карта покрытия и список недостающих Playwright- и Django-тестов.

Запусти `python manage.py test` и `npm run build` (и e2e, если среда позволяет) и запиши фактический
результат. Ничего не исправляй.

## Фаза D — план и задачи

1. `docs/AUDIT_SUMMARY.md` — общая картина (1–2 страницы): процент готовности по направлениям,
   топ-15 критичных проблем, противоречия брифу.
2. `ROADMAP.md` — этапы 0–7 из брифа, в каждом задачи размером 1–3 сессии, с чек-боксами,
   номерами и зависимостями. Порядок внутри этапа: сначала то, от чего зависит остальное.
3. Для **каждой** задачи — файл `docs/tasks/<этап>.<номер>-<название>.md` строго по шаблону
   из раздела 7 брифа. Каждая задача ссылается на конкретные файлы и строки из аудита.
   Каждая находка «критично» и «важно» из отчётов должна попасть в какую-то задачу — в конце проверь
   это и выведи таблицу «находка → задача».
4. `docs/LAUNCH_CHECKLIST.md` — из `22_CONFIG.md`: что заполняет владелец, где взять, как проверить.
5. `docs/QUESTIONS.md` — только вопросы, без ответа на которые нельзя начать задачи этапов 0–7.
   Вопросы про реальные цены и ключи сюда не включать — они в LAUNCH_CHECKLIST.
