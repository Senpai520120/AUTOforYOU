Находки:
- **05-S1** (критично): тип фото C2C проверяется только по `content_type` клиента (`local_listings/views.py:251,292`), `objects.create` не валидирует `ImageField`, сохраняются исходное имя и расширение (`local_listings/views.py:303-307`, `local_listings/models.py:203`). Можно загрузить `x.html`/`x.svg` с заголовком `image/jpeg`; nginx отдаёт `/media/` с того же домена без `nosniff` (`nginx/nginx.conf:24-27`) → хранимый XSS.
- **05-S2** (критично): EXIF, включая GPS, не удаляется (`local_listings/views.py:301-310`) — фото машины у дома раскрывает адрес продавца.
- **04-S4** (важно): у `VehicleImage`/`TrackingEvent` нет EXIF-очистки, лимита размера, безопасных имён; фото трекинга (фото авто клиента в порту, возможно с GPS телефона брокера) публичны через `/media/` (`nginx/nginx.conf:24`) при закрытом API контейнеров (`shipments/views.py:30-55`, `IsAuthenticated` + watchers). Сериализатор отдаёт прямой URL: `shipments/serializers.py:14`.
- **03-S5** (важно): `upload_lot_photos` качает по любому `source_url` с редиректами, без лимита размера, без проверки, что это изображение, без удаления EXIF (`integrations/management/commands/upload_lot_photos.py:59-66`).
- **13-S8** (важно): нет тестов лимита размера, подмены содержимого, EXIF и имени файла; тип проверяется только одним тестом GIF по content-type (`local_listings/tests.py:506-510`).
- Связанная желательная **12-S7**: `/media/` без `X-Content-Type-Options: nosniff` и без проверки доступа, включая `tracking_photos/` (`nginx/nginx.conf:24-27`).
- Уже есть: `client_max_body_size 20M` в nginx (`nginx/nginx.conf:13`), лимит числа фото `LOCAL_LISTING_MAX_PHOTOS` (`core/settings.py:322`), Pillow 12.2.0 в `requirements.txt:6`. S3-режим уже использует приватный bucket с подписанными URL (`core/settings.py:174-191`, но см. 01-C1 — задача 7.2).

## Цель
- [ ] Один общий сервис `core/uploads.py` для всех точек 1–6:
  - открывает файл через Pillow, `verify()` + повторное открытие; разрешены только форматы из `UPLOAD_IMAGE_ALLOWED_FORMATS` (по умолчанию `JPEG,PNG,WEBP`); тип определяется по содержимому, `content_type` клиента и расширение игнорируются;
  - лимит размера файла `UPLOAD_IMAGE_MAX_SIZE_MB` (по умолчанию 8) и лимит пикселей `UPLOAD_IMAGE_MAX_PIXELS` (по умолчанию 40 000 000, защита от decompression bomb);
  - `ImageOps.exif_transpose`, затем пересохранение без EXIF/XMP/GPS (JPEG → JPEG, PNG → PNG, WEBP → WEBP; анимация не допускается);
  - имя — `uuid4().hex` + расширение по реальному формату, в подпапке по назначению;
  - ошибки — `ImageUploadError` с понятным украинским текстом.
- [ ] Поле `SanitizedImageField` (наследник `ImageField`), которое прогоняет через сервис каждый новый, ещё не сохранённый файл в `pre_save`. Поле используется в `LocalListingImage.image`, `VehicleImage.image`, `TrackingEvent.photo` — так покрываются API, админка, `advance_status` и команда без отдельного кода в каждой точке. Уже сохранённые строки (строка-путь, `_committed=True`) не трогаются.
- [ ] Валидатор формы `validate_image_upload` на том же сервисе — админка показывает ошибку поля, а не 500.
- [ ] `local_listings/views.py`: проверка по `content_type` удалена, ошибки сервиса возвращаются 400 со списком по файлам; лимит C2C — `LOCAL_LISTING_PHOTO_MAX_SIZE_MB`, если задан, иначе общий.
- [ ] `upload_lot_photos`: потоковое скачивание (`httpx.stream`) с обрывом после лимита байт; хост `source_url` и каждого редиректа — только из `LOT_PHOTO_ALLOWED_HOSTS` (`.env`, список через запятую); не-изображение отклоняется; файл проходит тот же сервис.
- [ ] Фото трекинга приватны: `TrackingEvent.photo` хранится в отдельном хранилище `private_media` (локально — `PRIVATE_MEDIA_ROOT` вне `MEDIA_ROOT`; при S3 — тот же приватный bucket с префиксом и подписанными URL). Отдача — `GET /api/v1/shipments/<pk>/events/<event_id>/photo/` с проверкой прав (staff или watcher контейнера): в dev — `FileResponse`, в проде — `X-Accel-Redirect` на `internal`-location nginx. Сериализатор отдаёт этот URL вместо прямого `/media/`.
- [ ] nginx: `add_header X-Content-Type-Options nosniff always;` и `Content-Disposition`-безопасная отдача для `location /media/` (12-S7); `internal`-location для приватных файлов.
- [ ] Команда `sanitize_existing_images [--dry-run]` — прогоняет уже загруженные файлы трёх моделей через сервис (новое имя, без EXIF), битые/не-изображения — в отчёт, не удаляются без флага `--delete-invalid`.
- [ ] Тесты по 13-S8 для каждой точки.

## Шаги
1. Размещение: `core` не входит в `INSTALLED_APPS` (`core/settings.py:48-80`), поэтому сервис и поле кладутся модулем `core/uploads.py` (импортируется как обычный модуль), а management-команда — в `vehicles/management/commands/` (или `core` добавляется в `INSTALLED_APPS` с объяснением в коммите). Выбрать один вариант и записать в `ARCHITECTURE.md`.
2. `core/uploads.py`: `sanitize_image(file, *, max_bytes=None, subdir) -> ContentFile` и `ImageUploadError`. Порядок: размер по `file.size`/чтению с лимитом → `Image.open` + `verify()` → повторное `open`, проверка `format` и `width*height` → `exif_transpose` → `save` в буфер без `exif`/`icc_profile`-метаданных GPS (для JPEG `quality` из `UPLOAD_IMAGE_JPEG_QUALITY`, по умолчанию 85) → имя `f'{uuid4().hex}.{ext}'`. Установить `Image.MAX_IMAGE_PIXELS` из настройки.
3. `SanitizedImageField(models.ImageField)`: `pre_save` — если у `FieldFile` есть несохранённый файл, заменить его результатом `sanitize_image`; `upload_to` — функция с uuid-именем. Миграции `AlterField` для трёх моделей. Причина: сменить класс поля и `upload_to`/`storage`; схема колонок не меняется.
4. `TrackingEvent.photo`: `storage=private_media_storage` (callable, чтобы миграция не зависела от окружения). Защищённый view и маршрут `events/<event_id>/photo/`; `shipments/serializers.py` — `photo_url` через `reverse`. nginx: `location /protected-media/ { internal; alias /private_media/; }`.
5. `local_listings/views.py:249-315`: убрать `ALLOWED_IMAGE_TYPES`, валидировать каждый файл сервисом до создания записей (всё или ничего), 400 со списком ошибок; сообщения без внутренних путей.
6. `upload_lot_photos`: `httpx.Client(follow_redirects=False)`, ручная обработка до 3 редиректов с проверкой хоста по `LOT_PHOTO_ALLOWED_HOSTS`; `stream` с подсчётом байт; пустой список хостов → команда пишет «не настроено» и выходит без скачивания.
7. `sanitize_existing_images`: проход батчами, `--dry-run` по умолчанию печатает план; при реальном запуске старый файл удаляется только после успешного сохранения нового.
8. `nginx/nginx.conf`: `nosniff` для `/media/`; убедиться, что `tracking_photos/` больше не лежит под `/media/` (после команды шага 7 старые файлы переносятся в приватное хранилище).
9. `.env.example`: `UPLOAD_IMAGE_MAX_SIZE_MB`, `UPLOAD_IMAGE_MAX_PIXELS`, `UPLOAD_IMAGE_ALLOWED_FORMATS`, `UPLOAD_IMAGE_JPEG_QUALITY`, `LOT_PHOTO_ALLOWED_HOSTS`, `PRIVATE_MEDIA_ROOT`, `PRIVATE_MEDIA_USE_X_ACCEL` с комментариями. Перегенерировать `openapi.yaml` (только против Postgres).
10. В тестах, сохраняющих файлы, — `override_settings(MEDIA_ROOT=tmp, PRIVATE_MEDIA_ROOT=tmp2)`, чтобы не засорять `media/`. Существующие тесты, создающие `LocalListingImage(image='a.jpg')` строкой (`local_listings/tests.py:520,538-539`), должны остаться зелёными — поле не трогает уже сохранённые значения.

## Тесты
Django:
- Сервис (`tests/test_uploads.py`): JPEG с EXIF GPS (собрать через `PIL.Image.Exif`) → на выходе `getexif()` пуст, GPS-тега нет; ориентация применена; PNG/WEBP сохраняют формат; GIF, SVG, HTML с расширением `.jpg`, текст с заголовком `image/jpeg`, обрезанный JPEG → `ImageUploadError`; файл больше лимита → ошибка; картинка больше `UPLOAD_IMAGE_MAX_PIXELS` → ошибка; имя результата — 32 hex + реальное расширение, исходное имя не сохраняется.
- 23-D19 (`local_listings/tests.py`): API — файл больше `LOCAL_LISTING_PHOTO_MAX_SIZE_MB` → 400; HTML с `content_type='image/jpeg'` → 400; PNG с `content_type='text/plain'` → 201 (тип по содержимому); после загрузки файл на диске без EXIF GPS и с uuid-именем; при одном плохом файле из трёх не создаётся ни одной записи.
- 23-D55 (`vehicles/tests.py`, `shipments/tests.py`): `VehicleImage` и `TrackingEvent`, созданные с `SimpleUploadedFile` (как это делает админка) и через `advance_status(photo=…)`, сохраняются без EXIF и с uuid-именем; форма админки с HTML-файлом возвращает ошибку поля (через `Client` суперпользователя, POST в change-форму `Vehicle` с inline) — 200 с ошибкой, не 500.
- Приватные фото трекинга: `GET …/events/<id>/photo/` аноним → 401; чужой пользователь (не watcher) → 404; watcher → 200 (или заголовок `X-Accel-Redirect` при `PRIVATE_MEDIA_USE_X_ACCEL=true`); staff → 200; в ответе `shipments/<pk>/` нет прямого `/media/tracking_photos/…`.
- 23-D63 (`integrations/tests.py`, `httpx` замокан через `MockTransport`): ответ больше лимита → запись пропущена, `image` пуст; `Content-Type: image/jpeg` с HTML-телом → пропущена; редирект на хост вне `LOT_PHOTO_ALLOWED_HOSTS` → не выполняется; разрешённый хост и валидный JPEG → сохранён без EXIF; пустой `LOT_PHOTO_ALLOWED_HOSTS` → «не настроено», сетевых вызовов нет.
- `sanitize_existing_images --dry-run` ничего не меняет; без `--dry-run` переименовывает и чистит EXIF у существующего файла.
Playwright (`frontend/e2e/uploads.spec.ts`, авторизация из 0.4):
- Успех — продавец загружает JPEG с GPS в своё объявление, фото появляется; `page.request.get(<url фото>)` отдаёт файл, имя в URL — uuid, заголовок `x-content-type-options: nosniff`.
- Ошибка/обход — загрузка `.html`, переименованного в `.jpg`, и файла больше лимита → видимая ошибка в форме, фото не появляется; прямой URL фото трекинга без авторизации → не 200.
