# Задача 7.1: HTTPS, HSTS, CSP и заголовки безопасности

## Контекст
Прод-сценарий «владелец подключает домен и запускает `docker compose up`» сейчас не работает. HTTPS нет, а заголовков безопасности на HTML-страницах нет совсем.

- **12-S2 (критично):** nginx слушает только `:80` (`nginx/nginx.conf:10`). TLS есть только в виде закомментированной заготовки (`nginx/nginx.conf:54-61`). При этом Django при `DEBUG=false` по умолчанию включает `SECURE_SSL_REDIRECT=true` (`core/settings.py:423`), поэтому `/api` и `/admin` редиректят на несуществующий https. За внешним TLS-балансировщиком получится бесконечный редирект: nginx перезаписывает `X-Forwarded-Proto $scheme` (`nginx/nginx.conf:35,47`) на `http`, а Django верит этому заголовку (`SECURE_PROXY_SSL_HEADER`, `core/settings.py:429`). CI обходит проблему через `SECURE_SSL_REDIRECT=false` (`.github/workflows/ci-cd.yml`, шаг «Generate .env for the stack»).
- **01-S9 (важно):** CSP нет нигде. HSTS в nginx закомментирован (`nginx/nginx.conf:61`), в Django HSTS включается только при `DEBUG=false` (`core/settings.py:418-431`).
- **12-S3 (важно):** на HTML-страницах Next.js нет HSTS, CSP, `X-Frame-Options`, `nosniff`, `Referrer-Policy` и `Permissions-Policy`. nginx заголовков не добавляет (`nginx/nginx.conf:9-62`), в `frontend/next.config.ts:12-36` нет `headers()`, `middleware.ts`/`proxy.ts` во фронтенде нет. Django-заголовки (`core/settings.py:430-431`) попадают только в ответы `/api` и `/admin`.

Связанные «желательные» находки тех же мест, закрываются здесь же:
- 01-S18: `SECURE_HSTS_PRELOAD=True` и `SECURE_HSTS_INCLUDE_SUBDOMAINS=True` (`core/settings.py:425-426`) включены без решения владельца. Preload почти необратим для домена.
- 08-S9: то же, что 12-S3, со стороны Next (`frontend/next.config.ts:12-36`).
- 12-S7 (частично): `/media/` отдаётся без `X-Content-Type-Options: nosniff` (`nginx/nginx.conf:24-27`). Вместе с 05-S1 это хранимый XSS через загруженный файл. Здесь добавляются только `nosniff` и `CSP: sandbox` на `/media/`. Закрытие приватных файлов (`tracking_photos/`) через X-Accel-Redirect в эту задачу не входит.
- 12-S10: нет `limit_req` на `/api/v1/auth/` и `/admin/login/`, не выключен `server_tokens`.
- 12-C3: `server_name localhost` и пути к сертификатам захардкожены (`nginx/nginx.conf:11,57-58`).
- 12-C10 (часть nginx): `client_max_body_size 20M` (`nginx/nginx.conf:13`) не связан с `LOCAL_LISTING_PHOTO_MAX_SIZE_MB` (`core/settings.py`, блок C2C).
- 12-Q12: `Connection 'upgrade'` задан для всех запросов к frontend (`nginx/nginx.conf:48-51`), `gzip_static on` без предсжатых файлов (`:20`), обычного `gzip` нет.

Ловушки, которые нужно учесть:
- В nginx `add_header` из server-блока **не наследуется** в location, где есть свой `add_header`. Сейчас это `location /static/` (`nginx/nginx.conf:19`). Поэтому заголовки выносятся в отдельный файл-сниппет и подключаются `include` в каждый location.
- Next.js App Router вставляет inline-скрипты гидратации. CSP с `script-src 'self'` без nonce ломает сайт. Nonce через `proxy.ts` (в Next 16 `middleware` переименован в `proxy`) делает все страницы динамическими. Вариант по умолчанию описан в шагах.
- Изменение 12-S9 из задачи 1.5 (`X-Forwarded-For $remote_addr` в nginx, `NUM_PROXIES` в DRF) при переводе конфига в шаблон нужно сохранить, а не затереть.
- `core/settings.py` читается один раз при импорте. `override_settings(DEBUG=False)` не выполнит ветку `if not DEBUG` (`core/settings.py:420`) заново. Тесты должны явно переопределять `SECURE_*` или проверять вынесенную чистую функцию.

## Цель
- [ ] nginx собирается из шаблона `nginx/templates/default.conf.template` (штатный envsubst образа `nginx`). Домен берётся из `DOMAIN` в `.env`, в шаблоне нет ни `localhost`, ни `autoforyou.ua`.
- [ ] Режим TLS задаётся одной переменной `TLS_MODE`:
  - `off` — только `:80`, как сейчас. Для локальной разработки и CI; Django получает `SECURE_SSL_REDIRECT=false`.
  - `selfsigned` — `:443` с самоподписанным сертификатом, который генерируется при старте. Для тестового TLS-стенда и Playwright.
  - `letsencrypt` — `:443` с сертификатом Let's Encrypt (certbot, webroot `/.well-known/acme-challenge/`), автопродление, `:80` отдаёт только challenge и 301 на https.
  - `external` — TLS снимает внешний балансировщик. nginx слушает `:80` и передаёт в Django исходный `X-Forwarded-Proto` балансировщика, а не `$scheme`. Редиректа по кругу нет.
- [ ] В режимах `selfsigned` и `letsencrypt` `http://DOMAIN/...` отвечает 301 на `https://DOMAIN/...` (кроме `/.well-known/acme-challenge/`).
- [ ] Первый запуск на чистом VPS не требует ручной правки конфигов. Скрипт `scripts/init-letsencrypt.sh` создаёт временный сертификат, поднимает nginx, получает настоящий сертификат и перезагружает nginx. Сертификаты лежат в именованном volume и переживают `docker compose down`.
- [ ] Сертификат продлевается автоматически (сервис `certbot` с циклом `certbot renew` раз в 12 часов, nginx перечитывает сертификаты через `nginx -s reload` по расписанию или по deploy-hook).
- [ ] На **всех** ответах через nginx (HTML Next, `/api`, `/admin`, `/static`, `/media`) есть заголовки: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` (камера, микрофон, геолокация, платёжный API выключены), `Content-Security-Policy`.
- [ ] `Strict-Transport-Security` отдаётся только по https. `max-age` из `HSTS_MAX_AGE` (по умолчанию 31536000), `includeSubDomains` и `preload` только по флагам `HSTS_INCLUDE_SUBDOMAINS` и `HSTS_PRELOAD` (по умолчанию `false`, 01-S18). Django использует те же переменные, двух разных политик нет.
- [ ] CSP по умолчанию: `default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob: https:; font-src 'self' data:; connect-src 'self'; frame-ancestors 'none'; base-uri 'self'; object-src 'none'; form-action 'self' https://www.liqpay.ua`. Дополнительные источники задаются в `.env` (`CSP_SCRIPT_SRC_EXTRA`, `CSP_CONNECT_SRC_EXTRA`, `CSP_FRAME_SRC_EXTRA`, `CSP_IMG_SRC_EXTRA`), например домен капчи из 1.6 или S3/R2. В коде доменов провайдеров нет.
- [ ] Режим `CSP_REPORT_ONLY=true` отдаёт ту же политику в `Content-Security-Policy-Report-Only`. Так владелец может проверить политику на проде, ничего не сломав.
- [ ] Сайт с включённой CSP работает: главная, каталоги, калькулятор, вход, форма объявления, оплата (редирект на LiqPay) без CSP-ошибок в консоли браузера.
- [ ] `/media/` отдаётся с `nosniff` и `Content-Security-Policy: default-src 'none'; sandbox`. HTML-файл, загруженный как фото, не выполняется.
- [ ] `server_tokens off`. На `/api/v1/auth/` и `/admin/login/` есть `limit_req` (лимит из `.env`, по умолчанию 10r/m с burst 5), превышение даёт 429 с JSON.
- [ ] `client_max_body_size` берётся из `NGINX_MAX_BODY_SIZE`. На превышение для `/api/` nginx отдаёт 413 с JSON `{"detail": "..."}` на украинском, а не HTML-страницу nginx (23-P52).
- [ ] `Connection 'upgrade'` ставится только при наличии `Upgrade` (через `map`). Включён обычный `gzip` для text/css/js/json/svg, `gzip_static` убран.
- [ ] Django: HSTS и `SECURE_SSL_REDIRECT` согласованы с `TLS_MODE` (при `off` редиректа нет, при `external` доверяем `X-Forwarded-Proto`). Если задача 1.3 не добавила `CSRF_TRUSTED_ORIGINS`, он собирается из `DOMAIN`/`SITE_URL` (нужен для `/admin/` по https за прокси).
- [ ] `manage.py check --deploy` на прод-переменных не выдаёт предупреждений о HSTS, SSL-редиректе и secure-cookie (остальное — 7.2).

## Шаги
1. Проверить, что сделано в 1.3, 1.5 и 1.6: `CSRF_TRUSTED_ORIGINS`, cookie `Secure`/`SameSite`, изменения XFF в nginx, домен капчи. Всё это нужно учесть в CSP и в шаблоне.
2. Вынести блок `core/settings.py:416-431` в `core/security_settings.py`: функция принимает словарь env и флаги `debug`/`testing` и возвращает словарь настроек. `settings.py` делает `globals().update(...)`. Поведение по умолчанию для `DEBUG=false` не меняется, кроме HSTS preload и subdomains (теперь по флагам, по умолчанию `false`).
3. Связать `TLS_MODE` и Django: `off` → `SECURE_SSL_REDIRECT=false`, HSTS 0; `selfsigned`/`letsencrypt` → редирект делает nginx, в Django `SECURE_SSL_REDIRECT` можно оставить `true` как вторую линию; `external` → доверять `X-Forwarded-Proto`. Явный `SECURE_SSL_REDIRECT` в `.env` по-прежнему имеет приоритет (обратная совместимость для CI).
4. Написать `nginx/templates/default.conf.template`: upstream'ы, `server_tokens off`, `map $http_upgrade $connection_upgrade`, `map` для `X-Forwarded-Proto` (в режиме `external` берётся `$http_x_forwarded_proto`, иначе `$scheme`), `limit_req_zone` для auth, `gzip`, `error_page 413` с JSON для `/api/`. Серверные блоки для 80 и 443 выбираются скриптом из `docker-entrypoint.d` по `TLS_MODE`.
5. Сниппет заголовков: все `add_header ... always`, `include` в каждом location (`/`, `/api|admin`, `/static/`, `/media/`, `/healthz`, если 7.3 уже добавила). HSTS только в server-блоке 443. CSP собирается из базовой политики и `CSP_*_EXTRA` на этапе envsubst. Имя заголовка (`Content-Security-Policy` или `-Report-Only`) зависит от `CSP_REPORT_ONLY`.
6. `/media/`: свой набор заголовков (`nosniff`, `CSP: default-src 'none'; sandbox`), те же общие заголовки через include.
7. Сервис `certbot` в compose и `scripts/init-letsencrypt.sh`: dummy-сертификат → nginx → `certbot certonly --webroot` с `LETSENCRYPT_EMAIL` и `DOMAIN` (плюс `www.`, если `DOMAIN_WWW=true`) → reload. Флаг `LETSENCRYPT_STAGING=true` для пробного запуска без лимитов Let's Encrypt. Перезапуск скрипта при существующем сертификате ничего не ломает.
8. CI: e2e-джоба поднимает стек с `TLS_MODE=off`. Добавить шаг (можно в той же джобе после основного прогона) с `TLS_MODE=selfsigned`, `DOMAIN=localhost` и запуском только `security-headers.spec.ts`.
9. Пройти сайт вручную с включённой CSP (главная, `/listings`, `/ua`, калькулятор, `/login`, `/local/new`, оплата продвижения) и убедиться, что в консоли нет CSP-нарушений. Если что-то ломается, расширить базовую политику или добавить `*_EXTRA` в шаблон `.env` с комментарием. Хардкодить домены провайдеров в шаблоне nginx нельзя.
10. Обновить `.env.example`/`.env.docker.example`, `docs/LAUNCH_CHECKLIST.md`, `ROADMAP.md`, `PROGRESS.md`.
