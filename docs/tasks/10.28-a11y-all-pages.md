# Задача 10.28: axe на всех публичных страницах, контраст юр. страниц, ошибки регистрации у полей

## Контекст
Источник: `docs/audit/41_REVIEW_2026-11-11.md`, раздел G. `frontend/e2e/a11y.spec.ts` проверял axe только на 5 страницах (`/`, `/login`, `/register`, `/calculator`, `/ua`). Подпись «Останнє оновлення» в `frontend/components/legal/LegalPage.tsx` была `text-slate-400` (контраст ~2.6:1). Форма `frontend/app/register/page.tsx` показывала все серверные ошибки одной строкой внизу, без `aria-invalid`/`aria-describedby`, поля без `autocomplete` и с шрифтом 14px.

## Цель
- axe (WCAG 2.0 A/AA, 0 serious/critical) проходит по одной таблице публичных страниц: `/`, `/calculator`, `/how-it-works`, `/prigon`, `/prigon/e2e-toyota-camry`, `/about`, `/privacy`, `/terms`, `/rules`, `/refund`, `/cookies`, `/ua`, карточка C2C-объявления, `/login`, `/register`, `/password-reset`, 404. `/faq` отдельной страницы нет (FAQ внутри `/how-it-works`).
- Юр. страницы: текст не светлее `slate-500` на белом.
- Регистрация: ошибки 400 по полям (`first_name`, `email`, `phone`, `password`, `password2`) выводятся у поля, `aria-invalid`, `aria-describedby`, фокус на первом ошибочном; прочие ошибки (капча, detail) — общим `role="alert"` как раньше.
- `autocomplete` (`given-name`, `email`, `tel`, `new-password`), `inputmode`, шрифт полей 16px; на `/login` и `/password-reset` — `autocomplete`/`inputmode`/16px.

## Файлы
