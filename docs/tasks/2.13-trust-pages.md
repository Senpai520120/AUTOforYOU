# Задача 2.13: Страницы доверия пригона — «Як працює пригон» и FAQ (тексты в админке)

> Источник: Н-30a (`docs/audit/36_PARITY_K_L.md`, K7.1, K7.2; P2.5 в `docs/audit/38_PARITY_O_P.md`; `docs/audit/32_NEW_TASKS_INDEX.md`). Волна: [ВОЛНА-1]. Оценка: 1 сессия. Security-reviewer не обязателен. Кейсы (`ImportCase`) — этап 9, здесь не делаются.

Модели вопросов-ответов нет (Grep по коду пуст).

Чисел и сроков в коде не придумываем.
- Шаблон работы с публичными данными задан 1.12: приложение с админкой, публичный GET (`AllowAny`, явный `permission_classes`, кэш со сбросом при `save`), на фронте серверный хелпер через `serverGet` и страницы с `export const dynamic = 'force-dynamic'` (иначе Next пререндерит пустые данные при build).
- Подвал: `frontend/components/layout/Footer.tsx:11-17` (юридические ссылки; контакты и реквизиты добавляют 1.12 и 6.4). Шапка с бургером — 6.1. Sitemap: `frontend/app/sitemap.ts:23-59` (правки — 6.3). Форма заявки и ссылка «Як працює пригон?» рядом с ней — 2.3 (показывается, только если страница опубликована); калькулятор: `frontend/app/calculator/page.tsx`.
- Язык: `LANGUAGE_CODE='uk'`, сообщения API по-украински — 6.4. В `frontend/lib/` централизованный словарь подписей `labels.ts`.

## Цель
- [ ] Новое приложение `content` с моделями `ImportStep` (порядок, заголовок, описание, «термін» как свободный текст, активность) и `FaqItem` (вопрос, ответ, порядок, активность, флаг `show_on_calculator`). Все поля текстовые, без чисел «из кода».
- [ ] Data-миграция создаёт **черновики** на украинском (этапы пригона и типовые вопросы). Сроки и суммы в черновиках заменены пометкой `[ПЕРЕВІРИТИ З БРОКЕРОМ: ...]` в тексте. Черновики созданы неактивными (`is_active=False`).
- [ ] Админка не даёт включить запись, пока в тексте остаётся пометка `[ПЕРЕВІРИТИ`: `clean()` модели отдаёт ошибку формы «Приберіть позначку «перевірити з брокером» перед публікацією». Так черновая пометка не попадёт на сайт.
- [ ] Публичный `GET /api/v1/content/how-it-works/` → `{published: bool, steps: [...], faq: [...]}` (только активные, по порядку, без служебных полей) и `GET /api/v1/content/faq/?place=calculator` → FAQ с `show_on_calculator=true`. Кэш со сбросом на `save`/`delete`. `published=false`, если нет активных этапов.
- [ ] Страница `/how-it-works` («Як працює пригон»): этапы по порядку, под ними FAQ, кнопка-ссылка «Розрахувати вартість» (`/calculator`) и «Залишити заявку» (якорь на форму 2.3). Если опубликованных записей нет — «Інформація скоро з'явиться», код 200, `noindex`.
- [ ] Блок FAQ под калькулятором (`frontend/app/calculator/page.tsx`) показывается, только если есть записи с `show_on_calculator`.
- [ ] Ссылка «Як працює пригон» и «Питання та відповіді» в подвале, если `published=true`.
- [ ] Ответы выводятся как обычный текст с переносами строк, без HTML и `dangerouslySetInnerHTML` (защита от XSS из админки).
- [ ] Метаданные страницы (title, description, canonical) в стиле 6.3; страница попадает в sitemap при `published=true`. Разметка FAQ (JSON-LD) — этап 9, здесь не делается.

## Шаги
1. Приложение `content`, модели, `TextChoices` не нужны. Миграция `0001` (причина: тексты пригона должны редактироваться в админке без правки кода, ANSWERS шаг 6). Валидатор пометки в `clean()` обеих моделей.
2. Data-миграция `0002`: список этапов (заявка и консультация, подбор авто и торги, выкуп и оплата, доставка по США, морем, растаможка в Украине, выдача) и 6–8 вопросов-ответов (что входит в стоимость, почему расчёт орієнтовний, как оплачивается, как отслеживать контейнер, что если авто повреждено и т.п.). Тексты — по-украински, нейтральные, без чисел; сроки и суммы — пометка `[ПЕРЕВІРИТИ З БРОКЕРОМ: ...]`. Всё `is_active=False`.
3. Админка: `list_editable` для `order` и `is_active`, поиск по тексту; права — только admin/superuser (роль `moderator` по Q10 доступа не имеет, группы 1.2 не расширять).
4. API: два view, сериализаторы с белым списком, кэш `content:how-it-works` и `content:faq:<place>` с очисткой в `post_save`/`post_delete`.
5. Фронт: страница, `FaqBlock` (нативные `<details>`/`<summary>` — доступность без JS-библиотек), подвал и sitemap читают `published`. Перед написанием страниц прочитать актуальные руководства Next в `frontend/node_modules/next/dist/docs/` (`frontend/AGENTS.md`).
6. LAUNCH_CHECKLIST: «Заповнити та опублікувати тексти сторінки "Як працює пригон" і FAQ (звірити зі сроками брокера)».

## Тесты
Django (`content/tests.py`):
- Аноним `GET how-it-works` → 200, только активные записи по порядку; все черновики неактивны → `published=false`, пустые списки. Ответ не содержит служебных полей.
- Форма админки: включение записи с `[ПЕРЕВІРИТИ` → ошибка; после очистки текста → сохраняется, ответ API обновился (кэш сброшен).
- `?place=calculator` отдаёт только записи с флагом; неизвестное значение → пустой список, а не 500.
- Раздел админки недоступен без прав (`moderator` и `buyer` → 403/редирект).
Playwright (`frontend/e2e/trust-pages.spec.ts`; данные через фикстуры 0.4):
- Успех: при двух активных этапах и вопросе `/how-it-works` показывает их по порядку, FAQ раскрывается, ссылки «Розрахувати вартість» ведут на `/calculator`; в подвале есть ссылка; под калькулятором виден блок FAQ.
- Ошибка/обход: при пустом контенте страница отвечает 200 с «Інформація скоро з'явиться», в подвале ссылки нет, и на странице и в HTML нет подстроки `ПЕРЕВІРИТИ`; API недоступен (`page.route` → 500) → страница не падает (состояние ошибки, без белого экрана); ответ с `<script>` в тексте выводится как текст, скрипт не выполняется.
