# Задача 5.3: Публикация C2C-объявлений в канал

## Контекст
Бриф (§1 п.3) обещает «публикацию объявлений в канал». Сейчас в канал попадают только импортные лоты `listings.Listing`: сигнал подписан только на них (`telegram_bot/signals.py:5`, `sender='listings.Listing'`). C2C-объявления `local_listings.LocalListing` в Telegram не публикуются вовсе.

- **05-Q11 (важно)** и **07-Q3 (важно)** — одна и та же находка из двух пакетов: C2C-объявления не публикуются в Telegram-канал (`telegram_bot/signals.py:5`). Сценарий 6, шаг 6 в `20_SCENARIOS.md` — «нет».

Где в коде меняется статус `LocalListing` (точки, к которым нужно подключить публикацию и снятие поста):
- одобрение модератором: `approve_listing` (`local_listings/services.py:19-28`, статус `active`), вызывается из админ-действия `approve_listings` (`local_listings/admin.py:45-52`);
- отклонение: `reject_listing` (`local_listings/services.py:30-38`);
- владелец снимает или продаёт: `validate_status` разрешает `hidden`/`sold` (`local_listings/serializers.py:243-248`);
- существенная правка активного объявления возвращает его в `pending` на ремодерацию (`local_listings/serializers.py:258-261`, `SUBSTANTIVE_FIELDS` в `local_listings/services.py:16`);
- истечение срока: задача переводит в `expired` (`local_listings/tasks.py:59-61`);
- задача 4.3 (жизненный цикл: продление, скрытие, удаление, 05-Q6/05-Q7) добавит или централизует переходы. Если после 4.3 появилась единая функция смены статуса — подключаться к ней, а не к каждому месту отдельно.

Фото C2C хранятся файлами (`LocalListingPhoto.image`, `local_listings/models.py:203`, плюс `source_url` в строке 204), а не по внешнему URL.

Модель `ChannelPost`, сервис `telegram_bot/channel.py`, настройки `ChannelPublishingSettings` и задачи публикации/обновления/удаления с `on_commit` и `rate_limit` делает задача 5.2 — здесь они переиспользуются. Экранирование HTML (`telegram_bot/formatting.py`) — задача 5.1.

## Цель
- [ ] Одобренное модератором C2C-объявление (переход в `active` через `approve_listing` или единый сервис 4.3) публикуется в канал, если в `ChannelPublishingSettings` включён флаг `autopost_local_listings` (новый, по умолчанию выключен, чтобы до решения владельца канал не заполнялся).
- [ ] Объявления в статусах `draft`, `pending`, `rejected` в канал не попадают никогда. Создание объявления пользователем публикации не вызывает.
- [ ] Канал: `TELEGRAM_LOCAL_CHANNEL_ID`, если задан, иначе `TELEGRAM_CHANNEL_ID`. Без обоих — `ChannelPost` со статусом `skipped` и причиной «не настроено», одобрение объявления проходит без ошибок.
- [ ] Текст поста — только публичные данные: марка, модель, год, пробег, цена с валютой и типом цены, город, ссылка `SITE_URL/local/<id>`. **Без** телефона, email, имени владельца и описания (описание может содержать контакты, см. антиспам `has_contact_in_text`). Все значения экранированы.
- [ ] Фото: основное фото отправляется файлом (`BufferedInputFile`) из `LocalListingPhoto.image` (загружено самим продавцом, после очистки EXIF из задачи 1.10, если она сделана); без фото — текстовый пост. Режимы `PHOTO_MODE` из Q8 касаются только фото аукционов (лотов пригона, задача 5.2) и сюда не применяются; `source_url` у C2C-фото к аукционным не относится, но берётся только если он есть и фото файла нет.
- [ ] При переходе опубликованного объявления в `sold` — пост помечается «ПРОДАНО» или удаляется (общая настройка `on_sold` из 5.2). При переходе в `hidden`, `expired`, `rejected`, `pending` (ремодерация) и при удалении объявления — пост удаляется из канала.
- [ ] **G1.3 / Q9 (ANSWERS):** при переходе в `blocked` (модератор/бан) пост удаляется; `hidden` (владелец) — тоже удаляется. Бесплатное продление `expired → active` (4.3, без повторной модерации) снова публикует пост (если `autopost_local_listings` включён и объявление не правилось). Восстановление `hidden → active` владельцем — то же. `blocked → active` модератором — публикация заново.
- [ ] При повторном одобрении после ремодерации — публикуется новый пост (старый уже удалён), дублей нет (уникальность `ChannelPost` по объявлению и каналу из 5.2).
- [ ] В админке `LocalListing` видно состояние публикации и есть действия «Опублікувати в Telegram-канал» и «Видалити з каналу» (для одобренных).
- [ ] Бан пользователя или скрытие объявления по жалобе (админ-действия в `reports`) тоже снимают пост, если они меняют статус объявления (проверить, идут ли они через тот же путь смены статуса; если нет — записать в отчёт, не расширять задачу).

## Тесты
Django (Bot API замокан, как в 5.2):
- Создание объявления пользователем через API (`POST` подачи) → задача публикации не поставлена, `ChannelPost` нет.
- Одобрение (`approve_listing`) при включённом `autopost_local_listings` → задача поставлена после коммита (`captureOnCommitCallbacks(execute=True)`), `ChannelPost.posted` с `message_id`. При выключенном флаге → не поставлена.
- Отклонение (`reject_listing`) → публикации нет.
- Текст поста: содержит марку, модель, цену, город и ссылку `/local/<id>`; **не** содержит `contact_phone`, email и имя владельца, текст описания (проверка по подстроке). Значения с `<`/`&` экранированы.
- Фото из `image` → вызван `send_photo` с `BufferedInputFile`; без фото → `send_message`.
- Канал: задан `TELEGRAM_LOCAL_CHANNEL_ID` → пост туда; не задан → в `TELEGRAM_CHANNEL_ID`; оба пусты → `skipped`, одобрение прошло, статус объявления `active`.
- Владелец ставит `sold` (`PATCH` → 200) → `edit`/`delete` поста по настройке `on_sold`. Владелец ставит `hidden` → `delete_message`. Задача истечения (`local_listings/tasks.py`) → `delete_message`. Существенная правка активного (ремодерация `pending`) → `delete_message`; повторное одобрение → новый пост, записей-дублей нет.
- G1.3: переход `active → blocked` → `delete_message`; `blocked` + правка владельца → поста нет; `blocked → active` модератором → новый пост. Q9: `expired` → `active` через бесплатное продление → новый пост (при включённом флаге), без дублей.
- Удаление объявления → `delete_message` с сохранёнными `chat_id`/`message_id`.
- Админ-действия «Опублікувати»/«Видалити з каналу» для staff работают; для `pending` объявления «Опублікувати» не публикует и показывает сообщение.

Playwright: нет публичного UI (публикация идёт из модерации в Django Admin и в Telegram), только Django-тесты с моками. Публикация не должна ломать существующие e2e C2C (4.8) — прогнать их.

## Изменения после ANSWERS
