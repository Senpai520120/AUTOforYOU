## Цель
Новые сценарии используют `storageState` и фикстуры из 0.4. Каждый — успех плюс ошибка/обход. Всё, что сейчас не работает, оформляется как `test.fixme('<ID находки> → задача N.M')`, а не как молча зелёный тест.

- [ ] **23-P1 Вход** (`auth.spec.ts`): верный пароль `seller@e2e.test` → URL `/me`, в шапке «Вийти» и email. Неверный пароль → текст «Невірний email або пароль», URL остаётся `/login`, в `localStorage` нет `access`.
- [ ] **23-P2 Закрытые страницы** (`private-pages.spec.ts`):
  - гость на `/me`, `/me/favorites`, `/me/local-listings`, `/me/messages`, `/b2b`, `/local/new`, `/dealers/apply` → `/login` (параметризованный тест);
  - buyer со `storageState` открывает те же страницы без редиректа.
  - `test.fixme` — возврат по `?next=` и игнор внешнего `next` (08-S7, 10-S7 → 1.4); серверный редирект без JS (08-S7 → 1.4).
- [ ] **23-P3 Выход** (часть «С»): после «Вийти» `/me` уводит на `/login`, в `localStorage` нет токенов. `test.fixme` — «refresh после выхода отклонён сервером» (08-S2 → 1.4).
- [ ] **23-P5 Страницы кабинета** (`cabinet.spec.ts`):
  - seller видит своё активное и pending-объявление `[E2E]` в `/me/local-listings`;
  - buyer видит диалог с seller в `/me/messages` и контейнер в `/me/shipments`;
  - `/me/favorites`, `/me/deals`, `/me/notifications` открываются без ошибок консоли (`page.on('pageerror')`).
  - Ошибка: `page.route('**/api/v1/favorites/**', 500)` → видимое сообщение об ошибке. Сейчас это пустое состояние, поэтому `test.fixme('08-Q6 → 6.2')`. Тест написан полностью: после 6.2 убрать `fixme`.
- [ ] **23-P6 Регистрация до конца** (`register-flow.spec.ts`):
  - уникальный email из фикстуры `uniqueEmail` (`@e2e.test`) + согласие → `/login?registered=1` → вход с этим паролем → `/me` с этим email;
  - дубль email (`buyer@e2e.test`) → текст ошибки сервера сверяется по тексту ответа `/auth/register/`, а не по классу (13-Q4).
- [ ] **23-P7 Баннер cookie** (`cookie-banner.spec.ts`, без подавления баннера):
  - первый визит — баннер виден;
  - «Лише необхідні» и «Прийняти всі» (две параметризации) скрывают баннер, после перезагрузки его нет, `localStorage['cookie_consent']` — `necessary`/`all`;
  - на `/cookies` текущий выбор отображается и меняется.
  - Если в UI есть отзыв согласия (сброс выбора), после него баннер возвращается. Если кнопки нет — `test.fixme('23-P7: нет отзыва согласия в UI → 6.x')`, и это находка в отчёт.
