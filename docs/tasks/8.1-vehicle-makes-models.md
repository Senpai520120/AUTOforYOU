# Задача 8.1: Справочник марок и моделей (с синонимами) для объявлений

Метка волны: [ВОЛНА-2].
Риск: обычный (данные каталога, без ПДн и платежей).

## Контекст
Без справочника «Volkswagen», «VW» и «Фольксваген» считаются разными марками, поиск, фильтры и сохранённые поиски разваливаются (пункты эталона A1.1, A1.3; `docs/audit/31_PARITY_A_B.md`, Н-1).

Что сейчас в коде:
- `LocalListing.make` и `LocalListing.model` — свободные `CharField(100)` (`local_listings/models.py:122-123`); индекс `ll_make_idx` по тексту (`local_listings/models.py:182`) бесполезен для поиска `icontains`.
- `Vehicle.make` и `Vehicle.model` — тоже текст, `CharField(50)` (`vehicles/models.py:17-18`). Моделей марок и моделей нет нигде.
- Фильтр каталога: `make__icontains` и `model__icontains` (`local_listings/filters.py:27-30`), параметры `make`/`model` описаны в схеме (`local_listings/views.py:101-102`); общий поиск по `make`/`model`/`description` (`local_listings/filters.py:74`).
- Сохранённые поиски хранят текст марки в JSON `filters` (`saved_searches/models.py:12`), задача рассылки фильтрует `make__icontains` (`saved_searches/tasks.py:64-65`); ссылка каталога передаёт `make` и `model` как текст (`frontend/app/ua/page.tsx:30`, `frontend/components/local/SaveSearchButton.tsx:25`).
- Сериализаторы объявления принимают текст: `local_listings/serializers.py:79,156,229` (список, создание, правка). `SUBSTANTIVE_FIELDS = {make, model, year, price, description}` (`local_listings/services.py:16`) — правка марки/модели ремодерирует объявление; сравнение «по значению» вводит 4.2.
- Форма: свободные поля марки и модели (`frontend/components/local/LocalListingForm.tsx:75,238`), фильтр каталога — текстовое поле с подсказкой «Toyota» (`frontend/components/local/LocalListingFilters.tsx:14,44,81`). Автозаполнение по VIN (NHTSA vPIC, `VinPrefillView`, `local_listings/views.py:205-227`) возвращает марку текстом, форма подставляет её как есть (`LocalListingForm.tsx:125`).
- Импорт лотов пишет марку «как пришла» или `'Unknown'` (`integrations/importer.py:38`).
- Сиды справочников запускаются из `docker/entrypoint.sh:20-22` (`run_seed ...`), идемпотентно.

Решение владельца (`docs/ANSWERS.md`, порядок открытия): справочники марок и населённых пунктов относятся к ВОЛНЕ-2 (объявления по Украине). Реальные списки и источник — часть данных, не кода; проверка условий использования источника — вопрос владельцу.

## Цель
- [ ] Новые модели в `vehicles/models.py`: `VehicleMake` (`name`, `slug` уникальный, `is_active`, `sort_order`), `VehicleModel` (`make` FK `PROTECT`, `name`, `slug`, `is_active`; уникальность (`make`, `slug`)), `VehicleMakeAlias` (`make` FK, `alias` — нормализованная форма без регистра и пробелов, уникальна). Синонимы: «VW», «Фольксваген» → Volkswagen; аналогично для моделей (`VehicleModelAlias`). Все редактируются в админке без релиза.
- [ ] `LocalListing` получает `make_ref` и `model_ref` (FK `PROTECT`, `null=True` на время миграции данных). Текстовые `make` и `model` остаются как денормализованное отображаемое имя и заполняются из справочника при сохранении (старые клиенты, Telegram-канал, сохранённые поиски и экспорт не ломаются).
- [ ] Новые объявления: марка и модель обязательны из справочника. Создание принимает `make_id` и `model_id` (400 «Оберіть марку зі списку», «Модель не належить обраній марці»); прежние текстовые `make`/`model` в POST больше не создают новых марок.
- [ ] Публичное API (`AllowAny`, без ПДн): `GET /api/v1/local/makes/` (активные марки, без пагинации, кешируемый ответ с короткой жизнью по настройке) и `GET /api/v1/local/makes/<id>/models/`. Списки объявлений и деталь возвращают и `make_id`/`model_id`, и текстовые поля.
- [ ] Фильтр каталога: основной путь — `make_id`, `model_id` (точное сравнение по индексированному FK). Для совместимости прежний текстовый параметр `make`/`model` сначала разрешается через `VehicleMakeAlias` в справочную марку («vw» находит «Volkswagen»), и только если справочник не знает такого значения — прежний `icontains`. Общий helper `vehicles/catalog.py::resolve_make(text)` / `resolve_model(make, text)` используется и фильтром, и задачей сохранённых поисков (`saved_searches/tasks.py:64-65`), и автозаполнением по VIN, и импортом лотов.
- [ ] Автозаполнение по VIN (`VinPrefillView`) возвращает дополнительно `make_id`/`model_id`, если марка и модель однозначно распознаны через справочник и синонимы; если не распознаны — поля пустые, форма просит выбрать вручную (ответ 200, не ошибка).
- [ ] Импорт лотов (`integrations/importer.py:38`) нормализует текст марки к каноническому названию через синонимы; нераспознанная остаётся как есть (в `Vehicle` ссылка на справочник не вводится, это этап 9/A2.4).
- [ ] Фронт: в форме подачи — выпадающий список марки с поиском и зависимый список модели; в фильтре каталога тот же компонент; значение в URL — `make_id`/`model_id` (читаемая ссылка с названием — этап 9, SEO-страницы 9.9); старые ссылки с `?make=Toyota` продолжают работать через разрешение синонимов.
- [ ] Команды: `import_vehicle_catalog --file <csv|json> [--dry-run]` (идемпотентный импорт марок, моделей и синонимов из файла) и `link_listings_to_catalog [--dry-run]` (сопоставляет существующие `LocalListing` по тексту с записями справочника через синонимы, нераспознанные выводит отчётом и оставляет без ссылки; удаляет ничего). Источник данных — открытый набор или файл владельца; условия использования проверяются до загрузки (см. «Для владельца»). Сеть в команде — только по явному флагу `--from-vpic` (NHTSA, уже используется в проекте); без флага команда читает только локальный файл.
- [ ] Миграция данных: из существующих объявлений создаются марки и модели (по уникальным значениям текста), синонимы не угадываются автоматически; список «сомнительных дублей» (одинаковые после нормализации регистра и пробелов) выводится в отчёт команды, слияние — вручную в админке (действие «Об'єднати марки»: переносит объявления и синонимы, оригинал деактивируется).
- [ ] Админка: `VehicleMakeAdmin` (модели и синонимы как inline), поиск, фильтр «активні», действие «Об'єднати марки». Удалить марку с объявлениями нельзя (`PROTECT`, понятное сообщение Django).
- [ ] Индекс `(make_ref, model_ref)` у `LocalListing`; прежний индекс по тексту (`ll_make_idx`) остаётся до конца задачи и удаляется отдельным шагом после проверки. Индексы под остальные фильтры — 4.4 и 8.3.
- [ ] Правка марки/модели в объявлении — по-прежнему существенная (ремодерация), сравнение по `make_ref_id`/`model_ref_id`, а не по тексту (с 4.2).

## Шаги
1. Тесты-сначала (см. «Тесты»).
2. Модели справочника и миграции. Причины: `VehicleMake`/`VehicleModel`/алиасы — единый список марок и синонимов (A1.1, A1.3); `make_ref`/`model_ref` у `LocalListing` — выбор из справочника, фильтр по индексированному FK; nullable только на время миграции данных.
3. Data-миграция: марки и модели из существующих значений текста, привязка объявлений. Идемпотентна, обратимая (`reverse` обнуляет ссылки), без удаления данных.

5. Сериализаторы, фильтр, `VinPrefillView`, API `makes/`/`models/`, `saved_searches/tasks.py`, импорт лотов.
6. Фронт: `MakeModelSelect` (поиск по названию и синониму на клиенте, список приходит с сервера), подключение в форму, фильтр и сохранение поиска; обратная совместимость ссылок с текстовым `make`.
7. `.env.example`, `docs/openapi.yaml` (против Postgres), `PROGRESS.md`, LAUNCH_CHECKLIST. Прогон тестов `vehicles`, `local_listings`, `saved_searches`, `integrations`, затем полный прогон один раз; build, tsc, Playwright из `frontend/`.

## Тесты
Django:
- Справочник: уникальность алиасов; `resolve_make('vw')`, `resolve_make('  ФОЛЬКСВАГЕН ')` → Volkswagen; неизвестное → `None`; модель принадлежит марке (чужая модель → `None`).
- Создание объявления: `make_id`+`model_id` → 201, текстовые поля заполнены из справочника; модель другой марки → 400; только текст без ids → 400; неактивная марка → 400; правка марки у `active` → `pending` (по ссылкам), правка с теми же значениями → `active`.
- Фильтр: `?make_id=…&model_id=…` находит нужные объявления; `?make=vw` находит «Volkswagen»; неизвестный текст (`?make=Zzz`) → пустой результат без ошибки; число запросов не растёт с объёмом выдачи.
- `VinPrefillView` с моком NHTSA: марка и модель распознаны → в ответе `make_id`/`model_id`; не распознаны → поля пустые, статус 200; (мок, сеть не используется).
- `link_listings_to_catalog`: `--dry-run` ничего не меняет; обычный запуск связывает объявления и не трогает нераспознанные; повторный запуск идемпотентен. `import_vehicle_catalog` читает файл (фикстура CSV), повторный импорт не создаёт дублей, без `--from-vpic` сетевых вызовов нет (мок `httpx` падает при обращении).
- Data-миграция: объявления с «Toyota», «toyota », «TOYOTA» создают одну марку (после нормализации) и связываются; отчёт по сомнительным дублям.
- Сохранённые поиски: поиск с текстовой маркой «VW» находит новые объявления Volkswagen.
- Импорт лотов: «VW» → «Volkswagen» в `Vehicle.make`; неизвестная марка сохраняется как есть.
- Админка: удаление марки с объявлениями → ошибка Django (`PROTECT`); действие слияния переносит объявления и синонимы.
- `GET /local/makes/` и `GET /local/makes/<id>/models/` доступны анониму, не содержат лишних полей, неизвестная марка → пустой список/404 (выбрать и закрепить).
Playwright (`frontend/e2e/vehicle-catalog.spec.ts`; справочник — из `e2e_seed` из 0.4):
- Успех: продавец в форме подачи выбирает марку из списка (ввод «Volk» находит «Volkswagen»), затем модель из зависимого списка → объявление создаётся; в каталоге `/ua` фильтр по этой марке и модели находит его; перезагрузка страницы восстанавливает выбор из URL.
- Успех: старая ссылка `/ua?make=VW` показывает объявления Volkswagen.
- Ошибка/обход: прямой `POST` объявления с моделью чужой марки (через `page.request`) → 400 и видимая ошибка в форме при выборе несовпадающей пары; пока марка не выбрана, список моделей пуст, а отправка формы показывает «Оберіть марку зі списку».
