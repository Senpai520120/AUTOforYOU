## Цель
- [ ] **Модель `ListingDailyStat`** (`listing` FK CASCADE, `date`, `views`, `phone_reveals`, `favorites_added`, `dialogs`; уникальность `(listing, date)`; индекс `(date)`). Без ПДн. Сервис `record_listing_event(listing_id, event)` в `local_listings/stats.py`: атомарное увеличение через `F()` (`get_or_create` + `update` в транзакции, без гонок), при сбое — запись в лог и продолжение (сбор метрик не ломает основной запрос), вызов выполняется через `transaction.on_commit`. Тот же вызов делает `record_metric` из 8.7 (сайтовый ключ вида `listing_view`, `listing_phone_reveal`, `listing_favorite_added`, `listing_dialog_started`).
- [ ] **Просмотры.** `POST /api/v1/local/listings/<pk>/view/` (AllowAny, тело пустое, ответ 204, всегда 204 — без раскрытия причин отказа; не-`active` объявления не считаются). Вызывается клиентским компонентом `ViewTracker` после монтирования страницы, один раз на открытие (SSR не считает). Не считаются: просмотры владельцем собственного объявления, запросы с user-agent из списка `LISTING_VIEW_BOT_UA_PATTERNS` (настройка, список подстрок: bot, crawler, spider, headless, preview и т. п., значения — в `settings`), повтор того же посетителя в течение суток. Ключ дедупликации — хэш (`sha256` с `SECRET_KEY` и датой) от `listing_id` + (id пользователя или IP + user-agent), хранится только в кэше с TTL 24 часа (`cache.add`); в БД и логи ни IP, ни UA не пишутся. IP определяется так же, как в throttle DRF (`get_ident`, учитывает прокси по настройке 7.1). Отдельный throttle scope `listing_view` (`THROTTLE_LISTING_VIEW_RATE`).
- [ ] **Показы телефона.** В `LocalListingContactView` рядом с записью `ContactView` (4.5), при тех же условиях дедупликации (повтор того же пользователя за час не считается; показ гостю считается каждый раз): `record_listing_event(pk, 'phone_reveal')`. Вызов только после успешной выдачи телефона (не при 400/403/429).
- [ ] **Избранное.** В `FavoriteListView.post` (`favorites/views.py:37-41`) при `created=True` и `listing_type='local'` — событие `favorite_added`. Повторное добавление и добавление импортных лотов не считается; удаление счётчик не уменьшает.
- [ ] **Диалоги.** В `get_or_create_conversation` (`messaging/services.py:46`) при создании нового диалога по локальному объявлению — событие `dialog_started`; новое сообщение в существующий диалог не считается.
- [ ] **Админка (только чтение).** `ListingDailyStat` с фильтрами по дате и объявлению, суммы по странице; без add/change/delete. Продавцу и в публичный API данные не отдаются (это 9.13); `views_count` в публичные ответы не добавляется.
- [ ] Хранение: строки удаляются каскадом вместе с объявлением; агрегаты не содержат персональных данных, срок хранения не ограничивается; пометка в политике конфиденциальности не нужна, но отмечается в LAUNCH_CHECKLIST. При удалении аккаунта (Q3, 1.8) объявления архивируются — статистика сохраняется.
- [ ] Нагрузка (решение владельца, шаг 14): дневные счётчики — прямой атомарный `UPDATE` с `F()` (`update_or_create`/`get_or_create` + `update(views=F('views') + 1)`), один `UPDATE`/`INSERT` по индексу на событие; это основной и окончательный вариант запуска. Буфер в кэше с периодическим сбросом Celery — Рост (этап 9), в задачу не входит, указывается в `PROGRESS.md`.

## Тесты
Django (кэш очищать в `setUp`, Telegram/email не затрагиваются):
- Просмотр: `POST /view/` анонимом → 204, `views=1`; повтор тем же клиентом в тот же день → по-прежнему 1; другой клиент (другой IP/UA) → 2; следующий день (`freeze_time`/подмена даты) → новая строка `date`.
- Не считаются: владелец объявления, UA из `LISTING_VIEW_BOT_UA_PATTERNS` (`Googlebot`, `HeadlessChrome`), объявление `pending`/`blocked`/`expired`, несуществующий id — во всех случаях 204 и запись не создаётся (ответ не различается).
- В БД и логах нет IP/UA: у модели нет таких полей (`_meta.get_fields()`), `assertLogs` не содержит адреса.
- Throttle: `listing_view='3/hour'` → четвёртый запрос 429, счётчик не растёт.
- Телефон: успешный `/contact/` → `phone_reveals += 1`; повтор того же пользователя в течение часа → не растёт; гость → растёт каждый раз; 401/400/429 и не-`active` → не растёт.
- Избранное: первое добавление → `favorites_added=1`; повторное, удаление и повторное добавление после удаления → событие только при `created=True`; импортный лот → без события.
- Диалог: первый `get_or_create_conversation` по локальному объявлению → `dialogs=1`; второе сообщение в тот же диалог → не растёт; диалог по лоту пригона → без события.
- Сбой записи (мок бросает исключение) → ответ API без изменений, ошибка в логе.
- Параллельность: два вызова подряд не теряют инкремент (проверка `F()`-обновления).
- Админка: пользователь без права → 403; с правом → 200; add/change/delete запрещены.

Playwright (`frontend/e2e/c2c-listing-events.spec.ts`; чтение счётчика — через admin/`request` под staff или тестовый хелпер из 0.4):
- Успех: покупатель открывает страницу объявления → отправлен один `POST /view/`, в админке `views` +1; повторное открытие/перезагрузка в тот же день → счётчик прежний; добавление в избранное → `favorites_added` +1; «Написати продавцю» → `dialogs` +1; «Показати телефон» → `phone_reveals` +1.
- Ошибка/обход: владелец открывает своё объявление → просмотр не растёт; заблокированный сетевой запрос `/view/` (route abort) не ломает страницу; прямые 50 `POST /view/` через `request` от одного клиента → счётчик +1 (или 429 после лимита), страница и каталог продолжают работать; для UA `Googlebot` счётчик не растёт.
