# Задача 4.9: Отписка одной ссылкой из письма и история платежей `/me/payments`

Метка волны: [ВОЛНА-2].
Риск: высокий (платежи, подписанный токен без входа). После выполнения обязательна проверка security-reviewer.

Эта задача — единственный владелец двух пунктов, вынесенных из 4.3 (решение шага 12/13): отписка одной ссылкой (H4.3) и страница истории платежей с эндпоинтом `GET /payments/mine/` (H6.1). Задачи 4.3 и 4.7 только ссылаются сюда; 4.1 не меняется (модель и сервис платежей), 6.2 даёт компоненты состояний.

## Контекст
Отписка:
- Писем «не по запросу пользователя» сейчас нет, но они появляются с 4.3 (напоминание о сроке `listing_expiring`, email-канал, Q9) и с рассылкой сохранённых поисков. Сейчас письма уходят голым `send_mail(...)` с захардкоженным отправителем: `local_listings/services.py:62` (решение модерации), `users/services.py:74` (дилер). Ни ссылки отписки, ни заголовков `List-Unsubscribe` нет (Grep `unsubscribe` по коду и `docs/tasks` был пуст до этой задачи).
- Тип уведомления `LISTING_EXPIRING` уже есть как заготовка в `notifications/models.py:10`; шаблон `listing_expiring` и отправку делает 4.7 и 4.3.
- Сохранённые поиски: флаг `SavedSearch.notify` (`saved_searches/models.py:13`), ежедневная задача `check_saved_searches` (`saved_searches/tasks.py:9-39`) пока шлёт только Telegram. Если в 4.4/4.7 или позже появится email по поискам — он подчиняется этой отписке.
- SMTP-адаптер и отправитель по умолчанию (`DEFAULT_FROM_EMAIL`, `core/settings.py:344`) — задача 3.4; публичный базовый URL — `SITE_URL` (`core/settings.py:414`).
- Решение владельца (шаг 4, `docs/ANSWERS.md`): отписка одной ссылкой из письма — приоритет «Запуск». Юридические требования к рассылкам — вопрос юристу, не придумываются здесь.

История платежей:
- Есть модель `Payment` (`payments/models.py:5-74`: `user`, `local_listing`, `tariff`, `order_id`, `amount`, `currency`, `description`, `purpose`, `status`, `created_at`), маршруты только `liqpay/checkout/` и `liqpay/callback/` (`payments/urls.py:5-8`). Списка платежей пользователя и страницы нет (H6.1).
- После 4.1 появятся `GET /api/v1/payments/<order_id>/`, `GET /api/v1/payments/config/` и флаг `PAYMENTS_ENABLED` (по умолчанию `false`). Новый маршрут `mine/` обязан стоять в `payments/urls.py` до `<order_id>/`, иначе `mine` разберётся как номер заказа.
- Платежи на запуске выключены (решение шага 5). Страница должна честно говорить «Платні послуги тимчасово недоступні», а не падать.
- Кабинет: пункты меню — `frontend/app/me/page.tsx` (ссылки через `Link`, строка `href`), аналогичные страницы — `frontend/app/me/calculations/page.tsx`, `frontend/app/me/deals/page.tsx`.

## Цель
Отписка:
- [ ] Реестр «видов писем» с признаком `unsubscribable`: `listing_expiring` и `saved_search` отписываются; транзакционные (подтверждение email и сброс пароля из 1.6/1.7, решение модерации, платёжные уведомления) — нет. Список видов и подпись «не можна відписатися» — в одном модуле `notifications/email_kinds.py`, не размазан по коду.
- [ ] Модель `notifications.EmailUnsubscribe`: `user` (FK `settings.AUTH_USER_MODEL`, `CASCADE`), `kind` (код вида), `created_at`; уникальность (`user`, `kind`).
- [ ] Подписанный токен без входа: `django.core.signing` (соль `unsubscribe`), в токене `user_id` и `kind`, без email и без ПДн. Срок действия — настройка `UNSUBSCRIBE_TOKEN_MAX_AGE_DAYS` (`.env`; `0` = без срока, по умолчанию 0: ссылка из старого письма должна работать). Подделанный или повреждённый токен → 400 «Недійсне посилання для відписки», без раскрытия причины и без различия «нет пользователя»/«плохая подпись».
- [ ] Единый хелпер отправки `notifications/email.py::send_user_email(user, kind, subject, text, html=None)`: если `kind` отписываемый и пользователь отписан — письмо не уходит (возвращает `False`, запись в лог без ПДн); иначе добавляет в тело строку «Відписатися від таких листів: <ссылка>» и заголовки `List-Unsubscribe: <https://…/unsubscribe/<token>>` и `List-Unsubscribe-Post: List-Unsubscribe=One-Click`. Транзакционные виды отправляются всегда, без ссылки отписки. Хелпер использует отправителя из `DEFAULT_FROM_EMAIL`, не хардкод.
- [ ] Эндпоинты (`AllowAny`, без сессии, свой throttle-scope `unsubscribe`, ставка в `.env`): `GET /api/v1/notifications/unsubscribe/<token>/` — только описание (какой вид, активна ли отписка), состояния не меняет (защита от предзагрузки ссылок почтовыми сканерами); `POST` — выполняет отписку (поддерживает форму `List-Unsubscribe=One-Click` из RFC 8058 и JSON), идемпотентен; `POST` с `{"action": "resubscribe"}` — возвращает подписку («Повернути підписку»).
- [ ] Страница фронта `/unsubscribe/<token>`: при открытии клиентский код сам делает `POST` (одной ссылкой), показывает «Ви відписалися від листів про <вид>» и кнопку «Повернути підписку»; на ошибке — «Посилання недійсне або застаріле»; состояния загрузки/ошибки — компоненты 6.2. Страница без индексации (`noindex`), без хедера кабинета, не требует входа.
- [ ] Авторизованная отписка/подписка тоже работает: в кабинете для объявления с напоминанием и в `/me/saved-searches` остаются существующие переключатели; общая страница настроек каналов — этап 9 (9.14, 9.20), здесь не делается.
- [ ] Задача 4.7 и 4.3 вызывают `send_user_email` для видов `listing_expiring` и `saved_search`; прямые `send_mail` для этих видов запрещены (проверка Grep в «Готово, когда»).

История платежей:
- [ ] `GET /api/v1/payments/mine/` (`IsAuthenticated`, только платежи автора, пагинация): `order_id`, `created_at`, `purpose` и человекочитаемая метка, `description`, `amount`, `currency`, `status` и метка статуса, `tariff` (название), `local_listing_id` и короткий заголовок объявления (`make model year`, `null` если объявление удалено). В ответе нет `liqpay_raw`, `liqpay_payment_id`, `liqpay_status`, email и ключей. Аноним → 401; чужие платежи в выдачу не попадают.
- [ ] При `PAYMENTS_ENABLED=false` эндпоинт отвечает 404 (как остальные платёжные, решение шага 5). Страница `/me/payments` в этом случае не вызывает `mine/`, а проверяет `GET /payments/config/` (поле `enabled`) и показывает «Платні послуги тимчасово недоступні».
- [ ] Страница `/me/payments`: таблица (на мобильном — карточки) «Дата · Послуга · Оголошення (ссылка) · Сума · Статус»; пустой список — «Платежів ще не було»; состояния загрузки и ошибки — компоненты 6.2; пункт «Платежі» в меню кабинета (`frontend/app/me/page.tsx`) показывается только при включённых платежах.
- [ ] Платёж в статусе `pending` показывается как «Очікує оплати», `failed` — «Відхилено», `completed` — «Оплачено», `reversed` — «Повернено». Квитанции, повторная оплата, возврат — этап 9 (9.17), здесь нет.
- [ ] Индекс `Payment(user, -created_at)` для списка.

## Тесты
Django:
- Отписка: валидный токен, `GET` → 200 и описание, запись `EmailUnsubscribe` НЕ создаётся; `POST` → запись создана, второй `POST` → 200 без дубля; `POST` с `{"action": "resubscribe"}` → запись удалена; тело формы `List-Unsubscribe=One-Click` принимается; токен с чужим `kind` не отписывает от другого вида; подделанный/усечённый токен → 400 с одинаковым текстом; токен несуществующего пользователя → тот же 400; `override_settings(UNSUBSCRIBE_TOKEN_MAX_AGE_DAYS=1)` и просроченный токен (через подмену времени) → 400; при `0` старый токен работает; throttle `unsubscribe` → 429.
- `send_user_email`: отписываемый вид — в теле письма есть ссылка, в `message.extra_headers` есть `List-Unsubscribe` и `List-Unsubscribe-Post`; после отписки письмо не отправлено (`mail.outbox` пуст), результат `False`; транзакционный вид (подтверждение email) отправляется даже если запись отписки есть и без ссылки отписки; в ссылке и токене нет email.
- Подписи: токен для `user A` не работает как токен `user B` (подмена `user_id` ломает подпись).
- История платежей: аноним `GET /payments/mine/` → 401; пользователь видит только свои платежи (чужой платёж в выдаче отсутствует), порядок «новые сверху», пагинация; в ответе нет `liqpay_raw`, `liqpay_payment_id`, `liqpay_status`; платёж с удалённым объявлением → `local_listing_id` и заголовок `null`, без 500; `override_settings(PAYMENTS_ENABLED=False)` → 404 (маршрут `mine/` не перехватывается `<order_id>/`); с `True` → 200.
- Число SQL-запросов в `mine/` не растёт с числом платежей (`assertNumQueries` при 1 и при 20 платежах).
Playwright (`frontend/e2e/unsubscribe-payments.spec.ts`; платежи в окружении e2e — через `e2e_seed` из 0.4 с `PAYMENTS_ENABLED=true`):
- Успех: открыть ссылку отписки из письма (токен берётся из тестового API/seed) → «Ви відписалися…»; нажать «Повернути підписку» → подтверждение; затем напоминание о сроке для этого пользователя снова ставится в очередь.
- Ошибка/обход: `/unsubscribe/неправильний-токен` → «Посилання недійсне або застаріле», подписка не меняется; токен одного пользователя нельзя использовать для другого вида писем.
- Успех: пользователь с платежами открывает `/me/payments` и видит свои строки с метками статусов на украинском; ссылка на объявление ведёт на `/local/<id>`.
- Ошибка/обход: аноним на `/me/payments` перенаправлен на вход; при `PAYMENTS_ENABLED=false` страница показывает «Платні послуги тимчасово недоступні», а пункт «Платежі» в меню кабинета скрыт; чужой платёж (`order_id` другого пользователя) в таблице отсутствует.
