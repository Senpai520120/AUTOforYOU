# Задача 4.10: Вход и подтверждение телефона через Telegram-бота (share contact) [ВОЛНА-2] 🔒

## Контекст
Новая задача сверки с бизнес-планом (`docs/audit/40_BUSINESS_PLAN_SYNC.md` §1.1 п.2, §7; решение владельца в `docs/ANSWERS.md`, «Сверка с бизнес-планом»: подтверждение телефона через бота обязательно для подачи объявления, SMS — адаптер, выключен до этапа «Рост»). Защита от «мошенников и перекупов» (BUSINESS_PLAN, риски): подавать объявления может только пользователь с подтверждённым телефоном.

Что есть в коде (проверить Grep перед работой):
- Бот на aiogram: `telegram_bot/` (`handlers.py`, `views.py` — webhook и link-token, `middleware.py`, `models.py` — `TelegramLinkToken`). Привязка аккаунта к чату сейчас идёт по одноразовому токену из кабинета (задача 5.4 доводит тексты, `/unlink`, аннулирование старых токенов, throttle).
- Webhook с секретом `TELEGRAM_WEBHOOK_SECRET` и сравнением за постоянное время — задача 5.1; установка вебхука без секрета запрещена — 5.4.
- Телефон объявления сейчас — просто поле формы (`local_listings`, задача 4.2); признака «телефон подтверждён» у `CustomUser` нет.
- Капча и rate limit на входе — 1.5/1.6.

## Цель
- [ ] **Связка аккаунт ↔ Telegram-чат.** На сайте (кабинет, шаг «Підтвердіть телефон» при подаче объявления) кнопка «Підтвердити через Telegram» создаёт одноразовый токен связки (`POST`, только вошедшему) и открывает deep-link `https://t.me/<bot_username>?start=<token>`. Токен: случайный (`secrets.token_urlsafe`), в БД хранится только хэш, TTL из `TELEGRAM_LINK_TOKEN_TTL_MINUTES` (по умолчанию 10), одноразовый, новый токен аннулирует старые, привязан к `user_id`.
- [ ] **Share contact.** Бот по `/start <token>` проверяет токен и просит кнопкой `request_contact` («Поділитися контактом»). Принимается только сообщение с `message.contact`, у которого **`contact.user_id == message.from_user.id`** (контакт самого отправителя). Чужой контакт, пересланная карточка, контакт без `user_id` → отказ с понятным текстом, телефон не сохраняется, токен остаётся (или аннулируется после `TELEGRAM_LINK_MAX_ATTEMPTS` неудач).
- [ ] **Защита от перехвата.** Токен погашается атомарно (`select_for_update`/условный `update`), чат, уже привязанный к другому аккаунту, не привязывается повторно (ошибка «Цей Telegram уже підключено до іншого акаунта»); если у аккаунта привязан другой чат — замена только после явного подтверждения в кабинете. Телефон, уже подтверждённый на другом аккаунте, второй раз не подтверждается (уникальность нормализованного E.164).
- [ ] **Результат.** `CustomUser.phone_verified_at` (nullable) и нормализованный `phone` (E.164) заполняются из контакта; в кабинете статус «Телефон підтверджено». Телефон из контакта не подменяется телефоном из формы объявления: если они различаются, объявление использует подтверждённый номер (или показывает предупреждение, решает 4.2 по этому полю).
- [ ] **Обязательность для подачи.** `POST` создания/публикации объявления в `local_listings` при `phone_verified_at is None` → 403 с кодом `phone_not_verified` и текстом «Підтвердіть телефон через Telegram, щоб подати оголошення». Staff в режиме «засев» ВОЛНЫ-1 не блокируются. На фронте форма подачи показывает шаг подтверждения вместо формы.
- [ ] **Вход через Telegram — не включается автоматически.** Задача подтверждает телефон уже вошедшего пользователя (email+пароль, 1.x). Вход одним Telegram (без пароля) вне объёма: если нужен — вопрос владельцу (отдельная задача, риск захвата аккаунтов по номеру).
- [ ] **SMS-адаптер.** Интерфейс `PhoneVerifier` (методы `start`, `confirm`) с реализациями `TelegramContactVerifier` (включён) и `SmsVerifier` (заглушка, `SMS_VERIFY_ENABLED=false`, любой вызов → `NotConfigured`). Реальный SMS-провайдер — этап «Рост», здесь не подключается.
- [ ] **Rate limit и безопасность.** Throttle scope `tg_link` (`THROTTLE_TG_LINK_RATE`, по умолчанию `5/hour` на пользователя) на выдачу токена; webhook принимает апдейты только с верным `X-Telegram-Bot-Api-Secret-Token` (5.1), иначе 403; токены и телефоны не пишутся в логи целиком (маска), в админке токены read-only с маской (5.4).
- [ ] Все тексты бота — через `BotText` (5.4), на украинском; тексты интерфейса — на украинском.

## Тесты
Django (aiogram/Telegram API — моки, без сети):
- Успех: токен → апдейт `/start <token>` → апдейт с `contact` и `contact.user_id == from.id` → `phone_verified_at` задан, телефон в E.164, токен погашен.
- Обход: контакт с `contact.user_id != from.id` → телефон не сохранён, `phone_verified_at` пуст; контакт без `user_id` → отказ; повторное использование токена → отказ; токен старше TTL → отказ; старый токен после выдачи нового → отказ.
- Перехват: чат уже привязан к другому аккаунту → отказ; телефон уже подтверждён на другом аккаунте → отказ; токен чужого пользователя нельзя получить через API.
- Rate limit: шестой запрос токена за час → 429; неверный секрет вебхука → 403 и никаких изменений в БД.
- Подача объявления без подтверждения → 403 `phone_not_verified`; с подтверждением → 201; staff без подтверждения проходит (засев).
- `SmsVerifier` при `SMS_VERIFY_ENABLED=false` → `NotConfigured`; в логах и ответах API нет токена целиком и телефона целиком.
Playwright (`frontend/e2e/phone-verify.spec.ts`; бот и Telegram мокаются, апдейт имитируется POST на webhook с секретом тестового стека):
- Успех: пользователь без подтверждения открывает форму подачи → видит шаг «Підтвердіть телефон», жмёт «Підтвердити через Telegram» (ссылка `t.me/...?start=...`), после имитации апдейта со своим контактом форма подачи доступна.
- Ошибка/обход: апдейт с чужим контактом → статус остаётся «не підтверджено», форма подачи закрыта; прямой `POST` создания объявления без подтверждения → 403.
