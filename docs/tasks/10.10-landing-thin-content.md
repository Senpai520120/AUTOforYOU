## Цель
1. Порог уникального текста — условие публикации. «Уникальный текст» = сумма длин (после `strip`) полей `intro` + `description` + `included_text`. Не считаются: `h1`, `meta_*`, `typical_term_text` (короткие, шаблонные), ответы FAQ. Порог — поле `LandingSettings.min_text_chars` (по умолчанию **600**, допущение, ждёт подтверждения владельца в диапазоне 600-1000), правится в админке. Расчёт длины — одна функция в `landings/services.py`; в других местах числа нет.
2. Публикация (чекбокс в форме и действие «Опублікувати вибрані») отклоняется при коротком тексте с сообщением на украинском: «Текст замалий: N із M символів (вступ, опис, що входить у ціну). Допишіть унікальний текст про модель.» Достаточный текст — публикуется.
3. Уже опубликованные страницы не затрагиваются: миграция не меняет `is_published`, сайт их по-прежнему отдаёт, проверка срабатывает только при переходе «не опубликована -> опубликована» (иначе правка `sort_order` в `list_editable` у короткой страницы падала бы).
4. `launch_check`: WARNING со списком slug опубликованных страниц, не проходящих порог («Тонкий контент на N опублікованих сторінках: slug1, slug2, ...»); OK, если таких нет; без лендингов — молчит. Владелец решает сам: дописать текст или снять публикацию.
5. Поля с данными по модели: новых выдуманных данных нет. API `LandingDetailSerializer` отдаёт дополнительно `fuel_type` (человекочитаемое название), `engine_cc`, `battery_capacity_kwh` (уже вводятся владельцем), плюс новое необязательное поле `generation` (поколение/кузов, свободный текст до 100 символов). Пустые значения (`""`/`null`) в ответе не отдаются (ключ отсутствует), а на странице блок «Коротко про модель» не рендерится, если все пустые.
6. FAQ: новая модель `LandingFaqItem` (FK на `ModelLandingPage`, `question`, `answer`, `order`, `is_active=False` по умолчанию; тот же draft-маркер, что у `content.FaqItem`), редактируется inline на странице лендинга в админке. API отдаёт `faq: [{question, answer}]` только из активных без draft-маркера; пустой список не отдаётся. Страница рендерит блок «Поширені запитання» и `FAQPage` JSON-LD (по образцу `breadcrumbLd`), если вопросы есть. `content.FaqItem` не переиспользуется (нет связи и фильтра по модели, расширять общий справочник нецелесообразно).
7. Фикстура 13 -> 30 моделей — вне кода (список и тексты вносит владелец), пункт в LAUNCH_CHECKLIST.

## Шаги
1. Миграция и модели: `min_text_chars` (PositiveSmallIntegerField, default 600, min 100), `generation`, `LandingFaqItem`.
2. `services.py`: `unique_text_length(page)`, `thin_published_pages()`; в `clean()` — проверка длины, когда страница становится опубликованной (сравнить с сохранённым значением из БД); то же в `publish_selected` (через `clean()`/общий хелпер, не дублировать порог).
3. Сериализатор: новые поля и `faq`, пустое не отдаётся.
4. `core/launch.py`: `check_landing_content()` + вызов в `run_checks`.
5. Фронт: блок «Коротко про модель» (покоління, роки, паливо, об’єм, батарея), блок FAQ, `faqLd`, типы. Тексты интерфейса — украинский, по `modern-web-guidance`.
6. `e2e_seed` и LAUNCH_CHECKLIST (пункт «довести фикстуру до 30 моделей и написать тексты; порог 600 символов — подтвердить или изменить», раздел 5.2 рядом с п. «Список 30 моделей», стр. ~618).

## Тесты
Django (`landings/tests.py`, `core/tests_launch_check.py`; фабрики из `tests/factories.py`):
- публикация короткого текста через `full_clean()` и через `publish_selected` отклоняется с точным текстом сообщения (N и M в нём); достаточный текст публикуется; граница = порог ровно (проходит) и порог-1 (не проходит); изменение `min_text_chars` меняет результат.
- уже опубликованная короткая страница: правка `sort_order`/сохранение не падает, по API отдаётся 200 (миграция/проверка не снимает публикацию).
- `launch_check`: WARNING со slug тонких опубликованных; OK при отсутствии; неопубликованные в список не попадают.
- API: `fuel_type`, `engine_cc`, `generation` отдаются при заполнении и отсутствуют в ответе при пустых; `faq` — только активные и без draft-маркера, порядок по `order`, пустой — ключа нет; чужое/неопубликованное по-прежнему 404.
- Мутации: убрать проверку порога — тест красный; отдавать пустые поля — тест красный.
Playwright (`frontend/e2e/landing.spec.ts`): успех — на `[E2E]` лендинге `e2e-toyota-camry` виден блок «Коротко про модель» и FAQ (вопрос раскрывается/виден по тексту), в JSON-LD есть `FAQPage` с теми же вопросами; ошибка/обход — на `e2e-honda-accord` (без FAQ и без `generation`) блока FAQ нет и `FAQPage` в JSON-LD отсутствует; неактивный вопрос не показывается.

## Для владельца (LAUNCH_CHECKLIST)
- Подтвердить порог (допущение 600 символов; можно 600-1000) — админка → «Налаштування сторінок моделей» → «Мінімальна довжина унікального тексту».
- Довести список моделей с 13 до 30 и написать тексты (вступ, опис, «що входить у ціну») по каждой; при необходимости вопросы FAQ по модели (inline в админке).
- После деплоя прогнать `launch_check`: WARNING «Тонкий контент» показывает опубликованные страницы, которые нужно дописать или снять. Новых переменных `.env` нет.
