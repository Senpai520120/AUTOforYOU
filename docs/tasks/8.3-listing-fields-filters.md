# Задача 8.3: Поля объявления «Запуск», сортировки, фильтры, дата публикации

> Метка: [ВОЛНА-2]. Объединяет Н-3a, Н-11a, Н-13a (docs/audit/32_NEW_TASKS_INDEX.md). Оценка: 2 сессии (1 — модель, сериализаторы, фильтры, индексы; 2 — фронт и Playwright).

## Контекст
У C2C-объявления нет базовых для украинского рынка признаков, а покупатель не видит возраст объявления (пакеты 31_PARITY_A_B, 33_PARITY_E_F):
- Модель `LocalListing` (`local_listings/models.py:64-174`): нет привода, цвета, признаков «розмитнений» и «після ДТП». Есть `condition` (`:89-92`, `damaged`), но это другой смысл. `mileage_km` — `PositiveIntegerField` без верхней границы (`:125`); `LocalListingCreateSerializer`/`LocalListingUpdateSerializer` (`local_listings/serializers.py:149-234`) диапазон не проверяют (проверка есть только у `year`, `:180-184`).
- Фильтр `LocalListingFilter` (`local_listings/filters.py:6-96`) знает `make, model, year_*, price_*, fuel_type, transmission, body_type, region, city, mileage_max, search`; сортировки только `created_at, -created_at, price, -price` (`:88`). Задача 4.4 заменяет его на `LocalListingQuerySerializer` + `apply_local_listing_filters` и создаёт `frontend/lib/labels.ts`; здесь только расширение.
- Публичные сериализаторы (`local_listings/serializers.py:68-88`) отдают `created_at`/`updated_at`, но карточка и страница их не выводят (`frontend/components/local/LocalListingCard.tsx`, `frontend/app/local/[id]/LocalListingDetail.tsx`); `moderated_at` (`models.py:160`) в публичный ответ не входит. Возраст объявления покупатель не видит.
- Фронт: фильтры — `frontend/components/local/LocalListingFilters.tsx` (сортировка `:157-161`, кнопка «Скинути» `:176`), форма — `frontend/components/local/LocalListingForm.tsx`.
- `SUBSTANTIVE_FIELDS` (`local_listings/services.py:16`) задаёт, какие правки возвращают active в pending; помощник сравнения значений вводит 4.2.
- Индексы: `models.py:180-187` (`status, make, year, price, region, fuel_type`). Индексы под фильтры 4.4 — в самой 4.4 (Н-14a); здесь только индексы под новые поля и сортировки.

## Цель
- [ ] **Привод и цвет (A2.2, B3.2).** `drive_type` (`front`/`rear`/`awd`, подпись «Передній / Задній / Повний») и `color` (список из `TextChoices`: чорний, білий, сірий, сріблястий, синій, червоний, зелений, коричневий, бежевий, жовтий, помаранчевий, інший). Оба необязательные для старых записей (`blank`), но обязательные в форме подачи.
- [ ] **«Розмитнений» и «Після ДТП» (A5.5/B3.3).** `customs_cleared` и `accident` — `BooleanField(null=True)`: `null` = «не вказано» (старые записи). В форме подачи оба обязательны (явный выбор «Так/Ні», без значения по умолчанию). На карточке и странице — бейджи «Розмитнене / Не розмитнене», «Після ДТП» (при `null` ничего не показывается). Смена `customs_cleared` или `accident` у active-объявления считается существенной правкой (ремодерация) — добавить в `SUBSTANTIVE_FIELDS`, согласовав с хелпером сравнения значений из 4.2.
- [ ] **Верхняя граница пробега (A5.5).** `mileage_km` валидируется сверху настройкой `LOCAL_LISTING_MILEAGE_MAX` (`.env`/`core/settings.py`; значение — решение владельца, см. «Для владельца»); превышение → 400 с ошибкой у поля `mileage_km`. Значение приходит фронту из `GET /api/v1/local/config/` (эндпоинт создаёт 4.2).
- [ ] **Дата публикации и обновления (F2.2).** В публичном списке и детали новые поля `published_at` (= `moderated_at`, для старых без неё — `created_at`) и `updated_at`. Карточка: «Опубліковано N днів тому», страница: полная дата публикации и «Оновлено <дата>» (если отличается). Формат дат и «N днів тому» — через единый хелпер `frontend/lib/format.ts` (создать, если нет, — сначала Grep).
- [ ] **Сортировки (E2.1).** В `ordering` добавлены `year`, `-year`, `mileage_km`, `-mileage_km`; выпадающий список: «Рік: новіші», «Рік: старіші», «Пробіг: менший», «Пробіг: більший». Белый список — в `LocalListingQuerySerializer` (4.4).
- [ ] **Фильтры (E1.8, E2.1).** Параметры `customs_cleared` (`true`/`false`), `drive_type`, `color`, `accident` (`true`/`false`) валидируются тем же сериализатором (мусор → 400, не игнор). Записи с `null` не проходят фильтр «розмитнений = так/ні».
- [ ] **«Скинути фільтри» и пустая выдача.** Кнопка называется «Скинути фільтри», очищает все параметры и URL, видна только при активных фильтрах; при пустой выдаче под списком текст «За вашими фільтрами нічого не знайдено» и та же кнопка.
- [ ] **Индексы.** Миграция добавляет индексы под новые сортировки и фильтры (`(status, mileage_km)`, `(status, customs_cleared)`; финальный набор подтвердить `EXPLAIN` на Postgres, лишних не добавлять). Индексы под старые фильтры не дублируются (они в 4.4).
- [ ] Справочники привода и цвета, подписи бейджей — только в `frontend/lib/labels.ts` (создан в 4.4); форма, фильтр, карточка и страница импортируют их оттуда.

## Шаги
1. Тесты-сначала (см. «Тесты»).
2. Модель и миграция. **Причина изменения схемы:** признаки «розмитнений», «після ДТП», привод и цвет нужны покупателю для выбора и фильтрации, их нельзя вывести из существующих полей; индексы — под новые сортировки/фильтры. Старые записи: `null`/пусто, data-миграция не нужна.
3. Сериализаторы: новые поля в create/update/list/detail; `validate_mileage_km` по `LOCAL_LISTING_MILEAGE_MAX`; `published_at` как `SerializerMethodField`; новые поля обязательны только при создании (старые объявления редактируются без них).
4. `LocalListingQuerySerializer` и `apply_local_listing_filters` (4.4): новые параметры и сортировки; комментарий-перечень для индексов не нужен, индексы добавлены здесь.
5. `SUBSTANTIVE_FIELDS` + согласование с `is_substantive_change` (4.2): `customs_cleared`, `accident` существенны, `drive_type`, `color` — нет.
6. Фронт: поля формы (радио «Так/Ні», селекты), фильтры, сортировка, бейджи, даты, пустая выдача, `labels.ts`, лимит пробега из `/local/config/`.
7. Регенерировать `docs/openapi.yaml` (против Postgres). Прогон `DATABASE_URL= REDIS_URL= .venv/Scripts/python.exe manage.py test local_listings`, потом полный прогон один раз (через test-runner), `npm run build`, `npx tsc --noEmit`, Playwright.

## Тесты
Django (`local_listings/tests.py`):
- Создание без `customs_cleared`/`accident`/`drive_type`/`color` → 400 с ошибкой у каждого поля; с полями → 201 и значения в ответе.
- `mileage_km` = `LOCAL_LISTING_MILEAGE_MAX + 1` (через `override_settings`) → 400 `mileage_km`; ровно граница → 201.
- Старая запись с `customs_cleared=None`: PATCH только телефона → 200 и статус остаётся `active`; PATCH `accident` → статус `pending`; PATCH `color` → остаётся `active`.
- Фильтры: `customs_cleared=true` возвращает только `True` (не `null`), `accident=false`, `drive_type=awd`, `color=black`; `drive_type=xxx`, `customs_cleared=maybe` → 400.
- Сортировки: `ordering=year`, `-mileage_km` дают ожидаемый порядок; `ordering=hack` → 400.
- `published_at` равен `moderated_at`; при `moderated_at=None` равен `created_at`; публичный ответ не содержит `contact_phone`.
- Каталог по-прежнему исключает не-`active` при любых новых фильтрах.

Playwright (`frontend/e2e/c2c-listing-fields.spec.ts`; storageState из 0.4):
- Успех: продавец подаёт объявление с новыми полями → в кабинете и (после одобрения фикстурой) на карточке видны «Розмитнене», «Повний привід», цвет, «Опубліковано …». Покупатель на `/ua` включает фильтр «Розмитнені» → в выдаче только такие; выбирает «Пробіг: менший» → порядок верный; «Скинути фільтри» очищает URL и поля.
- Ошибка/обход: форма не отправляется без выбора «Розмитнений»; пробег выше лимита из `/local/config/` → ошибка под полем; `/ua?drive_type=xxx` открывается без падения и показывает «Некоректні параметри фільтра» (поведение 4.4); фильтр с пустой выдачей показывает «За вашими фільтрами нічого не знайдено».
