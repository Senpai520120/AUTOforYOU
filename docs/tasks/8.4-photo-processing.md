# Задача 8.4: Фото объявлений: ресайз, миниатюры, минимум фото

Метка волны: [ВОЛНА-2] (возвращена решением владельца после промта 02; на ВОЛНЕ-1 фото в админке без ресайза, см. «Изменения после бизнес-плана»).
Риск: обычный (серверная обработка изображений поверх уже проверенного слоя 1.10; ПДн и права не меняются).

## Контекст
Фото хранятся в исходном размере: при загрузке по 8 МБ каталог на мобильной сети тянет оригиналы (пункты эталона B4.1, B4.3; `docs/audit/31_PARITY_A_B.md`, Н-4a). WebP, порядок и поворот, водяной знак — Рост (этап 9, 9.2).

Что сейчас в коде:
- `LocalListingImage` — поле `image` с `upload_to='local_listings/'`, `source_url`, `is_primary`, `created_at`; порядок `['-is_primary', 'created_at']` (`local_listings/models.py:199-215`). Поля миниатюры нет, порядка (`position`) нет.
- Загрузка: `LocalListingImageUploadView` (`local_listings/views.py:266-315`): лимит числа `LOCAL_LISTING_MAX_PHOTOS` (`core/settings.py:322`, по умолчанию 15), лимит размера `LOCAL_LISTING_PHOTO_MAX_SIZE_MB`, всё или ничего по ошибкам; сохранение через `LocalListingImage.objects.create(image=f)` (`views.py:303-307`). Удаление и выбор главного — `LocalListingImageDetailView` (`views.py:322-354`).
- Сериализатор фото отдаёт `id`, `image`, `source_url`, `is_primary` (`local_listings/serializers.py:62-65`); публичный список объявлений включает все фото (`serializers.py:70`), карточка берёт главное или первое (`frontend/components/local/LocalListingCard.tsx:16-17`: `primary?.image || primary?.source_url || PLACEHOLDER_SVG`).
- Минимума фото нет: объявление создаётся и сразу получает статус `pending` (`local_listings/serializers.py:206-207`), а фото загружаются отдельным запросом после создания (4.2, пункт 10-Q5: «создано, а фото не загрузились»). Объявление без фото уходит на модерацию и выглядит недоделанным. Модерация — `approve_listing` (`local_listings/services.py:19-27`) без проверки числа фото.
- Задача 1.10 (1.10a) вводит `core/uploads.py`: `sanitize_image(file, *, max_bytes=None, subdir)`, поле `SanitizedImageField`, EXIF-очистку, uuid-имена, проверку по содержимому; пересохранение в тот же формат **без ресайза и миниатюр** (`docs/tasks/1.10-safe-uploads.md`, цели). Эта задача строится поверх неё и не дублирует проверку типа, размера, EXIF.
- Задача 4.2 вводит `GET /api/v1/local/config/` (`max_photos`, `photo_max_size_mb`, `max_active_listings`) и клиентскую проверку лимитов в `PhotoUploadBlock`; минимум фото туда не включён (отмечено в `docs/audit/31_PARITY_A_B.md`, B4.1).
- Файлы при удалении записи на диске не удаляются (стандартное поведение `FileField`); в 1.10 и 1.8 (Q3) заложено «не падать на уже отсутствующем файле».

## Цель
- [ ] Ресайз: изображение объявления приводится к максимальной стороне `LOCAL_LISTING_PHOTO_MAX_SIDE` (`.env`, пикселей; без увеличения маленьких, с сохранением пропорций, после `exif_transpose` из 1.10). Формат сохраняется (JPEG → JPEG, PNG → PNG, WEBP → WEBP), WebP-конвертации нет (9.2).
- [ ] Миниатюра для списков: поле `LocalListingImage.thumbnail` (файл, создаётся сервисом при загрузке, uuid-имя в подпапке `local_listings/thumbs/`), максимальная сторона `LOCAL_LISTING_THUMB_MAX_SIDE` (`.env`). Миниатюра без EXIF. Оба файла (оригинал после ресайза и миниатюра) создаются в одной операции: сбой любой — ни одной записи (поведение «всё или ничего» из 1.10 сохраняется).
- [ ] Сервис в `core/uploads.py` (расширение 1.10, не новая проверка): параметр `max_side` в `sanitize_image` и функция `make_thumbnail(file, *, max_side, subdir)`; ресайз применяется только там, где его явно запрашивают (`LocalListingImage`), поведение для фото трекинга и лотов не меняется.
- [ ] API: `LocalListingImageSerializer` отдаёт `thumbnail` (URL или `null` для старых фото); карточка каталога использует `thumbnail`, при `null` — `image`, затем `source_url`, затем заглушку; страница объявления — полный `image`. Размеры в публичном списке не раздувают ответ (оригиналы остаются в `image`, но карточка их не загружает).
- [ ] Минимум фото: настройка `LOCAL_LISTING_MIN_PHOTOS` (`.env`, по умолчанию 1; 0 = без минимума). Правила:
  - `approve_listing` (`local_listings/services.py:19`) отказывает, если фото меньше минимума: исключение `ListingNotReadyError` с текстом «Недостатньо фото: потрібно щонайменше N», админ-действие «Схвалити» показывает его сообщением и не меняет статус; в админке очереди есть фильтр «Достатньо фото» (аннотация числа фото);
  - владелец видит в кабинете `/me/local-listings` и на странице редактирования жёлтую плашку «Додайте щонайменше N фото, щоб оголошення пройшло модерацію», пока фото меньше минимума; число фото приходит в owner-сериализатор (`photos_count`), минимум — в `GET /local/config/` как `min_photos`;
  - удаление фото, после которого останется меньше минимума, отклоняется (400 «Не можна видалити: потрібно щонайменше N фото», главное фото перед этим можно заменить загрузкой нового);
  - клиентская проверка формы: при подаче нового объявления без выбранных фото кнопка отправки показывает «Додайте щонайменше N фото» до запроса.
- [ ] Файлы чистятся: при удалении `LocalListingImage` (и при каскадном удалении объявления) оба файла (оригинал и миниатюра) удаляются из хранилища сигналом `post_delete`; отсутствие файла не ошибка (не падает, как требует 1.10 при обезличивании по Q3).
- [ ] Команда `regenerate_listing_photos [--dry-run] [--batch N] [--resize-originals]`: создаёт миниатюры для уже загруженных фото; `--resize-originals` дополнительно пересохраняет оригиналы по `LOCAL_LISTING_PHOTO_MAX_SIDE` (старый файл удаляется только после успешной записи нового); идемпотентна, битые файлы выводятся в отчёт и не удаляются.
- [ ] Лимиты по умолчанию — настройки, не хардкод; ни фронт, ни бэк не содержат чисел: `min_photos`, `max_photos`, размеры приходят из настроек и `/local/config/`.

## Тесты
Django:
- Ресайз: JPEG 4000x3000 → максимальная сторона равна `LOCAL_LISTING_PHOTO_MAX_SIDE` (`override_settings`), пропорции сохранены; изображение меньше лимита не увеличивается; формат сохраняется (JPEG/PNG/WEBP); ориентация применена до ресайза.
- Миниатюра: создана при загрузке, размер не больше `LOCAL_LISTING_THUMB_MAX_SIDE`, имя — uuid в `thumbs/`, EXIF/GPS в миниатюре и оригинале пусты; PNG с прозрачностью не теряет формат; три файла в одном запросе → три миниатюры.
- Всё или ничего: один испорченный файл из трёх → ни одной записи и ни одного файла на диске (`override_settings(MEDIA_ROOT=tmp)` и проверка каталога).
- Сигнал: удаление фото и удаление объявления удаляют оба файла; повторное удаление записи с уже отсутствующим файлом не падает.
- Минимум: `approve_listing` без фото при `LOCAL_LISTING_MIN_PHOTOS=1` → `ListingNotReadyError`, статус не меняется; админ-действие показывает сообщение и не одобряет; при достаточном числе фото — одобряет; `LOCAL_LISTING_MIN_PHOTOS=0` → одобряет без фото; удаление последнего фото при минимуме 1 → 400, при 0 → 204; удаление при остатке ≥ минимума → 204; `GET /local/config/` содержит `min_photos`; owner-сериализатор отдаёт `photos_count`.
- Сериализатор: у нового фото `thumbnail` — абсолютный URL; у старого `null`; публичный список без утечек новых полей.
- Команда: `--dry-run` ничего не меняет; обычный запуск создаёт миниатюры только там, где их нет (повторный запуск идемпотентен); `--resize-originals` уменьшает большой оригинал и удаляет старый файл после успеха; битый файл попадает в отчёт без удаления.
Playwright (`frontend/e2e/photo-processing.spec.ts`; продавец и staff из 0.4):
- Успех: продавец загружает большой по пикселям JPEG → в `/ua` карточка грузит миниатюру (`img.src` из `thumbnail`, `naturalWidth` не больше настройки миниатюры), на странице объявления — файл с максимальной стороной не больше настройки ресайза.
- Успех: объявление с достаточным числом фото одобряется staff и появляется в каталоге.
- Ошибка/обход: подача формы без фото — «Додайте щонайменше N фото», запрос создания не отправлен; в кабинете у объявления без достаточного числа фото жёлтая плашка; попытка удалить последнее фото через API (`page.request`) → 400, в интерфейсе видно сообщение; staff в Django-админке нажимает «Схвалити» на объявлении без фото → сообщение «Недостатньо фото…» и статус не изменился.
