## Цель
- [ ] Настройка `C2C_ENABLED` (булева) в `core/settings.py`: читается из окружения, **в коде по умолчанию `false`** (безопасное значение при забытой переменной). Значения: `.env.docker.example` (шаблон прод/докер) — `false`; `.env.example` (dev) — `true`, чтобы разработчик видел раздел; тестовый блок настроек принудительно `true` (как токен бота `core/settings.py:401`), отдельные тесты включают/выключают через `override_settings`. Имя не конфликтует с существующими настройками (проверено grep).
- [ ] Одна точка чтения в бэкенде: `core/c2c.py` с функцией `c2c_enabled()`; больше нигде `settings.C2C_ENABLED` напрямую не читается.
- [ ] API под флагом (25 маршрутов выше) при выключенном флаге отвечает 404 `{"detail": "Not found."}` для любого метода и любого пользователя (включая staff), через **один** middleware по списку префиксов (`api/v1/local/`, `api/v1/deals/`, `api/v1/messages/`, `api/v1/saved-searches/`, `api/v1/payments/`), а не правкой каждого view. Новый маршрут под этими префиксами закрывается автоматически. Админка Django (`admin/`) не затрагивается: модерация и правка C2C-данных остаются доступными.
- [ ] Переписка (`messaging`) и сделки (`deals`) закрыты целиком, в том числе диалоги по лотам. Смешанные API закрываются на уровне сервиса, а не префиксом, и **лоты остаются рабочими**: `favorites` — любые операции с `listing_type='local'` → 404, список не содержит C2C-записей; `reports` — жалоба на C2C-объявление → 404. Включённый флаг ничего не меняет в их поведении.
- [ ] Публичный флаг для фронта: поле `c2c_enabled` (bool, только чтение, значение берётся из `c2c_enabled()`, не из модели `SiteSettings`) в ответе `GET /api/v1/site-settings/` из 1.12. Обоснование выбора: отдельной переменной `NEXT_PUBLIC_*` нельзя, она зашивается в сборку, и включение ВОЛНЫ-2 потребовало бы пересборки фронта (то есть не «на работающем сайте»); второй эндпоинт заводить не нужно. Источник правды один: переменная бэкенда.
- [ ] При выключенном флаге на фронте: пункты меню скрыты (шапка, бургер 6.1, главная, плитки кабинета `/me`, ссылки в подвале и пустых состояниях избранного); на карточке лота «Написати» заменено на «Залишити заявку», иконка чата в шапке скрыта и опрос `messages/unread-count/` не выполняется; все 8 маршрутов (7 C2C + `/me/messages`) отдают страницу «Скоро» с текстом «Оголошення по Україні — незабаром» и ссылкой «Перейти до калькулятора» на `/calculator`, с `robots: noindex, nofollow`; `sitemap.ts` не содержит `/ua` и `/local/...` и не делает запрос за C2C-объявлениями; `robots.ts` закрывает `/ua` и `/local/` на время выключенного флага. Недоступность `GET /api/v1/site-settings/` трактуется как «флаг выключен» (закрытый по умолчанию режим).
- [ ] Бот и фон: при выключенном флаге три задачи (`check_saved_searches`, `warn_expiring_listings`, `expire_listings`) возвращаются сразу, не обращаясь к БД и не отправляя писем и сообщений. Публикация C2C в канал (5.3) проверяет `c2c_enabled()` первой строкой; публикация лотов (`post_listing_to_channel`) не затронута.
- [ ] Включение ВОЛНЫ-2 = смена переменной и перезапуск бэкенда, без пересборки фронта и без миграций; фронт подхватывает значение по кэшу `getSiteSettings()` (не более нескольких минут).
- [ ] Лоты, калькулятор, заявки брокеру, вход/регистрация, `pricing`, `listings`, `shipments`, `users` флаг не затрагивает.

## Тесты
Django (`core/tests_c2c_flag.py`; общий список, никаких жёстко записанных URL):
- Параметризованный (`subTest`) обход резолвера: рекурсивно собрать все URL-паттерны из `get_resolver()`, для каждого маршрута с префиксом из константы middleware подставить тестовые значения параметров и проверить, что при `override_settings(C2C_ENABLED=False)` GET/POST/PATCH/DELETE (то, что маршрут допускает) дают 404, в том числе для анонима, обычного пользователя и staff.
- Тест «не проскочило»: каждый маршрут резолвера обязан попасть в один из трёх явных списков (`C2C_PREFIXES` с `local`, `deals`, `messages`, `saved-searches`, `payments`; `MIXED_API` (favorites, reports); `OPEN_API`); новый неклассифицированный эндпоинт валит тест.
