# Задача 1.14: Журнал согласий, версия документов, чекбокс 18+, «Налаштування cookie» в футере

> Источник: Н-32 (`docs/audit/37_PARITY_M_N.md`, N3.2, N4.1–N4.4, N5.1; `docs/audit/32_NEW_TASKS_INDEX.md`). Волна: [ВОЛНА-1]. Оценка: 1 сессия (запас до 2). Проверка security-reviewer: **обязательна** (ПДн, согласия).

## Контекст
- Согласие при регистрации хранится одним временем: `CustomUser.agreed_to_terms_at` (`users/models.py:38`), пишется в `RegisterSerializer.create` (`users/serializers.py:33-37`). Одно поле на два документа (условия и политика), версии и способа нет.
- Заявка дилера: `DealerApplication.agreed_to_processing_at` (`users/models.py:117`), запись в `users/services.py:36`; чекбокс проверяет `DealerApplicationCreateSerializer.validate` (`users/serializers.py:82-89`). Заявка брокеру (2.1) сохранит `Lead.consent_at`, но тоже без версии.
- Возраста 18+ нигде нет: в `RegisterSerializer` (`users/serializers.py:11,22`) и в форме `frontend/app/register/page.tsx:10,18,26,68-77` только согласие с условиями. Дату рождения не собираем (лишние ПДн).
- Cookie-согласие: `frontend/lib/consent.ts:15` ключ `cookie_consent`, значение — голая строка `'all'` или `'necessary'` (`:41-51`), без версии и даты. Отзыв уже работает: `clearConsent()` (`:54-58`) и кнопка «Відкликати згоду» в `frontend/components/ui/CookieSettings.tsx` (код кнопки не трогать). Баннер: `frontend/components/ui/CookieBanner.tsx` (показывается при `consent === null`).
- В футере только ссылка `/cookies` с подписью «Cookie» (`frontend/components/layout/Footer.tsx:16`); способа открыть настройки cookie с любой страницы нет (23-P7 в задаче 0.5 проверяет отзыв на `/cookies`).
- Версия документов появится в 1.12: `SiteSettings.legal_docs_version` и `legal_docs_reconsent_required` (публичный `GET /api/v1/site-settings/`, хелпер `frontend/lib/site-settings.ts`). Правило владельца (ANSWERS, шаг 7): повторное согласие нужно, только если изменились категории данных, цели, получатели или сроки хранения; остальные правки — новая версия без повторного согласия.
- Существующие тесты, которые придётся обновить из-за обязательного 18+: `users/tests.py:263-267`, `tests/test_e2e.py:109`, `frontend/e2e/register.spec.ts`.

## Цель
- [ ] Модель `ConsentRecord` (приложение `users`): `user` (FK, `SET_NULL`, null для гостя), `lead` (FK на `leads.Lead`, `SET_NULL`, null), `document` (module-level `TextChoices`: `terms`, `privacy`, `dealer_processing`, `lead_processing`, `age_18`), `doc_version` (строка, копия `legal_docs_version` на момент согласия; может быть пустой, если владелец ещё не задал), `given_at`, `method` (`register`, `dealer_form`, `lead_form`). **IP, user-agent и текст чекбокса не хранятся.** Запись только создаётся, не меняется.
- [ ] Регистрация: обязательный чекбокс «Мені виповнилося 18 років» (поле `confirmed_age_18`, без него 400 с понятной ошибкой, пользователь и записи не создаются). При успехе пишутся три записи: `terms`, `privacy`, `age_18` (`method=register`). `agreed_to_terms_at` остаётся как есть (совместимость).
- [ ] Заявка дилера: тот же чекбокс 18+; записи `dealer_processing` и `age_18` (`method=dealer_form`).
- [ ] Заявка брокеру: после `create_lead` (2.1) в той же транзакции запись `lead_processing` с привязкой `lead`, `user` — если вошёл (гость: `user=null`). Контактные данные в запись не копируются.
- [ ] `cookie_consent` в localStorage хранится как JSON `{level, version, ts}`; старое значение-строка читается как `level` без версии (выбор пользователя не теряется). `version` берётся из публичных настроек (`legal_docs_version`).
- [ ] Баннер показывается заново, только если сохранённая версия отличается от текущей **и** `legal_docs_reconsent_required=true`. Иначе выбор остаётся (новая версия без повторного согласия).
- [ ] В футере на всех страницах кнопка «Налаштування cookie» (рядом с юридическими ссылками): открывает баннер/панель выбора поверх страницы без перехода и показывает текущий выбор. Ссылка «Cookie» на `/cookies` остаётся.
- [ ] Админка `ConsentRecordAdmin`: только чтение (add, change, delete запрещены), фильтры по документу, версии, дате, поиск по email пользователя; доступ — только admin/superuser (не `moderator` и не `broker`, Q10).
- [ ] Выгрузка данных (1.8) включает записи согласий пользователя; при удалении аккаунта (Q3) запись остаётся без привязки к пользователю (`user=null`) как доказательство согласия; срок хранения таких записей — вопрос юристу (см. «Для владельца»), код их не удаляет.
- [ ] Тексты интерфейса на украинском; текст чекбокса и ошибок лежит в `frontend/lib/labels.ts` / серверных сообщениях, не размазан по компонентам.

## Шаги
1. Миграция `ConsentRecord` (причина: версию, дату и способ согласия нельзя восстановить задним числом, а `agreed_to_terms_at` их не хранит). Индексы `(user, document)` и `(document, doc_version)`. `TextChoices` на уровне модуля (ловушка проекта).
2. `users/consents.py`: `record_consents(...)` читает `SiteSettings.load().legal_docs_version` (1.12); пустая версия допустима, пишется пустая строка и предупреждение в лог без ПДн.
3. `RegisterSerializer`: поле `confirmed_age_18` (write-only, обязательно, как `agreed_to_terms`); `validate` отдаёт ошибку на украинском; `create` вызывает `record_consents(...)` в одной транзакции с созданием пользователя (`transaction.atomic`). Так же для заявки дилера и `create_lead`.
4. Админка и выгрузка/удаление (1.8): записи видны владельцу в выгрузке; при удалении аккаунта `user` обнуляется.
5. `consent.ts`: `readConsent()` → `{level, version, ts} | null` (JSON, безопасный разбор; старая строка → `{level, version: null, ts: null}`); `setConsent(level, version)`; `getConsent()` и `hasAnalyticsConsent()` сохраняют текущие сигнатуры (их использует 3.5). Новая функция `shouldAskAgain(storedVersion, currentVersion, reconsentRequired)`.
6. `layout.tsx` (серверный) берёт `getSiteSettings()` (1.12) и передаёт `CookieBanner` пропсы `legalVersion` и `reconsentRequired`; при недоступном API — без версии, баннер ведёт себя как раньше. Страницы не должны пререндериться с пустыми данными (ловушка `force-dynamic`, см. 1.12).
7. `CookieSettingsLink.tsx` (client): кнопка в футере диспатчит событие, баннер слушает его через `subscribeConsent`-совместимый механизм и показывается независимо от сохранённого выбора. Перед работой с Next прочитать актуальные руководства в `frontend/node_modules/next/dist/docs/` (версия Next нестандартная, см. `frontend/AGENTS.md`).
8. Фронт регистрации и заявки дилера: чекбокс «Мені виповнилося 18 років» с `htmlFor`/`id`, кнопка не отправляет без него, ошибка поля под чекбоксом.
9. Обновить старые тесты (см. «Контекст»), перегенерировать `openapi.yaml` (только против Postgres).

## Тесты
Django (`users/tests.py`, `leads/tests.py`):
- Регистрация без `confirmed_age_18` → 400, пользователь и `ConsentRecord` не созданы; с ним → 201 и ровно три записи (`terms`, `privacy`, `age_18`, `method=register`, `doc_version` равен `legal_docs_version` на момент запроса).
- Изменили `legal_docs_version` → новая регистрация пишет новую версию, старые записи не меняются.
- Заявка дилера без 18+ → 400; с ним — две записи, `agreed_to_processing_at` по-прежнему заполнен.
- `create_lead` от гостя → запись `lead_processing` с `lead`, `user=None`; от вошедшего — с `user`. Откат транзакции создания заявки не оставляет «висящей» записи.
- Админка: add/change/delete → 403; `moderator` и `broker` не видят раздел; в записи нет полей IP и user-agent (проверка по `_meta`).
- Выгрузка 1.8 содержит записи согласий пользователя; удаление аккаунта оставляет записи с `user=None`.
Playwright (`frontend/e2e/consent.spec.ts`, `register.spec.ts`; данные ставятся через фикстуры 0.4):
- Успех: регистрация с обоими чекбоксами проходит; в футере на `/`, `/calculator` и `/privacy` есть «Налаштування cookie», клик открывает панель, выбор «Лише необхідні» сохраняется как JSON с `version`.
- Успех: в localStorage лежит старое значение `'all'` → страница не показывает баннер заново и не падает, `hasAnalyticsConsent()` остаётся `true`.
- Повторное согласие: версия в настройках сменилась и `reconsent_required=true` (мок `GET /api/v1/site-settings/` через `page.route`) → баннер появился заново; при `reconsent_required=false` — не появился.
- Ошибка/обход: регистрация без 18+ (кнопка заблокирована; прямой POST без поля) → ошибка, аккаунт не создан; повреждённое значение `cookie_consent` (невалидный JSON) → страница работает, баннер показан как при первом визите; API настроек недоступен (500) → баннер работает без версии.
