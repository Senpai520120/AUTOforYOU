# Задача 4.5: Журнал показов телефона и уведомления модерации

## Контекст
Телефон продавца отдаёт только `GET /api/v1/local/listings/<pk>/contact/` (`local_listings/views.py:364-378`): авторизованным, только `active`, throttle scope `contact` (`THROTTLE_CONTACT_RATE`, по умолчанию `20/hour`, `core/settings.py:238`). Модерация идёт в админке (`local_listings/admin.py`), жалобы — `POST /api/v1/reports/` (`reports/views.py:6-8`) и экшены админки (`reports/admin.py:8-61`). Шаги 2 и 5 сценария 3 (`docs/audit/20_SCENARIOS.md`).

Что сейчас в коде:
- **05-S6 (важно):** показ телефона нигде не журналируется (кто, когда, какое объявление). Лимит только почасовой на аккаунт — массовый сбор номеров через несколько аккаунтов или равномерно в течение суток не обнаружить и не остановить (`local_listings/views.py:364-378`, `core/settings.py:238`).
- **05-Q9 (важно):** никто не уведомляется:
  - о новом `pending`-объявлении (создание `local_listings/serializers.py:186-222`, ремодерация `:258-266`) — модератор узнаёт, только открыв админку;
  - о новой жалобе (`reports/views.py:6-8` — голый `CreateAPIView`);
  - владелец объявления не получает уведомления, когда его объявление скрыто по жалобе (`reports/admin.py:8-18` меняет статус через `save()` без причины и без уведомления); автор жалобы не узнаёт результат (`dismiss_report`, `reports/admin.py:46-48` — `queryset.update`).
- Роли и право модерации вводит задача **1.2**: `role=broker`, менеджер `CustomUser.objects.brokers_and_admins()`, Django-permission `local_listings.moderate_locallisting` (вопрос Q10 «кто модерирует», по умолчанию — broker и admin с этим правом). Здесь получатели уведомлений модерации — пользователи с этим правом.
- Желательные того же места: 05-Q15 (ошибки уведомлений глушатся `except Exception: pass`, `local_listings/services.py:65-78`), 05-C3 (from-адрес `noreply@autoforyou.ua` захардкожен вместо `DEFAULT_FROM_EMAIL`, `local_listings/services.py:62`), 05-Q18 (`ban_reported_user` банит без подтверждения, `reports/admin.py:23-41`), 05-Q16 (гонка двойной жалобы → `IntegrityError` → 500, `reports/serializers.py:22-29`, `reports/models.py:51-62`).
- Отправка email и Telegram идёт через адаптеры задачи 3.4 (SMTP, Telegram). Если к моменту задачи адаптеров нет — через текущие `send_mail` и `integrations.tasks.send_notification`, но из `transaction.on_commit`.

## Цель
- [ ] **05-S6:** модель `ContactView` (`user` FK, `listing` FK, `created_at`, индекс `(user, created_at)` и `(listing, created_at)`). Номер телефона, IP и user-agent **не хранятся** (бриф §3: логирование без ПДн сверх необходимого). Каждый успешный ответ `/contact/` пишет запись; повторный просмотр того же объявления тем же пользователем в течение часа новой записи не создаёт.
- [ ] Суточный лимит на аккаунт: второй throttle-класс `contact_daily` (`THROTTLE_CONTACT_DAILY_RATE`, по умолчанию `60/day`) вдобавок к почасовому. Сверх лимита → 429 с понятным текстом «Ліміт переглядів телефонів на сьогодні вичерпано».
- [ ] Аномалии: если пользователь за сутки открыл телефоны у ≥ `CONTACT_VIEW_ALERT_THRESHOLD` разных объявлений (по умолчанию 30), модераторы получают одно in-app уведомление (не чаще раза в сутки на пользователя) со ссылкой на фильтр журнала в админке. Содержимое — id и email-маска пользователя, число просмотров; телефоны — нет.
- [ ] В админке «Перегляди телефонів» (только чтение, только для пользователей с правом `local_listings.moderate_locallisting` или superuser): фильтры по дате, пользователю, объявлению; колонка «переглядів за добу».
- [ ] Хранение: Celery-задача раз в сутки удаляет записи старше `CONTACT_VIEW_RETENTION_DAYS` (по умолчанию 90). Срок указан в политике конфиденциальности (фраза для владельца — в LAUNCH_CHECKLIST; текст страницы меняет задача 6.4, если она ещё не закрыта — пункт передаётся ей через `PROGRESS.md`).
- [ ] **05-Q9, модерация:** при переходе объявления в `pending` (создание и ремодерация) модераторы (право `moderate_locallisting`) получают in-app уведомление «Нове оголошення на модерації» со ссылкой на очередь модерации в админке. Telegram — одной сводкой, не чаще раза в `MODERATION_DIGEST_MINUTES` (по умолчанию 15), чтобы не спамить при потоке.
- [ ] **05-Q9, жалобы:** новая жалоба → in-app уведомление модераторам (+ Telegram по той же схеме дайджеста). Скрытие объявления по жалобе → владелец получает in-app + Telegram + email «Оголошення приховано за скаргою» с причиной (из формы экшена, как `reject_reason.html`). Закрытие жалобы (скрыто/забанено/відхилено) → автор жалобы получает in-app «Вашу скаргу розглянуто» без подробностей о другой стороне.
- [ ] Все уведомления ставятся через `transaction.on_commit`; ошибки отправки логируются (05-Q15), from-адрес — `settings.DEFAULT_FROM_EMAIL` (05-C3).
- [ ] Экшен `ban_reported_user` — через промежуточную страницу подтверждения со списком пользователей (05-Q18). Двойная жалоба в гонке → 400, а не 500 (05-Q16).

## Шаги
1. Тесты-сначала (см. «Тесты»).
2. Миграции. **Причины изменения схемы:** `ContactView` — журнал показов телефона для обнаружения массового сбора номеров (05-S6, бриф §3); новые значения `Notification.Type` — уведомления модераторов, владельцев и авторов жалоб (05-Q9).
3. `LocalListingContactView`: throttle-классы `contact` + `contact_daily`, запись `ContactView` (дедупликация за час), проверка порога аномалии.
4. `local_listings/moderation_notify.py`: `moderators()` = пользователи с `moderate_locallisting` (через хелпер из 1.2), `notify_moderators(kind, obj)`; дайджест Telegram через кэш-ключ с TTL `MODERATION_DIGEST_MINUTES`.
5. Вызовы: создание и ремодерация объявления → `notify_moderators('pending', listing)`; `ReportCreateView.perform_create` → `notify_moderators('report', report)`; экшены жалоб → уведомления владельцу и автору; промежуточные формы причины скрытия и подтверждения бана.
6. Celery beat: `cleanup_contact_views` раз в сутки.
7. Админка журнала (read-only, права).
8. `.env.example`: новые переменные с комментариями. Регенерировать `docs/openapi.yaml` (против Postgres).
9. Прогон `DATABASE_URL= REDIS_URL= .venv/Scripts/python.exe manage.py test`, build, tsc, Playwright из `frontend/`.

## Тесты
Django (`local_listings/tests.py`, `reports/tests.py`; Telegram и email — мок/`locmem`):
- 23-D80 / 05-S6: `/contact/` авторизованным → 200 и запись `ContactView(user, listing)`; повтор в течение часа → записей по-прежнему 1; в `ContactView` нет полей с телефоном (проверка `_meta.get_fields()`).
- 23-D80: `override_settings` с `contact: '2/hour'` → третий запрос 429; `contact_daily: '3/day'` при большом почасовом → четвёртый 429 с текстом про добовий ліміт. Аноним → 401, не-active → 404 без записи в журнал.
- Аномалия: `CONTACT_VIEW_ALERT_THRESHOLD=3`, просмотр 3 разных объявлений → у модератора одно уведомление `contact_anomaly`; четвёртый просмотр в те же сутки новых уведомлений не создаёт; в тексте нет телефонов.
- Очистка: запись старше `CONTACT_VIEW_RETENTION_DAYS` удаляется задачей, свежая остаётся.
- Админка журнала: пользователь без права → 403; с правом → 200; add/change/delete запрещены.
- 05-Q9: создание объявления → у пользователя с правом модерации уведомление `moderation_pending`, у обычного staff без права — нет; `send_notification.delay` вызывается через `on_commit` (`captureOnCommitCallbacks`), два объявления подряд в окне дайджеста → один Telegram-вызов.
- 05-Q9: новая жалоба → `report_new` модератору. Экшен скрытия с причиной (через `Client` админа) → объявление `hidden`, владелец получил in-app и письмо (`mail.outbox`, from = `DEFAULT_FROM_EMAIL`) с причиной; автор жалобы — `report_reviewed`. `dismiss_report` → автор получил `report_reviewed`, владелец — ничего.
- 05-Q18: POST экшена бана без подтверждения показывает промежуточную страницу, пользователь не забанен; с подтверждением — забанен.
- 05-Q16: `IntegrityError` при второй жалобе (смоделировать обходом валидации) → 400.
- Ошибка отправки Telegram (мок бросает исключение) → уведомление in-app создано, ошибка в логе (`assertLogs`), ответ API 201.

Playwright (`frontend/e2e/c2c-phone.spec.ts`, 23-P30):
- Успех: покупатель (storageState из 0.4) на странице active-объявления жмёт «Показати телефон» → номер виден; в админке под staff с правом модерации в «Перегляди телефонів» есть запись с этим покупателем и объявлением.
