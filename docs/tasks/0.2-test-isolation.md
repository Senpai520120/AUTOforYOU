# Задача 0.2: Изоляция тестов от внешнего мира

## Контекст
Результат `manage.py test` зависит от локального `.env` и порядка запуска классов.

**13-S9 (важно).** Три теста работают без мока платного внешнего API:
- `integrations/tests.py:582-585`, `VinReportAccessTest.test_authenticated_allowed`. Вызывает `VinReportView`, а она зовёт `get_opendatabot_provider()` (`integrations/providers.py:252-254`, ключ из `settings.OPENDATABOT_API_KEY`). С ключом уходит реальный `httpx.get(..., params={'apikey': …})` (`integrations/providers.py:209`).
- `integrations/tests.py:452-462`, `test_apify_no_token_returns_demo_true`. Зелёный только при пустом `APIFY_TOKEN`, ассерт `assertIn(status, (200, 201, 400))` (13-Q10).
- `tests/test_e2e.py:555-567`, `test_within_limit_responds_normally`. `/registry/` без мока провайдера, ассерт `assertNotEqual(…, 429)` (13-Q10).

Почему это возможно:
- `core/settings.py:14` подгружает `.env` (`load_dotenv`);
- под тест-раннером обнуляется только Telegram (`core/settings.py:406-407`);
- `OPENDATABOT_API_KEY` (`:328`), `APIFY_TOKEN` (`:331`), `LIQPAY_*` (`:301-303`) и SMTP (`EMAIL_BACKEND`/`EMAIL_HOST_*`, `:335-343`) приходят из `.env` как есть (13-C1).

**13-Q13 (важно).** Кэш тарифов переживает откат транзакции `TestCase`:
- `_lookup_tier` читает тиры из `pricing_cache.get_auction_fee_tiers()` (`pricing/views.py:53`);
- классы, которые сидируют тарифы в `setUpClass` через `call_command`, оставляют в LocMem-кэше объекты удалённых строк: `pricing/tests.py:576-579` (`TestIAAITierBoundaryDB`), `:645-649` (`TestLandedCostE2ECopartBroker`), `tests/test_e2e.py:157-161` (`TestCalculatorAPIE2E`);
- `cache.clear()` вызывается только в отдельных классах: `pricing/tests.py:768,856`, `integrations/tests.py:137,476,499`, `tests/test_e2e.py:536`.

Сейчас ни один тест не ждёт пустых тарифов, поэтому зависимость скрытая. Задача 2.5/2.6 (422 при пустых тарифах) на неё наткнётся.

Связанные находки того же места:
- **13-C2 (желательно).** При заданном `REDIS_URL` и `DEBUG=false` кэш — живой Redis (`core/settings.py:147-157`): `cache.clear()` в тестах сотрёт его. Celery перестаёт быть eager (`:358-364`).
- **13-Q15 (желательно).** `setUpClass` + `call_command` вместо `setUpTestData` в тех же классах.
- **Ловушка aiogram (23-D4).** Очистка `Update.event_type.fget.cache_clear` есть только в `BotRuntimeTestCase` (`telegram_bot/tests.py:113`). Новый тест с настоящим `Update` вне наследника даст segfault 139 в CI.
- В `core/settings.py` два одинаковых флага тест-раннера: `_testing` (`:36`) и `_TESTING` (`:418`).

Ловушка для этой задачи: `local_listings/tests.py:735` подписывает колбэк LiqPay ключом `settings.LIQPAY_PRIVATE_KEY`. При пустом ключе тест проходит, и это маскирует 06-S1 (пустой ключ принимается). Нужны фиксированные тестовые ключи, как в `tests/test_e2e.py:269-270` (`override_settings` с `_TEST_PUB`/`_TEST_PRIV`), а не пустая строка.

## Цель
- [ ] Флаг тест-раннера в `core/settings.py` один (`_TESTING`), вычисляется один раз.
- [ ] Под тест-раннером независимо от `.env`:
  - пусты `OPENDATABOT_API_KEY`, `APIFY_TOKEN`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD` и `TELEGRAM_BOT_TOKEN`;
  - `EMAIL_BACKEND = 'django.core.mail.backends.locmem.EmailBackend'`;
  - `LIQPAY_PUBLIC_KEY`/`LIQPAY_PRIVATE_KEY` — пустые. Тесты, которым нужна подпись, задают ключи через `override_settings`;
  - будущие ключи провайдеров (carVertical и др., этап 3) обнуляются в том же блоке, рядом комментарий-правило.
- [ ] Под тест-раннером `CACHES` — всегда `LocMemCache`, а `CELERY_TASK_ALWAYS_EAGER=True` и `CELERY_BROKER_URL='memory://'` даже при заданных `REDIS_URL` и `DEBUG=false`.
- [ ] Сетевой предохранитель: свой `TEST_RUNNER` (`core/test_runner.py`) запрещает исходящие соединения на время тестов. Исключения — `localhost`, `127.0.0.1`, `::1` и хост из `DATABASE_URL` (Postgres в CI). Попытка соединения даёт исключение с понятным текстом: «Внешний сетевой запрос в тесте: <host>:<port>. Замокайте провайдер».
- [ ] Тот же раннер после прогона чистит кэш `Update.event_type` (если aiogram импортирован), закрывая ловушку 23-D4 для всех тестов, а не только для `BotRuntimeTestCase`.
- [ ] Три теста из 13-S9 не ходят в сеть и проверяют один ожидаемый код:
  - VIN-отчёт → 200 с моком провайдера и проверкой demo-флага/полей;
  - Apify без токена → конкретный код, который сейчас отдаёт вью (выяснить прогоном и зафиксировать с комментарием);
  - registry «в пределах лимита» → 200 с моком провайдера.
- [ ] `local_listings/tests.py:735`: подпись колбэка идёт через фиксированный тестовый ключ из `override_settings`.
- [ ] Классы с seed тарифов наследуются от общего базового класса. Он делает `cache.clear()` в `setUpClass` (после `super()`), в `setUp` и в `tearDownClass`, а seed перенесён в `setUpTestData` (13-Q15).
- [ ] Есть тест 23-D3: после класса с seed тариф без seed-данных не находится (`_lookup_tier` → `None`, API расчёта → текущий ответ «нет тарифов», сейчас 422).
- [ ] Полный прогон зелёный и при `REDIS_URL=redis://nonexistent:6379/0` в окружении: кэш и Celery не пытаются подключиться.
