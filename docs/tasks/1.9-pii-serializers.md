- Связанная желательная **08-S11**: показ email контрагентов на фронте (`me/deals/page.tsx:102`, `me/local-listings/page.tsx:133-134`) — закрывается вместе с 06-S5.

## Цель
- [ ] Один хелпер `users/display.py: public_display_name(user)`: «Ім'я П.» (имя + первая буква фамилии), если имени нет — «Користувач»; для удалённого (`deleted_at`, задача 1.8) — «Користувач видалений». Никогда не производится от email или телефона.
- [ ] `listing-buyers` возвращает `[{id, display_name}]` без email, имени и фамилии целиком.
- [ ] `DealUserSerializer` → `{id, display_name}`; `ReviewSerializer` → `author_name` вместо `author_email`.
- [ ] `ParticipantSerializer` → `{id, display_name}`; `sender_name` в сообщениях — через тот же хелпер.
- [ ] Тексты уведомлений (in-app и Telegram) в `deals/services.py:57` и `messaging/services.py:149` — через хелпер.
- [ ] `owner_name` в `local_listings` — через хелпер (никакой части email). В детальном сериализаторе появляется `is_owner: bool` (true только для владельца), `LocalListingDetail.tsx:38` использует его.
- [ ] Email пользователя по API видит только он сам (`/auth/profile/`, выгрузка из 1.8). Администратор видит email в Django Admin, а не в публичных/пользовательских эндпоинтах.
- [ ] Фронт: типы `DealUser`, `MessageParticipant`, `DealReview`, покупатель в `api/deals.ts` без `email`; места отображения (`me/deals/page.tsx:102`, `me/local-listings/page.tsx:133-134`, `me/messages/page.tsx:165`) показывают `display_name`.
- [ ] Тесты 401/403 на `listing-buyers` (13-S1) и тесты отсутствия email во всех перечисленных ответах.
