> Дубль (группа G17): подход к нечисловым query-параметрам (валидация сериализатором, 400 вместо 500) задаёт задача 2.8 (владелец группы); здесь тот же подход для `LocalListingFilter`.

## Контекст
Каталог `/ua` фильтруется ручным бэкендом `LocalListingFilter` (`local_listings/filters.py:9-96`). Сохранённые поиски хранят фильтры как JSON (`saved_searches/models.py:12`) и обрабатываются ежедневной задачей `check_saved_searches` (`saved_searches/tasks.py:8-57`) со своей копией логики фильтра (`saved_searches/tasks.py:60-88`). Избранное — `favorites/views.py:11-75`, сериализатор `favorites/serializers.py`. Это шаг 4 сценария 3 (`docs/audit/20_SCENARIOS.md`).

Что сейчас в коде:
- **05-Q3 (важно):** `price_min`/`price_max` сравнивают `price` без учёта валюты (`local_listings/filters.py:41-50`), сортировка `price`/`-price` тоже (`:88-94`). Объявления в UAH, USD и EUR перемешаны: «до 10 000» пропускает авто за 10 000 USD.
- **05-Q4 (важно):** `price_min=abc` → `filter(price__gte='abc')` бросает `django.core.exceptions.ValidationError`, а ловятся только `ValueError`/`TypeError` (`local_listings/filters.py:41-50`) → 500. Остальные числовые параметры (`year_*`, `region`, `city`, `mileage_max`, `:31-71`) мусор молча игнорируют.
- **05-Q1 (важно):** сохранённый поиск берёт объявления с `created_at > last_notified_at` (`saved_searches/tasks.py:27-31`), но объявление становится `active` только после модерации. Если задача прошла между подачей и одобрением, объявление не попадёт в уведомления никогда (`last_notified_at` сдвигается на `now`, `:43`).
- **05-Q2 (важно):** фильтры JSON не валидируются (`saved_searches/serializers.py:6-10`). `int('abc')` в `_apply_filters` (`saved_searches/tasks.py:68-71,86-87`) роняет всю задачу — уведомления перестают приходить всем. Логика расходится с каталогом: нет `search`, `region`/`city` без `int`, нет сортировки.
- **05-S7 (важно):** в избранное можно добавить любое объявление по id, включая чужое `pending`/`rejected`/`hidden` (`favorites/views.py:31-38`), и `FavoriteSerializer` затем отдаёт его заголовок, цену и фото (`favorites/serializers.py:25-67`) — утечка непубличных объявлений.
- **05-Q8 (важно):** `listing_id='abc'` → `ValueError` → 500; несуществующий id на Postgres даёт `IntegrityError` (FK) — `get_or_create` ловит его и возвращает `None` → 500 при сериализации (`favorites/views.py:26-46`). `DELETE` без `listing_type` удаляет по imported (`favorites/views.py:52-56`). Нет CHECK «ровно один FK» (`favorites/models.py:27-36`). `FavoriteStatusView` с мусорным id → 500 (`:66-75`).
- Желательные того же места: 05-Q21 (избранное и сохранённые поиски без пагинации и лимита, `favorites/views.py:14-22`), 05-Q15 (Telegram-ошибка в задаче глушится `except: pass`, `saved_searches/tasks.py:47-52`), 05-C5 (лимит 10 объявлений в уведомлении захардкожен, `saved_searches/tasks.py:33`), 10-Q13 (фильтры не синхронизируются с URL на «назад/вперёд» — `useState` инициализируется один раз, `frontend/components/local/LocalListingFilters.tsx:14-27`), 10-Q14 (`?page=abc` → `NaN`, все страницы подряд, `frontend/app/ua/LocalCatalogGrid.tsx:47-48,61`), 10-C4 (`PAGE_SIZE = 20` захардкожен, `LocalCatalogGrid.tsx:6`), 10-C5 (справочники топлива/КПП/кузова/состояния продублированы в 4 местах; в фильтре нет `convertible`/`other`, `LocalListingFilters.tsx:126-135`, а в форме есть, `LocalListingForm.tsx:289-290`), 10-C6 (текст «Раз на день» про частоту рассылки захардкожен, `frontend/components/local/SaveSearchButton.tsx:94`), кнопка «Зберегти пошук» появляется из-за одного `ordering` (`SaveSearchButton.tsx:18`), `HeartButton` глотает ошибки (`frontend/components/favorites/HeartButton.tsx:40-41`), DELETE избранного с JSON-телом (10-Q17, `frontend/api/favorites.ts:12-16`).

- [ ] **B3 (важно), `favorites/views.py:44-56`:** утечка скрытых объявлений. Сценарий: пользователь перебирает id, добавляет чужие `pending/rejected/hidden` в избранное, список избранного показывает марку, цену, фото (карточка при этом 404).
