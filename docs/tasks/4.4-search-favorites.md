# Задача 4.4: Поиск, фильтры, избранное, сохранённые поиски

## Контекст
Каталог `/ua` фильтруется ручным бэкендом `LocalListingFilter` (`local_listings/filters.py:9-96`). Сохранённые поиски хранят фильтры как JSON (`saved_searches/models.py:12`) и обрабатываются ежедневной задачей `check_saved_searches` (`saved_searches/tasks.py:8-57`) со своей копией логики фильтра (`saved_searches/tasks.py:60-88`). Избранное — `favorites/views.py:11-75`, сериализатор `favorites/serializers.py`. Это шаг 4 сценария 3 (`docs/audit/20_SCENARIOS.md`).

Что сейчас в коде:
- **05-Q3 (важно):** `price_min`/`price_max` сравнивают `price` без учёта валюты (`local_listings/filters.py:41-50`), сортировка `price`/`-price` тоже (`:88-94`). Объявления в UAH, USD и EUR перемешаны: «до 10 000» пропускает авто за 10 000 USD.
- **05-Q4 (важно):** `price_min=abc` → `filter(price__gte='abc')` бросает `django.core.exceptions.ValidationError`, а ловятся только `ValueError`/`TypeError` (`local_listings/filters.py:41-50`) → 500. Остальные числовые параметры (`year_*`, `region`, `city`, `mileage_max`, `:31-71`) мусор молча игнорируют.
- **05-Q1 (важно):** сохранённый поиск берёт объявления с `created_at > last_notified_at` (`saved_searches/tasks.py:27-31`), но объявление становится `active` только после модерации. Если задача прошла между подачей и одобрением, объявление не попадёт в уведомления никогда (`last_notified_at` сдвигается на `now`, `:43`).
- **05-Q2 (важно):** фильтры JSON не валидируются (`saved_searches/serializers.py:6-10`). `int('abc')` в `_apply_filters` (`saved_searches/tasks.py:68-71,86-87`) роняет всю задачу — уведомления перестают приходить всем. Логика расходится с каталогом: нет `search`, `region`/`city` без `int`, нет сортировки.
- **05-S7 (важно):** в избранное можно добавить любое объявление по id, включая чужое `pending`/`rejected`/`hidden` (`favorites/views.py:31-38`), и `FavoriteSerializer` затем отдаёт его заголовок, цену и фото (`favorites/serializers.py:25-67`) — утечка непубличных объявлений.
- **05-Q8 (важно):** `listing_id='abc'` → `ValueError` → 500; несуществующий id на Postgres даёт `IntegrityError` (FK) — `get_or_create` ловит его и возвращает `None` → 500 при сериализации (`favorites/views.py:26-46`). `DELETE` без `listing_type` удаляет по imported (`favorites/views.py:52-56`). Нет CHECK «ровно один FK» (`favorites/models.py:27-36`). `FavoriteStatusView` с мусорным id → 500 (`:66-75`).
- Желательные того же места: 05-Q21 (избранное и сохранённые поиски без пагинации и лимита, `favorites/views.py:14-22`), 05-Q15 (Telegram-ошибка в задаче глушится `except: pass`, `saved_searches/tasks.py:47-52`), 05-C5 (лимит 10 объявлений в уведомлении захардкожен, `saved_searches/tasks.py:33`), 10-Q13 (фильтры не синхронизируются с URL на «назад/вперёд» — `useState` инициализируется один раз, `frontend/components/local/LocalListingFilters.tsx:14-27`), 10-Q14 (`?page=abc` → `NaN`, все страницы подряд, `frontend/app/ua/LocalCatalogGrid.tsx:47-48,61`), 10-C4 (`PAGE_SIZE = 20` захардкожен, `LocalCatalogGrid.tsx:6`), 10-C5 (справочники топлива/КПП/кузова/состояния продублированы в 4 местах; в фильтре нет `convertible`/`other`, `LocalListingFilters.tsx:126-135`, а в форме есть, `LocalListingForm.tsx:289-290`), 10-C6 (текст «Раз на день» про частоту рассылки захардкожен, `frontend/components/local/SaveSearchButton.tsx:94`), кнопка «Зберегти пошук» появляется из-за одного `ordering` (`SaveSearchButton.tsx:18`), `HeartButton` глотает ошибки (`frontend/components/favorites/HeartButton.tsx:40-41`), DELETE избранного с JSON-телом (10-Q17, `frontend/api/favorites.ts:12-16`).
- Похожая находка в каталоге пригона (04-Q1, `max_price=abc`) закрывается в 2.8; решение здесь сделать тем же способом (валидация query-параметров сериализатором).

## Цель
- [ ] **05-Q4:** параметры каталога валидируются DRF-сериализатором `LocalListingQuerySerializer` (числа, choices, `ordering` из белого списка). Невалидное значение → 400 `{"<поле>": ["..."]}`, а не 500 и не молчаливое игнорирование.
- [ ] Логика фильтра одна: функция `apply_local_listing_filters(qs, params: dict)` в `local_listings/filters.py`, её используют и DRF-бэкенд, и задача сохранённых поисков.
- [ ] **05-Q3:** цены сравниваются в одной валюте. Параметр `price_currency` (`UAH` по умолчанию, `USD`, `EUR`). В запросе аннотируется `price_uah` через `Case/When` по последним курсам `ExchangeRate` (`pricing/cache.py:86 get_exchange_rates()`); `price_min/max` переводятся в UAH по тем же курсам; сортировка `price`/`-price` — по `price_uah`. Если курса для какой-то валюты нет — объявления в ней не проходят ценовой фильтр и в сортировке по цене идут последними, в лог WARNING. В ответе каталога — `price_currency_rates_date` (дата курса), чтобы UI мог написать «за курсом НБУ на <дата>».
- [ ] **05-Q2:** `SavedSearchSerializer` валидирует `filters` тем же `LocalListingQuerySerializer` (неизвестные ключи отбрасываются, невалидные значения → 400). Задача обрабатывает каждый поиск в `try/except` с логированием: один сломанный поиск (старые данные в БД) не останавливает остальные.
- [ ] **05-Q1:** задача ищет по дате публикации: `moderated_at > since` для `active` (для legacy без `moderated_at` — `created_at`). Объявление, одобренное после прогона, попадает в следующий прогон. Лимит объявлений в одном уведомлении — `SAVED_SEARCH_MAX_ITEMS` из `.env` (05-C5); Telegram-ошибка логируется (05-Q15).
- [ ] **05-S7:** добавить в избранное можно только `active` локальное объявление (или опубликованный импортный лот по правилам каталога пригона) — иначе 404 (не раскрываем существование). В списке избранного объявления, ставшие не-`active` (в т. ч. `deleted` из 4.3), отдаются без заголовка, цены и фото, с `unavailable: true` и текстом «Оголошення більше недоступне».
- [ ] **05-Q8:** `listing_id` и `listing_type` валидируются сериализатором: мусор → 400, несуществующий id → 404, без `listing_type` → 400 (DELETE и status). Добавлен `CheckConstraint` «ровно один из `local_listing`/`imported_listing`». DELETE принимает параметры в query-string (10-Q17), фронт обновлён.
- [ ] Избранное и сохранённые поиски — с пагинацией DRF; лимит сохранённых поисков на пользователя `SAVED_SEARCH_MAX_PER_USER` (05-Q21).
- [ ] Фронт `/ua`: фильтры синхронизируются с URL при «назад/вперёд» (10-Q13); `page=abc` → первая страница, пагинация сокращённая (1 … n-1 n n+1 … last) (10-Q14); число страниц считается по `count` и фактическому размеру страницы из ответа, а не по константе (10-C4); 400 от API показывается как «Некоректні параметри фільтра» с кнопкой «Скинути фільтри», страница не падает. Выбор валюты цены в фильтре.
- [ ] Справочники топлива, КПП, кузова, состояния — в одном модуле `frontend/lib/labels.ts`, используют карточка, фильтр, форма и страница объявления; в фильтре есть все значения, что и в форме (10-C5).
- [ ] «Зберегти пошук» появляется только при реальных фильтрах (`page` и `ordering` не считаются). Текст о частоте рассылки берётся из ответа API (`GET /api/v1/saved-searches/config/` → `{"schedule_text", "max_per_user"}`) или убран (10-C6). `HeartButton` показывает ошибку (тост/текст), а не молчит.
