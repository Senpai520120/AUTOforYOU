## Цель
- [ ] Backend-образ работает от непривилегированного пользователя `app` (фиксированный UID/GID 10001). `/app/media` и `/app/staticfiles` принадлежат ему. `backend`, `bot`, `celery_worker`, `celery_beat` стартуют и работают (`docker compose exec backend id -u` → 10001).
- [ ] Frontend-образ работает от пользователя `node`. Runtime-стадия собирается из `output: 'standalone'`: без dev-зависимостей, запуск `node server.js` с корректной обработкой SIGTERM (`init: true` в compose или `tini`). Размер образа уменьшился, это указано в PROGRESS.md.
- [ ] Уже существующие named volumes `media` и `static` (созданные от root) продолжают работать: при переходе есть однократный шаг смены владельца, описанный в `DEPLOY_NOTES.md`/`docs/LAUNCH_CHECKLIST.md` и выполняемый `deploy.sh` (7.5) или отдельной командой.
- [ ] `.dockerignore` исключает `.claude/`, `pgdata/`, `*.sql`, `dump.sql`, `test-results/`, `playwright-report/`, `.pytest_cache/`, `.ruff_cache/`, `htmlcov/`, `.coverage`, `.env.*` (кроме `*.example`), `.dev_secret_key`, `node_modules/`, `.github/`, `backups/`, `*.log`. `frontend/.dockerignore` исключает `test-results/`, `playwright-report/`, `.env*` (кроме `*.example`), `tsconfig.tsbuildinfo`.
- [ ] После сборки в образе backend нет `.claude`, `pgdata`, `dump.sql`: `docker run --rm <image> sh -c 'ls -a /app'` это подтверждает (шаг CI).
- [ ] Django отдаёт `GET /healthz` (без префикса `/api`, без аутентификации, без throttling): 200 и `{"status": "ok", "db": "ok", "cache": "ok|skipped"}`, если БД отвечает на `SELECT 1` и (при заданном `REDIS_URL`) кэш отвечает. 503 и `"status": "error"` с названием упавшей зависимости, если нет. В ответе нет версий, хостов, текста исключений.
- [ ] `/healthz` проходит проверку `ALLOWED_HOSTS` при обращении изнутри контейнера. Healthcheck шлёт запрос с `Host`, входящим в `ALLOWED_HOSTS`, либо в список добавляется внутреннее имя `backend`/`localhost` (решение описать).
- [ ] nginx проксирует `location = /healthz` на backend (если 7.1 уже перевела nginx на шаблон, то в шаблоне).
- [ ] Healthchecks есть у всех сервисов:
  - `backend` — HTTP `GET /healthz` через `python -c` (curl в slim-образе нет);
  - `redis` — `redis-cli ping`;
  - `frontend` — HTTP на внутренний маршрут без обращения к backend (`app/health/route.ts` → 200 `ok`);
  - `nginx` — `wget -q --spider http://127.0.0.1/healthz` (или `https://` с `--no-check-certificate` при TLS);
  - `celery_worker` — `celery -A core inspect ping -d celery@$HOSTNAME` с интервалом ≥ 60 с;
  - `celery_beat` и `bot` — проверка живости процесса (например, файл-heartbeat, который обновляет процесс, или `/proc/1` с разбором `cmdline`). Вариант выбрать и описать.
- [ ] Порядок старта: `celery_worker`, `celery_beat`, `bot` ждут `backend: service_healthy` (миграции выполнены). nginx ждёт `frontend: service_healthy` и `backend: service_healthy`.
- [ ] Gunicorn: `--timeout ${GUNICORN_TIMEOUT:-120}`, `--graceful-timeout 30`, `--max-requests ${GUNICORN_MAX_REQUESTS:-1000}`, `--max-requests-jitter 100`, `--worker-tmp-dir /dev/shm`. Формат access-лога не трогать (7.2).
- [ ] Образы с плавающими тегами закреплены на минорную версию: `redis:7.x-alpine`, `nginx:1.xx-alpine`, `postgres:18.x-alpine`, `python:3.12.x-slim`, `node:20.x-alpine` (точные версии на момент выполнения, в PROGRESS.md).
- [ ] `NEXT_PUBLIC_DEMO_MODE` передаётся в сборку фронтенда как `ARG`/`ENV` и `args:` в compose, если после задачи 2.6 переменная ещё нужна. Если 2.6 перевела демо-баннер на данные из API и переменная удалена, пункт закрывается ссылкой на 2.6.
- [ ] Корневой `Dockerfile` удалён (`git rm Dockerfile`), если проверка показала, что на него нет ссылок в `docker-compose.yml`, `.github/`, `deploy.sh`, `scripts/`, `docker/`, документации; упоминания в документах (`DEPLOY_NOTES.md`, `README.md`) убраны. Если ссылка найдена — не удалять, записать в отчёт.

## Тесты

- Аноним `GET /healthz` → 200, JSON `status == 'ok'`, `db == 'ok'`, заголовок `Cache-Control: no-store`.
- Мок `connection.cursor` бросает `OperationalError` → 503, `status == 'error'`, `db == 'error'`, в теле нет текста исключения.

- `POST /healthz` → 405.

Shell/CI:
- `docker compose config --quiet`.
- `hadolint Dockerfile.backend Dockerfile.frontend` (без ошибок уровня error).
- После сборки: `docker run --rm <backend-image> id -u` → `10001`; `docker run --rm <backend-image> sh -c 'test ! -e /app/.claude && test ! -e /app/pgdata && test ! -e /app/dump.sql'`; для frontend `id -u` → не 0.
