## Контекст
Три VIN-провайдера из брифа §2 переводятся на каркас задачи 3.1 (`integrations/base.py`, `integrations/registry.py`, `*_MODE`). Сейчас:

- **03-S2 (важно):** `RealOpendatabotProvider` возвращает `owners` и полный сырой ответ `raw` (`integrations/providers.py:236-238`). `RegistryReportView` отдаёт это любому залогиненному (`integrations/views.py:183`) и бессрочно хранит в `RegistryReport.payload` (`:175-181`). Если в ответе есть данные владельцев, это ПДн третьих лиц.
- **03-S3 (важно):** VIN и номер проверяются только по длине (`integrations/views.py:45-47`, `:96-101`, `:149-158`; также `local_listings/views.py:209-212`). Значение подставляется в URL внешнего API через `.format()` без экранирования (`integrations/providers.py:80`, `:203-205`). `%3F` или `%23` в path-параметре меняют путь или query запроса к Opendatabot/NHTSA. Номер длиннее 20 символов даёт 500 на Postgres (`RegistryReport.plate`, `integrations/models.py:4-21`).
- **03-Q1 (важно):** `RegistryReportView` кэширует любой ответ, включая `error` и `demo: True`, и отдаёт его всегда через `.first()` без TTL (`integrations/views.py:163-181`). Один сбой или запрос до ввода ключа «замораживают» ответ навсегда, пометка «демо» после ввода ключа не исчезает.
- **03-Q4 (важно):** `VinReportView` кэширует под жёстким `provider='stub'` (`integrations/views.py:50`, `:71`). Реальные данные Opendatabot вшиваются в отчёт под общим `demo: True` (`:59-69`), ошибка Opendatabot теряется, `RegistryReport` не пишется. Поэтому повторные платные вызовы идут при каждом новом VIN.
- **03-Q5 (важно):** `autoretry_for=(OSError, ConnectionError)` в `integrations/tasks.py:12` (`import_lot_task`) и `:50` (`send_notification`). Исключения httpx не наследуют `OSError` (проверено аудитом: `issubclass(httpx.ConnectError, OSError) == False`), поэтому ретраи фактически не работают.
- carVertical: реального клиента нет. `get_vin_provider()` всегда возвращает `StubVinProvider` (`integrations/providers.py:244-245`, 03-C4). Stub отдаёт правдоподобный фейковый отчёт «Toyota Camry, salvage, ДТП» по любому VIN (`:29-50`, 03-S7 — желательно).
- История торгов BidFax: только stub с фейковым лотом (`integrations/providers.py:128-144`, `:248-249`). В списке провайдеров брифа §2 BidFax нет.
- NHTSA: класс без интерфейса (`integrations/providers.py:70`), нет demo-реализации. Ошибка сети возвращается клиенту текстом исключения httpx (`:85-86`, 03-S6 — желательно). Фронт показывает этот текст как есть: `frontend/components/local/LocalListingForm.tsx:124` (`Помилка VIN: ${data.error}`). NHTSA на невалидный VIN отвечает 200 с `ErrorCode`, и такой «пустой» ответ кэшируется навсегда (`integrations/views.py:109-115`, 03-Q9 — желательно). Логика кэша NHTSA продублирована: `integrations/views.py:103-115` делает `create()` (гонка → IntegrityError, 03-Q8 — желательно), `local_listings/views.py:213-227` делает `get_or_create`.
- Базовые URL Opendatabot помечены «сверить с документацией» (`integrations/providers.py:149-152`, 03-C3). TTL кэша отчётов нет (03-C6). У `RegistryReport` нет индексов по `vin`/`plate` (03-Q10 — желательно).
- **03-S1** (ключ Opendatabot в тексте ошибки и кэше) закрывается в задаче **1.1**. Здесь её не дублировать, только не сломать: тест 23-D57 из 1.1 должен остаться зелёным.
- Фронтенд не вызывает `/report/`, `/registry/` и `/decode/` (`docs/audit/03_integrations.md:33`). Страницы проверки VIN нет, поэтому сценарии 23-P25 и 23-P26 проверить нечем.
