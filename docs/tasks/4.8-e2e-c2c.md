# Задача 4.8: Playwright полного цикла C2C

## Контекст
Для C2C сейчас нет ни одного e2e-сценария: пакета касаются только `frontend/e2e/ssr.spec.ts:18,49-51` (карточки `/ua` в HTML и `/ua` в sitemap) и навигационные проверки ссылки на `/ua` (`frontend/e2e/home.spec.ts:36`, `frontend/e2e/test-1.spec.ts:37,56`) — `docs/audit/10_fe_local_messaging.md`, раздел «Тесты»; `docs/audit/06_deals_messaging.md`: «0 Playwright». Сценарий 3 (`docs/audit/20_SCENARIOS.md`) «подача → модерация → публикация → поиск → телефон → переписка → сделка → продвижение» в браузере не прогонялся ни разу (Playwright-стек на Windows не поднимался, 12-Q14 — задача 0.1).

Задачи 4.1–4.7 каждая добавляют свой spec на свои функции (23-P28…P40):

|---|---|---|

Эти spec проверяют функции по отдельности на данных `e2e_seed`. Не хватает сквозного прогона одного объявления через весь цикл двумя-тремя пользователями, мобильной проверки ключевых экранов C2C и единого запуска этапа в CI. Инфраструктура (setup-проект, `storageState` ролей, фикстуры `api`/`asRole`, `e2e_seed`/`e2e_cleanup`, мобильные проекты с тегом `@mobile`, запрет запуска на прод, джоба `e2e` в CI) — задача **0.4**.

Находок уровня «критично»/«важно» за задачей нет: она закрывает требование брифа §5 п.3 для этапа 4 целиком и проверяет, что исправления 4.1–4.7 работают вместе.

## Цель
- [ ] `frontend/e2e/c2c-full-cycle.spec.ts` — один `test.describe.serial` на свежем объявлении (создаётся в тесте, не из сида; заголовок с префиксом `[E2E]`, уникальный по `workerIndex` и времени):
  1. Продавец подаёт объявление с 2 фото → «на модерації».
  2. Staff одобряет (API или `e2e_seed --approve`, как принято в 0.4/4.3) → объявление в `/ua`, находится фильтром по марке и цене.
  3. Покупатель: избранное → «Показати телефон» → номер виден.
  4. Покупатель пишет продавцу → продавец видит непрочитанное и отвечает.
  5. Продавец «Продано» → выбирает покупателя → покупатель подтверждает → объявление «Продано» (страница без телефона), отзыв → рейтинг продавца обновился.
  6. Отдельная ветка на втором свежем объявлении (e2e-стек с `PAYMENTS_ENABLED=true`): продавец покупает ТОП → перехваченный переход на LiqPay с суммой тарифа → подписанный тестовым ключом callback `success` → возврат по `result_url` → плашка «Оплату отримано» → объявление первое в `/ua`.
  7. (ANSWERS, Q9/F6) Продление и «Продано»: у объявления из фикстуры с истёкшим сроком — «Продовжити безкоштовно» → «Активне» (повторное продление снова доступно, лимита нет); «Продано поза сайтом» с опросом → страница «Продано» без телефона, со ссылкой «Пригнати схоже зі США».
