# Задача 10.22: Сохранённые поиски — проверка filters, устойчивая рассылка, без потерь

## Контекст
Источник: `docs/audit/41_REVIEW_2026-11-11.md`, находка E1. `saved_searches/serializers.py` принимал любой `filters`; `saved_searches/tasks.py` брал `qs[:10]` и сдвигал `last_notified_at` на `now` (объявления после десятого терялись), отбирал по `created_at` (а не по дате публикации/модерации), а `_apply_filters` дублировал публичный фильтр каталога и падал на битых значениях.

## Цель
- `POST/PATCH /api/v1/saved-searches/`: `filters` проходит белый список ключей и типов (как у каталога `LocalListingFilter`); неизвестный ключ, не-скаляр, нечисловое/огромное число, неверный вариант choices, NUL -> 400 с понятным текстом. NUL в `name` -> 400.
- Старые битые записи в БД не удаляются; рассылка их пропускает с `logger.warning` (только id записи).
- Сбой одной записи (любое исключение) не обрывает цикл (try/except на запись, лог, дальше).
- Отбор по дате публикации: `Coalesce(moderated_at, created_at)`; курсор `last_notified_at` = дата публикации последнего учтённого объявления.
- Без потерь: первые 10 новых (по возрастанию даты) - отдельные уведомления, остальные - одно «і ще N нових оголошень» со ссылкой `/local?<filters>`; курсор - на самое новое учтённое.

3. Задача: выборка `_matching_listings`, верхняя граница по `Max(published_at)`, порция + «і ще N», курсор, пропуск битых записей.
