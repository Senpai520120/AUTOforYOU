# Задача 9.56: Флаг «email завжди» и письмо брокеру без ПДн (M11) 🔒

## Контекст
По задаче 2.12 письмо брокеру о новой заявке уходит только если Telegram не доставил. Если Telegram недоступен или ограничен, брокер узнаёт о заявке с задержкой; если Telegram доставил, второй независимый канал не срабатывает. Тело письма по умолчанию содержит имя, телефон и email клиента, а такое письмо проходит через SMTP-провайдера, почтовые ящики и демо-Outbox. Из штурма (`docs/BRAINSTORM_2026-11.md`, M11, §8.8).

## Цель
- Настройка «Листа брокеру надсилати завжди» (админка «Налаштування сповіщень про заявки», по умолчанию выключена): при включении письмо уходит всегда, независимо от итога Telegram. Выключена: поведение 2.12 не меняется.
- Письмо без ПДн: ни в теме, ни в теле нет имени, телефона, email, контакта в мессенджере, комментария, referrer и page_url клиента. Только номер AFY, авто, сумма, способ связи (название канала), источник и ссылки в админку и кабинет брокера. Шаблоны из админки не могут вернуть эти поля: в контексте письма они пустые.
- Повторы и журнал 2.12 без дублей: письмо идемпотентно по `email_status`; заявка не считается недоставленной, если дошёл один канал.

## Файлы
Изменить: `leads/models.py`, `leads/notify.py`, `leads/tasks.py`, `leads/tests_delivery.py`, `docs/LAUNCH_CHECKLIST.md`, `ROADMAP.md`, `PROGRESS.md`.
Создать: миграция `leads/migrations/0011_email_always_pii_free.py`, `leads/tests_email_always.py`.
Не трогать: `.env`, `cars/`, правки задачи 9.50 (`leads/funnel.py`, `metrics/*`).

## Шаги
1. Поле `email_always` и миграция: добавляет поле и заменяет сохранённый дефолтный текст письма из 0010 на безличный (изменённые владельцем тексты не трогаются).
2. `notify.email_context()` без ПДн; `render_new_lead_email` использует его; безличный `FALLBACK_EMAIL_BODY`.
3. `notify_broker_new_lead`: письмо ставится в очередь и при доставленном Telegram, если включён флаг.
4. Проверка Outbox и логов: демо-Outbox хранит тему и тело письма, значит они без ПДн; лог содержит только `lead_id` и класс ошибки.

## Тесты
Django: `leads/tests_email_always.py` — флаг выкл/вкл (Telegram доставил, не доставил, не настроен), один канал упал, повторный запуск и досыл без дублей, заявка с одним доставленным каналом не недоставлена, письмо, тема и Outbox без узнаваемых значений клиента (имя, телефон, email, handle, комментарий, URL), шаблон из админки с `{name}` не возвращает ПДн, без сети. Обновлены тесты 2.12, которые ждали ПДн в письме.

## Для владельца (LAUNCH_CHECKLIST)
Включить «Листа брокеру надсилати завжди» после настройки SMTP и адреса брокера. Контакты клиента в письме больше не приходят: брокер открывает заявку по ссылке (нужен вход в кабинет); в Telegram они по-прежнему есть.
