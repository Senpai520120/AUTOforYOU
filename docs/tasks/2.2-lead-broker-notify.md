# Задача 2.2: Мгновенное уведомление брокеру (Telegram + админка)

## Контекст
- **07-Q2 (критично)**: заявок брокеру в Telegram нет. Нет модели, роли и chat_id (`docs/audit/07_telegram_bot.md`, «Функции», строка «Заявки брокеру в Telegram»). Модель заявки и роль появляются в 2.1 и 1.2. Эта задача закрывает доставку.
- 07-C1 (связано): chat_id брокера или группы брокеров негде задать, ни в `.env`, ни в админке. В `core/settings.py:399-411` есть только `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`, `TELEGRAM_CHANNEL_ID`, `TELEGRAM_B2B_CHANNEL_ID` и `TELEGRAM_WEBHOOK_SECRET`.
- 07-C2 (связано): тексты бота захардкожены (`telegram_bot/tasks.py:57-63,75`, `telegram_bot/handlers.py`). Текст для брокера по брифу §2 должен редактироваться в админке.
- 07-C3 (связано): `aiogram.Bot` создаётся напрямую в `telegram_bot/tasks.py:72`, `telegram_bot/views.py:109` и `integrations/tasks.py:88`. Общий адаптер Telegram делает задача 3.4. Здесь нельзя добавить четвёртое такое место, отправку нужно вынести в одну функцию, которую 3.4 обернёт адаптером.
- Образец отправки: `integrations/tasks.py:47-104` (`send_notification`, Celery, без токена молча пропускает). У него нет HTML-экранирования, а у `telegram_bot/tasks.py:58-63` нет экранирования при `parse_mode='HTML'` (07-S3, задача 5.1). В заявке имя и комментарий вводит гость, поэтому экранирование обязательно.
- In-app уведомления: `notifications/services.py:4-12` (`create_notification`), типы в `notifications/models.py:6-15`. Типа «новая заявка» нет.
- Celery в тестах без `REDIS_URL` работает в eager-режиме (`core/settings.py:363-365`), а `on_commit` в `TestCase` срабатывает только в `captureOnCommitCallbacks(execute=True)`.
- Хук `leads.services.notify_new_lead` появляется в 2.1 как заглушка и вызывается через `transaction.on_commit`.

## Цель
- [ ] Новая заявка сразу после коммита ставит Celery-задачу `leads.tasks.notify_broker_new_lead`, и та отправляет сообщение в Telegram-чат брокера (личный или групповой).
- [ ] Chat_id брокера берётся из админки (`LeadNotificationSettings.telegram_chat_id`), а если там пусто, то из `.env` `TELEGRAM_BROKER_CHAT_ID`. В коде значения нет.
- [ ] Текст сообщения — шаблон в админке (`LeadNotificationSettings.new_lead_template`) с плейсхолдерами `{name}`, `{phone}`, `{contact_method}`, `{contact_handle}`, `{car}`, `{total_usd}`, `{total_uah}`, `{source}`, `{admin_url}`, `{cabinet_url}`, `{comment}`. Дефолтный текст на украинском создаёт data-миграция. Все подставляемые значения проходят через `html.escape`.
- [ ] В сообщении кнопка «Відкрити заявку». Она ведёт в кабинет брокера `{SITE_URL}/broker/leads/<id>` (2.4), а пока кабинета нет — на страницу заявки в админке.
- [ ] «Мгновенно в админку»: заявка видна в админке сразу (запись из 2.1). Дополнительно:
  - в списке `LeadAdmin` колонка статуса доставки (`telegram_status`: `sent`, `skipped_not_configured`, `failed`, `pending`) и время отправки;
  - admin-action «Надіслати брокеру повторно»;
  - in-app уведомление (`Notification`, новый тип `new_lead`) всем активным пользователям с ролью broker (из 1.2), если это включено в настройках.
- [ ] Если Telegram не настроен (нет токена или chat_id) или выключен в админке, сайт не падает, заявка создаётся, `telegram_status=skipped_not_configured`, в лог пишется предупреждение без ПДн. Админ видит в списке заявок, что Telegram не настроен (честный статус, бриф §2).
- [ ] Ошибка Telegram (сеть, неверный chat_id, `TelegramRetryAfter`) не ломает создание заявки. Сетевые ошибки ретраятся (как в `integrations/tasks.py:47-51`), в конце `telegram_status=failed` и короткий код ошибки без токена и ПДн.
- [ ] Повторный запуск задачи для той же заявки не шлёт второе сообщение, если уже `sent` (идемпотентность при ретраях). Ручной «повторно» — только через admin-action с `force=True`.
- [ ] Отправка сделана одной функцией `telegram_bot/sender.py: send_message(chat_id, text, buttons=None, parse_mode='HTML')`. 3.4 обернёт её адаптером. Новые места с прямым `aiogram.Bot(...)` не появляются.
- [ ] Сервис уведомления переиспользуем: 2.9 (20-G1, заявка дилера) вызовет тот же `notify_brokers(text, link)`.

## Шаги
1. Миграция `0002` (причина: нужно хранить статус доставки уведомления и настройки получателя/текста в админке):
   - `Lead`: `telegram_status` (module-level `NotifyStatus` TextChoices: `pending`, `sent`, `skipped_not_configured`, `failed`; default `pending`), `telegram_sent_at` (null), `telegram_error` (≤200, blank).
   - `LeadNotificationSettings` (singleton, `pk=1`, `get_solo()` через `get_or_create`): `telegram_enabled` (bool, default True), `telegram_chat_id` (≤64, blank, help_text «ID чату або групи брокера. Порожньо → TELEGRAM_BROKER_CHAT_ID з .env»), `new_lead_template` (TextField), `notify_brokers_in_app` (bool, default True). В админке запретить добавление второй записи и удаление.
2. Data-миграция `0003`: создать запись `pk=1` с дефолтным шаблоном, например:
   `🆕 <b>Нова заявка #{id}</b>\n👤 {name}\n📞 {phone} ({contact_method}{contact_handle})\n🚗 {car}\n💵 ≈ ${total_usd} / {total_uah} грн\n💬 {comment}`.
   Дефолт — текст, не контакт и не цена. Хардкодом это не считается, но в админке он редактируется.
3. `notifications/models.py`: `NEW_LEAD = 'new_lead', 'Нова заявка брокеру'` (миграция меняет только choices).
4. `core/settings.py`: `TELEGRAM_BROKER_CHAT_ID = os.environ.get('TELEGRAM_BROKER_CHAT_ID', '')` рядом с остальными `TELEGRAM_*`. В `.env.example` — с комментарием.
5. `telegram_bot/sender.py`: `send_message(chat_id, text, buttons=None, parse_mode='HTML') -> SendResult`. Внутри `asyncio.run` и `aiogram.Bot` с закрытием сессии (как `integrations/tasks.py:83-100`). Без токена возвращает `SendResult(ok=False, reason='not_configured')`. `TelegramRetryAfter` пробрасывает наверх для ретрая Celery.
6. `leads/notify.py`:
   - `render_new_lead_text(lead, template) -> str`: собирает контекст (марка/модель/год из снимка или лота; итоги; способ связи), делает `html.escape` каждого значения и подставляет через `str.format_map` с `defaultdict(str)`, чтобы неизвестный плейсхолдер в шаблоне из админки не ронял отправку.
   - `broker_chat_id() -> str`: сначала настройки, потом `settings.TELEGRAM_BROKER_CHAT_ID`.
   - `notify_brokers_in_app(title, link)`: `create_notification` каждому активному пользователю с ролью broker (как её определяет 1.2).
7. `leads/tasks.py`: `@shared_task(bind=True, autoretry_for=(OSError, ConnectionError), retry_kwargs={'max_retries': 3, 'countdown': 30}) notify_broker_new_lead(lead_id, force=False)`:
   - `select_for_update` не нужен, достаточно проверки: если `telegram_status == sent` и не `force`, выйти.
   - Если выключено или не настроено: `skipped_not_configured`, лог `lead_id` без ПДн, выход.
   - Иначе `send_message(...)`. Успех → `sent` и `telegram_sent_at`. Ошибка → `failed` и короткий код ошибки (класс исключения, без текста, где может быть токен).
   - In-app уведомление брокерам создаётся независимо от Telegram, один раз на заявку.
8. `leads/services.py`: `notify_new_lead(lead_id)` делает `notify_broker_new_lead.delay(lead_id)`. Вызов через `on_commit` уже есть из 2.1.
9. `leads/admin.py`: колонки `telegram_status` и `telegram_sent_at`, фильтр по `telegram_status`, action «Надіслати брокеру повторно» (`delay(lead_id, force=True)`), `LeadNotificationSettingsAdmin`. В changelist `LeadAdmin` выводить сообщение `messages.warning` «Telegram для заявок не налаштовано», если нет токена или chat_id.
10. `docs/LAUNCH_CHECKLIST.md`: как узнать chat_id группы (добавить бота в группу, `getUpdates`), где задать (админка → «Налаштування сповіщень про заявки» или `.env`), как проверить (создать тестовую заявку, увидеть `sent`).

## Тесты
Django (`leads/tests.py`, Telegram всегда замокан: `patch('telegram_bot.sender.send_message')` или `patch('aiogram.Bot.send_message', new_callable=AsyncMock)`; настоящие aiogram `Update` не нужны, но если появятся — `addCleanup(Update.event_type.fget.cache_clear)`):
- Создание заявки через API в `captureOnCommitCallbacks(execute=True)` → `send_message` вызван один раз с chat_id из админки. `telegram_status=sent`.
- chat_id пуст в админке, `TELEGRAM_BROKER_CHAT_ID='-100123'` в `override_settings` → отправка на `-100123`.
- Нет токена (`TELEGRAM_BOT_TOKEN=''`) → `send_message` не вызван, `skipped_not_configured`, заявка создана, ответ API 201.
- `telegram_enabled=False` → `skipped_not_configured`.
- Без `captureOnCommitCallbacks` (транзакция откатывается) → задача не ставится.
- Имя `<b>x</b>&<script>` → в тексте `&lt;b&gt;x&lt;/b&gt;&amp;&lt;script&gt;`, HTML-разметка шаблона сохранена.
- Неизвестный плейсхолдер `{foo}` в шаблоне → отправка проходит, `{foo}` заменён пустой строкой.
- `send_message` бросает `ConnectionError` → ретраи, в конце `failed`. Создание заявки не падает.
- Повторный вызов задачи для `sent` → второго `send_message` нет. С `force=True` отправка идёт.
- In-app: пользователи с ролью broker получают `Notification(type='new_lead')` со ссылкой на заявку. buyer не получает. `notify_brokers_in_app=False` → уведомлений нет.
- В логах (`assertLogs`) нет телефона и имени заявителя.
- Admin-action «повторно» ставит задачу с `force=True`.

Playwright: нет UI для клиента. Django-тесты с моками Telegram. Сценарий «заявка из калькулятора видна в админке» проверяется Django-тестом на changelist `LeadAdmin` (200, в HTML есть номер заявки и статус доставки).
