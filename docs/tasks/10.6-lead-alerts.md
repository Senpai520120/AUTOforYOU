# Задача 10.6: Заявка не должна теряться молча (алерт владельцу + «без ответа 2 ч / 24 ч»)

## Контекст
Источник: `docs/audit/41_REVIEW_2026-11-11.md`, находки C2, C3 и п.3 «Заявку можно потерять молча». Размер S–M, 1 сессия.

Что сейчас:
- Алерт о недоставленной заявке: `leads/notify.py:215` `alert_admins_undelivered` создаёт только in-app уведомление (`Notification.Type.LEAD_UNDELIVERED`) администраторам (`admin_recipient_ids`, `leads/notify.py:209`). Вызывается из `leads/tasks.py:271` (`resend_undelivered_leads`, раз в `LEAD_NOTIFY_RETRY_MINUTES`=10 мин, `core/settings.py:754-757`) после исчерпания `LEAD_NOTIFY_MAX_ATTEMPTS`; метка `Lead.undelivered_alerted_at` (`leads/models.py:257`) ставится атомарно (`leads/tasks.py:270`), поэтому повторов нет. Админ, не заходящий на сайт, алерта не увидит.
- Канал владельца уже есть и в Telegram, и в email, новый заводить не нужно: `FAILED_TASK_ALERT_CHAT_ID` / `FAILED_TASK_ALERT_EMAIL` (`core/settings.py:661-662`, `.env.example:281-282`, в тестах обнуляются `core/settings.py:829-830`). Готовая отправка во все настроенные каналы с защитой от сбоя канала: `core/tasks.py:83` `_send_failed_task_alert(text, subject)` (используют `alert_failed_task_growth`, `core/tasks.py:105`, и `alert_disk_usage`, `core/tasks.py:147`); дедупликация через `cache.add(key, 1, timeout)` и откат ключа при недоставке (`core/tasks.py:166-178`). Образец текста без ПДн: `core/tasks.py:69`, `:140`.
- Отдельные каналы: `FUNNEL_REPORT_CHAT_ID` / `FUNNEL_REPORT_EMAIL` (`core/settings.py:787-788`) только для недельного отчёта; `TELEGRAM_BROKER_CHAT_ID` / `BROKER_NOTIFY_EMAIL` и `LeadNotificationSettings` (`leads/notify.py:40,142`) только для брокера. Настроек `OWNER_*`, `ADMINS`, `ALERT_*` в проекте нет (Grep по репозиторию). Задача 9.56 «email завжди» касается писем брокеру (`leads/notify.py:127-136`, `EMAIL_PII_KEYS`), владельца не затрагивает.
- «Ответ брокера»: `Lead.first_response_at` (`leads/models.py:227`) ставится при первом переходе из `LeadStatus.NEW` в любой статус, кроме `SPAM` (`leads/services.py:216-218`); `LeadStatus.NEW` / `SPAM` — `leads/models.py:10,18`. «Без ответа» = `first_response_at IS NULL`, статус `new`.
- Недельный отчёт: `metrics/tasks.py:18` `send_weekly_funnel_report` (понедельник 09:00, `core/settings.py:693-697`), данные — `metrics/reports.py:42` `collect_funnel`; медиана считается только по отвеченным (`metrics/reports.py:53-57`), текст — `render_report` (`reports.py:96`, строка «Медіана першої відповіді» на `:119`), `undelivered` на `:58,:74`. Заявки без ответа в отчёте не видны.
- Ежечасной проверки заявок нет: в `CELERY_BEAT_SCHEDULE` (`core/settings.py:673-758`) есть только `resend-undelivered-leads` (10 мин, досыл, не про ответ брокера), `failed-task-alert` (10 мин), `disk-usage-alert` (30 мин). Новую задачу нужно завести.
- Двойной клик: на клиенте защита есть (`frontend/components/leads/LeadForm.tsx:94,117,121,326`, `submitting` блокирует кнопку). На сервере защиты от дубля нет: в `leads/views.py` и `leads/services.py` нет idempotency-ключа или поиска повторной заявки (Grep), создаётся вторая заявка. Серверный дедуп требует нового поля и миграции — вынесен из этой задачи (см. «Осталось»).
- Тесты: freezegun в проекте нет; время подменяют `mock.patch('django.utils.timezone.now', return_value=moment)` (`metrics/tests_report.py:37`, `metrics/tests.py:63`). Фабрики — `tests/factories.py`. Сеть запрещена предохранителем `core/test_runner.py`.

## Цель
1. Недоставленная заявка (после исчерпания попыток) дублируется владельцу в Telegram и email через `FAILED_TASK_ALERT_CHAT_ID` / `FAILED_TASK_ALERT_EMAIL`, в дополнение к in-app. Текст без ПДн: только номер заявки (`public_id`) и ссылка на админку (`admin_url`), без имени, телефона, email, комментария, авто. Один алерт на заявку (метка `undelivered_alerted_at` уже даёт идемпотентность).
2. Новая ежечасная Celery-задача считает заявки без ответа: `first_response_at IS NULL`, статус `new`, не спам, возраст >= 2 ч и отдельно >= 24 ч. Если счётчик > 0 — алерт владельцу: два числа и ссылка на список заявок в админке (`reverse('admin:leads_lead_changelist')`). Без id заявок и без ПДн.
3. Тот же счётчик «без ответа > 2 год / > 24 год» в недельном отчёте (`collect_funnel` + `render_report`), срез на момент отправки отчёта; существующая медиана по отвеченным остаётся.
4. Повторный запуск проверки не шлёт одинаковый алерт: дедуп через `cache.add` (ключ — хэш пары счётчиков и набора id, пауза `LEAD_UNANSWERED_ALERT_COOLDOWN_MINUTES`, по умолчанию 360, как у диска); при недоставке ключ откатывается. Рост числа заявок без ответа даёт новый алерт.
5. Канал владельца не настроен — задача пишет `logger.warning` и ничего не шлёт, не падает (как `alert_disk_usage`).
6. Пороги часов и пауза — переменные `.env` (`LEAD_UNANSWERED_WARN_HOURS`=2, `LEAD_UNANSWERED_CRITICAL_HOURS`=24, `LEAD_UNANSWERED_ALERT_COOLDOWN_MINUTES`=360), без хардкода в коде; значения 2 и 24 — из ROADMAP 10.6. Тексты алертов — на украинском.

Не трогать: модель `Lead` и миграции (метки `undelivered_alerted_at` достаточно; кэш — для проверки «без ответа»), `cars/`, фронтенд, каналы брокера (`TELEGRAM_BROKER_CHAT_ID`, `BROKER_NOTIFY_EMAIL`), логику `resend_undelivered_leads` кроме добавленного вызова.

## Шаги
1. Вынести в `leads/notify.py` функцию `build_owner_undelivered_text(lead)`: `public_id` + `admin_url`, без полей гостя. Отправку делать через `core.tasks._send_failed_task_alert` (импорт внутри функции, чтобы не было циклов) или, если приватное имя неудобно, переименовать в общую публичную обёртку без смены поведения.
2. В `leads/tasks.py` после `alert_admins_undelivered(lead)` вызвать алерт владельцу; сбой канала не должен ронять задачу и не должен снимать метку `undelivered_alerted_at`.
3. Добавить в `metrics/reports.py` хелпер подсчёта «без ответа» (общий для отчёта и новой задачи, чтобы определение было одно), добавить ключи в `collect_funnel` и строки в `render_report`.
4. Добавить задачу `leads.tasks.alert_unanswered_leads` (`base=ResilientTask`, `ignore_result=True`), расписание `_crontab(minute=5)` (раз в час) с `expire_seconds=3300`; логика дедупа и отката ключа — как в `core/tasks.py:166-178`.
5. Переменные в `core/settings.py` через `_positive_int_env`; в тестовом блоке `if _TESTING:` каналы уже обнулены (`FAILED_TASK_ALERT_*`), новых ключей провайдера не добавляется.
6. Документация: `.env.example`, `.env.docker.example`, `LAUNCH_CHECKLIST.md` (пункт «Канал алертов владельцу: `FAILED_TASK_ALERT_CHAT_ID` и/или `FAILED_TASK_ALERT_EMAIL` — без них алерт о заявке не уйдёт, а только in-app»), `RUNBOOK.md`.

## Тесты
Django (моки `telegram_bot.sender.send_message` и `integrations.email.send_email`, время — `mock.patch('django.utils.timezone.now')`, данные — `tests/factories.py`, мутационная проверка каждого):
- Недоставленная заявка после исчерпания попыток: отправлено и в Telegram, и в email (мок вызван по одному разу), in-app уведомление админам сохранилось.
- Текст алерта не содержит имя, телефон, email, комментарий, подпись авто клиента (заявка с маркерными значениями; `assertNotIn`), содержит `public_id` и ссылку на админку.
- Падение Telegram не мешает email и наоборот; задача не падает; метка `undelivered_alerted_at` остаётся.
- Оба канала не настроены: ничего не отправлено, предупреждение в лог, задача завершается без ошибки.
- Повторный запуск `resend_undelivered_leads` не шлёт второй алерт владельцу по той же заявке.
- Счётчик «без ответа» на границах: заявка 1 ч 59 мин (не считается), ровно 2 ч (считается в «2 ч», не в «24 ч»), 23 ч 59 мин, ровно 24 ч (в обоих); заявка со `first_response_at`, статусом `spam`, статусом не `new` не считается.
- `alert_unanswered_leads`: счётчики 0 — ничего не шлёт; > 0 — один алерт с двумя числами и ссылкой на список, без id заявок и ПДн; повторный запуск в паузе не шлёт; после появления новой заявки без ответа шлёт снова; недоставка в оба канала откатывает ключ (следующий запуск повторяет).
- Недельный отчёт: строки «без відповіді > 2 год / > 24 год» присутствуют; медиана по отвеченным не изменилась (существующие тесты `metrics/tests_report.py` зелёные).
Playwright: UI не меняется (алерты, Celery и текст отчёта), по BRIEF §5 п.3 достаточно Django-тестов.
