# Задача 9.57: Пилот Telegram-каналов: `source_channel`, бейдж, отчёт (M12) 🔒

## Контекст
План пилота (`docs/BRAINSTORM_2026-11.md`, M7, M12, §8.4): staff вносит объявления вручную (флаг 6.7) из каналов с письменным согласия владельцев; на сайте объявление помечено «від @канал». Публичная подача остаётся закрытой, автоимпорта и скрейпинга нет. Договорённости с каналами, письменное согласие и абзац в `rules` — материал владельца, не код.

## Цель
- Поле `LocalListing.source_channel` (имя канала Telegram без `@`), редактируется в админке; валидируется форматом имени Telegram (латиница, цифры, `_`, 5–32 символа, начинается с буквы); ввод с `@` нормализуется.
- Бейдж «від @канал» на карточке в каталоге и на странице объявления: ссылка `https://t.me/<канал>` с `rel="nofollow noopener noreferrer"` и `target="_blank"`. Ссылка собирается только из проверенного имени, чужие хосты и `javascript:` невозможны. Персональных данных продавца бейдж не показывает.
- Команда `channel_report`: по существующей атрибуции заявок (`Lead.utm`, соглашение `utm_source=tg_<канал>`) считает заявки по каналам за окно и показывает число активных объявлений канала; только счётчики. Визиты с канала в базе не хранятся (они в аналитике), порог «менее 50 визитов за 14 дней» владелец смотрит там.

## Шаги
1. Поле, валидатор, нормализация, миграция.
2. Админка и публичный сериализатор (только чтение, имя канала).
3. Бейдж и тесты.
4. Команда отчёта на существующей атрибуции.

## Тесты
Django: валидация (хорошие и плохие имена, `@`, XSS, `javascript:`, длина), сериализатор отдаёт канал и не отдаёт телефон, публичный API не позволяет записать поле, отчёт (счётчики, чужие источники не попадают, ПДн нет), мутации. Playwright: бейдж на карточке и странице, ссылка и `rel`, плохое имя из API не даёт ссылки.

## Для владельца (LAUNCH_CHECKLIST)
Письменное согласие канала, условия на одной странице, абзац в `rules` о сторонних данных, отбор каналов, метка источника на сайте: тексты и договорённости только владельца.

## Готово, когда
Тесты зелёные, мутации ловятся, ревью безопасности без «критично» и «важно», `openapi.yaml` на PostgreSQL, `tsc`, `build`, `ruff`.
