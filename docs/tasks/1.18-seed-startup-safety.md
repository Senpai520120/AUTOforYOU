# Задача 1.18: Сиды при старте контейнера — не затирать реальные данные (E1, E2)

Источник: `docs/audit/SECURITY_AUDIT_2026-10-25.md`, раздел E. Проверяет `test-runner`; затронуты деньги (курс, ставки), поэтому результат сверяет основная сессия.

## Контекст
- **E1 (важно), `pricing/management/commands/seed_rates.py:79-83`, `docker/entrypoint.sh:30`:** сид при каждом старте контейнера кладёт **демо-курс 41.50/0.92 на сегодня**, если курс НБУ за сегодня ещё не загружен. Сценарий: рестарт контейнера до загрузки курса дня — все расчёты и снимки `Calculation` идут по демо-курсу, хотя вчерашний настоящий есть.
- **E2 (важно), `seed_rates.py:51,66,73,109,135`, `seed_auction_fees.py:178,198`:** `get_or_create` без `valid_from` на каждом старте. Сценарии: (1) владелец закрыл старую ставку и создал новую → при рестарте `MultipleObjectsReturned`, справочники досеиваются частично; (2) админ удалил плейсхолдер → после рестарта он **возвращается** и попадает в расчёт.
- Поле `ExchangeRate.source` (`nbu`/`demo`/`manual`) вводит задача 3.4a; если её код ещё не закоммичен, проверка «пустая таблица» работает и без него.

## Цель
- [ ] **E1:** демо-курс создаётся только если таблица `ExchangeRate` пуста или `NBU_MODE=demo`. Если есть любой реальный курс (`nbu`/`manual`), старт контейнера курс не добавляет.
- [ ] **E2:** сиды справочников (`seed_rates`, `seed_auction_fees` и остальные, вызываемые из `docker/entrypoint.sh`) выполняются только на пустом справочнике (по таблице) либо вручную флагом `--force`; удалённые и изменённые админом записи не воскрешаются и не дублируются; `get_or_create` с `valid_from` в ключе не используется для «досева» по умолчанию.
- [ ] `entrypoint.sh` вызывает сиды в безопасном режиме (`--if-empty` или `SEED_ON_START`), повторный старт не меняет данные; поведение описано в комментарии.
- [ ] Для пустой базы (первый запуск, e2e) поведение прежнее: справочники заполняются.

## Шаги
1. Тесты-сначала: сценарии из «Контекст» воспроизводятся красным тестом.
2. `seed_rates`: проверка пустоты каждого справочника; демо-курс по условию E1.
3. `seed_auction_fees`: то же; вывод «пропущено, справочник не пуст».
4. `entrypoint.sh`: вызовы без изменения порядка; новые аргументы.
5. Проверка на стеке: `docker compose up -d`, удалить плейсхолдер в админке, `docker compose restart backend` — запись не вернулась (e2e-стек, правила CLAUDE.md).

## Тесты
Django (`CleanCacheTestCase`, если читается кэш тарифов; мутация обязательна):
- **E1:** в базе курс `source='nbu'` за вчера; `call_command('seed_rates')` → нового курса за сегодня нет; пустая база → демо-курс создан с `source='demo'` (если поле есть); `NBU_MODE=demo` + реальный курс → демо создаётся.
- **E2:** закрыть старую ставку (`valid_to`), создать новую → `seed_rates` повторно не падает (`MultipleObjectsReturned`) и ничего не добавляет; удалить плейсхолдер → после `seed_*` его нет; пустая таблица → сид заполняет; `--force` (если введён) работает и пишет в вывод, что именно создано.
- Идемпотентность: двойной вызов на пустой базе даёт то же число строк.
Playwright: UI не затронут; существующий e2e-набор (калькулятор считает на сидовых тарифах) остаётся зелёным.
