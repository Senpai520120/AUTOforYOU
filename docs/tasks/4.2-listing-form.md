# Задача 4.2: Форма объявления: телефон, частичное сохранение, ошибки, is_owner

> Дубль (группа G10): поле `is_owner` в API и переключение `LocalListingDetail.tsx:38` на него делает задача 1.9 (владелец группы); здесь остаётся остальная логика владельца (`LocalListingDetail.tsx:181-202`).
> Дубль (группа G18): общий разбор ошибки (`err.data` вместо `err.detail`) вводит задача 2.9 (владелец группы); здесь `ReportButton` использует тот же хелпер, новый не создавать.

## Контекст
Подача и редактирование C2C-объявления: `frontend/components/local/LocalListingForm.tsx` (429 строк), страницы `frontend/app/local/new/page.tsx` и `frontend/app/local/[id]/edit/page.tsx`, бэкенд `local_listings/serializers.py` и `local_listings/views.py`. Это шаги 1 и 5 сценария 3 (`docs/audit/20_SCENARIOS.md`).

Что сейчас в коде:
- **10-Q1 (критично): редактирование стирает телефон продавца.** Страница edit грузит объявление через публичный detail: `localApi.detail(id)` (`frontend/app/local/[id]/edit/page.tsx:24`). Detail-сериализатор всегда обнуляет телефон: `data['contact_phone'] = None` (`local_listings/serializers.py:133-134`), и `LocalListingOwnerSerializer` наследует это обнуление (`local_listings/serializers.py:143-146`). Форма кладёт в состояние `''` (`LocalListingForm.tsx:90`) и отправляет `contact_phone: ''` в PATCH (`LocalListingForm.tsx:147`). `LocalListingUpdateSerializer` принимает пустую строку (`local_listings/serializers.py:233`, модель `blank=True`, `local_listings/models.py:150`). После первого же сохранения `/contact/` отдаёт `null` (`local_listings/views.py:378`).
- **10-Q3 (важно):** форма всегда шлёт все поля (`LocalListingForm.tsx:141-149`), а бэкенд решает о ремодерации по наличию ключей, а не по изменению значений: `substantive_changed = bool(SUBSTANTIVE_FIELDS & set(validated_data.keys()))` (`local_listings/serializers.py:256`, набор полей `local_listings/services.py:16`). Любое сохранение active-объявления, даже смена телефона, отправляет его на модерацию.
- **10-Q4 (важно):** ошибки выводятся только под make, model, year, mileage_km, price, region, city, agreed_to_rules (`LocalListingForm.tsx:168-177` собирает их в `errors`, отображение в `:239-407`). Ошибки `description` (антиспам hard, `local_listings/serializers.py:216-219`), `contact_phone`, `engine_cc`, ошибка лимита объявлений (`local_listings/serializers.py:200-204`: `ValidationError` со строкой бросается внутри `create()`, поэтому DRF отдаёт тело-список `["..."]`, а не словарь — форма такой ответ не разбирает вовсе) и `detail` (403, 429 throttle) не видны: форма молча не сохраняется.
- **10-Q5 (важно):** если фото не загрузились после создания, `setPhotoError(...)` (`LocalListingForm.tsx:161`) тут же перекрывается `setSubmitted(true)` (`:164`), и экран успеха (`:187-199`) ошибку не показывает.
- **05-Q10 / 10-Q2 (важно, дубли):** «я владелец» определяется сравнением `owner_name` с именем или префиксом email текущего пользователя (`frontend/app/local/[id]/LocalListingDetail.tsx:38`). От этого зависят кнопки «Написати продавцю», «Редагувати», «Поскаржитися» (`LocalListingDetail.tsx:180-202`). API не отдаёт `is_owner`. Тёзки видят чужие кнопки владельца, владелец после смены имени — нет.
- **10-Q6 (важно, по `docs/audit/24_TRACEABILITY.md` относится к 4.2):** `ReportButton` читает `err.detail` (`frontend/components/reports/ReportButton.tsx:46`), а `apiFetch` кладёт тело ответа в `err.data` (`frontend/api/client.ts:43`). Причина отказа сервера (повторная жалоба и т. п.) не видна.
- Желательные того же места: 10-S5 (страница edit не проверяет владельца, чужой видит форму, `edit/page.tsx:22-34`), 10-S6 и 10-C2 (лимиты фото 15 и «до 8 МБ» захардкожены на фронте, `LocalListingForm.tsx:14,31,36`, `PhotoUploadBlock.tsx:67,72,99`, при этом на бэке они в `.env`: `core/settings.py:322-323`), 10-C3 (максимальный год 2026 в форме, `LocalListingForm.tsx:248`), 10-Q12 (`URL.createObjectURL` без освобождения, `LocalListingForm.tsx:44`).
- `owner_name` с частью email (05-S3/10-S1) закрывает задача 1.9, cookie-аутентификацию — 1.4. Проверку содержимого фото на сервере — 1.10.

## Цель
- [ ] **10-Q1:** есть эндпоинт владельца `GET /api/v1/local/my-listings/<pk>/` (`LocalListingOwnerSerializer`, только автор или staff, чужой и аноним → 404/401). Owner-сериализатор отдаёт владельцу его `contact_phone`. Публичный detail по-прежнему отдаёт `contact_phone: null`.
- [ ] Страница `/local/<id>/edit` грузит объявление через `my-listings/<pk>/`. Чужой пользователь получает понятное «Оголошення не знайдено або ви не власник» (404-состояние), формы нет (10-S5). Ошибка загрузки показывается, а не молча уводит на `/ua`.
- [ ] Бэкенд не даёт затереть телефон: `contact_phone` в PATCH, если передан, должен быть непустым и проходить формат (`+380XXXXXXXXX` или 10 цифр `0XXXXXXXXX`), иначе 400 с ошибкой у поля. Отсутствие поля в PATCH телефон не меняет.
- [ ] **10-Q3:** форма редактирования отправляет только изменённые поля (diff с исходными значениями). Бэкенд считает правку существенной, только если значение поля из `SUBSTANTIVE_FIELDS` действительно отличается от текущего (сравнение значений, `Decimal` для цены, `strip()` для текста). Смена только телефона, пробега или города не отправляет active-объявление на модерацию.
- [ ] Проверка лимита активных объявлений перенесена из `create()` в `validate()`: ответ 400 `{"non_field_errors": [...]}`.
- [ ] **10-Q4:** все ошибки ответа видны (включая тело-список, если такое встретится). Ошибки полей `description`, `contact_phone`, `engine_cc` и прочих выводятся у соответствующего поля. `non_field_errors` и `detail` — в общем блоке вверху формы (с `role="alert"`). 429 → «Забагато спроб. Спробуйте за кілька хвилин». Поля, для которых в форме нет места, выводятся в общем блоке с названием поля. Кнопка «Зберегти» после ошибки снова активна.
- [ ] **10-Q5:** если объявление создано, а фото не загрузились, экран «надіслано на модерацію» показывает жёлтый блок с ошибкой и ссылкой «Додати фото» на `/local/<id>/edit`. Текст ошибки сервера (тип, размер, лимит) выводится, а не общая фраза.
- [ ] **05-Q10 / 10-Q2:** detail-сериализатор отдаёт `is_owner: bool` (по `request.user`, для анонима `false`). Страница объявления определяет владельца только по `is_owner`: при SSR (анонимном) — `false`; после монтирования у вошедшего пользователя клиент перезапрашивает `GET /local/listings/<id>/` и берёт `is_owner` оттуда. Сравнение по `owner_name` удалено.
- [ ] **10-Q6:** `ReportButton` показывает `err.data.detail`, `err.data.non_field_errors` или первую ошибку поля; общий текст — только если тела нет.
- [ ] Лимиты фото (количество и размер) приходят с бэкенда: `GET /api/v1/local/config/` → `{"max_photos", "photo_max_size_mb", "max_active_listings"}` из `settings`. Форма и `PhotoUploadBlock` проверяют размер, тип (`image/jpeg|png|webp`) и количество до отправки и показывают понятную ошибку; хардкода 15 и 8 на фронте нет (10-S6, 10-C2). Максимальный год — `new Date().getFullYear() + 1` (10-C3).
- [ ] `URL.createObjectURL` освобождается (`revokeObjectURL` в cleanup) (10-Q12).
