# Задача 4.3: Жизненный цикл объявления: модерация, продление, скрытие, удаление

## Контекст
Статусы `LocalListing`: draft, active, pending, rejected, expired, sold, hidden (`local_listings/models.py:103-110`, вложенный `TextChoices`). Срок жизни ставится в `save()` при создании (`local_listings/models.py:189-193`), снятие просроченных — Celery `expire_listings` раз в сутки (`local_listings/tasks.py:44-75`). Правка — `LocalListingUpdateSerializer` (`local_listings/serializers.py:225-280`), промо и оплата — `LocalListingPromoteView` (`local_listings/views.py:402-453`) и эффект в callback (`payments/views.py:20-50`; после задачи 4.1 — `payments/services.py`).

Что сейчас в коде:
- **05-S4 (важно): обход модерации.** Ремодерация при правке срабатывает только для `active` (существенные поля) и `rejected` (`local_listings/serializers.py:258-266`). Правка `expired`-объявления статус не трогает, а оплата RENEW переводит `expired → active` без модерации (`payments/views.py:33-39`). Так можно после одобрения заменить текст на что угодно и вернуть в каталог.
- **05-S5 (важно): жёсткое удаление.** `LocalListingDetailView` — `RetrieveUpdateDestroyAPIView` (`local_listings/views.py:146-148`), DELETE удаляет строку. Сделки (`deals/models.py:12-15`) и жалобы (`reports/models.py:26-31`) — `on_delete=CASCADE`, отзывы уходят вместе со сделками (OneToOne к Deal). Продавец стирает свою репутацию и улики. Избранное тоже каскадится (`favorites/models.py:11-14`).
- **05-Q5 (важно):** промо можно купить для объявления в любом статусе: view проверяет только владельца и тариф (`local_listings/views.py:405-417`). ТОП/bump применяются к невидимому объявлению.
- **05-Q6 (важно, вопрос Q9):** продлить можно только платно (RENEW, `payments/views.py:33-39`). Уведомление при снятии обещает «Натисніть «Продовжити»» (`local_listings/tasks.py:66`), а кнопка «Продовжити» в кабинете открывает платную модалку (`frontend/app/me/local-listings/page.tsx:247-260`).
- **05-Q7 (важно):** владелец может поставить только `hidden` или `sold` (`local_listings/serializers.py:243-248`), вернуть `hidden` в каталог не может.
- **10-Q8 (важно):** страница `/local/<id>` рендерится на сервере анонимно (`frontend/app/local/[id]/page.tsx:10-18`, `fetch` без cookie, `revalidate: 60`). Бэкенд владельцу своё не-active объявление отдаёт (`local_listings/views.py:155-172`), но SSR-запрос анонимный → `notFound()` (`page.tsx:40`). Владелец не видит своё pending/rejected/hidden. Проданное (`sold`) отдаёт 404 вместо страницы «Продано».
- Желательные того же места: 20-G2 (срок жизни считается от создания, а не от одобрения: `approve_listing` не трогает `expires_at`, `local_listings/services.py:19-27`; долго модерируемое объявление снимается сразу после одобрения), 05-Q14 (смена статуса в форме админки обходит `approve_listing`/`reject_listing`: поле `status` редактируемое, `local_listings/admin.py:113-118`), 05-Q13 (каталог не проверяет `expires_at`, `local_listings/views.py:137-138`), 05-S9 (фото в active меняются без ремодерации, `local_listings/views.py:266-354`), 10-Q18 (`revalidate: 60` — снятое объявление видно ещё минуту, `page.tsx:12`), 05-C4 (порог предупреждения «за 3 дні» захардкожен, `local_listings/tasks.py:16`), 10-C7 (страница объявления дублирует базовый URL API вместо `lib/server-api.ts`, `frontend/app/local/[id]/page.tsx:8-18`).
- Решение по Q9 получено (`docs/ANSWERS.md`, см. «Изменения после ANSWERS» ниже): срок 30 дней от одобрения модератором, бесплатное продление без ограничения количества (`LISTING_FREE_RENEWALS`, 0 = без лимита, по умолчанию 0), платное продление не нужно (тариф RENEW деактивируется), после срока — архив с восстановлением. Платежи на запуске выключены (`PAYMENTS_ENABLED=false`), поэтому промо в этой задаче доводится до готовности, но в интерфейсе скрыто.

## Цель
- [ ] **20-G2 / Q9:** `approve_listing` ставит `expires_at = now + LOCAL_LISTING_EXPIRY_DAYS` (и сбрасывает `expiry_warned`). Для новых объявлений `save()` больше не ставит срок при создании (pending без срока). Существующие pending-объявления: data-миграция очищает `expires_at` у `pending`.
- [ ] **05-Q6 / Q9 (по ANSWERS):** бесплатное продление в один клик: `POST /api/v1/local/listings/<pk>/renew/` (только владелец). Разрешено для `expired` (архив, он же «восстановление») и для `active`, у которого до конца срока ≤ порога напоминания (вручную, раз в срок жизни). Лимит — `LISTING_FREE_RENEWALS` (настройка, по умолчанию 0 = без лимита); счётчик `free_renewals_used` ведётся для статистики, а при значении > 0 лимит исчерпан → 400 «Безкоштовні продовження вичерпано». Продление: `expires_at = max(expires_at, now) + LOCAL_LISTING_EXPIRY_DAYS` (по умолчанию 30), `expired → active` только если объявление не правилось после модерации (см. следующий пункт). Платного продления нет: кнопка «Продовжити» в кабинете всегда вызывает бесплатное продление, `PromoteModal` с RENEW из кабинета убирается. Тариф RENEW деактивируется (data-миграция в `pricing`/`payments`) до выполнения этой задачи.
- [ ] **Q9 (напоминания и архив):** пороги напоминаний (за N дней и в день окончания) — настройки в админке (не хардкод; `SiteSettings` из 1.12 или отдельная модель настроек объявлений), каналы email + Telegram. Просроченные уходят в архив (`expired`) с восстановлением кнопкой «Відновити» (то же продление). Лимит бесплатных активных объявлений частника — настройка (если ещё нет в 4.2, добавить здесь; 0 = без лимита).
- [ ] **G1.3 (ANSWERS, шаг 4): `blocked` ≠ `hidden`.** Новый статус `blocked` (блокировка модератором/баном) отдельно от `hidden` (скрыл владелец). Владелец возвращает в `active` только своё `hidden`; из `blocked` владелец вернуть не может (PATCH → 403 «Оголошення заблоковано модератором»). `blocked` снимает только роль `moderator`/staff через сервис `unblock_listing` с записью в журнал аудита (Q10). Блокировка (`block_listing`) тоже через сервис с записью в аудит; кабинет владельца показывает плашку «Заблоковано модератором» с причиной, без кнопки «Показати знову». Действия модератора в UI — задача 4.5; здесь — статус, сервисы, права.
- [ ] **F6 (ANSWERS, шаг 1–3): страница «Продано».** Остаётся в индексе (без `noindex`): контакты скрыты, блок «Схожі оголошення» и ссылка «Пригнати схоже зі США» на калькулятор. Через `LOCAL_LISTING_SOLD_NOINDEX_DAYS` (настройка в админке, по умолчанию 90) после `sold_at` — `noindex`. Нужна дата продажи: поле `sold_at` (если нет — добавить в миграцию).
- [ ] **Кабинет продавца (ANSWERS, шаг 4):** кнопка «Приховати» (`hidden`), отметка «Продано поза сайтом» (`sold` + `sold_channel`: на сайте / поза сайтом, опрос «Де продали?» с вариантами и «інше»), отписка от напоминаний одной ссылкой из письма (подписанный токен без входа, связать с 4.7), страница `/me/payments` с историей платежей (если не покрыта 6.2 — здесь страница-заглушка списка из 4.1; при `PAYMENTS_ENABLED=false` — «Платні послуги тимчасово недоступні»).
- [ ] **05-S4:** существенная правка (по значению, хелпер из 4.2) объявления в статусе `active`, `expired` или `hidden` → `pending` (ремодерация); `rejected` → `pending` при любой правке, как сейчас. `blocked` правкой не снимается. Продление (только бесплатное, Q9) переводит в `active` только `expired`-объявление; `pending` остаётся `pending`, продлевается только срок. Добавление или удаление фото в `active` → `pending` (05-S9, 23-D78).
- [ ] **05-Q5:** промо разрешено: TOP и BUMP — только для `active` (RENEW как платная услуга не существует, см. Q9). При `PAYMENTS_ENABLED=false` эндпоинт promote отвечает 404/403 (по решению шага 5), кнопки промо в кабинете скрыты. Иначе 400 «Просування доступне лише для активних оголошень». Проверка и в `promote`, и в применении эффекта в callback (если к моменту оплаты статус не подходит, эффект не применяется, платёж помечается для ручного разбора, в лог WARNING). В кабинете кнопки промо показываются только для разрешённых статусов.
- [ ] **05-Q7:** владелец может вернуть `hidden → active` через PATCH `{"status": "active"}`, если объявление ранее одобрено (`moderated_at` не пусто), срок не истёк и после модерации не было существенной правки. Иначе → `pending` (если правилось) или 400 «Термін дії закінчився, продовжте оголошення» (если истёк). `sold` — финальный для владельца. Кнопка «Показати знову» в кабинете.
- [ ] **05-S5:** DELETE владельцем — мягкое удаление: новый статус `deleted` (исчезает из каталога, кабинета владельца, избранного и поиска, detail → 404 для всех, кроме staff). Сделки, отзывы, жалобы, диалоги и платежи сохраняются. `Deal.listing` и `Report.listing` получают `on_delete=PROTECT`, чтобы и из админки объявление со сделками/жалобами нельзя было удалить каскадом (админ видит понятную ошибку Django «нельзя удалить, есть связанные объекты»). В кабинете подтверждение «Оголошення буде видалено з сайту. Історія угод і відгуків збережеться».
- [ ] **10-Q8:** страница `/local/<id>` передаёт на бэкенд cookie пользователя при SSR (через серверный хелпер из задачи 1.4) и не кэширует персональный ответ (`cache: 'no-store'` при наличии cookie, публичный ответ — прежний `revalidate`, но не больше 60 с). Владелец видит своё `pending`/`rejected`/`hidden`/`expired` объявление с плашкой статуса (и причиной отклонения для `rejected`), кнопки «Показати телефон», «Написати», «Поскаржитися» не показываются. `sold` публичен: страница «Продано» без телефона и кнопки «Написати», с блоком похожих и ссылкой «Пригнати схоже зі США», `noindex` только после `LOCAL_LISTING_SOLD_NOINDEX_DAYS` (F6). `blocked` владельцу — плашка, публично 404. `deleted` → 404. Запрос идёт через общий серверный хелпер (`serverGet` из `frontend/lib/server-api.ts`), собственная константа `API` в `page.tsx` удалена (10-C7).
- [ ] Админка (05-Q14): поле `status` в форме `LocalListing` только для чтения; модерация — только через экшены approve/reject (они вызывают сервисы). Каталог дополнительно фильтрует `expires_at > now` (05-Q13). Пороги предупреждения (за N дней и в день окончания) — настройки в админке, значения по умолчанию 3 и 0 (05-C4, Q9).
- [ ] Тексты уведомлений о сроке: «Продовжте безкоштовно в кабінеті» (одним кликом), email + Telegram.
