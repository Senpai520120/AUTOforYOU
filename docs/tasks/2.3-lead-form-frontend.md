## Шаги
1. `frontend/api/leads.ts`: `create(payload)` → `POST /api/v1/leads/`, `mine()` → `GET /api/v1/leads/mine/`. Типы в `lib/types.ts`.
2. `LeadForm.tsx` (client component): props `source`, `calculationId?`, `listingId?`. Все `<label htmlFor>` связаны с `id`. Телефон `type="tel"` с `inputMode="tel"` и подсказкой формата `+380…`. Не `type="number"` (ловушка: `fill()` с нечисловым значением бросает исключение). Honeypot `website`: визуально скрыт, `tabIndex={-1}`, `autoComplete="off"`, `aria-hidden`.
3. Разбор ошибок: `err.status` и `err.data` из `apiFetch`. Для 400 — `data[field][0]` под полем, `non_field_errors` над кнопкой. Для 429/5xx/сети — общие тексты. `JSON.stringify` не использовать.
4. `CalcBreakdown.tsx`: после таблицы и предупреждения — `<LeadForm source="calculator" calculationId={result.calculation_id} />`. Над формой одна строка о том, что сумма орієнтовна (`result.is_estimate`).
5. `app/calculator/page.tsx`: при новом расчёте форма заявки сбрасывается (новый `calculation_id`). Если калькулятор открыт со страницы лота (2.6 передаёт `listing` в query), `listing_id` тоже передаётся в заявку.
6. `ListingDetail.tsx`: кнопка «Залишити заявку» раскрывает `LeadForm source="listing" listingId={listing.id}`.
7. `app/me/leads/page.tsx`: список заявок (номер, дата, статус по-украински, итог, ссылка на лот). Гость → `/login`. Пустое состояние «Заявок ще немає» со ссылкой на калькулятор. Ошибка загрузки — сообщение, а не пустой список. Клиентская страница, поэтому ловушки пререндера нет. Если страница станет серверной, нужен `export const dynamic = 'force-dynamic'`.
8. `app/me/page.tsx`: пункт меню «Мої заявки».
9. Playwright-спека (запускать только из `frontend/`), с фикстурами и `storageState` из 0.4. Запрос `POST /api/v1/leads/` можно проверять через `page.waitForResponse`. В негативных тестах проверять, что запроса не было (правило из 23_TESTS, раздел «Инфраструктура e2e»).
