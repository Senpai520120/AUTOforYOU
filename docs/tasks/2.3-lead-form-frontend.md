## Контекст
- **09-Q1 (критично, фронт-часть)**: у `CalcBreakdown` нет CTA и формы (имя, телефон, способ связи, согласие). `frontend/components/calculator/CalcBreakdown.tsx:14-56` заканчивается блоком `#{calculation_id} · {warning}` (`:51-53`). `frontend/api/pricing.ts:15-21` не знает про заявки. Бэкенд (`POST /api/v1/leads/`, `GET /api/v1/leads/mine/`) делает 2.1.
- 02-Q1 (критично) закрывается вместе с 2.1 и 2.2. Здесь его пользовательская часть: клиент может отправить заявку и видит, что она принята.
- Вторая точка входа по Q4 (по умолчанию): страница лота. Сейчас там только «Порахувати вартість» и «Написати продавцю» (`frontend/components/listings/ListingDetail.tsx:108-115`).
- Ошибки клиента: `apiFetch` кладёт ответ сервера в `err.data` (`frontend/api/client.ts:42-44`). В дилерской форме из-за чтения `err.detail` ошибки полей не показываются (09-Q8, задача 2.9). Эту ошибку не повторять.
- 09-Q7 (задача 1.4): аноним с протухшим токеном при 401 уходит на `/login` (`frontend/api/client.ts:31-38`) и теряет форму. После 1.4 (cookie) этого быть не должно. Для `AllowAny`-эндпоинта заявки это критично: гость не должен терять введённые данные.
- В кабинете (`frontend/app/me/page.tsx:17-28`) раздела «Мої заявки» нет.
- `result.is_estimate` фронт не читает (`frontend/lib/types.ts:84-89`, 09 «Функции»). В форме заявки клиенту нужно явно сказать, что расчёт орієнтовний.

## Цель
- [ ] Под разбивкой расчёта есть блок «Залишити заявку брокеру» с полями: ім'я, телефон (`type="tel"`), зручний спосіб зв'язку (радио: телефон / Telegram / Viber / WhatsApp), необязательный нік або контакт (для Telegram), коментар, чекбокс згоди з посиланням на `/privacy`, скрытый honeypot. `calculation_id` берётся из результата расчёта.
- [ ] Если пользователь вошёл, имя и телефон предзаполняются из профиля. Изменить их можно.
- [ ] Отправка → экран «Заявку №… отримано. Брокер зв'яжеться з вами найближчим часом зручним для вас способом», повторная отправка той же формы заблокирована. Кнопка «Новий розрахунок».
- [ ] Клиентская валидация: без згоди и без телефона кнопка не отправляет запрос. Ошибки сервера (400) показываются у соответствующих полей, 429 — понятным сообщением «Забагато заявок, спробуйте пізніше», 500 и сеть — общим сообщением без сырого JSON.
- [ ] На странице лота (`ListingDetail`) есть кнопка «Залишити заявку», она открывает ту же форму с `source=listing` и `listing_id`.
- [ ] Гость с протухшим токеном не выкидывается на `/login` при отправке заявки (проверка регресса 09-Q7 после 1.4).
- [ ] В кабинете есть раздел «Мої заявки» (`/me/leads`): список своих заявок со статусом и датой (`GET /api/v1/leads/mine/`), пустое состояние и ошибка.
- [ ] Тексты интерфейса на украинском. Контактов брокера в коде нет.

## Шаги
1. `frontend/api/leads.ts`: `create(payload)` → `POST /api/v1/leads/`, `mine()` → `GET /api/v1/leads/mine/`. Типы в `lib/types.ts`.
2. `LeadForm.tsx` (client component): props `source`, `calculationId?`, `listingId?`. Все `<label htmlFor>` связаны с `id`. Телефон `type="tel"` с `inputMode="tel"` и подсказкой формата `+380…`. Не `type="number"` (ловушка: `fill()` с нечисловым значением бросает исключение). Honeypot `website`: визуально скрыт, `tabIndex={-1}`, `autoComplete="off"`, `aria-hidden`.
3. Разбор ошибок: `err.status` и `err.data` из `apiFetch`. Для 400 — `data[field][0]` под полем, `non_field_errors` над кнопкой. Для 429/5xx/сети — общие тексты. `JSON.stringify` не использовать.
4. `CalcBreakdown.tsx`: после таблицы и предупреждения — `<LeadForm source="calculator" calculationId={result.calculation_id} />`. Над формой одна строка о том, что сумма орієнтовна (`result.is_estimate`).
5. `app/calculator/page.tsx`: при новом расчёте форма заявки сбрасывается (новый `calculation_id`). Если калькулятор открыт со страницы лота (2.6 передаёт `listing` в query), `listing_id` тоже передаётся в заявку.
6. `ListingDetail.tsx`: кнопка «Залишити заявку» раскрывает `LeadForm source="listing" listingId={listing.id}`.
7. `app/me/leads/page.tsx`: список заявок (номер, дата, статус по-украински, итог, ссылка на лот). Гость → `/login`. Пустое состояние «Заявок ще немає» со ссылкой на калькулятор. Ошибка загрузки — сообщение, а не пустой список. Клиентская страница, поэтому ловушки пререндера нет. Если страница станет серверной, нужен `export const dynamic = 'force-dynamic'`.
8. `app/me/page.tsx`: пункт меню «Мої заявки».
9. Playwright-спека (запускать только из `frontend/`), с фикстурами и `storageState` из 0.4. Запрос `POST /api/v1/leads/` можно проверять через `page.waitForResponse`. В негативных тестах проверять, что запроса не было (правило из 23_TESTS, раздел «Инфраструктура e2e»).
