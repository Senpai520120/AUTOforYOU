# Задача 8.2: Населённые пункты по КАТОТТГ и поиск города

Метка волны: [ВОЛНА-2].
Риск: обычный (справочные данные, без ПДн и платежей).

## Контекст
Продавец из села или небольшого города не найдёт свой населённый пункт: ответ «Місто не знайдено» — потеря пользователей (пункты эталона A3.1, A3.2; `docs/audit/31_PARITY_A_B.md`, Н-2).

Что сейчас в коде:
- `Region` и `City` без кода КАТОТТГ: `local_listings/models.py:8-33` (`Region.name` уникальна; `City.region` FK `CASCADE`, `City.name`, `City.slug`, уникальность (`region`, `slug`) — `models.py:30`). Поля `katottg`, типа пункта, района, признака «крупный» нет.
- Справочник — литеральные списки в `local_listings/management/commands/seed_regions.py` (24 области + «місто Київ», порядка 300 городов; в шапке файла комментарий «неполный КАТОТТГ, для повного потрібен офіційний CSV»). Нет Автономної Республіки Крим и Севастополя; сёл и ПГТ нет. Команда запускается при каждом старте контейнера (`docker/entrypoint.sh:20`, `run_seed seed_regions`) и в тесте (`local_listings/tests.py:440`).
- API: `GET /api/v1/local/regions/` (`local_listings/views.py:231-235`) и `GET /api/v1/local/regions/<id>/cities/` (`views.py:239-246`, `pagination_class = None`, возвращает все города области; маршруты — `local_listings/urls.py:27-28`). Параметра поиска нет; при полном КАТОТТГ (десятки тысяч пунктов) вывод всех городов области непригоден.
- Форма подачи: `<select>` области и затем `<select>` городов (`frontend/components/local/LocalListingForm.tsx:107-116` загрузка, `:333-345` селекты); фильтр каталога — тот же приём (`frontend/components/local/LocalListingFilters.tsx:11-40,139`); клиент API — `frontend/api/local.ts:39-43`.
- Объявление: `LocalListing.region` и `LocalListing.city` — FK `PROTECT` (`local_listings/models.py:140-141`); проверка «город принадлежит области» есть при создании и правке (`local_listings/serializers.py:174-177`, `237-240`). Фильтр каталога по городу — по числовому id (`local_listings/filters.py:57-60` для области, аналогично город).
- Админка: `CityAdmin` (`local_listings/admin.py:35-40`) и `CityInline` (`:29-32`); поле города в форме объявления при десятках тысяч записей станет неподъёмным выпадающим списком.

Решение владельца (`docs/ANSWERS.md`, порядок открытия): справочник населённых пунктов — ВОЛНА-2. Лицензию открытого набора КАТОТТГ проверяет владелец до загрузки (вопрос в LAUNCH_CHECKLIST), полный набор данных в задачу не вшивается: команда импорта читает файл по пути из `.env`.

## Цель

Индекс по `City.search_name` и по (`region`, `is_major`). Существующие `City.id` и `Region.id` не меняются (объявления ссылаются на них с `PROTECT`).
- [ ] Нормализация имени `normalize_place_name()` (общий модуль `local_listings/places.py`): регистр, единый апостроф (`'`, `’`, `ʼ`, `` ` `` → один вид), единый дефис и тире, схлопывание пробелов. Поиск «Кам'янське» находит и «Кам’янське».
- [ ] Команда `import_katottg --file <путь> [--dry-run] [--deactivate-missing]`: идемпотентный импорт из CSV нормализованного формата (колонки и пример описаны в справке команды и в `docs/`-заметке после выполнения; конвертер из реального файла источника входит в задачу, когда владелец положит файл). Сопоставление с существующими записями по `katottg`, а для старых записей без кода — по (область, нормализованное имя): так ссылки существующих объявлений сохраняются, ничего не удаляется. `slug` уникален в области: при одинаковых именах к `slug` добавляется хвост кода КАТОТТГ. `--dry-run` печатает план (создано/обновлено/конфликты) и ничего не пишет. `--deactivate-missing` только помечает отсутствующие в файле пункты `is_active=False` и не трогает пункты, на которые ссылаются объявления (они остаются `is_active=True`, выводятся в отчёт).
- [ ] Область: добавляются записи, которых нет в текущем сиде (Автономна Республіка Крим, Севастополь) с `is_active` по решению владельца (вопрос в «Для владельца»); состав областей берётся из файла источника, не из кода.
- [ ] `seed_regions` остаётся запасным вариантом для dev и тестов, но не создаёт дублей при уже импортированном справочнике: сопоставляет по (область, нормализованное имя) и проставляет `is_major=True` существующим ~300 городам. `docker/entrypoint.sh` после `seed_regions` вызывает `import_katottg`, только если задан `KATOTTG_FILE` (иначе строка пропускается с понятным сообщением в лог).
- [ ] API поиска: `GET /api/v1/local/cities/?q=<текст>&region=<id>&limit=<n>` (`AllowAny`, throttle-scope `city_search`, ставка в `.env`). Ответ — до `CITY_SEARCH_LIMIT` результатов (настройка) вида `{id, name, region, region_name, district_name, label}`. Минимальная длина `q` — `CITY_SEARCH_MIN_CHARS` (настройка, `.env`); короче — пустой список. Порядок: сначала совпадение по началу слова, затем по вхождению; внутри — `is_major` выше, потом по имени. Только `is_active=True`. Лишние поля (коды, служебные) наружу не отдаются, кроме `label` для показа.
- [ ] Существующий `GET /regions/<id>/cities/` остаётся для совместимости: без `q` возвращает только `is_major`-города области (быстрый список), с `q` — результаты поиска по области; полный перебор десятков тысяч пунктов отключается.
- [ ] Валидация объявления: город должен быть `is_active` (иначе 400 «Населений пункт недоступний для вибору»), проверка принадлежности области остаётся. Старые объявления с городом, ставшим неактивным, продолжают отображаться.
- [ ] Фронт: компонент `CityAutocomplete` (combobox): ввод ≥ `min_chars` символов → подсказки с областью и районом, выбор клавишами (стрелки, Enter, Escape) и касанием, текст «Нічого не знайдено» с подсказкой проверить написание, индикатор загрузки, отмена устаревших запросов (debounce из настройки/константы интерфейса без бизнес-смысла), роли ARIA (`combobox`, `listbox`, `option`). При выборе пункта область выставляется автоматически; отдельный `<select>` области в форме подачи убирается, в фильтре каталога остаётся.
- [ ] Лимиты поиска (`min_chars`, `limit`) приходят с бэкенда в `GET /api/v1/local/config/` (расширение из 4.2), фронт их не хардкодит.
- [ ] Админка: `CityAdmin` — поиск по `name`, `katottg`, области; фильтры по области, `is_major`, `is_active`; `list_per_page`; поле города в `LocalListingAdmin` — `autocomplete_fields`; запись КАТОТТГ только чтение после импорта.

## Тесты
Django:
- Нормализация: «Кам'янське», «Кам’янське», «КАМ`ЯНСЬКЕ» дают одно значение; пробелы и дефисы выравниваются.
- Поиск `GET /local/cities/`: `q` короче `CITY_SEARCH_MIN_CHARS` → пустой список; префикс идёт выше вхождения; `is_major` выше при равном совпадении; не больше `CITY_SEARCH_LIMIT` (`override_settings`); `region=<id>` ограничивает область; неактивный пункт не возвращается; в ответе нет `katottg` и служебных полей; анонимный доступ работает; throttle `city_search` → 429.
- `GET /regions/<id>/cities/` без `q` — только `is_major`; с `q` — поиск по области.
- Импорт: фикстура `katottg_sample.csv` создаёт записи; повторный импорт идемпотентен (без дублей, число запросов разумно); существующий город без кода сопоставляется по (область, имя) и сохраняет `id`, объявление на него по-прежнему валидно; `--dry-run` ничего не пишет; одноимённые сёла в одной области получают разные `slug`; `--deactivate-missing` деактивирует отсутствующий в файле пункт без объявлений и не трогает пункт с объявлением (попадает в отчёт).
- `seed_regions` после импорта не создаёт дублей; без файла `entrypoint` пропускает импорт (проверка функции выбора по настройке).
- Объявление: создание с неактивным городом → 400; город из другой области → 400 (прежнее поведение); старое объявление с позже отключённым городом отдаётся без ошибки.
- Админка: `CityAdmin` поиск по `katottg`; `LocalListingAdmin` открывается без загрузки всех городов (число запросов не растёт с числом городов).
Playwright (`frontend/e2e/city-search.spec.ts`; фикстурные города — из `e2e_seed` из 0.4, включая село с одноимёнными пунктами):
- Успех: продавец в форме подачи вводит первые буквы села, выбирает подсказку «Село · район · область» → область подставляется сама, объявление создаётся; в каталоге `/ua` фильтр по этому городу находит его; выбор клавишами (стрелка вниз + Enter) работает.
- Успех: быстрый список крупных городов доступен без ввода (если решено показывать) и выбирается касанием на мобильном проекте Playwright.
- Ошибка/обход: ввод несуществующего названия → «Нічого не знайдено», кнопка отправки формы недоступна/показывает «Оберіть населений пункт зі списку»; прямой `POST` объявления с городом другой области (через `page.request`) → 400; запрос поиска короче минимума не отправляется (проверка через `page.on('request')`).
