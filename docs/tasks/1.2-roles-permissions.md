# Задача 1.2: Роли buyer/dealer/broker/admin и права по умолчанию

## Контекст

**01-S7 / 02-S6 (важно), роли broker нет.**
- `users/models.py:25-28`: `Role` содержит только `BUYER`, `DEALER`, `ADMIN`.
- `core/settings.py:272`: `UserRoleEnum` для OpenAPI без broker (01-C12).
- Бриф §1 и §3 требуют, чтобы заявки видел брокер по роли. Сейчас «брокер» — это любой `is_staff`.

**06-S9 (важно), все `is_staff` видят и получают уведомления по всем импортным диалогам.**
- `messaging/views.py:62-65`: список диалогов для `is_staff` включает все импортные.
- `messaging/views.py:28`: доступ к импортному диалогу по `is_staff`.
- `messaging/services.py:18`: получатель импортного диалога — «первый `is_staff`».
- `messaging/services.py:77,97`: признак отправителя и видимость по `is_staff`.
- `messaging/services.py:157-161`: уведомления всем `is_staff`.

**01-S8 (важно), `DEFAULT_PERMISSION_CLASSES = AllowAny`** (`core/settings.py:223-225`). Любой новый view без явных прав становится публичным. Views без явного `permission_classes` сейчас:
- `pricing/views.py:144` (`CalculateView`) и `:375` (`ActiveRatesView`);
- `vehicles/views.py:11,21`;
- `listings/views.py:52,69`;
- один из `local_listings/views.py` (`VinPrefillView`, `:205`);
- `integrations/views.py` (`VinDecodeView`);
- legacy `cars/views.py:26,58`.

**01-Q3 (важно), роль выбирается при регистрации и ни на что не влияет.**
- `users/serializers.py:15-18` разрешает самому выбрать `dealer`.
- Права дают только `is_verified_dealer` и `is_staff` (`listings/permissions.py:14-18`, `users/services.py:49-51`).
- В итоге два источника истины о правах.

**01-Q2 (важно), одобрение дилера через форму админки обходит сервис.** В `users/admin.py:88-99` поле `status` редактируется в fieldset «Рассмотрение» (`:98`). Если поставить `approved` вручную, `approve_application` (`users/services.py:40-52`) не вызывается: `is_verified_dealer` и `role` не меняются, письмо не уходит. `agreed_to_processing_at` в админке не показан.

**09-S2 (важно), фронт B2B проверяет доступ по самовыбранной роли.** `frontend/app/b2b/page.tsx:17`: `user.is_verified_dealer || user.role === 'admin'`. Сервер проверяет правильно (`listings/permissions.py:14-18`). Связанная находка 04-S6 (желательно), то же место.

Связанное вне ROADMAP-списка задачи:
- `frontend/lib/types.ts:9`: тип роли без broker;
- `frontend/app/me/page.tsx:42`: метка роли не знает broker;
- модерация объявлений сейчас проверяется через `is_staff`: `local_listings/views.py:93,170,177,256,407`, `local_listings/serializers.py:131-137`, admin-actions `local_listings/admin.py:45-57,102,166`.

**Вопрос Q10:** нужна ли отдельная роль модератора. По умолчанию: отдельной роли нет, модерируют broker и admin, право модерации — отдельное Django-разрешение.
