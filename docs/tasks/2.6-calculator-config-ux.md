# Задача 2.6: Калькулятор: справочники из API, демо по данным, честные ошибки

## Контекст
Суммы считает сервер, но справочники формы, подписи ставок и демо-флаг зашиты во фронт или в переменную сборки. Ошибки показываются сырым JSON, а анонимный калькулятор без ограничений пишет в БД (`docs/audit/02_pricing.md`, `docs/audit/09_fe_import.md`).

- **09-C1 (важно)**: справочники калькулятора зашиты во фронт: топливо `frontend/app/calculator/page.tsx:71-74`, аукционы `:86-87`, порты США `:94-96`, порты ЕС `:103-104`, локации `:111-112`. Маршрут, добавленный в админке, в форме не появится. Смежно, 02-C4 (желательно): порты ЕС зашиты ещё и в choices моделей (`pricing/models.py:112-114,129-131`) и сериализатора (`pricing/serializers.py:27`). 02-C5 (желательно): порты, локации и топливо в UI (PHEV и поле батареи добавляет 2.5).
- **09-C2 (важно)**: подписи «Пошлина 10%» и «НДС 20%» зашиты (`frontend/components/calculator/CalcBreakdown.tsx:35-36`). Для EV пошлина 0%, подпись врёт (02-C13).
- **09-C3 (важно)**: демо-баннер управляется переменной сборки `NEXT_PUBLIC_DEMO_MODE` (`frontend/components/ui/DemoBanner.tsx:4`), по умолчанию включён, от данных не зависит. Рендерится в `page.tsx:135` и `CalcBreakdown.tsx:18`. Бриф §2 требует, чтобы после заполнения данных пометки исчезали сами. Корень на бэкенде — 02-C2 (желательно): `is_estimate=True` константой (`pricing/views.py:335,341`, `pricing/calculator.py:140`), у тарифов нет признака «проверено». 02-C8 (желательно): демо-курс 41.50 / 0.92 из сида (`pricing/management/commands/seed_rates.py:82-89`) выглядит как настоящий.
- **12-C2 (важно)**: `NEXT_PUBLIC_DEMO_MODE` не пробрасывается в Docker-сборку фронта: в `Dockerfile.frontend:14-20` есть только `NEXT_PUBLIC_API_URL` и `NEXT_PUBLIC_SITE_URL`, в `docker-compose.yml:59-62` тоже. В проде баннер всегда включён. Закрывается тем, что флаг сборки больше не нужен.
- **09-Q6 (важно)**: ошибки калькулятора выводятся сырым `JSON.stringify(e2?.data)` (`frontend/app/calculator/page.tsx:45-48`). 422 «Отсутствуют активные тарифы в БД» (`pricing/views.py:273-277`) не превращается в «калькулятор ещё не настроен». Смежно, 09-S5 (желательно): текст 500 попадает в UI.
- **09-Q3 (важно)**: «Порахувати вартість» подставляет `listing.price` (розничная цена в `listing.currency`, возможно UAH или EUR) в поле «Ціна аукціону ($)» (`frontend/components/listings/ListingDetail.tsx:110`, `frontend/app/calculator/page.tsx:25`). У `Listing` нет цены аукциона (`listings/models.py:48-49`: `price`, `currency`).
- **02-S1 (важно)**: `except Exception as exc: return Response({'error': str(exc)}, 500)` (`pricing/views.py:279-280`) отдаёт клиенту внутренние детали.
- **02-S2 (важно)**: анонимный `POST /api/v1/pricing/calculate/` (`pricing/views.py:144`) пишет `Calculation` на каждый вызов (`:328-336`). Действует только общий anon-throttle (`core/settings.py:214`, `:229-238`), очистки анонимных расчётов нет.
- Q11 (по умолчанию): `GET /api/v1/pricing/rates/` (`pricing/views.py:375-419`) сейчас анонимно отдаёт всю тарифную сетку брокера (02-S3). Решение по умолчанию: анонимам только справочники для формы, полная сетка — staff и broker.
- Смежные желательные: 02-C1 и 09-C6 (текст `warning` с датой «янв–чер 2026» в `pricing/views.py:344-348` и текст баннера в `DemoBanner.tsx:16-18`), 02-Q8 (мёртвый сломанный `ActiveRatesSerializer`, `pricing/serializers.py:41-62`).
- 2.7 будет добавлять в `/rates/` справочник доставки по Украине и услуги брокера. Формат ответа, заданный здесь, должен это позволять.

## Цель
- [ ] `GET /api/v1/pricing/rates/` (Q11):
  - аноним и обычный пользователь получают только справочники формы без сумм: `auctions`, `auction_locations`, `us_ports`, `eu_ports` (с учётом того, какие порты США на какие порты ЕС реально ведут), `fuel_types` (из активных `CustomsExciseRate`), `member_types`/`payment_types`/`title_types` с дефолтами, `requires_battery` для типов топлива, и `is_demo`;
  - staff и broker получают то же плюс полную сетку (текущий формат ответа);
  - ответ кэшируется на уровне `pricing/cache.py`, как остальные справочники.
- [ ] Форма калькулятора строит все select'ы из этого ответа. В `page.tsx` не остаётся списков значений. Пока справочники грузятся — скелетон. Если их нет (пустые тарифы) — сообщение «Калькулятор ще не налаштовано», форма не показывается (09-C1).
- [ ] Новый порт ЕС, добавленный в админке (маршрут фрахта и доставки), появляется в форме и принимается сервером без правки кода: `eu_port` валидируется по активным тарифам, choices у моделей убраны (02-C4).
- [ ] Подписи пошлины, НДС и пенсионного сбора в разбивке берут процент из ответа (`applied_rates.duty_rate`, `vat_rate`, `pension_fund_rate`). Для EV показывается фактическая ставка, например «Мито 0%» (09-C2).
- [ ] У всех тарифных моделей есть `is_verified` (default `False`), у `ExchangeRate` — `source` (`nbu`, `manual`, `demo`). `is_demo` в ответе расчёта = хотя бы одна применённая запись не проверена или курс `demo`. В `/rates/` `is_demo` = среди активных тарифов есть непроверенные. `is_estimate: true` остаётся всегда (CLAUDE.md), `is_demo` — отдельный флаг (02-C2).
- [ ] Демо-баннер показывается по `is_demo` из API (на форме — из `/rates/`, в результате — из ответа расчёта). `NEXT_PUBLIC_DEMO_MODE` из кода удалён. Когда владелец отметил все тарифы проверенными, баннер исчезает без пересборки (09-C3, 12-C2).
- [ ] Тексты предупреждения расчёта и демо-баннера редактируются в админке (`CalculatorSettings`), дефолты создаёт data-миграция (02-C1, 09-C6).
- [ ] Ошибки на фронте: 400 — сообщения под полями, 422 — «Калькулятор ще не налаштовано для цих параметрів» (и список недостающего человеческим языком — для staff/broker, для остальных без технических имён моделей), 429 — «Забагато розрахунків, спробуйте за годину», 500 и сеть — общее сообщение. Сырого JSON нет (09-Q6, 09-S5).
- [ ] Сервер при непредвиденной ошибке логирует исключение (`logger.exception`) и отдаёт `{'error': 'internal_error'}` с 500 без текста исключения (02-S1).
- [ ] `POST /calculate/` защищён отдельным scope `calculator` (ставка из `.env`, `THROTTLE_CALCULATOR_RATE`). Анонимные `Calculation` старше `ANON_CALCULATION_TTL_DAYS` удаляются ежедневной Celery-задачей, кроме тех, на которые ссылается заявка (`leads.Lead`) или `Listing` (02-S2).
- [ ] «Порахувати вартість» на странице лота передаёт в калькулятор только параметры авто (`engine_cc`, `fuel_type`, `year`, `auction` по `vehicle.source_auction`) и `listing` (id). Розничная цена лота в поле цены аукциона не подставляется, поле пустое с подсказкой (09-Q3). `listing` из query передаётся в форму заявки (2.3).
- [ ] Удалён мёртвый `ActiveRatesSerializer` (02-Q8).

## Шаги
1. **Миграция данных тарифов** (причина: системе нужно знать, какие ставки владелец подтвердил, чтобы демо-пометки исчезали сами, бриф §2):
   - `is_verified = BooleanField(default=False, verbose_name='Перевірено власником')` в `DateRangeModel` (одна миграция на все модели) и в `CustomsCalcRule` из 2.5 (наследуется).
   - `ExchangeRate.source`: module-level `RateSource(TextChoices)`: `nbu`, `manual`, `demo`; default `manual`. Сид пишет `demo`, `pricing/nbu.py` — `nbu`.
   - Снять `choices` с `OceanFreightRate.eu_port` и `EuToUaDeliveryRate.eu_port` (изменяются только choices, схема та же). Существующие значения сохраняются.
2. **`CalculatorSettings`** (singleton `pk=1`): `result_warning` (текущий текст `warning` из `pricing/views.py:344-348` без жёсткой даты), `demo_banner_title`, `demo_banner_text`. Data-миграция создаёт запись с текущими текстами.
3. **`/rates/` по Q11.** В `ActiveRatesView`:
   - `build_form_options(catalog, today)` — чистая функция (в `pricing/calculator.py` рядом с `select_rates` из 2.5): уникальные значения из активных тарифов. Метки: `value` и `label` (для портов `label` = значение с заглавной буквы. Отдельную модель подписей не заводить, это желательное улучшение на потом).
   - Ответ всем: `{'options': {...}, 'is_demo': bool}`. Если пользователь staff или broker (permission из 1.2) — плюс ключи полной сетки в текущем формате.
   - Схема `extend_schema` с обоими вариантами.
4. **`CalculateView`:**
   - `throttle_classes = [ScopedRateThrottle]`, `throttle_scope = 'calculator'`, `'calculator': os.environ.get('THROTTLE_CALCULATOR_RATE', '30/hour')` в settings.
   - Непредвиденная ошибка: `logger.exception('calculate failed')`, ответ `{'error': 'internal_error'}` 500. Тело запроса в лог не писать.
   - 422: оставить `missing` для staff/broker. Остальным `{'error': 'not_configured', 'missing_count': N}` без имён моделей.
   - В ответ добавить `is_demo` и `applied_rates` (`duty_rate`, `vat_rate`, `pension_fund_rate`, `excise_eur_per_100cc` или `ev_excise_eur_per_kwh`), `warning` из `CalculatorSettings`. `is_demo` кладётся и в `rates_snapshot`.
   - `eu_port` в сериализаторе — `CharField`. Проверка «есть такой активный маршрут» идёт через `select_rates` (422, если нет).
5. **Очистка (02-S2).** `pricing/tasks.py: purge_anonymous_calculations()`: `Calculation.objects.filter(user__isnull=True, created_at__lt=now - TTL).exclude(leads__isnull=False).exclude(listing__isnull=False).delete()` (related_name проверить по факту). `ANON_CALCULATION_TTL_DAYS` из `.env` (по умолчанию 30). Задача в `CELERY_BEAT_SCHEDULE`. Заявка хранит свою копию снимка (2.1), поэтому исключение — страховка.

7. **Фронт, справочники.** `pricingApi.options()` → `GET /api/v1/pricing/rates/`. `page.tsx`: начальные значения — первые пункты из `options` или значения из query. Селект порта ЕС фильтруется по выбранному порту США (если маршрута нет, опция недоступна). Поле батареи — по `requires_battery` (из 2.5 перенести условие на данные).
