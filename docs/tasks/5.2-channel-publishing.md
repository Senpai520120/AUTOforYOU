# Задача 5.2: Публикация в канал: только одобренное, без B2B-утечки, message_id

## Контекст
Автопост импортных лотов (`listings.Listing`) в Telegram-канал сделан сигналом и Celery-задачей.

- **07-S1 (критично):** сигнал `on_listing_created` (`telegram_bot/signals.py:5-13`) публикует **любой** созданный `Listing` с `channel='retail'` или `is_express_buyout=True`. Создать `Listing` через `POST /api/v1/listings/create/` может любой авторизованный (`listings/views.py:84-86`, 04-S1), и пост уходит в официальный канал без модерации и решения админа. Закрытие самого эндпоинта — задача 2.8 (04-S1). Эта задача делает так, чтобы в канал попадало только то, что явно разрешено админом/брокером, даже если `Listing` появился.
- **07-S2 (важно):** выбор канала в `telegram_bot/tasks.py:45-49`: для `is_express_buyout` берётся `TELEGRAM_B2B_CHANNEL_ID or TELEGRAM_CHANNEL_ID`. Если B2B-канал не задан, wholesale-лоты со срочным выкупом (на сайте их видят только верифицированные дилеры, `listings/views.py:76-77,97-99`) уходят в публичный канал. Утечка B2B-цен.
- **07-Q4 (важно):** `message_id` поста нигде не сохраняется (`tasks.py:79-98` результат `send_photo`/`send_message` выбрасывается). Сигнал реагирует только на `created` (`signals.py:7-8`). Поэтому пост нельзя удалить или пометить «продано», обновить цену, защититься от дублей, опубликовать повторно.
- **07-Q5 (важно):** `post_listing_to_channel.delay()` вызывается прямо в `post_save` (`signals.py:13`) без `transaction.on_commit`. С реальным воркером задача может стартовать до коммита и получить «listing not found». При `DEBUG=True` или без Redis задачи eager (`core/settings.py:358-365`): создание листинга ждёт сетевой запрос в Telegram и `time.sleep(3)` (`tasks.py:115`).

Связанные «желательные» находки в тех же местах, закрываются здесь же:
- 07-Q7: `self.retry()` при `TelegramRetryAfter` (`tasks.py:99-100`) бросает `Retry`, которое ловит внешний `except Exception` (`tasks.py:108-112`); `autoretry_for=(OSError, ConnectionError)` почти не срабатывает.
- 07-Q8: N+1 `v.images.filter(is_primary=True).first()` (`tasks.py:64`), фото только из `source_url`, загруженные `VehicleImage.image` (`vehicles/models.py:42`) в канал не попадают.
- 07-Q10: ошибка `send_photo` глушится `except Exception: pass` без лога (`tasks.py:90-91`).
- 07-Q14: массовый импорт (`integrations/importer.py:62` — `Listing.objects.get_or_create`, retail `in_transit`) публикует каждый лот с паузой 3 с, воркер блокируется, канал заваливается.
- 07-C7: пауза и параметры повторов захардкожены (`tasks.py:10,16`).
- 07-C8: правила «что публиковать» зашиты в сигнал (`signals.py:9-11`).
- 07-C6 (часть): дефолт `SITE_URL='https://autoforyou.ua'` продублирован в `tasks.py:56` (и `handlers.py:87`). Здесь убрать дубли в `telegram_bot/`; проверка `SITE_URL` в проде — задача 7.2.

Экранирование HTML в тексте поста (07-S3) уже сделано в 5.1 (`telegram_bot/formatting.py`) — использовать его. C2C-объявления в канал — задача 5.3, она переиспользует модель и сервис из этой задачи. Заявки брокеру в Telegram — задача 2.2 (07-Q2), здесь не делаются.

## Цель
- [ ] Новый `Listing` сам по себе в канал не публикуется. Публикация происходит только:
  - по действию в админке «Опублікувати в Telegram-канал» (для staff/broker);
  - автоматически при создании, **только** если включён флаг в админке (`autopost_listings`, по умолчанию выключен) и лот создан не импортом (импорт помечает создание так, чтобы автопост его пропускал; 07-Q14).
- [ ] Wholesale и `is_express_buyout` публикуются **только** в `TELEGRAM_B2B_CHANNEL_ID`. Если он пуст — пост не отправляется, запись получает статус «пропущено: B2B-канал не задан». В публичный канал такие лоты не попадают никогда. Wholesale без срочного выкупа не публикуется вовсе (как сейчас).
- [ ] Каждая публикация хранится в новой модели `ChannelPost`: объект, `chat_id`, `message_id`, статус (`queued`, `posted`, `skipped`, `failed`, `deleted`), причина, время. Повторная постановка того же объекта в тот же канал при статусе `posted`/`queued` ничего не отправляет (защита от дублей, уникальность на уровне БД).
- [ ] При смене статуса `Listing` на `sold` пост помечается «ПРОДАНО» (редактирование подписи/текста) или удаляется — выбирается флагом в админке (`on_sold`: `mark`/`delete`, по умолчанию `mark`). При удалении `Listing` пост удаляется из канала (задача получает `chat_id`/`message_id` заранее, до удаления строки).
- [ ] При изменении цены опубликованного лота текст поста обновляется (`edit_message_text`/`edit_message_caption`).
- [ ] В админке у `Listing` видно состояние публикации; есть действия «Опублікувати», «Опублікувати повторно» (удаляет старый пост и создаёт новый), «Видалити з каналу». Список `ChannelPost` в админке только для чтения.
- [ ] Все постановки задач — через `transaction.on_commit`. `time.sleep` из задачи убран; ограничение скорости — `rate_limit` Celery из settings (`TELEGRAM_CHANNEL_RATE_LIMIT`, по умолчанию `'20/m'`).
- [ ] `TelegramRetryAfter` приводит к настоящему повтору задачи (`Retry` не перехватывается общим `except`). Сетевые ошибки повторяются по `autoretry_for` с ограничением, после исчерпания — статус `failed` с причиной. Ошибка `send_photo` логируется, затем откат на текст.
- [ ] Фото: сначала основное фото без N+1 (использовать prefetch), `VehicleImage.image` отправляется файлом (`BufferedInputFile`) или по абсолютному URL медиа, если он публичный; иначе `source_url`; иначе текстовый пост.
- [ ] Без токена или без канала сайт работает, создание/сохранение `Listing` не блокируется и не падает; `ChannelPost` получает `skipped` с причиной «не настроено».
- [ ] Если к моменту выполнения готова задача 3.4, отправка идёт через адаптер `TelegramProvider` (в demo-режиме пост пишется в лог/админку, `message_id` фиктивный и помечен как demo). Если 3.4 ещё не сделана — все вызовы Bot API собраны в одном модуле `telegram_bot/channel.py`, чтобы 3.4 заменила его одним местом.

## Шаги
1. Проверить, что 2.8 сделана: `POST /api/v1/listings/create/` недоступен обычному пользователю. Если нет — остановиться и сообщить.
2. Модели `ChannelPost`, `ChannelPublishingSettings` + миграция. `TextChoices` статусов — на уровне модуля (ловушка проекта). Singleton: `get_solo()`-подобный метод, запрет второй записи в админке.
3. `telegram_bot/channel.py`:
   - `pick_channel(listing)`: retail без срочного выкупа → `TELEGRAM_CHANNEL_ID`; `is_express_buyout` или wholesale → только `TELEGRAM_B2B_CHANNEL_ID`, иначе `None` с причиной `'no_b2b_channel'`; wholesale без срочного выкупа → `None`, `'wholesale_not_published'`;
   - `request_publish(listing, *, force=False)`: `get_or_create` `ChannelPost` в статусе `queued` (если уже `posted`/`queued` и не `force` — ничего не делать), затем `transaction.on_commit(lambda: publish_to_channel.delay(post.pk))`;
   - `request_update`, `request_delete` аналогично; для удаления заранее копировать `chat_id`/`message_id` в аргументы задачи.
4. Задачи в `tasks.py`: `@shared_task(bind=True, rate_limit=settings.TELEGRAM_CHANNEL_RATE_LIMIT, autoretry_for=(TelegramNetworkError, OSError), max_retries=..., retry_backoff=True)`. `TelegramRetryAfter` → `raise self.retry(countdown=...)` вне общего `except`. После успеха сохранить `message_id`, `posted_at`, статус `posted`. Ошибки Bot API (`TelegramBadRequest`, `TelegramForbiddenError`) → `failed` с причиной, без повтора. Убрать `time.sleep` и `_CHANNEL_THROTTLE_SECONDS`.
5. Сигналы (`signals.py`):
   - `post_save` при `created`: только если `ChannelPublishingSettings.autopost_listings` и у экземпляра нет пометки импорта (атрибут `_skip_autopost`, который ставит `importer.py` перед `get_or_create`, либо `created_by_import` — выбрать вариант без новой колонки, если он достаточен);
   - `pre_save` запоминает прежние `status` и `price`; `post_save` при переходе в `sold` → `request_update` c пометкой «продано» или `request_delete` по настройке; при смене цены у `posted` → `request_update`;
   - `pre_delete` → `request_delete` с копией `chat_id`/`message_id`.
6. Админка: действия в `ListingAdmin`, колонка «Telegram» (статус последнего `ChannelPost`), `ChannelPostAdmin` read-only, админка настроек.
7. Фото: использовать prefetched `vehicle.images.all()` и выбрать основное в Python; для `image` — `BufferedInputFile(image.read(), filename)`; `source_url` — как сейчас.
8. Тесты, затем полный прогон, `makemigrations --check`, `check`.
9. Проверить в eager-режиме (`REDIS_URL=` + `DEBUG=True`): сохранение `Listing` в админке не ждёт сеть и не спит.
