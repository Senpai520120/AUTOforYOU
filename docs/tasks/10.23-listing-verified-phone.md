# Задача 10.23: Телефон в объявлении = подтверждённый номер владельца

## Контекст
Источник: `docs/audit/41_REVIEW_2026-11-11.md`, находки F1, F4. Телефон подтверждается ботом (`telegram_bot/phone_verify.py`: `CustomUser.verified_phone` + `phone_verified_at`, только собственный контакт Telegram), но `LocalListing.contact_phone` вводил клиент: `LocalListingCreateSerializer` не проверял его, `LocalListingUpdateSerializer.validate_contact_phone` (`local_listings/serializers.py:367`) проверял только формат. Можно было опубликовать чужой номер. `unlink_telegram` (сайт, `/unlink`, блокировка бота) подтверждение не сбрасывал. Показ номера идёт через `LocalListingContactView` (журнал `ContactView`, троттлинг 4.5a); публичный список и деталь телефон не отдают.

## Цель
- Создание/правка: присланный `contact_phone` игнорируется, сохраняется `verified_phone` владельца (при правке модератором - владельца объявления, не модератора).
- Нет подтверждённого номера: создание -> 403 `phone_not_verified` (право 4.10) либо 400 с подсказкой (сериализатор, страховка); уход на модерацию при правке (`rejected`/существенная правка -> `pending`) -> 400 «Підтвердіть телефон через Telegram…». Скрыть/продать без номера можно.
- Исключения прежнего поведения: роль admin/суперпользователь (засев; модератор и брокер с `is_staff` не исключены) и `PHONE_VERIFICATION_REQUIRED=false` - номер из запроса.
- Показ: безопасный вариант - показывается только подтверждённый номер владельца; если подтверждения нет (после `/unlink`), телефон скрыт (`contact_phone: null`), данные в БД не удаляются; несовпавший сохранённый номер заменяется подтверждённым. Журнал и троттлинг показа сохранены.
- `unlink_telegram` сбрасывает `verified_phone` и `phone_verified_at` (сайт, `/unlink`, блокировка бота); при гонке (`only_telegram_id` другой) - не трогает.
- Форма `/local/new`: при подтверждённом номере поле только для чтения с подсказкой, в запрос не уходит.

## Файлы
Изменить: `local_listings/serializers.py`, `local_listings/views.py` (`_reveal`), `telegram_bot/models.py` (`unlink_telegram`), `frontend/components/local/LocalListingForm.tsx`, `ROADMAP.md`, `PROGRESS.md`.
Создать: `local_listings/phone.py`, `local_listings/tests_verified_phone.py`, этот файл.
Не трогать: `cars/`, миграции (существующие объявления не меняются), `users/export.py`.

## Шаги
1. Хелперы `verified_phone`, `can_publish`, `effective_contact_phone` (`local_listings/phone.py`).
2. Сериализаторы create/update подставляют номер владельца; `update()` блокирует переход в `pending` без номера.
3. `LocalListingContactView._reveal` и кабинет владельца отдают `effective_contact_phone`.
4. `unlink_telegram` сбрасывает подтверждение.
5. Фронт: поле только для чтения при подтверждённом номере.
