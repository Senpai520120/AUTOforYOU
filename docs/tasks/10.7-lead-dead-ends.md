# Задача 10.7: Тупики перед заявкой — запасной контакт и «Спробувати ще раз»

Размер S, 1 сессия. Источник: `docs/audit/41_REVIEW_2026-11-11.md` (находки A5, G2; п.2 «Путь к заявке обрывается»). Для фронта обязателен скилл `.claude/skills/modern-web-guidance`; перед правкой Next-кода прочитать нужный раздел `frontend/node_modules/next/dist/docs/` (`frontend/AGENTS.md`).

## Контекст

**Что значит «партнёр не настроен».** Поле `SiteSettings.partner_name` пустое (`site_settings/models.py:59`, `blank=True, default=''`). Тогда `partner_consent_text` в публичном API пустой (`site_settings/serializers.py:57`, `get_partner_consent_text` ~126-128). Заодно «не настроен» = запрос `/api/v1/site-settings/` упал: `LeadForm` в `catch` тоже ставит `consentText = ''` (`frontend/components/leads/LeadForm.tsx:99-105`), то есть сбой сети выглядит как «партнёр не задан».

**Тупики сейчас (тексты служебные, без контакта и без повтора):**
1. `frontend/components/leads/LeadForm.tsx:116-117` (`partnerReady = !!consentText`, кнопка отправки заблокирована), `:299` (чекбокс `disabled`), `:304-308` — «Прийом заявок тимчасово недоступний: партнера ще не налаштовано.» Ещё один тупик — `:171` («Прийом заявок тимчасово недоступний. Спробуйте пізніше.», ответ сервера при отправке). Существующий тест: `frontend/e2e/lead.spec.ts:374-385`.
2. `frontend/app/calculator/page.tsx:248-253` (`CalculatorLoader`, `!data.options.is_configured`) — «Калькулятор ще не налаштовано. Залиште заявку — брокер порахує вартість вручну.» Текст отсылает к заявке, но формы заявки на этой странице нет. Тест: `frontend/e2e/calculator-config.spec.ts:124-129` (проверяет `data-testid="calc-not-configured"`, это поведение сохранить).
3. `frontend/app/calculator/page.tsx:236-246` — не загрузился справочник (`pricingApi.options()` → `catch → failed`): «Не вдалося завантажити калькулятор. Спробуйте пізніше.», повторить нельзя, только перезагрузка страницы.
4. `frontend/lib/calc-errors.ts:10` (`NOT_CONFIGURED`, 422 при расчёте) и `:12` (`GENERIC`, 5xx/сеть) — показываются в `calc-error` (`calculator/page.tsx:209-216`). Это ошибка расчёта, не загрузки: в объём входит только добавление запасного контакта, если он есть; кнопка повтора уже есть («Розрахувати»).
5. `frontend/components/landing/LandingCalc.tsx` (весь компонент, `calculation: LandingCalculation` обязателен) — тупика нет: лендинг публикуется только с расчётом (`landings/`, CLAUDE.md), `app/prigon/[slug]/page.tsx:74` рендерит блок безусловно. В объём не входит; в задаче только проверить и зафиксировать.

**Откуда брать запасной контакт (без хардкода).** `SiteSettings` (singleton, админка «Налаштування сайту»), поля, уже отдаваемые публичным `GET /api/v1/site-settings/` (`site_settings/serializers.py:134-136`) и описанные в `frontend/lib/types.ts:544-550` (`SiteSettings`):
- `phone` (`site_settings/models.py:45`) — телефон, ссылка `tel:`;
- `manager_contact` (`:52`, свободный текст до 255, сейчас используется на `frontend/app/me/shipments/page.tsx:31`);
- `support_email` (`:40`) — `mailto:`;
- `telegram_channel_url` (`:56`, https://t.me/…, проверяется в `components/layout/Footer.tsx:12`) и `telegram_bot_username` (`serializers.py:33,93`, ссылка `https://t.me/<bot>`, как в `Footer.tsx:13`).
Порядок показа: телефон, `manager_contact`, email, Telegram-бот/канал; показывать только непустые. Контакты в футере уже читаются серверно (`Footer.tsx:9-14`, `getSiteConfig`), для клиентских компонентов — тот же `apiGet<SiteSettings>('/api/v1/site-settings/')`, что в `LeadForm.tsx:101`. Все эти поля уже публичны, новых утечек нет; новых полей и миграций не нужно.

**Если контакта нет вообще** (все перечисленные поля пустые, либо сам запрос настроек упал): показать честный текст без контакта — «Зараз ми не можемо прийняти заявку онлайн. Спробуйте ще раз трохи пізніше.» — и кнопку «Спробувати ще раз»; без выдуманных номеров и без обещаний «зателефонуємо». Это пункт LAUNCH_CHECKLIST (см. ниже), `launch_check` уже требует `phone` (ошибка).

**`launch_check`.** Management-команда `core/management/commands/launch_check.py`, логика в `core/launch.py`: `run_checks` (~447-454) вызывает `check_site_settings` (`core/launch.py:265-294`). Проверка партнёра **уже есть**: `core/launch.py:282-285` — `Finding(ERROR, 'назва партнера не заповнена: чекбокс згоди на передачу контактів неактивний')`, иначе `OK 'Назва партнера задана'`; пустой `phone`/`support_email`/`privacy_email` — тоже ERROR (`:272-279`). Тесты есть: `core/tests_launch_check.py:368` (`test_empty_partner_name_is_error_with_exact_text`), `:385` (`test_filled_settings_give_no_site_settings_errors`), фикстура с `partner_name='Партнер Тест'` — `:70`. Значит часть roadmap «launch_check — ошибка, если партнёр не задан» выполнена; в этой задаче — только проверить (мутацией) и при необходимости дописать текст ошибки: указать, что без партнёра посетитель видит запасной контакт вместо формы. Отсутствие всех контактов отдельно не проверять: `phone` уже обязателен.

## Цель

1. Общий клиентский компонент `FallbackContact` (рядом с `components/ui/ErrorState.tsx`, который уже содержит кнопку «Спробувати ще раз», `ErrorState.tsx:19`): принимает `SiteSettings | null`, выводит доступные контакты ссылками (`tel:`, `mailto:`, `https://t.me/…`), `data-testid="fallback-contact"`; без контактов — честный текст без контакта (см. выше), `data-testid="fallback-no-contact"`.
2. `LeadForm`: если `partner_name` пуст или настройки не загрузились, вместо служебной фразы (`:304-308`) — заголовок «Заявки онлайн тимчасово недоступні», `FallbackContact` и кнопка «Спробувати ще раз» (повторный `apiGet` настроек; при успехе с непустым `partner_consent_text` форма становится рабочей без перезагрузки). Различать «настройки не загрузились» (повтор имеет смысл) и «партнёр пуст на сервере» (кнопка всё равно есть — владелец мог только что заполнить).
3. Страница калькулятора: «не сконфигурирован» (`:248-253`) и «не загрузился» (`:244-245`) — оба состояния показывают `FallbackContact`; для «не загрузился» — кнопка «Спробувати ще раз» (повторяет `pricingApi.options()`, при успехе показывается форма). Для «не сконфигурирован» кнопка тоже (конфигурацию могли исправить), текст `Калькулятор ще не налаштовано` и `data-testid="calc-not-configured"` сохранить. Текст «Залиште заявку — брокер порахує…» заменить на тот, что не ссылается на несуществующую форму.
4. В `calculator/page.tsx` не показывать запасной контакт при обычных ошибках валидации расчёта (400/429) — только при 422 «не налаштовано» и сетевых/5xx сбоях, и то как дополнение под текстом ошибки.
5. Сброс состояния и повтор без полной перезагрузки: во время повтора кнопка `disabled`, виден `Spinner`/`aria-busy`; повторные клики не создают параллельных запросов.
6. Нигде нет хардкода номеров/адресов — всё из `SiteSettings`.
