# Задача 7.2: Прод-настройки Django: DEBUG, SECRET_KEY, STORAGES, логи без ПДн

## Контекст
- **01-S10 (важно):** если в `.env` стоит `DEBUG=true`, в проде отключаются все `SECURE_*` (ветка `if not DEBUG and not _TESTING`, `core/settings.py:420`), а при пустом `SECRET_KEY` используется известный из публичного репозитория ключ `django-insecure-...` (`core/settings.py:22-33`, сам ключ на строке 27). Backend берёт `DEBUG` из `.env` (`docker-compose.yml:36`, `env_file: .env`). Ни одной проверки «DEBUG=true на внешнем хосте» нет. `deploy.sh:47-50` отсекает `DEBUG=true`, но только при запуске через него, и сейчас он сломан (12-Q1).
  - Уточнение: `DEBUG=true` также переводит Celery в eager-режим (`core/settings.py`, блок Celery, условие `if _REDIS_URL and not DEBUG`), а `ALLOWED_HOSTS` при пустой переменной становится `['localhost', '127.0.0.1', '0.0.0.0']` (`core/settings.py:40-41`).
- **01-C1 (важно):** S3 настроен удалёнными в Django 5.1 настройками `DEFAULT_FILE_STORAGE`/`STATICFILES_STORAGE` (`core/settings.py:175-176`). Проект на Django 6.0.6 (`requirements.txt:2`), эти настройки игнорируются. При `USE_S3` файлы пойдут в локальное хранилище, а `MEDIA_ROOT` в этой ветке не задан (он задаётся только в `else`, `core/settings.py:193`). `MEDIA_URL` при этом указывает на S3 (`core/settings.py:190`), ссылки битые. Запуском не проверено, но по документации Django 5.1+ это так.
- **12-S8 (важно):** логи с ПДн и без ротации. Gunicorn пишет access-лог с полным URL и query-строкой (`docker/entrypoint.sh:32`, формат по умолчанию). nginx пишет лог в формате по умолчанию (в `nginx/nginx.conf` нет `log_format`). В Django нет `LOGGING`. В compose нет `logging:`, json-file растёт без ограничений. В query-строке бывают email, телефон, токены (ссылки подтверждения и сброса пароля из 1.6 и 1.7, `?q=` поиска).

Связанные «желательные» находки тех же мест, закрываются здесь же:
- 01-C8: insecure `SECRET_KEY` в репозитории как dev-фолбэк (`core/settings.py:27`).
- 01-S14: `LOGGING` отсутствует, нет фильтра ПДн (`core/settings.py`).
- 03-S4, 07-S9: `telegram_id` вместе с `user pk` в info-логе (`integrations/tasks.py:103`).
- 12-C5: дефолты `https://autoforyou.ua` для `SITE_URL` (`core/settings.py:414`) и `noreply@autoforyou.ua` для `DEFAULT_FROM_EMAIL` (`core/settings.py:344`, `.env.example:62`).
- 12-C6: `MEDIA_URL` для S3 собирается по шаблону `*.s3.<region>.amazonaws.com` даже при `S3_ENDPOINT_URL` (R2) (`core/settings.py:187-191`).
- 23-D106, 23-D107, 23-D108 из `docs/audit/23_TESTS.md` (этап 7).

Вне задачи: HSTS, SSL-редирект и CSP (7.1); мониторинг ошибок (7.6, но фильтр ПДн из этой задачи он переиспользует); healthchecks и параметры gunicorn, кроме формата access-лога (7.3).

## Цель
- [ ] В репозитории нет ни одного фиксированного `SECRET_KEY`. При `DEBUG=true` и пустом `SECRET_KEY` ключ генерируется один раз и сохраняется в `BASE_DIR/.dev_secret_key` (файл в `.gitignore` и `.dockerignore`), так что сессии переживают перезапуск `runserver`. В тестах ключ случайный на прогон. При `DEBUG=false` пустой ключ по-прежнему даёт `ImproperlyConfigured`.
- [ ] `DEBUG=true` вместе с `ALLOWED_HOSTS`, в котором есть хост кроме `localhost`, `127.0.0.1`, `0.0.0.0`, `backend`, `testserver`, даёт `ImproperlyConfigured` с понятным текстом при старте. Обойти можно только явным `ALLOW_DEBUG_ON_PUBLIC_HOST=true` (для отладки стенда осознанно).
- [ ] При `DEBUG=false` `SECRET_KEY` короче 50 символов, содержащий `REPLACE`, `local-docker-dev` или `django-insecure` → `ImproperlyConfigured` (та же логика, что в `deploy.sh:23-33`, но в самом Django, поэтому работает при любом способе запуска).
- [ ] Хранилища задаются словарём `STORAGES`. `MEDIA_ROOT` задан всегда. При `USE_S3` `default` — `storages.backends.s3boto3.S3Boto3Storage`, `staticfiles` остаётся локальным (`StaticFilesStorage` с `STATIC_ROOT`: статику раздаёт nginx из volume). Без S3 оба локальные, поведение dev не меняется.
- [ ] `MEDIA_URL` при S3 берётся из `S3_CUSTOM_DOMAIN` (или `AWS_S3_CUSTOM_DOMAIN`), если задан. Иначе, при заданном `S3_ENDPOINT_URL`, для приватного bucket'а используются подписанные URL от storage (не шаблон amazonaws). Шаблон `*.s3.<region>.amazonaws.com` остаётся только для AWS без endpoint (12-C6).
- [ ] `default_storage` при S3-переменных на самом деле `S3Boto3Storage` (проверяется тестом, без сети).
- [ ] В `settings.py` есть `LOGGING`: вывод в stdout, уровень из `LOG_LEVEL` (по умолчанию `INFO`), формат с временем, уровнем, логгером. На все handler'ы навешан фильтр `core.logging_filters.PiiScrubFilter`: маскирует email, украинские и международные телефоны, значения `token`, `key`, `signature`, `password`, `secret`, `code` в query-строках и JSON, заголовки `Authorization` и `Cookie`.
- [ ] Логгер `django.request` (ошибки 500) пишет путь без query-строки и без тела запроса, ПДн в лог не попадают.
- [ ] Gunicorn пишет access-лог без query-строки: `--access-logformat` с `%(U)s` (путь без query) вместо `%(r)s`. IP в access-логах gunicorn не пишется (IP клиента знает nginx).
- [ ] nginx пишет access-лог в своём `log_format` без `$args` и `$request_uri` (только `$uri`), IP анонимизирован (последний октет IPv4 обнулён через `map`). Если к моменту выполнения 7.1 уже перевела nginx на шаблон, формат добавляется в шаблон.
- [ ] Все сервисы compose ограничивают логи: общий блок `x-logging: &default-logging {driver: json-file, options: {max-size: "10m", max-file: "5"}}`, значения из `.env` (`LOG_MAX_SIZE`, `LOG_MAX_FILES`).
- [ ] `integrations/tasks.py:103` логирует только `user pk` и результат, без `telegram_id` (03-S4, 07-S9).
- [ ] `SITE_URL` и `DEFAULT_FROM_EMAIL` без дефолта `autoforyou.ua`: по умолчанию `http://localhost` и `noreply@localhost`. При `DEBUG=false` и `SITE_URL`, указывающем на localhost, при старте пишется предупреждение (не ошибка: CI и e2e работают на localhost). Если задача 6.4 уже вынесла контакты в настройки, согласовать с ней.
- [ ] `flushexpiredtokens` (очистка истёкших refresh-токенов SimpleJWT) стоит в `CELERY_BEAT_SCHEDULE` раз в сутки, если задачи 1.3/1.7 этого не сделали (23-D108).
- [ ] `manage.py check --deploy` на прод-переменных (`DEBUG=false`, реальный по длине `SECRET_KEY`, `ALLOWED_HOSTS=example.com`, `TLS_MODE=letsencrypt`) проходит без предупреждений (23-D106, вместе с 7.1).

## Шаги
1. `SECRET_KEY`: удалить фиксированный ключ. В ветке `DEBUG` читать или создавать `.dev_secret_key` через `get_random_secret_key()`. Если директория только для чтения (контейнер), генерировать ключ в памяти с предупреждением в лог. В тестах (`_testing`) ключ случайный. Для `DEBUG=false` добавить проверку длины и маркеров-заглушек.
2. Проверка DEBUG: после вычисления `ALLOWED_HOSTS` при `DEBUG=true` сравнить хосты с безопасным списком. Сообщение об ошибке на русском, с подсказкой «поставьте DEBUG=false в .env».
3. Хранилища: перенести блок `core/settings.py:161-196` в `build_storage_settings()`. `settings.py` делает `globals().update(build_storage_settings(os.environ, BASE_DIR))`. Сохранить `AWS_DEFAULT_ACL='private'` и `AWS_QUERYSTRING_AUTH=True`. Если `MEDIA_URL` для приватного bucket'а по сути не нужен (URL даёт `storage.url()`), оставить его пустым путём-префиксом и проверить, что сериализаторы используют `.url`, а не `MEDIA_URL + name` (grep `MEDIA_URL` по проекту; если где-то склеивается вручную, отметить в отчёте, не чинить вне задачи).
4. Проверить S3 вручную, если есть возможность: MinIO в отдельном compose-профиле или локальный контейнер `minio/minio`, загрузка фото объявления, открытие по URL. Если проверить нельзя, так и написать в PROGRESS.md.
5. `LOGGING` и `PiiScrubFilter`. Регулярные выражения для email, телефонов (`+380...`, `0XX...`, международные `+\d{10,15}`), `(?i)(token|key|signature|password|secret|code)=[^&\s]+`, `Bearer \S+`. Фильтр меняет `record.msg` и `record.args` (отформатировать и заменить), а не выбрасывает запись. `django.request`: свой форматтер или фильтр, который обрезает query у `request.get_full_path()`.
6. Gunicorn `--access-logformat '%(t)s "%(m)s %(U)s %(H)s" %(s)s %(b)s %(L)s'`. nginx `log_format main_anon '$remote_addr_anon - [$time_local] "$request_method $uri $server_protocol" $status $body_bytes_sent $request_time'` и `map $remote_addr $remote_addr_anon`.
7. Compose: `x-logging` в начале файла, `logging: *default-logging` для db, redis, backend, frontend, bot, celery_worker, celery_beat, nginx (и новых сервисов других задач этапа 7, если они уже есть).
8. `integrations/tasks.py:103` → `logger.info('send_notification: user pk=%s → sent=%s', user_id, sent)`.
9. `SITE_URL`/`DEFAULT_FROM_EMAIL`: убрать `autoforyou.ua` из дефолтов и из `.env.example:62` (там `noreply@yourdomain.com`).
10. `flushexpiredtokens`: проверить `CELERY_BEAT_SCHEDULE`. Если записи нет, добавить задачу-обёртку (`users/tasks.py` с `call_command('flushexpiredtokens')`) и запись в расписание.
11. Обновить шаблоны `.env*`, `docs/LAUNCH_CHECKLIST.md`, `ROADMAP.md`, `PROGRESS.md`.

## Тесты
Django (`core/tests/test_prod_settings.py`). Настройки читаются при импорте, поэтому проверки делаются через чистые функции или через `subprocess` с `python -c "import django; django.setup()"` и нужным env:
- `SECRET_KEY` пустой, `DEBUG=false` → процесс завершается с `ImproperlyConfigured` (subprocess, код ≠ 0, в stderr «SECRET_KEY»).
- `SECRET_KEY=local-docker-dev-secret-key-REPLACE...`, `DEBUG=false` → `ImproperlyConfigured`.
- `DEBUG=true`, `ALLOWED_HOSTS=example.com` → `ImproperlyConfigured`; с `ALLOW_DEBUG_ON_PUBLIC_HOST=true` → старт успешен.
- `DEBUG=true`, `ALLOWED_HOSTS=localhost` и пустой `SECRET_KEY` → старт успешен, ключ не равен строке из старого фолбэка, при повторном запуске тот же (файл во временной директории через `BASE_DIR`-переопределение или env `DEV_SECRET_KEY_FILE`).
- `grep`-тест: в `core/settings.py` нет подстроки `django-insecure-` (защита от возврата фолбэка).
- `build_storage_settings({})` → `STORAGES['default']['BACKEND'] == 'django.core.files.storage.FileSystemStorage'`, `MEDIA_ROOT` задан.
- `build_storage_settings` с `S3_BUCKET_NAME`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` → `STORAGES['default']['BACKEND']` — `S3Boto3Storage`, `staticfiles` локальный, `MEDIA_ROOT` задан; нет ключей `DEFAULT_FILE_STORAGE`/`STATICFILES_STORAGE` (01-C1).
- С `S3_ENDPOINT_URL=https://acc.r2.cloudflarestorage.com` и без `S3_CUSTOM_DOMAIN` → `MEDIA_URL` не содержит `amazonaws.com` (12-C6); с `S3_CUSTOM_DOMAIN=cdn.example.com` → `MEDIA_URL == 'https://cdn.example.com/'`.
- `override_settings(STORAGES=...S3...)` + `storages.reset` → `default_storage` — экземпляр `S3Boto3Storage` (без сетевых вызовов).
- 23-D107: `PiiScrubFilter` на записи `'user test@example.com phone +380501234567 /reset?token=abc'` → в выводе нет `test@example.com`, `+380501234567`, `abc`. `assertLogs('django.request', 'ERROR')` на view, которая бросает исключение, при запросе `/api/.../?email=a@b.c` → в тексте лога нет `a@b.c`.
- `send_notification` (с моком бота): `assertLogs('integrations.tasks', 'INFO')` не содержит `telegram_id` и само значение id.
- 23-D108: `'flushexpiredtokens'` встречается в задаче из `CELERY_BEAT_SCHEDULE`, задача вызывает `call_command('flushexpiredtokens')` (мок).
- 23-D106: `call_command('check', '--deploy')` на прод-наборе настроек (результаты `build_security_settings` из 7.1 и `build_storage_settings`, `DEBUG=False`, длинный `SECRET_KEY`) → нет предупреждений `security.W0xx`. Если 7.1 ещё не сделана, тест помечается `skipUnless` с причиной и включается в 7.1.

Shell/CI: `docker compose config --quiet`; у всех сервисов в выводе `docker compose config` есть `logging`.

Playwright: нет UI, только Django-тесты. Общий e2e-набор должен остаться зелёным (стек в CI с `DEBUG=false`).
