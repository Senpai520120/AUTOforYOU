> **После сверки с бизнес-планом:** в ВОЛНЕ-1 делаются только GA4 (по согласию) и Cloudflare Web Analytics (без cookies, в CSP). Пиксели Meta и TikTok — **Рост** (строка 9.29). Шаги, файлы и тесты про пиксели ниже не выполнять; при расхождении главнее раздел «Изменения после бизнес-плана».

> Источник: Н-38a (`docs/audit/38_PARITY_O_P.md`, O3.1–O3.4, P5.3; `docs/audit/32_NEW_TASKS_INDEX.md`). Решения владельца (ANSWERS, шаг 8): GA4 — адаптер, Запуск, включается только после согласия на cookie, ID в `.env`; пиксели Meta и TikTok — адаптеры готовы к запуску, по умолчанию выключены (ID позже); Plausible не нужен. Волна: [ВОЛНА-1]. Оценка: 1 сессия (если не влезает, пиксели выделяются в 3.5b). Проверка security-reviewer: **обязательна** (третьи лица, согласие).

## Контекст
- Гейт согласия есть, но им ничто не пользуется: `hasAnalyticsConsent()` (`frontend/lib/consent.ts:64-66`) возвращает `true` только при выборе «Прийняти всі»; подписка `subscribeConsent` (`:69-77`). В комментарии `:8` прямо сказано, что аналитики нет. Версию и JSON-формат согласия вводит 1.14, сигнатуры `getConsent()` и `hasAnalyticsConsent()` сохраняются.
- Баннер говорит, что аналитика «зараз не використовується» (`frontend/components/ui/CookieBanner.tsx:30-31`): после этой задачи формулировка станет неверной, текст надо обновить. Страница `/cookies` (`frontend/app/cookies/page.tsx`) перечисляет только необходимое хранилище.
- Все `NEXT_PUBLIC_*` вшиваются при сборке (в `.env`/compose есть только `NEXT_PUBLIC_API_URL`, `NEXT_PUBLIC_SITE_URL`, `NEXT_PUBLIC_IMAGE_HOSTS`, `NEXT_PUBLIC_DEMO_MODE`), поэтому смена ID счётчика потребовала бы пересборки. Решение (находка 3 в `38_PARITY_O_P.md`): ID отдаёт бэкенд из `.env` через публичный `GET /api/v1/site-settings/` (1.12; тот же приём, что у `/auth/config/` в 1.6).
- Корневой layout: `frontend/app/layout.tsx:31-46` (`AuthProvider`, `Header`, `Footer`, `CookieBanner`); точки событий: заявка (`LeadForm`, 2.3), регистрация (`frontend/app/register/page.tsx`), расчёт (`frontend/app/calculator/page.tsx`), показ телефона (`frontend/app/local/[id]/LocalListingDetail.tsx:52-61`).
- Реестр статусов интеграций: 3.1 сделала реестр расширяемым (адаптер регистрирует себя сам, `integrations/registry.py`); аналитика и пиксели должны быть там видны (P5.3). CSP вводит 7.1 (`CSP_*` переменные, `docs/tasks/7.1-https-headers.md`).
- Собственные дневные счётчики без ПДн и без согласия — отдельная задача 8.7, здесь не делаются.

## Цель
- [ ] Бэкенд: `.env` `GA4_MEASUREMENT_ID`, `META_PIXEL_ID`, `TIKTOK_PIXEL_ID` (все по умолчанию пусты). Публичный ответ `GET /api/v1/site-settings/` дополнен объектом `analytics` с только непустыми ID (секретов нет; ID счётчиков публичны по природе). Пустой ID = провайдер выключен.
- [ ] В статусе интеграций (3.1) три строки: `ga4`, `meta_pixel`, `tiktok_pixel` со статусом «не налаштовано» / «налаштовано (вмикається лише після згоди)». Значения ID в статусе не показываются целиком (маскируются).
- [ ] Фронт: интерфейс `AnalyticsProvider` (`load()`, `unload()`, `track(event, params)`), три реализации (GA4, Meta Pixel, TikTok Pixel) и общий загрузчик `AnalyticsLoader`, подключённый в `layout.tsx`. Скрипты грузятся (`next/script`, `afterInteractive`) **только** когда `hasAnalyticsConsent()` истинно и у провайдера есть ID. До согласия не создаётся ни `<script>`, ни сетевого запроса к доменам провайдеров.
- [ ] Отзыв согласия (кнопка «Відкликати згоду», `clearConsent()`) или переключение на «Лише необхідні»: загрузчик убирает скрипты, отключает отправку (`window['ga-disable-<ID>']=true`, отзыв согласия у пикселей по документации провайдеров), удаляет их cookie (`_ga*`, `_fbp`, `_ttp` и аналогичные) и перестаёт отправлять события.
- [ ] События через единый `trackEvent(name, params)`: `calculator_calculate` (расчёт), `lead_submit` (заявка; GA4 `generate_lead`, Meta `Lead`, TikTok `SubmitForm`), `sign_up` (регистрация), `phone_reveal` (показ телефона), `listing_submit` (подача объявления). В параметрах только категории (`source: calculator|listing`), **никаких** имён, телефонов, email, id заявок и текстов.
- [ ] Страница `/cookies` и текст баннера обновлены: перечислены категории «аналітичні» (GA4) и «рекламні» (Meta, TikTok), вставляются в список только провайдеры с заданным ID; формулировка «зараз не використовуються» убрана.
- [ ] Если провайдер недоступен (скрипт заблокирован блокировщиком, сеть) — сайт работает, ошибок в консоли от нашего кода нет.
- [ ] CSP (7.1): домены провайдеров добавляются в разрешённые источники скриптов и соединений **только при заданных ID**, значения — из настроек, а не жёсткий список в коде.

## Шаги
1. Бэкенд: переменные, объект `analytics` в публичных настройках, три строки реестра (если реестр 3.1 ещё не расширяемый, добавить регистрацию в `registry.py` по образцу капчи 1.6).
2. `AnalyticsProvider` и реализации. Не вставлять сторонние скрипты через `dangerouslySetInnerHTML` с подстановкой неэкранированного ID: ID проходит проверку по шаблону (`G-…`, цифры) перед вставкой, иначе провайдер считается выключенным.
3. `AnalyticsLoader` (client): читает `analytics` из пропсов (layout берёт `getSiteSettings()` из 1.12), подписывается на `subscribeConsent`, грузит или выгружает провайдеров по `hasAnalyticsConsent()`. Страницы не должны пререндериться с пустыми данными (`force-dynamic`, ловушка из 1.12). Прочитать актуальные руководства Next по `next/script` в `frontend/node_modules/next/dist/docs/` (`frontend/AGENTS.md`).
4. События: единственный вызов `trackEvent(...)` в каждой точке, после успешного ответа сервера; без согласия `trackEvent` ничего не делает и не копит очередь.
5. Тексты баннера и `/cookies` (украинский), список провайдеров строится из публичного объекта `analytics`.
6. CSP: переменные доменов по именам из 7.1; тест на то, что при пустых ID дополнительных доменов в политике нет.
7. LAUNCH_CHECKLIST: раздел «Аналітика та пікселі».

## Тесты
Django:
- `GET /api/v1/site-settings/` при пустых переменных → `analytics` пуст; при `GA4_MEASUREMENT_ID='G-TEST'` → только `ga4_id`; других настроек и секретов в ответе нет.
- Статус интеграций показывает три строки; ID замаскирован.
- (если CSP строится из настроек) домены провайдеров появляются только при заданных ID.
Playwright (`frontend/e2e/analytics.spec.ts`; ID задаются через фикстуру или мок публичных настроек, запросы к доменам провайдеров перехватываются `page.route` и не уходят в сеть):
- Успех: до выбора в баннере и при «Лише необхідні» — ни одного запроса к доменам GA, Meta, TikTok, нет их `<script>` и нет `window.gtag`; после «Прийняти всі» скрипты запрошены, в `dataLayer` появляется событие при отправке заявки с категорией `source`, **без** телефона, имени и email.
- Успех: отзыв согласия на `/cookies` — новые события не отправляются, cookie `_ga*` удалены, `window['ga-disable-<ID>']` установлен.
- Ошибка/обход: все ID пусты и выбрано «Прийняти всі» → нет загрузки скриптов и нет ошибок в консоли; ID с недопустимым форматом (`G-"><script>`) → провайдер выключен, ничего не вставлено; скрипт провайдера заблокирован (`route.abort`) → регистрация, заявка и расчёт работают; повреждённое значение `cookie_consent` → считается «не выбрано», трекеры не стартуют.
