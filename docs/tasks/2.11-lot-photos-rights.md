# Задача 2.11: Фото лотов Copart/IAAI: атрибуция и флаг показа

## Контекст
- **09-S3** (важно, issue #11). Фото лотов аукционов показываются на сайте по `VehicleImage.source_url` (прямая ссылка на CDN Copart/IAAI):
  - в карточке каталога — `frontend/components/listings/ListingCard.tsx:22`;
  - в галерее лота — `frontend/components/listings/ListingDetail.tsx:20,52`;
  - как `og:image`/`twitter:image` — `frontend/app/listings/[id]/page.tsx:40-41,54,60`.

  Картинки идут через оптимизатор Next: он скачивает и кэширует копию на нашем сервере. Хосты `*.copart.com`, `*.iaai.com`, `*.cloudfront.net` разрешены в `frontend/next.config.ts:30-33`. Атрибуции источника нигде нет. Юридический статус не выяснен (issue #11: «Вопрос к юристу, не к коду»).
- Другие пути, по которым идут те же фото:
  - публикация в Telegram-канал берёт `img.source_url` (`telegram_bot/tasks.py:64-65`). Выбор фото для канала меняет задача 5.2 (07-Q8);
  - команда `integrations/management/commands/upload_lot_photos.py` копирует фото аукциона в наше хранилище (`VehicleImage.image`). После этого фото аукциона уже не отличить по пустому `image`: признак происхождения — непустой `source_url`;
  - импорт лота создаёт `VehicleImage(source_url=...)` (`integrations/importer.py:56`).
- Поле аукциона — `Vehicle.source_auction` (`vehicles/models.py:24`), номер лота — `lot_number` (`:25`). Сериализатор фото — `VehicleImageSerializer` (`vehicles/serializers.py:6-9`), поля `id`, `image`, `source_url`, `is_primary`.
- Желательные находки того же места (по просьбе координатора):
  - **08-C8**: хосты Copart/IAAI/CDN захардкожены в `remotePatterns` (`frontend/next.config.ts:27-33`);
  - **08-S10**: `*.cloudfront.net` и `*.amazonaws.com` разрешают оптимизатору проксировать любой чужой дистрибутив (`frontend/next.config.ts:28-33`).
- Вопрос **Q8** (`docs/QUESTIONS.md`) без ответа. Вариант по умолчанию: показывать на странице лота с подписью источника, из og:image убрать, всё за флагом в админке.

## Цель
- [ ] Режим показа фото аукционов задаётся в админке. Поле `auction_photos_mode` в модели настроек сайта из задачи 1.12 (условно `SiteSettings`; новую модель не заводить, как и в 6.4). Значения — module-level `TextChoices`:
  - `hidden` — не показывать нигде;
  - `page_only` — только на сайте с подписью (**по умолчанию**, вариант Q8);
  - `full` — на сайте, в og:image и в Telegram-канале.
  Если 1.12 ещё не сделана, до неё действует `.env` `AUCTION_PHOTOS_MODE` с тем же значением по умолчанию `page_only`. После 1.12 админка переопределяет `.env`.
- [ ] Решение принимает бэкенд, фронт его только исполняет. `VehicleImageSerializer` отдаёт:
  - `is_auction_photo` (непустой `source_url`);
  - `attribution` — например «Фото: Copart, лот 12345678» из `source_auction`/`lot_number`, у своих фото `null`;
  - `shareable` — можно ли использовать в og:image и канале.
  В режиме `hidden` фото аукциона не попадают в выдачу вообще: ни `image`, ни `source_url`.
- [ ] **09-S3**: на карточке и в галерее лота под фото аукциона видна подпись `attribution`. Если фото нет (режим `hidden`), показывается существующая заглушка.
- [ ] **09-S3**: `og:image`/`twitter:image` строятся только из фото с `shareable: true`. В `page_only` у лота только с фото аукциона og-картинки нет (или берётся нейтральная картинка сайта, если она есть в настройках).
- [ ] Фото аукциона с внешнего CDN грузятся мимо оптимизатора (`<Image unoptimized>`): наш сервер не делает и не кэширует копии. Это не нужно, если владелец выберет `full` и разрешит хранение.
- [ ] **08-C8 / 08-S10**: `remotePatterns` строится из `.env`:
  - `NEXT_PUBLIC_IMAGE_HOSTS` — список конкретных хостов через запятую для S3/R2-хранилища;
  - хосты аукционов нужны только при `unoptimized`-загрузке, поэтому их можно убрать из `remotePatterns`.
  Широких шаблонов `*.cloudfront.net`, `*.amazonaws.com` больше нет. Хост медиа бэкенда по-прежнему берётся из `NEXT_PUBLIC_API_URL`.
- [ ] Telegram-канал: фото аукциона отправляется только при `shareable: true`, иначе пост без фото. Одна функция `vehicles/photos.py::shareable_images(vehicle)` используется и сериализатором, и каналом.
- [ ] `upload_lot_photos` в режиме, отличном от `full`, отказывается копировать фото аукциона с понятным сообщением (флаг `--force` не добавлять).

## Тесты
Django (`vehicles/tests.py`, `listings/tests.py`, `telegram_bot/tests.py`):
- `page_only`: `/api/v1/listings/<id>/` → у фото аукциона `is_auction_photo: true`, `attribution` содержит «Copart» и номер лота, `shareable: false`; у своего фото (`image` без `source_url`) — `attribution: null`, `shareable: true`;
- `hidden`: в `vehicle_detail.images` нет фото с непустым `source_url`, свои фото остались; в JSON нет строки хоста `copart`;
- `full`: `shareable: true` у фото аукциона;
- число запросов каталога не выросло (существующий тест `test_listing_list_query_count` зелёный);
- канал (мок `aiogram.Bot`): в `page_only` вызывается `send_message` без фото, `send_photo` не вызывается; в `full` вызывается `send_photo` с `source_url`;
- `upload_lot_photos` в `page_only` ничего не скачивает (мок `httpx`, 0 вызовов) и пишет сообщение;
- смена режима в админке (после 1.12) сразу меняет ответ API.

Playwright (`frontend/e2e/lot-photos.spec.ts`, запускать из `frontend/`; фикстура retail-лота с фото, у которого есть `source_url`):
- успех: на `/listings` и `/listings/<id>` видна подпись «Фото: Copart…»; `<img>` фото аукциона указывает прямо на CDN, а не на `/_next/image`;
- ошибка/обход: `page.request.get('/listings/<id>')` → в HTML нет `og:image` с хостом аукциона (`page_only`); `page.request.get('/_next/image?url=https://<хост аукциона>/x.jpg&w=640&q=75')` → 400 (хост не разрешён в `remotePatterns`); `/_next/image` с произвольным `*.cloudfront.net` → 400.
