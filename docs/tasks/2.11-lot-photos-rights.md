# Задача 2.11: Фото лотов Copart/IAAI: атрибуция и флаг показа

> **[ЗАМОРОЖЕНО]** (сверка с бизнес-планом, `docs/audit/40_BUSINESS_PLAN_SYNC.md` §1.2; ANSWERS «Сверка с бизнес-планом»).
> **Причина:** каталог лотов `/listings` заморожен (2.8), фото Copart/IAAI на сайте не показываются; юридический статус фото не выяснен (issue #11).
> **Условие разморозки:** письменное подтверждение прав от аукциона или решение владельца вернуть каталог лотов с фото. Тогда: выполнить тело задачи ниже (режимы `off`/`partner`/`auction`, `PhotoPlaceholder`, `shareable_images`), поставить в ROADMAP заново.
> **Сессии:** 0 на ВОЛНЕ-1 (оценка 1 сохраняется для разморозки). На ВОЛНЕ-1 действует только режим `off` по умолчанию: `.env` `AUCTION_PHOTOS_MODE=off`, `AUCTION_PHOTOS_RIGHTS_CONFIRMED=false` (переменные и проверка в `core/settings.py` вводит 2.8 вместе с флагами).
>
> **Находки аудита, закрытые режимом `off` и флагом `LOTS_ENABLED=false` (полное исправление — при разморозке):**
> - 09-S3 (хотлинк и кэш чужих фото через оптимизатор, нет атрибуции) — лоты и их страницы закрыты 404, а при включённом по ошибке каталоге режим `off` не отдаёт фото аукционов: фронт получает пустой список изображений. Фото не показываются, `og:image` не строится, оптимизатор Next не ходит на хосты аукционов.
> - 04-C5 (хотлинк `source_url`) — тот же режим `off`; `upload_lot_photos` не используется, т.к. импорт лотов выключен (3.3).
> - 08-C8 / 08-S10 (широкие шаблоны `*.cloudfront.net`, `*.amazonaws.com` в `remotePatterns`) — **не закрыты флагом**, переносятся в 7.2 (`NEXT_PUBLIC_IMAGE_HOSTS`, R2 как основной вариант хранилища), потому что хосты нужны фото объявлений.
> - Достаточность: пока модуль выключен, ни одна страница не показывает фото аукциона; включение каталога без этой задачи запрещено (условие разморозки).
>
> Тело задачи ниже не удалено и на ВОЛНЕ-1 не выполняется (кроме переноса пункта в 7.2).

## Контекст
- **09-S3** (важно, issue #11). Фото лотов аукционов показываются на сайте по `VehicleImage.source_url` (прямая ссылка на CDN Copart/IAAI):
  - в карточке каталога — `frontend/components/listings/ListingCard.tsx:22`;
  - в галерее лота — `frontend/components/listings/ListingDetail.tsx:20,52`;
  - как `og:image`/`twitter:image` — `frontend/app/listings/[id]/page.tsx:40-41,54,60`.

  Картинки идут через оптимизатор Next: он скачивает и кэширует копию на нашем сервере. Хосты `*.copart.com`, `*.iaai.com`, `*.cloudfront.net` разрешены в `frontend/next.config.ts:30-33`. Атрибуции источника нигде нет. Юридический статус не выяснен (issue #11: «Вопрос к юристу, не к коду»).
- Другие пути, по которым идут те же фото:
  - публикация в Telegram-канал берёт `img.source_url` (`telegram_bot/tasks.py:64-65`). Выбор фото для канала меняет задача 5.2 (07-Q8);
  - команда `integrations/management/commands/upload_lot_photos.py` копирует фото аукциона в наше хранилище (`VehicleImage.image`). После этого фото аукциона уже не отличить по пустому `image`: признак происхождения — непустой `source_url`;
  - импорт лота создаёт `VehicleImage(source_url=...)` (`integrations/importer.py:56`).
- Поле аукциона — `Vehicle.source_auction` (`vehicles/models.py:24`), номер лота — `lot_number` (`:25`). Сериализатор фото — `VehicleImageSerializer` (`vehicles/serializers.py:6-9`), поля `id`, `image`, `source_url`, `is_primary`.
- Желательные находки того же места (по просьбе координатора):
  - **08-C8**: хосты Copart/IAAI/CDN захардкожены в `remotePatterns` (`frontend/next.config.ts:27-33`);
  - **08-S10**: `*.cloudfront.net` и `*.amazonaws.com` разрешают оптимизатору проксировать любой чужой дистрибутив (`frontend/next.config.ts:28-33`).
- **Q8 (решено, `docs/ANSWERS.md`):** фото Copart/IAAI по умолчанию не показывать (режим `off`). Режимы: `off` / `partner` (фото, загруженные брокером) / `auction` (включается только после письменного подтверждения прав). Для каталога без фото — аккуратная заглушка. Это заменяет прежний вариант по умолчанию (`page_only` с подписью), см. «Изменения после ANSWERS».

## Цель
- [ ] Режим показа фото задаётся в админке. Поле `auction_photos_mode` в модели настроек сайта из задачи 1.12 (условно `SiteSettings`; новую модель не заводить, как и в 6.4). Значения — module-level `TextChoices` (Q8):
  - `off` — фото лотов не показывать нигде, вместо них заглушка (**по умолчанию**; рабочий вариант, см. вопрос владельцу в конце);
  - `partner` — показывать только фото, загруженные брокером (наши файлы `image` без `source_url`), фото аукционов скрыты;
  - `auction` — дополнительно показывать фото аукционов (с подписью источника, в og:image и в канале). Режим действует только при `auction_photos_rights_confirmed=True` (булево поле рядом + поле для заметки о документе, «письменне підтвердження прав»); без отметки `auction` работает как `partner`.
  Если 1.12 ещё не сделана, до неё действуют `.env` `AUCTION_PHOTOS_MODE` (по умолчанию `off`) и `AUCTION_PHOTOS_RIGHTS_CONFIRMED` (по умолчанию `false`). После 1.12 админка переопределяет `.env`.
- [ ] **(Q8)** Для лотов и объявлений без показываемых фото везде (карточка, галерея, список, мини-карточки) выводится аккуратная заглушка: единый компонент `PhotoPlaceholder` (нейтральный фон, иконка авто, подпись «Фото ще не додано» (формулировку подтвердить), правильное соотношение сторон без прыжков вёрстки), он же — запасная og-картинка сайта (6.3/Н-12).
- [ ] Решение принимает бэкенд, фронт его только исполняет. `VehicleImageSerializer` отдаёт:
  - `is_auction_photo` (непустой `source_url`);
  - `attribution` — например «Фото: Copart, лот 12345678» из `source_auction`/`lot_number`, у своих фото `null`;
  - `shareable` — можно ли использовать в og:image и канале.
  В режимах `off` и `partner` фото аукциона не попадают в выдачу вообще: ни `image` (копия из `upload_lot_photos`), ни `source_url`.
- [ ] **09-S3**: на карточке и в галерее лота под фото аукциона (режим `auction`) видна подпись `attribution`. Если показываемых фото нет (режимы `off`/`partner` и у лота только фото аукциона), показывается заглушка `PhotoPlaceholder`.
- [ ] **09-S3**: `og:image`/`twitter:image` строятся только из фото с `shareable: true`. В `off`/`partner` у лота только с фото аукциона og-картинки лота нет, берётся нейтральная картинка сайта (заглушка/дефолтная OG, 6.3).
- [ ] Фото аукциона с внешнего CDN (только в режиме `auction`) грузятся мимо оптимизатора (`<Image unoptimized>`): наш сервер не делает и не кэширует копии. Это не нужно, если владелец получит письменное подтверждение и разрешит хранение.
- [ ] **08-C8 / 08-S10**: `remotePatterns` строится из `.env`:
  - `NEXT_PUBLIC_IMAGE_HOSTS` — список конкретных хостов через запятую для S3/R2-хранилища;
  - хосты аукционов нужны только при `unoptimized`-загрузке, поэтому их можно убрать из `remotePatterns`.
  Широких шаблонов `*.cloudfront.net`, `*.amazonaws.com` больше нет. Хост медиа бэкенда по-прежнему берётся из `NEXT_PUBLIC_API_URL`.
- [ ] Telegram-канал: фото аукциона отправляется только при `shareable: true`, иначе пост без фото. Одна функция `vehicles/photos.py::shareable_images(vehicle)` используется и сериализатором, и каналом.
- [ ] `upload_lot_photos` в режиме, отличном от `auction` (с подтверждёнными правами), отказывается копировать фото аукциона с понятным сообщением (флаг `--force` не добавлять).
