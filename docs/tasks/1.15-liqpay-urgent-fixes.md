Источник: `docs/audit/SECURITY_AUDIT_2026-10-25.md`, раздел F. Находки F1 и F2 — **критично**. Задача стоит **первой в очереди** (раньше 3.4a и всего остального). После неё **обязательна проверка `security-reviewer`** (платежи).

## Контекст
Номера строк — из аудита; перед правкой проверить Grep (код мог сдвинуться).

- **F1 (критично), `payments/liqpay_client.py:216-222, 275-285`:** при пустом `LIQPAY_PRIVATE_KEY` (дефолт, пока LiqPay не подключён) подпись = `base64(sha1(data))`. Атака: пользователь вызывает `promote` → получает `order_id` → анонимно шлёт на `/api/v1/payments/liqpay/callback/` свой `data` со `status=success` и подпись, посчитанную пустым ключом → TOP/RENEW бесплатно. `LIQPAY_MODE` нигде не применяется (3.4b заводила режим, но `decode_callback` его не проверяет).
- **F2 (критично), `payments/views.py:66-115`, `payments/models.py:377-380`:** общий checkout берёт сумму, валюту, `listing_id`, `purpose` от клиента, владелец листинга не проверяется. Атака: оплата 0.01 (sandbox или подделка из F1) → `unlock_listing()` переводит **чужой** `Listing` в `in_stock`.
- **F3 (важно), `payments/views.py:158-179`:** callback без `atomic`/`select_for_update`, переход из `COMPLETED` обратно разрешён. Атака: двойной `success` (или `success → failure → success`) продлевает TOP дважды.
- **F4 (важно), `payments/views.py:154-175`:** `amount`/`currency`/`action` из callback не сверяются с `Payment`.
- **F5 (важно), `payments/serializers.py:421-422`:** `server_url`/`result_url` задаёт клиент. Атака: подписанные callback'и LiqPay уходят на сервер атакующего (материал для replay), open redirect через `result_url`.
- **F6 (важно), `core/settings.py:406`:** `LIQPAY_SANDBOX` по умолчанию `true`, статус `sandbox` засчитывается как `completed`. Атака: на проде с забытой переменной тарифы оплачиваются тестовой картой.
- **F12 (недочёт, часть LiqPay), `payments/liqpay_client.py:281`:** подпись сравнивается `!=` (timing). Часть Telegram (`telegram_bot/views.py:88`) — задача 5.5.
- **F14 (недочёт), `local_listings/tests.py:894`, `tests/test_e2e.py:252`:** нет тестов на пустой ключ, чужой `listing_id`, расхождение суммы, откат из `COMPLETED`, параллельный callback. Пункт про токен бота (C2) в `docs/LAUNCH_CHECKLIST.md` (раздел 0, строки 50–56) — действие владельца, см. «Для владельца».

## Цель
- [ ] **F1:** пустой, плейсхолдерный (`integrations.base.is_placeholder`) `LIQPAY_PRIVATE_KEY`/`LIQPAY_PUBLIC_KEY` или `LIQPAY_MODE=off` → checkout (promote и legacy) и callback отвечают 503 `{"detail": "Оплата тимчасово недоступна"}`, БД не меняется. `decode_callback` в этом состоянии бросает исключение (`LiqPayNotConfigured`), а не считает подпись пустым ключом. `LIQPAY_MODE` применяется в обоих местах.
- [ ] **F2:** цена и `purpose` определяются только сервером. Legacy checkout `payments/liqpay/checkout/` скрыт флагом `PAYMENTS_LEGACY_CHECKOUT_ENABLED` (по умолчанию `false`) → 404 без создания `Payment`. При включённом флаге: поля `amount`, `currency`, `server_url`, `result_url` из запроса игнорируются, `listing.seller == request.user` (иначе 403/404), допускаются только `purpose` с серверной ценой (сейчас таких нет → 400). `Payment.unlock_listing()` проверяет владельца и исходный статус листинга. Пока цена не определена владельцем (Q13/Q14: `listing_unlock`/`listing_vip` не нужны) — эндпоинт закрыт флагом.
- [ ] **F3:** callback в `transaction.atomic()` с `Payment.objects.select_for_update().get(order_id=...)`. `COMPLETED` — конечный статус: `completed → failed/pending` не меняют платёж (только лог). Эффект применяется один раз: поле `Payment.applied_at` (миграция, см. «Шаги»), применяем только при `applied_at is None`.
- [ ] **F4:** callback сверяет `amount` (`Decimal`), `currency` и `action == 'pay'` с `Payment`. При расхождении: `Payment.status = failed`, `liqpay_raw` сохранён, WARNING в логе без ПДн, эффект не применяется, ответ 200 с нейтральным телом (чтобы LiqPay не ретраил).
- [ ] **F5:** `server_url` и `result_url` строятся только из `settings.SITE_URL` (хелпер `build_liqpay_urls(order_id)`), значения из запроса игнорируются; используется и в promote (`local_listings/views.py`), и в legacy checkout.
- [ ] **F6:** `LIQPAY_SANDBOX` — при `not DEBUG` без явного значения в окружении `ImproperlyConfigured` (либо дефолт `false`; выбрать один вариант и описать в PROGRESS.md). Статус `sandbox` засчитывается как оплата только при `LIQPAY_SANDBOX=true`; при `false` → `failed` + WARNING.
- [ ] **F12 (LiqPay):** подпись сравнивается `hmac.compare_digest`.
- [ ] **F14:** тесты на каждый пункт выше (см. «Тесты»); в LAUNCH_CHECKLIST пункт про токен бота (раздел 0) дополнен ссылкой на аудит C2 (если ещё не дополнен).
- [ ] Ответы callback не раскрывают `order_id` и причину отказа подписи (неверная подпись → 400 `{"detail": "invalid"}`, неизвестный `order_id` → 200 `{"ok": false}`).

## Тесты
Django (сеть не нужна, LiqPay не вызывается). Каждый тест проверяется мутацией (CLAUDE.md): сломать код — красный — откатить.
- **F1:** `LIQPAY_PRIVATE_KEY=''` + callback, подписанный пустым ключом → 503, `Payment` остаётся `pending`, `promoted_until` не изменился. То же для `your_liqpay_private_key`. `LIQPAY_MODE=off` → 503. Promote при пустом ключе → 503, `Payment` не создан. Прямой вызов `decode_callback` с пустым ключом → исключение.
- **F2:** legacy checkout при `PAYMENTS_LEGACY_CHECKOUT_ENABLED=false` → 404, `Payment` не создан; при `true`: аноним → 401, чужой `listing_id` → 403/404, `purpose=listing_unlock` → 400; `amount`, `currency`, `result_url`, `server_url` из тела не влияют на `Payment` и `data`. `unlock_listing()` чужого листинга не меняет статус. Promote с `{"amount": "0.01"}` → `Payment.amount == tariff.price`.
- **F3:** `success → failure → success` — TOP применён один раз (`promoted_until` = база + `duration_days`, не 2×); дубль `success` → `applied_at` не меняется; `completed → failed` статус не меняет. Параллельный callback: `TransactionTestCase` с двумя потоками, `skipUnless(connection.vendor == 'postgresql')`; на sqlite — последовательный сценарий.
- **F4:** `amount` меньше → `failed`, эффект не применён; другая `currency` → `failed`; `action='subscribe'` → `failed`; ответ 200.
- **F5:** `data` checkout содержит `server_url == f'{SITE_URL}/api/v1/payments/liqpay/callback/'`; значения из запроса игнорируются.
- **F6:** `LIQPAY_SANDBOX=False` + статус `sandbox` → `failed`, эффект не применён; `True` + `sandbox` → `completed`; проверка настройки при `DEBUG=False` без значения (`ImproperlyConfigured` или `false` по выбранному варианту).
- **F12:** тест, что сравнение идёт через `hmac.compare_digest` (мок), и что подпись с отличием в последнем символе → 400.
- **F14:** миграция — платёж, бывший `completed`, получает `applied_at`; повторный `success` эффект не применяет.
- Неверная подпись → 400 без `order_id` в теле; неизвестный `order_id` → 200 `{"ok": false}` без `order_id`.
Playwright: UI не меняется (платные услуги скрыты `PAYMENTS_ENABLED=false`, сценарии UI — в 4.1). Проверка обхода — API-тестами Django выше; в `frontend/e2e/` существующий набор остаётся зелёным.
