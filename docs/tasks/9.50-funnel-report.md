# Задача 9.50: Визиты лендингов и еженедельный отчёт о воронке

## Контекст
`DailyMetric` считает визиты калькулятора, расчёты и заявки, но не визиты `/prigon/[slug]`: это главная точка входа, и данные первых недель иначе потеряются. «Воронка» 2.15 (`leads/funnel.py`) показывает только календарный месяц и только в админке, поэтому без захода туда владелец не видит проблему.

## Цель
- Ключ `landing_visit`: страница `/prigon/[slug]` шлёт один `POST /api/v1/metrics/event/` за вкладку (sessionStorage, без cookie), как `calculator_visit`.
- Команда `weekly_funnel_report` (`--days N`, `--dry-run`) и задача Celery beat: понедельник, 09:00 по Киеву, последние 7 полных дней.
- Отчёт в Telegram (`FUNNEL_REPORT_CHAT_ID`) и на email (`FUNNEL_REPORT_EMAIL`). Пустой адрес выключает канал, сбой одного канала не мешает другому.
- В отчёте только счётчики: визиты, расчёты, заявки, горячие, депозиты, выкупы, «не додзвонились», конверсии, топ источников, медиана первого ответа, `FailedTask`, недоставленные заявки. Без имён, телефонов и `public_id`. Коммерческих порогов в коде нет: репозиторий публичный.

## Тесты
Django: границы периода по Киеву, суммы, конверсии при нуле, депозит и выкуп по журналу без дублей, медиана, недоставленные, отсутствие ПДн, каналы независимы, `--dry-run` ничего не шлёт, `--days 0` — ошибка, повторы Telegram, расписание, 204 на `landing_visit`.
Playwright: один POST при открытии лендинга, при перезагрузке нового нет.

## Для владельца (LAUNCH_CHECKLIST)
Заполнить `FUNNEL_REPORT_CHAT_ID` и `FUNNEL_REPORT_EMAIL`, проверить командой `weekly_funnel_report`.

## Готово, когда
Тесты зелёные, мутации ловятся, `openapi.yaml` сверен с PostgreSQL, `npm run build` и `tsc` чистые, спек `metrics` зелёный.
