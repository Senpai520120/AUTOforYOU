# Задача 5.4: Тексты бота в админке, команды, set_webhook с секретом

## Контекст
Критичных и важных находок в задаче нет. Она закрывает конфигурационные и «желательные» находки бота, чтобы выполнить бриф §2 («тексты редактируются в Django Admin», «честный статус "не настроено"»).

- **07-C2:** все тексты бота и постов захардкожены на украинском: приветствия `telegram_bot/handlers.py:20-23` и `28-32`, `/help` `handlers.py:40-44`, «Наразі немає активних оголошень» `handlers.py:84`, кнопка «Переглянути» `handlers.py:91`, ответы привязки `handlers.py:130-134`, «ТЕРМІНОВИЙ ВИКУП» и текст поста `telegram_bot/tasks.py:57-63`, кнопка «Переглянути оголошення» `tasks.py:75`, `note` в ответе link-token `telegram_bot/views.py:43`. После 5.1–5.3 тексты ответов и постов собраны в `telegram_bot/formatting.py` — их и переносим.
- **07-C4:** `set_webhook` разрешает установку без секрета: `getattr(settings, 'TELEGRAM_WEBHOOK_SECRET', '') or None` (`telegram_bot/management/commands/set_webhook.py:27`, передаётся в `set_webhook` на строке 41). После этого webhook-view отвечает 503 на все апдейты (`views.py:76-85`). URL передаётся только позиционным аргументом, `SITE_URL` не используется.
- **20-G5:** без `TELEGRAM_BOT_USERNAME` link-token отдаёт `link: null` (`views.py:35-42`), а страница `/me/telegram` молча ничего не показывает (`frontend/app/me/telegram/page.tsx:35-36`: `setLink(data.link)` с `null` возвращает ту же кнопку, пользователь жмёт без результата).

Связанные «желательные» находки в тех же местах, закрываются здесь же:
- 07-Q12: `set_webhook --delete` дублирует `unset_webhook` и при этом требует позиционный `webhook_url` (`set_webhook.py:11-19,37-39`). `unset_webhook` снимает webhook с `drop_pending_updates=True` (`telegram_bot/management/commands/unset_webhook.py:33`), теряя апдейты.
- 07-S6: при выдаче нового токена старые не аннулируются; отвязка тоже не аннулирует неиспользованные токены (`views.py:29-33`, `views.py:54-60`), и старая ссылка 30 минут снова привязывает аккаунт. `GET` создаёт запись в БД на каждый вызов, отдельного лимита нет.
- 07-S7: админка токенов показывает токен целиком и даёт редактировать `user`, `expires_at`, `used` (`telegram_bot/admin.py:8-10`).
- 07-Q13: `send_notification` не обрабатывает `TelegramForbiddenError`/`TelegramBadRequest` (`integrations/tasks.py:95-99`): если пользователь заблокировал бота, задача падает, `telegram_id` не сбрасывается. Отвязаться из самого бота нельзя: команд `/stop`/`/unlink` нет.
- 07-Q11: `UserBindingMiddleware` делает SQL-запрос на каждое сообщение, результат не использует ни один хендлер (`telegram_bot/middleware.py:28-35`, `telegram_bot/dispatcher.py:21`). Здесь он начинает использоваться командой `/unlink`; если не нужен — убрать.
- 08-C4: имя бота `@AUTO_F_Y_bot` и «Посилання діє 30 хвилин» захардкожены на странице (`frontend/app/me/telegram/page.tsx:107,109`). Та же страница, что и 20-G5, поэтому делается здесь; задача 6.4 эту строку уже не трогает.
- Меню команд через `set_my_commands` не настроено (аудит 07, раздел «Команды бота»).

Вне задачи: шаблон текста **заявки брокеру** и её отправка — задача 2.2 (07-Q2, 07-C1). Если 2.2 уже создала модель шаблонов сообщений, здесь используется **та же** модель, вторую не заводить. Адаптер `TelegramProvider` и статус интеграции в админке (07-C3, 07-C5) — задача 3.4; здесь ими только пользуемся. Подтверждение привязки кнопкой/письмом (07-S5) и логирование `telegram_id` (07-S9, задача 7.2) не входят.

## Цель
- [ ] Все тексты бота (ответы команд, привязки/отвязки, подписи кнопок) и шаблоны постов канала (импортный лот, срочный выкуп, C2C, пометка «ПРОДАНО») хранятся в модели `BotText` (ключ, текст, описание, список допустимых плейсхолдеров) и редактируются в Django Admin. Дефолты — текущие тексты, заливаются data-миграцией.
- [ ] **Q9 (ANSWERS):** в реестр `BotText` входят тексты напоминаний о сроке объявления: `listing_expiring` («за N днів», плейсхолдеры `{title}`, `{days}`, `{renew_url}`), `listing_expires_today`, `listing_expired` (с ссылкой «Продовжити безкоштовно»). Числа дней в тексте — из настроек порогов напоминаний (4.3), не хардкод. Рассылку делает 4.3 (email + Telegram), здесь только тексты и их редактирование.
- [ ] **Шаг 6 (Н-28):** при недоступном Telegram у пользователя/брокера вызывающий код получает явный `not_configured`/`blocked` и переходит на резервный email; здесь `send_notification` лишь возвращает причину (уже в «Цели» для `blocked`).
- [ ] Если ключа в БД нет (например, миграцию откатили), используется дефолт из того же модуля, из которого заливает миграция, и пишется предупреждение в лог. Бот не падает.
- [ ] В админке нельзя сохранить текст с неизвестным плейсхолдером или с HTML-тегами вне разрешённых (`b`, `i`, `u`, `s`, `a`, `code`, `pre`) или незакрытыми тегами — `ValidationError` с понятным текстом. Значения, подставляемые в шаблон, по-прежнему экранируются (`formatting.py` из 5.1).
- [ ] Изменение текста в админке применяется без рестарта (кэш с инвалидацией при сохранении).
- [ ] Меню команд бота задаётся через `set_my_commands`: `/start`, `/help`, `/latest`, `/unlink`. Описания команд — тоже из `BotText`. Меню устанавливается командой `manage.py set_bot_commands` и автоматически при старте `run_bot` (polling и webhook-режим из 5.1).
- [ ] Команда `/unlink` в боте отвязывает Telegram от аккаунта (сбрасывает `telegram_id`, аннулирует неиспользованные токены) и отвечает текстом из `BotText`. У непривязанного — ответ «не привязан».
- [ ] `send_notification` при `TelegramForbiddenError` (бот заблокирован) сбрасывает `telegram_id` пользователя, аннулирует его токены и завершается без исключения с `{'sent': False, 'reason': 'blocked'}`. `TelegramBadRequest` логируется и не повторяется.
- [ ] `set_webhook`: без `TELEGRAM_WEBHOOK_SECRET` → `CommandError`; URL по умолчанию `SITE_URL + /api/v1/telegram/webhook/`, позиционный аргумент необязателен; не-`https` URL → `CommandError`. Использует общую функцию установки из 5.1. Опция `--delete` убрана (снятие — только `unset_webhook`).
- [ ] `unset_webhook` по умолчанию не выбрасывает накопленные апдейты; `--drop-pending` — явный флаг.
- [ ] Выдача ссылки привязки: эндпоинт `POST /api/v1/telegram/link-token/` (GET → 405), при выдаче нового токена все прежние неиспользованные токены пользователя помечаются `used=True`; отдельный throttle `telegram_link` из settings. Отвязка на сайте (`DELETE /api/v1/telegram/link/`) тоже аннулирует неиспользованные токены.
- [ ] Ответ link-token содержит `configured: bool` и `bot_username`. Если бот не настроен (нет токена или `TELEGRAM_BOT_USERNAME`, либо провайдер 3.4 в режиме `off`), ответ `configured: false`, `link: null`, токен **не создаётся**.
- [ ] Страница `/me/telegram`: при `configured: false` показывает понятное сообщение «Telegram-бот ще не налаштований, спробуйте пізніше» вместо кнопки-пустышки; имя бота берётся из `bot_username`, срок действия ссылки — из `expires_at`. Хардкода `@AUTO_F_Y_bot` и «30 хвилин» нет.
- [ ] Админка токенов привязки: токен замаскирован (первые 8 символов), все поля только для чтения, добавление запрещено.
- [ ] `UserBindingMiddleware` либо используется (`/unlink`), либо удалён из диспетчера — без лишнего SQL-запроса на каждое сообщение.
