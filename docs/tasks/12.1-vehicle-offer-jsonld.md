## Цель
1. В `jsonld-core.ts` новая чистая функция `buildVehicleOfferLd(input)`: возвращает узел schema.org `Car` с вложенным `offers: Offer` либо `null`, если нет обязательных данных (нет make/model, цена не положительное конечное число, неизвестная валюта). Поля:
   - `@type: 'Car'`, `name` («Make Model Year»), `brand: {'@type':'Brand', name: make}`, `model`, `vehicleModelDate` (год строкой);
   - `mileageFromOdometer: {'@type':'QuantitativeValue', value, unitCode:'KMT'}` — только если пробег передан и число ≥ 0;
   - `fuelType` (текст по-английски): petrol→Gasoline, diesel→Diesel, electric→Electric, hybrid→Hybrid, gas→LPG; неизвестное — ключ опущен;
   - `vehicleTransmission`: auto→Automatic, manual→Manual, cvt→CVT, robot→Automated manual; неизвестное — опущен;
   - `vehicleIdentificationNumber` — только если вызывающий передал `vin` и он подходит под `/^[A-HJ-NPR-Z0-9]{17}$/i` (никаких частичных и маскированных VIN);
   - `itemCondition` (необязательно): new→`https://schema.org/NewCondition`, used→`UsedCondition`, damaged→`DamagedCondition`;
   - `url` — абсолютный адрес страницы;
   - `offers: {'@type':'Offer', price, priceCurrency: 'UAH'|'USD'|'EUR', availability, url}`, где `price` — нормализованная десятичная строка без округления через float; `availability` — `https://schema.org/InStock` | `OutOfStock` | `PreOrder`.
   - Пустые значения никогда не выводятся (правило `noEmpty` из 9.54).
   - Тип входа намеренно **без полей продавца**: ПДн не могут попасть в разметку по построению.
2. Параметр `availability` в билдере необязателен только для лендинга. Для `/local` и `/listings` он обязателен: если статус не даёт availability (результат `null`), разметка не строится совсем.
3. Мапперы статус → availability лежат в ядре (чтобы тестировались без браузера):
   - локальные: `active`→InStock, `sold`→OutOfStock, любой другой статус → `null` (разметки нет);
   - лоты: `in_stock`→InStock, `in_transit`→PreOrder, `sold`→OutOfStock, неизвестный → `null`.
4. Привязки в `jsonld.ts` на `SITE_URL`: `localListingLd(listing)`, `listingLd(listing)`, `landingLd(page)`. Канонические адреса: лоты — `/listings/<slug>` через `listingSlug`, локальные — `/local/<id>`, лендинги — `/prigon/<slug>`.
5. Страницы:
   - `/local/[id]`: `<JsonLd>` только при включённом C2C и когда статус даёт availability. hidden/pending/rejected/draft/expired — ни Car, ни Offer, даже если API вернул объявление (например, владельцу или модератору с cookie в будущем).
   - `/listings/[id]`: разметка с VIN.
   - `/prigon/[slug]`: Car + Offer добавляются к существующему массиву BreadcrumbList + FAQPage. Цена — оценка `total_usd_full ?? total_usd` в USD. Без VIN, без пробега. **Окончательное решение: у Offer на лендинге поля `availability` нет** (это оценка услуги, а не остаток на складе); `description` не добавляется. `vehicleModelDate` не выводится (диапазон лет не нужен).
6. ПДн: JSON-LD на этих страницах не содержит `owner_name`, `seller_id`, названий города и региона, `contact_phone`, текста описания от продавца.

Django: не требуются (backend не меняется); при правке `e2e_seed` — прогнать существующие тесты команды, если они есть.

Unit (без браузера, в `seo.spec.ts`, рядом с describe ядра 9.54):
- полная форма Car + Offer для входа «локальное» и «лот»;
- VIN только валидный из 17 символов: маскированный `1HGCM82633A****` и короткий опускаются;
- мапперы availability для каждого статуса; hidden/pending → `null`, билдер возвращает `null`;
- цена `"12500.00"` → стабильная строка (`"12500.00"` или `"12500"`, выбрать одно и зафиксировать); `0`, отрицательная, `NaN` → `null`;
- неизвестная валюта → `null`; неизвестное топливо/КПП → ключа нет;
- `jsonLdString` экранирует `</script>` в make/model;
- вход с лишними полями продавца (`owner_name`, `contact_phone`, передан через cast) в выводе не появляется.
