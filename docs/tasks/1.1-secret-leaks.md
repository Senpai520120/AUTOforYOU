## Шаги

1. **Владелец**: в @BotFather выполнить `/revoke` для бота, получить новый токен и положить его только в `.env` сервера. Пока владелец не подтвердил отзыв, задачу не закрывать: удаление файла из индекса без отзыва токена ничего не защищает.
2. Проверить, что новый токен нигде не записан в отслеживаемые файлы: `git grep -nE '[0-9]{8,10}:AA[A-Za-z0-9_-]{30,}'` должен вернуть пусто после шага 3. Значение в терминал не выводить: использовать `-l` или `| cut -d: -f1`.
3. `git rm --cached .claude/settings.local.json`, затем коммит «chore(security): убрать .claude/settings.local.json из индекса (12-S1)». Проверить, что `.gitignore:44` дальше не даст файлу вернуться в индекс.
4. Добавить `.claude/` в `.dockerignore`.
5. Добавить в `ci-cd.yml` шаг `gitleaks detect --no-git --source .`, чтобы проверялось текущее дерево. Проверку по истории не включать, пока история не очищена: иначе CI будет всегда красным из-за старых коммитов. При варианте Q1 «переписать историю» после шага 6 включить `gitleaks detect` по всей истории. Действие брать из официального образа или action с закреплённой версией.
6. **История (только по Q1).** По умолчанию (Q1 без ответа или «не переписывать») шаг пропускается. Это нужно явно отметить в PROGRESS.md: «история содержит отозванный токен, решение владельца: не чистить». Если владелец **письменно** выбрал чистку:
   - сделать зеркальную резервную копию (`git clone --mirror`);
   - `git filter-repo --path .claude/settings.local.json --invert-paths` (или `--replace-text` с шаблоном токена);
   - `push --force` во **все** ветки и теги — **только после явного «да» владельца на force-push** (правило проекта). Предупредить владельца, что открытые PR и чужие клоны придётся пересоздать, а GitHub ещё какое-то время хранит старые коммиты по SHA: при необходимости запросить очистку кэша через поддержку GitHub.
7. Opendatabot, `providers.py`:
   - в `except` логировать `logger.warning('Opendatabot request failed: %s', _mask(str(exc)))`, где `_mask` заменяет `apikey=[^&\s']+` на `apikey=***`;
   - в результат класть `{'demo': False, 'provider': 'opendatabot', 'error': 'service_unavailable', 'message': '<общий текст>'}` без `str(exc)`;
   - общий текст не хардкодить в нескольких местах: одна константа модуля;
   - сверить с https://opendatabot.ua/doc, поддерживается ли заголовок для ключа. Если да, перенести ключ в заголовок.
8. `views.py`: если в `data` есть `error`, **не** создавать `RegistryReport` и вернуть 502 или 503 с общим текстом. Точный код согласовать с фронтом: сейчас registry на фронте не используется (grep `frontend/` пуст), поэтому ограничений нет. Кэширование ошибок в целом (TTL, 03-Q1) делает задача 3.2; здесь только запрет сохранять ответ с ключом или ошибкой.
9. Data-миграция: удалить `RegistryReport` с `payload__has_key='error'`. Причина: в этих записях может лежать ключ. `reverse_code = migrations.RunPython.noop`. Проверить, что `has_key` работает и на sqlite, и на Postgres (JSONField поддерживает оба).
10. (03-S6) То же для NHTSA (`providers.py:85-86`) и Apify (`:365-366`): общий текст наружу, детали в лог.
11. Замаскировать фрагмент токена в `docs/audit/12_infra.md:91` (заменить на `<скрыто>`). Файл ведёт основной агент, поэтому сделать это отдельным коммитом документации до того, как `docs/audit/` попадёт в git.
