## Цель
- [ ] `deploy.sh` работает на любом Linux-VPS с Docker Engine и Compose v2 (Ubuntu 22.04/24.04, Debian 12) без ручных `export`: загружает `.env` из каталога проекта, выполняет прежние проверки (`deploy.sh:21-57`) и новые: `DOMAIN` задан, `ALLOWED_HOSTS` содержит `DOMAIN`, `SITE_URL` начинается с `https://`, если `TLS_MODE` не `off`.
- [ ] Порядок `deploy.sh`: проверки → `git pull --ff-only` (флаг `--pull`, по умолчанию выключен) → бэкап `scripts/backup.sh --now` (флаг `--skip-backup` только осознанно) → сборка образов с тегом `IMAGE_TAG=<git short sha>` → `docker compose up -d --wait` → smoke: `curl` `/healthz` и `/` на `SITE_URL` (или `http://localhost` при `TLS_MODE=off`) → итог.
- [ ] Откат: предыдущий `IMAGE_TAG` записывается в `.deploy/previous_tag`. При провале `--wait` или smoke скрипт поднимает предыдущие образы и сообщает, что миграции БД автоматически не откатываются: для отката данных — `scripts/restore.sh` с дампом, сделанным перед деплоем (путь к нему печатается). Ручной откат: `./deploy.sh --rollback`.
- [ ] Нет захардкоженных имён контейнеров: только `docker compose ps -q backend`/`--wait`. `COMPOSE_PROJECT_NAME` есть в обоих шаблонах `.env`.
- [ ] Однократные шаги миграции со старого стека выполняются идемпотентно: смена владельца volumes `media`/`static` под non-root из 7.3 (если volume принадлежит root).
- [ ] `scripts/server-setup.sh` (необязательный помощник для чистого VPS): установка Docker из официального репозитория, пользователь `deploy` в группе docker, `ufw` (22, 80, 443), автоматические обновления безопасности. Скрипт идемпотентный, каждое действие печатает, запускается от root один раз. Всё то же описано вручную в документации для тех, кто не хочет запускать скрипт.
- [ ] CI-джоба деплоя: переименована в «Deploy», запускается только если `vars.DEPLOY_ENABLED == 'true'` (на push в main после зелёных backend/frontend/e2e) или вручную через `workflow_dispatch`. Без переменной джоба пропускается (`skipped`), main зелёный. По SSH выполняет `cd "$DEPLOY_PATH" && ./deploy.sh --pull --build`. Скрипт в репозитории, внешнего `/opt/autoforyou/redeploy.sh` нет.
- [ ] После деплоя CI (или сам `deploy.sh` с флагом `--smoke-e2e`) может запустить Playwright-набор `@smoke` против `SITE_URL` (только чтение, 23-P54).
- [ ] CI: `permissions: contents: read` на уровне workflow; ruff закреплён версией; Postgres в backend-джобе той же версии, что в compose; джоба `infra-lint` с `shellcheck` для `deploy.sh`, `docker/*.sh`, `scripts/*.sh`, проверкой отсутствия CRLF в `*.sh`, `docker compose config --quiet`; `gitleaks` (если нет после 1.1); `pip-audit` и `npm audit --audit-level=high` как отдельная необязательная джоба (не в required checks). Файл `.github/dependabot.yml` для pip, npm, docker, github-actions (раз в неделю).
- [ ] `DEPLOY_NOTES.md` переписан (файл не удаляется): требования к VPS, DNS, первый запуск, `.env` по `docs/LAUNCH_CHECKLIST.md`, `init-letsencrypt`, обычный деплой, откат, правило обратно совместимых миграций (миграция работает со старым и новым кодом; удаление поля или таблицы — отдельным релизом после того, как новый код уже в продакшене), бэкапы и восстановление (ссылки на 7.4), логи, обновление, частые ошибки. Упоминаний SQLite, `dumpdata`, «119 тестов» и запуска бота из терминала нет.

## Тесты
Django: не требуются (изменения в shell, CI и документации). Существующий набор должен остаться зелёным на Postgres 18 в CI.

Shell/CI:
- `shellcheck deploy.sh docker/*.sh scripts/*.sh` без ошибок; ни в одном `*.sh` нет `\r`.
- `docker compose config --quiet`.
- `deploy.sh` без `.env` → код ≠ 0 и сообщение «.env не найден»; с `.env` из `.env.docker.example` (`SECRET_KEY` с `REPLACE`) → код ≠ 0 и сообщение о заглушке; с `DEBUG=true` → код ≠ 0.
- В CI-джобе e2e (или отдельной) стек поднимается через `./deploy.sh --build --skip-backup` с `TLS_MODE=off`, а не голым `docker compose up`, так что скрипт проверяется на каждом PR.
- Workflow без `vars.DEPLOY_ENABLED`: джоба deploy в статусе `skipped` (проверяется по первому push в main после мержа).

Playwright (`frontend/e2e/smoke.spec.ts`, тег `@smoke`, только чтение):
- Успех: `/`, `/listings`, `/ua`, `/calculator`, `/privacy`, `/terms`, `/healthz` отвечают 200, у главной есть `<title>`.
- Ошибка: backend остановлен → главная и `/listings` показывают оформленную страницу ошибки с текстом и кнопкой «Спробувати ще раз», код ответа не сырой 502 nginx (если nginx отдаёт 502 для `/api`, фронт всё равно показывает свою страницу).
