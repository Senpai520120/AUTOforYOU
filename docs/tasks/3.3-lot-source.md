## Контекст
Лоты Copart/IAAI попадают в каталог только через админский импорт: API `POST /api/v1/lots/import/` (`integrations/views.py:206-241`) или CLI `manage.py import_lot` (`integrations/management/commands/import_lot.py`). Провайдеров два: `ManualLotProvider` (ручной JSON, рабочий, `integrations/providers.py:313-322`) и `ApifyLotProvider` (каркас, `:325-366`). Импорт выполняет сервис `import_lot` (`integrations/importer.py:16-77`).

- **03-Q2 (важно):** `import_lot` ищет объявление по паре `(vehicle, status=IN_TRANSIT)` (`integrations/importer.py:62-71`). Если объявление уже перешло в `in_stock` или `sold`, повторный импорт того же VIN создаёт второе `Listing` на тот же `Vehicle`. `Listing.vehicle` — обычный `ForeignKey` (`listings/models.py:34`), база дубль не остановит.
- **03-Q3 (важно):** `_normalize_lot` заявлен как «не кидает исключений» (`integrations/providers.py:267`), но `int(raw.get('year') or 2000)`, `int(raw.get('engine_cc') or 0)` и `int(raw.get('mileage_km') or 0)` (`:293-297`) бросают `ValueError` на нечисловом значении. В `LotImportView` вызов стоит до `try` (`integrations/views.py:218`), поэтому ответ — необработанная 500.
- **03-Q6 (важно):** Apify без токена возвращает `{'demo': True, 'vin': None}` без `error` (`integrations/providers.py:338-344`). `LotImportView` передаёт это в `import_lot`, получает `ValueError('VIN обязателен')` и отвечает 400 «VIN обязателен» (`integrations/views.py:223-229`) вместо «Apify не налаштовано». Тест принимает любой из кодов 200/201/400 (`integrations/tests.py:452-463`).
- 03-C2 (конфигурация): ID актора Apify захардкожен плейсхолдером `YOUR_ACTOR_ID` прямо в URL (`integrations/providers.py:351`). Реальный импорт невозможен без правки кода.
- 03-C8 и 04-C3: выдуманные значения попадают в каталог как настоящие. `year=2000`, `engine_cc=0`, `fuel_type='petrol'` в нормализации (`integrations/providers.py:281-283`, `:293`), `make/model='Unknown'`, `year=2000` в сервисе (`integrations/importer.py:38-43`), цена объявления = `final_bid` или 0 (`:60-67`, 03-Q13).
- 03-Q11 (желательно): `import_lot` без `transaction.atomic`: при ошибке на `Listing` остаются частично созданные `Vehicle` и фото.
- 03-Q7 (желательно): `import_lot_task` (`integrations/tasks.py:10-42`) нигде не вызывается. Обе ветки `get_lot_provider` одинаковы (`integrations/providers.py:369-374`).
- 03-Q15 (желательно): у `LotImportView` нет throttle (`integrations/views.py:206-207`). CLI по умолчанию берёт «первого суперюзера» продавцом (`_resolve_seller`, `integrations/management/commands/import_lot.py:101-111`).
- 03-C9: таймаут Apify 60 с захардкожен (`integrations/providers.py:358`).
- Режим провайдера определяется только наличием `APIFY_TOKEN` (`core/settings.py:331`), переключателя нет. Каркас `LOTS_MODE` и страница статуса появляются в задаче 3.1.
- Импорт лота вызывает автопост в Telegram-канал через сигнал на создание `Listing` (`telegram_bot/signals.py:5-13`, 07-S1). Это закрывает задача 5.2, здесь не трогать, но в тестах сигнал замокать.
- Перекачка фото `upload_lot_photos` (03-S5) — задача 1.10. Права на фото аукционов — задача 2.11 (Q8).

## Цель
- [ ] Источник лотов переведён на каркас 3.1 (ключ `lots`, режим `LOTS_MODE`):
  - `manual` работает всегда (ключ не нужен).
  - Импорт по URL через Apify в `auto` включается, только если заданы `APIFY_TOKEN` и `APIFY_ACTOR_ID` и оба не плейсхолдеры. Иначе он «не налаштовано».
  - `demo` — `DemoLotProvider`: по любому URL отдаёт фиксированный демо-лот с `demo: true`. Импорт в demo-режиме работает как предпросмотр (`saved: false`) и в каталог **не** пишет.
- [ ] **03-Q6:** `source=apify` без токена или ID актора → HTTP 503 `{'configured': false, 'error': 'Імпорт за посиланням не налаштовано: задайте APIFY_TOKEN і APIFY_ACTOR_ID'}`. Текста «VIN обязателен» в ответе нет. Провайдер в режиме «не настроено» всегда возвращает `error`, а не пустой лот.
- [ ] **03-C2:** ID актора берётся из `settings.APIFY_ACTOR_ID` (`.env`), URL собирается с экранированием. Таймаут — из `INTEGRATIONS_HTTP_TIMEOUT` или отдельной `APIFY_TIMEOUT` (03-C9).
- [ ] **03-Q3:** нормализация не бросает исключений. Нечисловые или вне диапазона `year` (1950…текущий+1), `engine_cc` (0…10000), `mileage_km` (≥0) → `{'error': ..., 'field_errors': {'year': '...'}}` и ответ 400 с понятным текстом по полю. Лучше сделать нормализацию через DRF-сериализатор `LotDataSerializer`, чтобы API, CLI и админ-форма валидировались одинаково.
- [ ] **03-C8 / 04-C3:** фейковых дефолтов нет. `make`, `model`, `year`, `fuel_type` и `mileage_km` обязательны, `engine_cc` обязателен для всех, кроме `electric`. Неизвестный `fuel_type` → ошибка поля, а не молчаливый `petrol`. Цена (03-Q13): если нет ни `price`, ни `final_bid > 0`, импорт отклоняется с ошибкой «Не вказано ціну». Если владелец захочет импорт без цены (черновик) — это отдельное решение, записать в `PROGRESS.md`.
- [ ] **03-Q2:** повторный импорт того же VIN не создаёт второе объявление при любом статусе существующего. Сервис ищет `Listing` по `vehicle` (самое новое), обновляет цену только у объявления в статусе `in_transit` / `in_stock`, а `sold` не трогает и возвращает `created: false`.
- [ ] **Q8 (ANSWERS):** импорт лота сохраняет фото аукциона как данные (`source_url`), но не решает, показывать ли их: показ управляется `PHOTO_MODE` (`off` по умолчанию / `partner` / `auction`) в 2.11 через `shareable_images`. Импорт не скачивает аукционные фото в медиа-хранилище, пока режим не `auction` (то есть не копирует чужие фото без подтверждённых прав); фото брокера (`partner`) загружаются отдельно, не импортом. Каталог лота без фото показывает заглушку (фронт, 2.11/6.x). Ответ импорта и админ-форма сообщают «Фото аукціону не показуються (режим off)» вместо молчаливого пропуска.
- [ ] **03-Q11:** `import_lot` целиком в `transaction.atomic()`.
- [ ] `LotImportView`: throttle-скоуп `lot_import` (ставка из `.env`, `THROTTLE_LOT_IMPORT_RATE`), общий текст ошибок провайдера без деталей httpx. Деталь ошибки уходит в `record_error('lots', exc)`. Успех → `record_success('lots')`.
- [ ] CLI `import_lot`: продавец — `--seller-email` или `LOTS_IMPORT_SELLER_EMAIL` из `.env`. Если ни того, ни другого нет → `CommandError` с подсказкой, без молчаливого «первого суперюзера» (03-Q15). Ошибки нормализации → `CommandError` с текстом поля.
- [ ] `import_lot_task` (03-Q7): не удалять (бриф §6). Использовать для импорта по URL из админ-формы, чтобы 60-секундный вызов Apify не держал HTTP-запрос. `autoretry_for` — `RETRYABLE_EXCEPTIONS` (исправлено в 3.2). Если в плане окажется, что асинхронность не нужна, оставить задачу как есть и записать в `PROGRESS.md`.
- [ ] Админ-форма «Імпорт лоту» (Django Admin, у `Listing` или отдельная страница `integrations`): два режима — «Вручну» (поля лота) и «За посиланням» (URL, если Apify настроен; иначе поле выключено с пояснением «Не налаштовано»). Ошибки полей показываются на форме. После успеха — ссылка на созданное объявление. Владелец и брокер импортируют лоты без curl и CLI.
- [ ] Статус `lots` на странице 3.1 показывает режим, наличие `APIFY_TOKEN` и `APIFY_ACTOR_ID`, последний успех и ошибку.

## Шаги
1. `LotDataSerializer` в `integrations/serializers.py`: обязательные поля, диапазоны, choices для `auction` и `fuel_type`, `price`/`final_bid` как `Decimal`. `_normalize_lot` превращается в тонкую обёртку над ним и возвращает `error` и `field_errors`.
2. `ManualLotProvider`, `ApifyLotProvider` (actor из settings, таймаут, общий текст ошибки + `record_error`), `DemoLotProvider`. Фабрика `get_lot_provider()` через `resolve_mode('lots', ...)`, без дублирующей ветки.
3. `import_lot`: `transaction.atomic()`, поиск `Listing` по `vehicle`, правило обновления цены по статусу, без фолбэков `Unknown`/`2000`/`0`.
4. `LotImportView`: 503 для «не настроено», 400 с `field_errors`, режим demo → 200 `saved: false`, throttle.
5. CLI: продавец из флага или `.env`, ошибки через `CommandError`, в demo-режиме вывод «Демо: лот не збережено».
6. Админ-форма импорта, для URL-режима через `import_lot_task.delay` (в eager-режиме dev выполнится сразу).
7. Статус `lots` в реестре 3.1. Обновить `.env*.example`, `openapi.yaml` (против Postgres), `docs/LAUNCH_CHECKLIST.md`.
8. Схема БД не меняется: миграций нет. Если в плане понадобится ограничение «одно активное объявление на `Vehicle`», это отдельное решение с миграцией и причиной, согласовать до кода.
