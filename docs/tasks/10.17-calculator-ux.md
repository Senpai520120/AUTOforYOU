# Задача 10.17: Удобство калькулятора

## Контекст
Аудит `docs/audit/41_REVIEW_2026-11-11.md` (находки A6, E, G). До задачи: форма `/calculator` (`frontend/app/calculator/page.tsx`) при прямом входе подставляла «чужие» значения (`EXAMPLE`: $10 000, 2000 см³, 2020), отправка с пустыми полями шла на сервер через нативные баблы браузера; в списках портов и локаций показывались коды («New jersey», «Klaipeda») — `build_form_options` (`pricing/calculator.py`) строит подписи из кодов в `UsLandRoute`, `OceanFreightRate`; деньги в `CalcBreakdown` форматировались `toLocaleString()` без локали (запятая или пробел зависели от браузера), на лендинге — отдельной локальной функцией. Отказ на `engine_cc=0` для ДВС/hybrid уже есть (`pricing/serializers.py`, ревью 2026-11-16, тесты `EngineCcByFuelTests`), но пропуск поля давал английское «This field is required».

## Цель
- Числовые поля (цена, объём, год) без query пустые, с `placeholder`-подсказкой; `FORM_DEFAULTS` (member/payment/title) не менялись. Лендинги не затронуты: `LandingCalc` только показывает расчёт, ссылка с лендинга передаёт значения query.
- Обязательные поля проверяются на клиенте (`noValidate` + тексты по-украински, фокус на первом ошибочном поле) и на сервере (украинские `error_messages`, `engine_cc` для электро/PHEV необязателен, для ДВС/hybrid — обязателен и >= 1).
- Украинские названия площадок и портов: необязательные `auction_location_uk`, `us_port_uk` (`UsLandRoute`), `us_port_uk`, `eu_port_uk` (`OceanFreightRate`); пусто — прежняя подпись из кода. Сид заполняет только однозначные названия и только пустые поля.
- Деньги: общий форматтер `formatUsd`/`formatUah`/`formatNumber` в `frontend/lib/format.ts` (`Intl.NumberFormat('uk-UA')`, пробел-разделитель тысяч U+00A0, десятичная запятая; обозначение валюты «$» и «грн», как в проекте). Применён в `CalcBreakdown`, `LandingCalc`, карточках заявок брокера, `/me/calculations`, `/me/leads`.
- Ставка акциза гибрида по объёму: сверка (см. «Для владельца»), код не менялся.

## Шаги
1. Модель и миграция `name_uk`; `build_form_options` берёт первое непустое название из активных тарифов, иначе прежний фолбэк.
2. Сид `seed_rates`: `fill_uk_names()` (только пустые поля, идемпотентно, сбрасывает кэш тарифов).
3. Серверная валидация: украинские сообщения, `engine_cc` необязателен для EV.
4. `lib/format.ts` и замена мест вывода денег.
5. Форма: пустые поля, `placeholder`, `validateForm`, фокус на ошибку.
6. e2e: хелпер `fillCalcForm` (заполняет только пустые поля) во всех спеках, что жмут «Розрахувати»; новые тесты в `calculator-config.spec.ts`; `landing.spec.ts` ждёт пустое поле при мусорной цене в query.

## Для владельца (LAUNCH_CHECKLIST)
1. Проверить украинские названия портов/площадок в `/admin/pricing/uslandroute/` и `/admin/pricing/oceanfreightrate/`; незаполненные (`general`) показываются как «General» — вписать перевод.
2. Вопрос по гибриду: в сиде HEV (`hybrid`) — одна строка 0–∞ см³ по 5 €/100 см³ («как бензин ≤3000», комментарий «уточнить у брокера»), у бензина — две строки (≤3000: 5, >3000: 10). Для HEV с объёмом больше 3000 см³ сейчас считается по ставке «до 3000». Что говорит закон и брокер: делить ли HEV по объёму и как считать дизельные гибриды? Это данные (`CustomsExciseRate`), код не менялся. Задача 9.51 касается только сборов аукционов, к акцизу гибрида отношения не имеет.
