# Задача 4.12: Блок «Купити готове vs пригнати схоже» на карточке (F7) [ВОЛНА-2]

## Контекст
Новая задача сверки с бизнес-планом (`docs/audit/40_BUSINESS_PLAN_SYNC.md` §4, строка про блок F7; `docs/ANSWERS.md`, «Сверка с бизнес-планом»: ВОЛНА-2). Идея (BUSINESS_PLAN, разделы 1–3): покупателю в карточке украинского объявления показать альтернативу «пригнати схоже авто зі США» с расчётом под ключ и вести в заявку на пригон.

Что есть (проверить Grep):
- Калькулятор: `pricing/calculator.py`, `POST /api/v1/pricing/calculate/`, корректность и `is_estimate`, `rules_confirmed` — 2.5; ответ всегда `is_estimate: true`.
- Форма заявки — 2.3 (`LeadForm`, props `source`, `calculationId?`, `listingId?`; на карточке лота уже есть источник `source=listing`); SEO-страницы пригона по моделям — 2.16.
- Карточка C2C-объявления: `frontend/app/local/[id]/LocalListingDetail.tsx`; поля объявления (марка, модель, год, топливо, цена в гривне) — `local_listings/models.py`; признак «пригнано зі США» и VIN — 4.11.

## Цель
- [ ] **Блок на карточке** активного объявления (для объявлений с `imported_from_usa=true` блок тоже показывается, заголовок «Пригнати такий же»): две колонки «Купити готове: <цена объявления>» и «Пригнати схоже зі США: орієнтовно <сумма під ключ>» с разницей. Блок под `C2C_ENABLED` и флагом `BUY_VS_IMPORT_ENABLED` (по умолчанию `false`, включает владелец).
- [ ] **Расчёт по входам объявления.** Сервис `pricing/listing_estimate.py` строит входы калькулятора из объявления: марка, модель, год, тип топлива/двигатель (поля объявления), **цена аналога на аукционе** — **не выдумывается**: берётся из админки (справочник `AnalogPriceEstimate` по марке/модели/диапазону годов, поля `price_usd`, `source_note`, `valid_from`/`valid_to`, правило как у тарифов) либо из настройки `SiteSetting`. Если оценки нет — блок не показывает цифру пригона, вместо этого кнопка «Дізнатися вартість пригону» (заявка без расчёта).
- [ ] Расчёт идёт через тот же `pricing/calculator.py` (никакой своей формулы), деньги `Decimal` с полем валюты, курс снимком, ставки из БД. Недостающие входы (нет объёма двигателя и т. п.) → блок использует значения по умолчанию из админки либо скрывает цифру и просит уточнить в заявке; ничего не додумывается.
- [ ] **Честность.** В ответе и в блоке всегда `is_estimate: true`; рядом подпись «Орієнтовний розрахунок, не публічна оферта. Фактична вартість залежить від аукціону, стану авто та діючих ставок на дату розрахунку» + дата ставок (из 2.5) + `rules_confirmed=false` → «правила розрахунку ще не підтверджено брокером». Единый дисклеймер из 2.x/6.x (партнёр оказывает услугу) подключается тем же компонентом. Сравнение «дешевше/дорожче» формулируется нейтрально; запрещены слова-обещания («гарантовано», «економія до»).
- [ ] **Кнопка «Пригнати такий же»** открывает форму заявки 2.3 с предзаполнением: `source=listing`, `listing_id`, марка/модель/год из объявления, бюджет = результат расчёта, `calculation_id` снимка. Имя и телефон предзаполняются из профиля (как в 2.3). Атрибуция UTM и `page_url` — как в 2.3; согласие на передачу контактов партнёру обязательно (2.1/2.3).
- [ ] **API:** `GET /api/v1/local/listings/<pk>/import-estimate/` — только `active` объявления (иначе 404), throttle-scope `import_estimate` (`THROTTLE_IMPORT_ESTIMATE_RATE`, по умолчанию `30/hour` на IP), результат кэшируется на короткий TTL; ответ не содержит контактов продавца. Каждый вызов создаёт `Calculation` со снимком (как обычный расчёт) либо возвращает кэшированный.
- [ ] Блок не мешает контактам продавца и не вытесняет кнопку «Показати телефон» (мобильная панель 6.6 не ломается).

## Шаги
1. Тесты-сначала (см. «Тесты»).
2. Миграция. **Причина:** справочник оценок цен аналогов (данные, не код; CLAUDE.md, принцип 3).
3. `listing_estimate.py`: входы из объявления + оценка аналога → вызов калькулятора; обработка `MissingRate` (422 → блок без цифры).
4. Эндпоинт с throttle, кэшем и проверкой `active`.
5. Компонент блока, предзаполнение `LeadForm`, дисклеймер, флаг.
6. Админка, `.env.example`, регенерация `docs/openapi.yaml`.
7. Тесты `pricing` и `local_listings`, затем полный прогон один раз; build, tsc, Playwright.

## Тесты
Django:
- Успех: объявление active с оценкой аналога в админке → 200, в ответе `is_estimate: true`, суммы `Decimal`-строками с валютой, курс/дата ставок в снимке, `calculation_id`; результат совпадает с прямым вызовом калькулятора на тех же входах.
- Оценки аналога нет → ответ без цифры (`estimate: null`, причина), статус 200, никаких выдуманных значений; `MissingRate` → блок без цифры, не 500.
- Не-active объявление → 404; флаг `BUY_VS_IMPORT_ENABLED=false` → 404; в ответе нет телефона и контактов продавца.
- Throttle: сверх `THROTTLE_IMPORT_ESTIMATE_RATE` → 429; чужие/неверные входы (отрицательный год, будущий год) не доходят до калькулятора.
- Тест на отсутствие хардкода: изменение цены аналога в админке меняет результат; истёкшая оценка (`valid_to` в прошлом) не используется.
Playwright (`frontend/e2e/buy-vs-import.spec.ts`):
- Успех: на карточке active-объявления с оценкой виден блок, итог «орієнтовно», дисклеймер и дата ставок; «Пригнати такий же» открывает форму, поля марка/модель/год и бюджет предзаполнены, после отправки показывается код AFY-…, заявка в `/me/leads` (залогиненный) с `source=listing`.
- Ошибка/обход: объявление без оценки → цифры нет, есть «Дізнатися вартість пригону»; при `BUY_VS_IMPORT_ENABLED=false` блока нет; отправка формы без согласия → ошибка; прямой запрос `import-estimate` чужого неактивного объявления → 404.
