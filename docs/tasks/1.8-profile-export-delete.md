## Цель
- [ ] `GET /api/v1/auth/me/export/` (IsAuthenticated) — JSON-файл (`Content-Disposition: attachment; filename="autoforyou-data-<дата>.json"`) со всеми данными пользователя (перечень — в шагах), только свои данные; контрагенты — отображаемым именем, без их email и телефона. Throttle-scope `data_export` (`THROTTLE_DATA_EXPORT_RATE`, по умолчанию `5/day`).
- [ ] `DELETE /api/v1/auth/profile/` с телом `{password}` (IsAuthenticated): неверный или пустой пароль → 400; успех (Q3) → 202 с датой `deletion_scheduled_for`: аккаунт ставится на удаление с «периодом отмены» `account_deletion_grace_days` (по умолчанию 14, настройка в админке, `SiteSettings` из 1.12; до её появления — `ACCOUNT_DELETION_GRACE_DAYS` в `.env`). Сразу при запросе: объявления снимаются с публикации, сессии отозваны (`revoke_all_sessions` из 1.7), cookie очищены, письмо «Видалення акаунту заплановано» со ссылкой отмены. Вход в период отмены возможен, `/me` показывает баннер «Акаунт буде видалено <дата>» и кнопку «Скасувати видалення» (`POST /api/v1/auth/profile/cancel-deletion/`; снятые объявления остаются снятыми, владелец публикует их заново сам).
- [ ] По истечении периода ежедневная Celery-задача `users.tasks.anonymize_due_accounts` вызывает `anonymize_user`; после этого вход этим email/паролем невозможен, email и телефон освобождены для повторной регистрации (Q3).
- [ ] Обезличивание не удаляет строки, на которые ссылаются другие люди: сделки, отзывы, переписка, жалобы, платежи остаются (сделки и платежи обезличенными); вторая сторона видит «Користувач видалений» (Q3). Срок хранения обезличенных сделок и платежей — настройка в админке (`SiteSettings`, 1.12): без значения не чистятся; конкретный срок определяет бухгалтер (вопрос в LAUNCH_CHECKLIST, цифру в код и миграции не вписывать).
- [ ] Объявления удалённого аккаунта переходят в архив: статус `deleted` (мягкое удаление из 4.3) без возможности восстановления; пока 4.3 не выполнена — `hidden`, а 4.3 при введении `deleted` переводит такие записи (data-миграция по `owner.deleted_at`). Личные данные в объявлении очищены.
- [ ] Сервис обезличивания — `users/services.py: anonymize_user(user)`, один для API и админки. В админке удаление пользователя заменено действием «Анонімізувати» (`has_delete_permission` → False для `CustomUser`), каскад больше невозможен (06-S11).
- [ ] Перед обезличиванием на email пользователя уходит письмо «Акаунт видалено» (если SMTP настроен; ошибка отправки не мешает удалению).
- [ ] Профиль: страница `/me/profile` — просмотр и правка имени, фамилии, телефона (PATCH `/api/v1/auth/profile/`), ошибки полей видны. Телефон проверяется по формату `+380XXXXXXXXX` (RegexValidator на сериализаторе, 01-S17).
- [ ] Выгрузка включает записи журнала согласий `users.ConsentRecord` пользователя (документ, версия, дата, способ, `lead_public_id`; задача 1.14). При обезличивании/удалении аккаунта записи не удаляются: `user` обнуляется (`SET_NULL`), записи неизменяемы (QuerySet.update/delete запрещены) — обезличивание должно идти через `Collector`/`delete()` пользователя или явный `UPDATE` вне `ConsentRecord.objects`.
- [ ] Страница `/me/data`: кнопка «Завантажити мої дані» (скачивание JSON) и блок «Видалити акаунт» с вводом пароля и подтверждением; после удаления — выход и переход на главную с сообщением.
- [ ] В меню `/me` — пункты «Профіль» и «Мої дані». В `privacy/page.tsx` §6 — ссылка на `/me/data` (полный текст политики переписывает 1.12).

## Шаги
1. Миграция `users`: `CustomUser.deletion_scheduled_at = DateTimeField(null=True, blank=True)` (время запроса удаления, начало периода отмены) и `CustomUser.deleted_at = DateTimeField(null=True, blank=True, db_index=True)`. Причина: отличать удалённый аккаунт от забаненного (`is_banned`) и от просто неактивного, показывать «Користувач видалений».
2. `users/services.py: anonymize_user(user)` в `transaction.atomic`:
   - `email = f'deleted-{user.pk}@deleted.invalid'`, `first_name = last_name = phone = ''`, `telegram_id = None`, `role = buyer`, `is_verified_dealer = False`, `is_active = False`, `set_unusable_password()`, `deleted_at = now()`;
   - удалить: `TrustedShop`, `SavedSearch`, `Favorite`, `Notification`, `TelegramLinkToken`, `DealerApplication` (ФИО, телефон, ссылка на документы);
   - `LocalListing` владельца: `status = deleted` (или `hidden`, пока 4.3 не выполнена; см. «Цель»), `contact_phone = ''`, файлы фото удалить (на фото могут быть номера и дом), записи `LocalListingImage` удалить;
   - `Calculation.user = None` (связь `SET_NULL`, `pricing/models.py:210-213`);
   - сделки, отзывы, переписка, жалобы, `Payment` — оставить (вторая сторона и бухгалтерия); в `Payment` поле `liqpay_raw` не трогать — срок хранения платёжных данных описывает 1.12;
   - `revoke_all_sessions(user)` (задача 1.7).
   Если к моменту выполнения уже есть журнал показов телефона (4.5) или заявки брокеру (2.1) — добавить их в обезличивание и выгрузку.
3. `users/export.py: build_user_export(user) -> dict` — разделы: `profile` (email, имя, фамилия, телефон, роль, `created_at`, `agreed_to_terms_at`, `is_email_verified`, привязан ли Telegram), `trusted_shops`, `dealer_applications` (с `agreed_to_processing_at`), `calculations` (входы и результат), `watched_shipments` (номер контейнера, статус), `local_listings` (все поля, включая `contact_phone`, и URL фото), `imported_listings` (`listings.Listing` как продавец), `favorites`, `saved_searches`, `notifications`, `conversations` (тема, сообщения: свои и адресованные пользователю; собеседник — отображаемое имя), `deals`, `reviews_written`, `reviews_received` (без email автора), `reports_filed` (без данных о чужих жалобах на пользователя), `payments` (сумма, валюта, назначение, статус, даты, без `liqpay_raw`). Список разделов сверить с моделями из 1.12 (перечень данных в политике должен совпадать с выгрузкой).
4. Views: `ProfileView` → `RetrieveUpdateDestroyAPIView` с переопределённым `destroy` (проверка пароля через сериализатор `AccountDeleteSerializer`, затем `schedule_account_deletion(user)`: `deletion_scheduled_at=now`, снять объявления, `revoke_all_sessions`, письмо; очистка cookie хелпером из 1.3); `CancelDeletionView` (сброс `deletion_scheduled_at`); Celery-задача `users.tasks.anonymize_due_accounts` в `CELERY_BEAT_SCHEDULE` (раз в сутки: `deletion_scheduled_at + grace <= now` → `anonymize_user`); `DataExportView` (IsAuthenticated, `throttle_scope = 'data_export'`). 5. `UserProfileSerializer`: `phone` — `RegexValidator(r'^\+380\d{9}$')`, пустое значение разрешено. Имя/фамилия — `max_length` модели, обрезка пробелов.
