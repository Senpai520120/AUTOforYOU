- Связанная желательная **01-S17**: `phone` в профиле без проверки формата (`users/models.py:34`, `users/serializers.py:43-46`) — появляется форма редактирования, валидация нужна сразу.
- **Q3** (`docs/QUESTIONS.md`): что происходит с данными при удалении. Вариант по умолчанию: обезличивание сразу, объявления снимаются, переписка и сделки остаются у второй стороны без ПДн удалённого, без задержки.

## Цель
- [ ] `GET /api/v1/auth/me/export/` (IsAuthenticated) — JSON-файл (`Content-Disposition: attachment; filename="autoforyou-data-<дата>.json"`) со всеми данными пользователя (перечень — в шагах), только свои данные; контрагенты — отображаемым именем, без их email и телефона. Throttle-scope `data_export` (`THROTTLE_DATA_EXPORT_RATE`, по умолчанию `5/day`).
- [ ] `DELETE /api/v1/auth/profile/` с телом `{password}` (IsAuthenticated): неверный или пустой пароль → 400; успех → 204, аккаунт обезличен по варианту Q3, все сессии отозваны (`revoke_all_sessions` из 1.7), cookie очищены, войти этим email/паролем нельзя.
- [ ] Обезличивание не удаляет строки, на которые ссылаются другие люди: сделки, отзывы, переписка, жалобы, платежи остаются; вторая сторона видит «Видалений користувач».
- [ ] Сервис обезличивания — `users/services.py: anonymize_user(user)`, один для API и админки. В админке удаление пользователя заменено действием «Анонімізувати» (`has_delete_permission` → False для `CustomUser`), каскад больше невозможен (06-S11).
- [ ] Перед обезличиванием на email пользователя уходит письмо «Акаунт видалено» (если SMTP настроен; ошибка отправки не мешает удалению).
- [ ] Профиль: страница `/me/profile` — просмотр и правка имени, фамилии, телефона (PATCH `/api/v1/auth/profile/`), ошибки полей видны. Телефон проверяется по формату `+380XXXXXXXXX` (RegexValidator на сериализаторе, 01-S17).
- [ ] Страница `/me/data`: кнопка «Завантажити мої дані» (скачивание JSON) и блок «Видалити акаунт» с вводом пароля и подтверждением; после удаления — выход и переход на главную с сообщением.
- [ ] В меню `/me` — пункты «Профіль» и «Мої дані». В `privacy/page.tsx` §6 — ссылка на `/me/data` (полный текст политики переписывает 1.12).

## Шаги
1. Миграция `users`: `CustomUser.deleted_at = DateTimeField(null=True, blank=True, db_index=True)`. Причина: отличать удалённый аккаунт от забаненного (`is_banned`) и от просто неактивного, показывать «Видалений користувач».
2. `users/services.py: anonymize_user(user)` в `transaction.atomic`:
   - `email = f'deleted-{user.pk}@deleted.invalid'`, `first_name = last_name = phone = ''`, `telegram_id = None`, `role = buyer`, `is_verified_dealer = False`, `is_active = False`, `set_unusable_password()`, `deleted_at = now()`;
   - удалить: `TrustedShop`, `SavedSearch`, `Favorite`, `Notification`, `TelegramLinkToken`, `DealerApplication` (ФИО, телефон, ссылка на документы);
   - `LocalListing` владельца: `status = hidden`, `contact_phone = ''`, файлы фото удалить (на фото могут быть номера и дом), записи `LocalListingImage` удалить;
   - `Calculation.user = None` (связь `SET_NULL`, `pricing/models.py:210-213`);
   - сделки, отзывы, переписка, жалобы, `Payment` — оставить (вторая сторона и бухгалтерия); в `Payment` поле `liqpay_raw` не трогать — срок хранения платёжных данных описывает 1.12;
   - `revoke_all_sessions(user)` (задача 1.7).
   Если к моменту выполнения уже есть журнал показов телефона (4.5) или заявки брокеру (2.1) — добавить их в обезличивание и выгрузку.
3. `users/export.py: build_user_export(user) -> dict` — разделы: `profile` (email, имя, фамилия, телефон, роль, `created_at`, `agreed_to_terms_at`, `is_email_verified`, привязан ли Telegram), `trusted_shops`, `dealer_applications` (с `agreed_to_processing_at`), `calculations` (входы и результат), `watched_shipments` (номер контейнера, статус), `local_listings` (все поля, включая `contact_phone`, и URL фото), `imported_listings` (`listings.Listing` как продавец), `favorites`, `saved_searches`, `notifications`, `conversations` (тема, сообщения: свои и адресованные пользователю; собеседник — отображаемое имя), `deals`, `reviews_written`, `reviews_received` (без email автора), `reports_filed` (без данных о чужих жалобах на пользователя), `payments` (сумма, валюта, назначение, статус, даты, без `liqpay_raw`). Список разделов сверить с моделями из 1.12 (перечень данных в политике должен совпадать с выгрузкой).
4. Views: `ProfileView` → `RetrieveUpdateDestroyAPIView` с переопределённым `destroy` (проверка пароля через сериализатор `AccountDeleteSerializer`, затем `anonymize_user`, очистка cookie хелпером из 1.3); `DataExportView` (IsAuthenticated, `throttle_scope = 'data_export'`). Маршрут `me/export/`.
5. `UserProfileSerializer`: `phone` — `RegexValidator(r'^\+380\d{9}$')`, пустое значение разрешено. Имя/фамилия — `max_length` модели, обрезка пробелов.
6. `users/admin.py`: действие «Анонімізувати» через `anonymize_user`, `has_delete_permission` → False; в `list_filter` — «видалений» по `deleted_at`.
7. Фронт: `meApi.profile.update`, `meApi.exportData` (скачивание через `blob` и `URL.createObjectURL`), `meApi.deleteAccount(password)`. Страницы `/me/profile` и `/me/data` в стиле существующих `me/*`; кнопка удаления активна только после ввода пароля и отметки «Я розумію, що це незворотно».
8. `.env.example`: `THROTTLE_DATA_EXPORT_RATE`. Перегенерировать `openapi.yaml` (только против Postgres).

## Тесты
Django (`users/tests.py`):
- 23-D29: `DELETE profile/` аноним → 401; без пароля и с неверным паролем → 400, данные не изменены; успех → 204, email/имя/телефон/`telegram_id` стёрты, `is_active=False`, `deleted_at` задан, refresh отозван (`token/refresh/` → 401), вход старыми данными → 401; сделка и сообщения второй стороны на месте, в `DealSerializer` и диалоге у второй стороны — «Видалений користувач»; объявления удалённого — `hidden`, без телефона; избранное, сохранённые поиски, уведомления, партнёры, заявка дилера удалены.
- 23-D30: `GET me/export/` аноним → 401; ответ — JSON-вложение; содержит все разделы из шага 3; пользователь A не видит в выгрузке ничего от B, кроме отображаемого имени собеседника; в выгрузке нет email и телефона контрагентов; throttle `data_export` (`override_settings` с `'2/min'`) → третий запрос 429.
- Админка: у суперпользователя нет кнопки удаления `CustomUser` (403 на `/admin/users/customuser/<id>/delete/`), действие «Анонімізувати» вызывает тот же сервис.
- Профиль: PATCH имени и телефона → 200; телефон `abc` → 400 (23-D36); `role`/`is_staff`/`email` через PATCH не меняются (существующие тесты остаются зелёными).
Playwright (`frontend/e2e/account-data.spec.ts`, фикстуры из 0.4, отдельный пользователь на тест):
- 23-P13 успех — правка имени и телефона в `/me/profile` сохраняется после перезагрузки; «Завантажити мої дані» скачивает JSON со своим email (`page.waitForEvent('download')`); удаление с паролем → выход, повторный вход этими данными → ошибка.
- Ошибка/обход — удаление с неверным паролем → текст ошибки, аккаунт жив; кнопка удаления неактивна без пароля; телефон неверного формата → ошибка поля.
