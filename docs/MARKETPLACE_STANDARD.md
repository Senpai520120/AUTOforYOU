# Эталон: что должно быть у зрелой автоплощадки (уровень AUTO.RIA / OLX Авто)

> Справочник для сверки. Это не требование сделать всё сразу: у каждого пункта при сверке
> определяется приоритет — «до запуска» (Запуск), «после запуска» (Рост) или «не нужно» (с причиной).
> Номер пункта (например, B7) используется в отчётах и задачах.
> Везде действует принцип брифа: цены, ставки, лимиты, тексты и ключи — в админке или .env.

---

## A. Справочники и данные

- A1. Справочник марок → моделей → поколений → модификаций (с годами выпуска). Импорт из открытого
  источника + редактирование в админке. Синонимы и нормализация («VW» = «Volkswagen»).
- A2. Справочники: тип кузова, топливо, КПП, привод, цвет, состояние, объём двигателя, мощность.
  Единые для C2C, каталога пригона и бота.
- A3. Регионы и города Украины (по КАТОТТГ), автодополнение, у каждого объявления — город.
- A4. Валюты: USD, UAH, EUR. Хранится валюта продавца, показ в выбранной валюте по курсу НБУ
  с датой курса. Сортировка по цене учитывает пересчёт.
- A5. Формат и валидация: телефон +380, VIN (17 символов, контрольная сумма для североамериканских),
  госномер Украины, пробег (км/мили для пригона), год (не больше текущего + 1).

## B. Подача объявления

- B1. Пошаговая форма (мастер) с автосохранением черновика и возвратом к нему.
- B2. Автозаполнение по VIN или госномеру (через адаптер Opendatabot/NHTSA, без ключа — ручной ввод).
- B3. Поля: марка/модель/поколение, год, пробег, кузов, двигатель, КПП, привод, цвет, город, цена, валюта,
  торг, обмен, растаможен/нет, после ДТП, был ли в такси, количество владельцев, пригнан из (США/Европа),
  VIN (скрытие части от публики — настройка), госномер (частичное скрытие).
- B4. Фото: мин/макс количество (настройка), drag-n-drop сортировка, выбор обложки, поворот,
  сжатие и WebP на сервере, несколько размеров превью, удаление EXIF, водяной знак (настройка),
  проверка дублей по перцептивному хешу, проверка реального типа файла.
- B5. Описание: лимит символов, фильтр телефонов/ссылок/email в тексте (контакты — только через поля),
  фильтр мата и стоп-слов (список в админке).
- B6. Предпросмотр перед публикацией. Понятные ошибки валидации на украинском.
- B7. Лимиты: бесплатные активные объявления для частника, лимит подачи в сутки, один VIN — одно
  активное объявление.

## C. Модерация и антифрод

- C1. Очередь модерации с фильтрами, приоритетом платных, счётчиком ожидания.
- C2. Автопроверки до модератора: стоп-слова, дубль VIN, дубль фото, цена сильно ниже рынка для модели,
  новый аккаунт + дорогая машина, контакты в тексте. Результат — флаги-подсказки модератору.
- C3. Отклонение с причиной из шаблонов (редактируются в админке) + уведомление автору с причиной.
- C4. Повторная модерация при изменении существенных полей (цена ±X%, фото, VIN, марка/модель).
- C5. Жалобы пользователей с причинами. Порог автоскрытия (настройка), разбор модератором.
- C6. Блокировка пользователя: полная, временная и «теневой бан». Причина, срок, журнал.
- C7. Журнал аудита всех действий модераторов и админов (кто, что, когда, до/после).
- C8. Предупреждения о мошенничестве: баннер «не вносите предоплату», подсветка подозрительных
  фраз в переписке (карта, «доставка через службу», внешние ссылки).

## D. Доверие и профиль продавца

- D1. Тип продавца: частное лицо / дилер / автосалон. Бейдж у объявления.
- D2. Верификация: телефон (SMS или звонок через адаптер, без ключа — выключено), email,
  дилер — по ЕДРПОУ/ИНН через Opendatabot (адаптер) + ручное подтверждение.
- D3. Публичный профиль продавца: дата регистрации, число активных объявлений, «на сайте с…»,
  страница автосалона с логотипом, адресом, графиком работы.
- D4. «Перевірений VIN» — бейдж, если VIN сверен с реестром (адаптер).
- D5. История цены на объявлении (снижения видны покупателю).
- D6. Отзывы о продавце — пункт «Рост», если не нужен к запуску.

## E. Поиск и каталог

- E1. Фильтры: все поля из B3, диапазоны (цена, год, пробег, объём), мультивыбор марок и моделей,
  город + радиус или регион, «только с фото», «только проверенный VIN», тип продавца, растаможен.
- E2. Сортировки: дата, цена ↑↓, год, пробег. Платные поднятия учитываются по понятным правилам.
- E3. Счётчик результатов, мгновенное обновление, фильтры в URL (ссылкой можно поделиться).
- E4. SEO-страницы: `/used/<марка>/<модель>/<город>/` с уникальными title/description/H1,
  canonical, пагинация без дублей, пустые страницы — `noindex`.
- E5. Полнотекстовый поиск (PostgreSQL FTS) с морфологией и опечатками (trigram).
- E6. Пустой результат — подсказки («расширьте фильтр», похожие объявления).
- E7. Сохранённый поиск + уведомления о новых объявлениях (email/Telegram, частота — выбор пользователя).
- E8. Недавно просмотренные, похожие объявления на карточке.
- E9. Производительность: индексы под все фильтры, пагинация по курсору или с лимитом, кеш счётчиков.

## F. Карточка объявления

- F1. Галерея: свайп на мобильном, зум, полноэкранный режим, ленивая загрузка.
- F2. Характеристики таблицей, город, дата публикации и обновления, число просмотров.
- F3. Телефон — по клику, для гостей через антибот-проверку, лимит показов в сутки,
  журнал показов (для статистики продавца и защиты от парсинга). Кнопки «Позвонить», Telegram, Viber.
- F4. Написать продавцу (внутренняя переписка), в избранное, поделиться, пожаловаться.
- F5. Разметка schema.org (Vehicle/Offer), OpenGraph и Twitter Card с автогенерируемой картинкой-превью
  (фото + марка + цена): ссылки красиво выглядят в Telegram, Instagram, TikTok, Viber.
- F6. Проданное/архивное объявление: страница остаётся (SEO), с пометкой и похожими вариантами,
  контакты скрыты.
- F7. Блок «Пригнать похожее из США» — ссылка на калькулятор с подставленной моделью
  (связь C2C и пригона).

## G. Жизненный цикл объявления

- G1. Статусы: черновик → на модерации → активно → истекает → архив / продано / отклонено / заблокировано.
- G2. Срок жизни, продление, напоминания (см. ANSWERS Q9).
- G3. «Продано» с опросом, где продали (статистика для владельца площадки).
- G4. Редактирование, снятие, восстановление из архива, удаление.
- G5. Статистика продавцу: просмотры, показы телефона, добавления в избранное, сообщения — по дням.

## H. Личный кабинет

- H1. Мои объявления (по статусам) со статистикой и быстрыми действиями.
- H2. Избранное (с уведомлением о снижении цены), сохранённые поиски, недавно просмотренные.
- H3. Сообщения: список диалогов, непрочитанные, привязка к объявлению, вложения-фото, блокировка собеседника.
- H4. Уведомления: центр уведомлений + настройки по каналам (сайт/email/Telegram) и типам, отписка
  одной ссылкой из письма.
- H5. Профиль и безопасность: смена пароля, email, телефона, активные сессии с выходом везде,
  привязка Telegram, выгрузка данных, удаление аккаунта.
- H6. Платежи: история, статусы, чеки/квитанции для скачивания.
- H7. Мои расчёты и заявки на пригон со статусами.

## I. Монетизация (код готов, цены — в админке)

- I1. Услуги продвижения: поднятие, ТОП на N дней, выделение цветом, VIP-блок на главной.
  Тарифы, сроки, валидность (valid_from/valid_to) — в админке.
- I2. Пакеты и подписка для дилеров: лимит объявлений, скидка на продвижение (пункт «Рост» — если не к запуску).
- I3. Оплата через LiqPay: сумма только с сервера, идемпотентный callback, проверка подписи,
  sandbox-режим, возврат, повторная попытка оплаты, письмо-квитанция.
- I4. **Фискализация.** Проверить у бухгалтера, нужен ли ФОП/ТОВ ПРРО и фискальный чек при оплате
  картой через интернет. Если нужен — адаптер к ПРРО-сервису (Checkbox и аналоги) с выключателем.
  Вопрос владельцу — в LAUNCH_CHECKLIST.
- I5. Промокоды и бесплатное продвижение для первых пользователей (инструмент привлечения, в админке).

## J. Дилеры и B2B

- J1. Заявка на статус дилера → проверка → роль dealer.
- J2. Страница автосалона, все его объявления.
- J3. Массовая загрузка объявлений: CSV/XML-фид по ссылке с расписанием, отчёт об ошибках импорта
  (пункт «Рост», если не к запуску).
- J4. B2B-доска лотов пригона для верифицированных дилеров.

## K. Пригон и брокер

- K1. Калькулятор: пошаговая разбивка (аукцион, сборы аукциона, доставка по США, порт, море,
  растаможка по статьям, доставка по Украине, услуги брокера), дата курса и тарифов,
  пометка «орієнтовно».
- K2. Сохранение расчёта, постоянная ссылка на расчёт, отправка себе на email/Telegram, PDF-версия
  (пункт «Рост», если не к запуску).
- K3. Заявка (ANSWERS Q4) с прикреплённым расчётом и источником (UTM).
- K4. Кабинет брокера — мини-CRM: список заявок, статусы (новая → в работе → договор → авто куплено →
  в пути → растаможка → выдано / отказ), комментарии, назначение ответственного, напоминания,
  отметка времени первого ответа, поиск дублей по телефону.
- K5. Уведомление брокеру: Telegram мгновенно + резервный email. Если Telegram недоступен — повтор
  из очереди, заявка не теряется.
- K6. Клиент видит статус своей заявки и трекинг контейнера в кабинете (и по ссылке без входа — настройка).
- K7. Страницы доверия для пригона: «Як працює пригон», этапы и сроки, FAQ, реальные кейсы брокера
  (фото и цифры добавляет владелец в админке).

## L. Уведомления и коммуникации

- L1. Шаблоны писем и Telegram-сообщений в админке, на украинском, с переменными.
- L2. Очередь отправки с повторами, журнал доставки, защита от дублей.
- L3. Транзакционные письма: подтверждение email, сброс пароля, модерация (одобрено/отклонено),
  истечение срока, новое сообщение, новое по сохранённому поиску, снижение цены в избранном,
  оплата, статус заявки.
- L4. Привязка Telegram к аккаунту (deep link с одноразовым кодом), команды бота, отвязка.
- L5. Настройка тихих часов и частоты дайджестов (пункт «Рост», если не к запуску).

## M. Защита платформы

- M1. Rate limit на все чувствительные эндпоинты (вход, регистрация, телефон, сообщения, заявки, поиск).
- M2. Защита от парсинга: телефоны только по клику, лимиты, отсутствие контактов в HTML и API-списках.
- M3. Антиспам в переписке: лимиты новых диалогов для новых аккаунтов, фильтр ссылок.
- M4. Логи с IP хранятся ограниченный срок (настройка), без паролей, токенов и полных телефонов.
- M5. Секреты: сканирование в pre-commit и CI.

## N. Юридическое (Украина)

- N1. Интерфейс по умолчанию на **украинском** (закон о государственном языке). Другие языки —
  только дополнительно.
- N2. Реквизиты ФОП/ТОВ, контакты и адрес в футере и в оферте (закон об электронной коммерции).
- N3. Оферта, правила размещения, политика конфиденциальности, cookie, возвраты — тексты в админке,
  с версией и датой. При изменении — повторное согласие, если меняется суть.
- N4. Согласия фиксируются: версия документа, дата, способ. Возможность отозвать согласие на cookie
  и маркетинг в интерфейсе.
- N5. Возраст 18+ при регистрации.
- N6. Запрещённый контент в правилах (авто без документов, в розыске, в залоге — по возможности
  проверка через адаптер Opendatabot/МВС).

## O. SEO, маркетинг и аналитика

- O1. Динамический sitemap (объявления, SEO-страницы, статьи), robots, canonical, hreflang при
  нескольких языках, 301 для изменённых URL.
- O2. Сохранение UTM и источника при регистрации, заявке, подаче объявления — чтобы понимать,
  какой ролик в TikTok/Instagram приводит заявки.
- O3. Пиксели Meta и TikTok, GA4 или Plausible — через адаптеры, включаются только после согласия
  на cookie, ID в .env.
- O4. Лендинги под рекламу (пригон конкретных моделей) с быстрым калькулятором и формой заявки.
- O5. Блог/статьи (пункт «Рост») — управление в админке.
- O6. Core Web Vitals: LCP < 2.5 с на мобильном, оптимизация изображений, шрифтов, кеш.

## P. Админка и управление

- P1. Дашборд владельца: новые пользователи, объявления, заявки, конверсия расчёт → заявка,
  выручка, очередь модерации — по дням.
- P2. Управление справочниками, тарифами, шаблонами, текстами страниц, баннерами, FAQ — без кода.
- P3. Роли и права: admin, moderator, broker, dealer, user — принцип минимальных прав.
- P4. Экспорт данных (CSV) для заявок и платежей.
- P5. Статус интеграций: какие адаптеры включены, последний успешный вызов, ошибки.

## Q. Надёжность и эксплуатация

- Q1. Бэкапы БД **и медиафайлов**, проверенное восстановление (скрипт + инструкция).
- Q2. Мониторинг ошибок (адаптер), uptime-проверка /healthz, алерт владельцу в Telegram.
- Q3. Фоновые задачи с повторами и мёртвой очередью. Периодические задачи: курс НБУ, истечение
  объявлений, напоминания, очистка старых логов.
- Q4. Feature-флаги в админке для всех необязательных модулей.
- Q5. Миграции без простоя, откат деплоя одной командой.

## R. UX и мобильная версия

- R1. Mobile-first: основной трафик придёт из TikTok и Instagram на телефонах.
- R2. Бургер-меню, нижняя панель быстрых действий на карточке (позвонить / написать).
- R3. Состояния загрузки, пустые состояния, ошибки (отличать «нет данных» от «ошибка сервера»),
  страница 404/500 с навигацией.
- R4. Доступность: контраст, фокус, подписи к полям, alt у фото.
- R5. Единая дизайн-система: цвета, отступы, кнопки, формы.
- R6. Контакты поддержки и форма обратной связи на каждой странице (футер).
